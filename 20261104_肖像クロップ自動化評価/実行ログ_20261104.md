# 実行ログ 20261104 肖像クロップ自動化評価（J-02）

## 指示
J-02（肖像クロップ自動化）の実現可能性を実測で評価する。testdata/ の人物画像8枚を対象に、顔検出（Haar→アニメ顔LBPの連鎖）→主顔選択→3:4クロップ→600×800 JPEG出力のパイプラインを実装・実行し、結果を正直に記録する。設計判断や研究は行わない。

## 実施
- `crop_pipeline.py` を1本で実装した。処理の連鎖は仕様どおり、Haar(frontalface_default) → lbpcascade_animeface → need_manual の順。全顔を検出し最も大きいものを主顔とする。余白は左右=顔幅60%ずつ・上=顔高45%・下=顔高90%（冒頭の定数）。3:4へ短い辺を広げた後、画像範囲内にクランプする。
- アニメ顔カスケードは `models/lbpcascade_animeface.xml` に取得済み（curl でダウンロード成功、246,945バイト）。スクリプトにも urllib による再取得処理を入れ、失敗時は当該検出器を飛ばして続行する。
- 画像の入出力は日本語パスに対応させるため `np.fromfile`+`cv2.imdecode` / `cv2.imencode`+`tofile` を使用した。

### 実装上の注意（つまった点と対処）
1. 環境に導入済みの opencv-python が 5.0.0 で、Python バインディングから `cv2.CascadeClassifier` が削除されていた（`cv2.data.haarcascades` のXMLは残存）。仕様が Haar cascade を必須とするため、`pip install "opencv-python<5.0"` で 4.14.0.94 へ揃えた（pip 成功、flatt.tech 経由でブロックなし）。
2. OpenCV の FileStorage（CascadeClassifier の読み込み）は Windows で日本語パスを開けない。models/ 配下の実体はそのままに、読み込み時のみ ASCII 名の temp ファイルへコピーして渡す方式で回避した。
3. 笠本縫ル.png は横長(1175×1024)の原図で、3:4に広げたクロップ領域が画像の下端でクランプされる。リサイズ前の段階で厳密な3:4から外れるため、600×800への出力時にやや縦方向へ引き伸ばされる。仕様（クランプ→リサイズ）どおりの挙動であり、目視上の違和感は軽微。
4. 灯篭リュエ.png（油絵様式）で Haar が4件を返した。うち最大のボックスが実際の顔で、残りは絵具の陰影への誤反応とみられる。主顔選択は最大面積のものを採る規則どおりで、出力は正しい顔を中心に収まった。

### 集計
- 全体件数: 8 / ok: 6（率 75.0%）/ need_manual: 2
- 検出器別内訳: haar=5, animeface=1, none=2
- 1枚あたり平均処理時間: 0.213 秒
- 出力JPEGは6枚とも 600×800 を確認。mapping.csv の BOM と8行分の列値を確認済み。
- need_manual の2件（竜宮セツ・詠壽ラカン）は失敗としてそのまま記録した。0件検出を成功扱いにしていない。

### 実測から読み取れる適合範囲
- 実写風・油絵様式の正面顔は Haar で高い反応を示した（6/8）。
- アニメ様式は Haar が不発で、アニメ顔カスケードが補完した（1/8）。連鎖の設計は実効がある。
- 極小顔（遠景人物）と、両検出器が反応しない1枚が need_manual に残った。Haar+アニメ顔LBPの2段構成では処理できない画像がある点が、本手法の限界として明確になった。
