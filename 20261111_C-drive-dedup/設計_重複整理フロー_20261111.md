# Cドライブ 重複データ整理 設計書

- 作成日: 2026-11-11
- 対象: C: ドライブ（承認範囲: 業務データ＋OneDrive/保管庫）
- 方式: 完全一致のみを対象とし、削除ではなく隔離（移動）を経由する
- 現状: 使用 213.16 GB / 空き 24.38 GB / ごみ箱 0.14 GB（183項目）

## 1. 目的と原則

容量の解放と冗長データの整理を目的とする。ただし、次の原則を破らない。

1. 内容が同一と確認できたファイルだけを重複とみなす。名前・類似度・サイズのみでの削除は行わない。
2. 削除は行わず、まず隔離領域へ移動する。復元手順を同時に生成する。
3. 判断に迷うものは残す。削除の取りこぼしより、必要なデータの消失を重く扱う。
4. システム領域、認証情報、患者情報に類する可能性のある領域は対象外とする。
5. 実行は乾式実行（一覧出力のみ）→ 承認 → 隔離移動 → 検証 → 保持期間後の削除、の順とする。

## 2. データ分類と扱い

| 分類 | 主な場所 | 扱い | 実行主体 |
|---|---|---|---|
| A. OS・アプリ管理 | C:\Windows, Program Files, ProgramData, AppData | 対象外。ディスククリーンアップ／Storage Sense に委ねる | OS標準機能 |
| B. 業務成果物・文書 | Documents, Desktop, OneDrive - NK, NK, C:\work | 完全一致の重複のみ隔離。正本を1つ残す | 本スクリプト |
| C. 一時・再生成可能 | Temp, パッケージキャッシュ, ブラウザキャッシュ, ビルド成果物 | 規則で一括削除（再生成可能なものに限定） | OS標準機能／個別コマンド |
| D. コード・リポジトリ | repos, work_vault-clone, worktree | 手動の重複削除は行わない。git gc／パッケージマネージャの清理を使う | 専用コマンド |
| E. 保管庫（Vault） | OneDrive - NK\...\Work_Vault | git 管理下のため原則対象外。ミラーは再取得可能 | vault-sync |
| F. メディア・大容量 | Videos, Pictures, アーカイブ | 完全一致のみ。内容の類似判定は行わない | 本スクリプト（承認時） |

補足: OneDrive 配下の移動はクラウド側の削除として同期される。既定では OneDrive を対象外とし、明示指定時のみ実行する。

## 3. 重複判定の条件

次をすべて満たすものだけを重複とする。

1. ファイルサイズが同一
2. SHA-256 ハッシュが同一
3. どちらもクラウド未実体化（Offline / RecallOnDataAccess）でない
4. リパースポイント（ジャンクション／シンボリックリンク）配下でない
5. 最終更新から7日以上経過している
6. 除外規則に該当しない

除外規則（パス）: `.git`, `node_modules`, `.venv`, `venv`, `__pycache__`, `.cache`, `AppData`, `$Recycle.Bin`, `System Volume Information`, `.tmp.drivedownload`, `.tmp.driveupload`
除外規則（ファイル名）: `.env*`, `*credential*`, `*password*`, `*secret*`, `*token*`, `*.pfx`, `*.p12`, `*.key`, `*.kdbx`, `*.ovpn`, `98_Pass*`

## 4. 正本の選定規則

重複群ごとに1件を正本として残す。優先順位は次のとおり。

1. 保管場所: Documents > OneDrive - NK（対象時）> C:\work > Desktop > Downloads
2. 同一条件なら最終更新が新しいもの
3. それも同一ならパスが短いもの

Downloads は再取得可能な一時置き場として最も低い優先順位とする。

## 5. 実行フロー

1. 基準値の記録: 空き容量、対象件数、対象容量
2. 乾式実行: 重複候補群、削減見込み容量、隔離先を出力（ファイル名は画面に出さない）
3. 承認: 削減見込みと除外件数を確認
4. 隔離移動: `C:\_dedup_quarantine\20261111\` へ元パスを保って移動
5. マニフェスト出力: ハッシュ、サイズ、元パス、残した正本、移動先、日時
6. 復元スクリプト生成: マニフェストから逆移動する `restore.ps1`
7. 検証: 移動件数・容量の一致、サンプルの再ハッシュ、主要プロジェクトの参照確認
8. 保持: 7日間は復元可能な状態で保持
9. 削除: 利用者の最終承認後に隔離領域を削除
10. 記録: 実行ログと結果（削減容量）を残す

## 6. 安全装置

- 乾式実行が既定。`-Execute` を明示しない限り移動しない
- 隔離先が走査対象の内側にある場合は中止
- システム領域・リポジトリ・保管庫は既定で対象外
- 移動前にハッシュを再確認し、一致しないものは移動しない
- 1件でも移動に失敗した場合は中断し、移動済みの一覧を出力
- 同一ボリューム内の移動とし、コピー後の削除は行わない（容量を消費しない）
