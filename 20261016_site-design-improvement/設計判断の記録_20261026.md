## 1. 文書表現の運用方針

全頁で守る表現の規則。根拠は MDN `<strong>` 要素（https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/strong）と WCAG 2.2 SC 1.4.1（https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html）。

- 下線はリンクに限る。`<u>` 要素は使わない。
- 太字は `<strong>`（重要性・切迫性の意味付け）に限る。装飾目的の太字は CSS の font-weight を使う。`<b>` は使わない。
- `<strong>` の用途は空状態と警告の結論文（例: 「条件に合う項目が無い。」）。本文中の語の強調には使わない。
- リンクは色だけで区別しない。本文リンクは下線付き、`.b-links a` は枠線付きで区別する。
- 検証状態の badge（確認済/要補足/未検証/出典なし）は色に文字ラベルを併記する。
- `<em>`・`<mark>`・`<br>` は現状不使用。必要になった時点で方針を追記する。

## 2. 方向別の設計判断（頁から移動した内容）

### 方向A — 静かな資料館

#### home-a（入口）
- 最も大切にする行動: 入り口で全体の規模を知り、一室へ足を踏み入れる
- 入口の型: 展示室の4室。額縁と題箋で誘う
- 0件の扱い: 催事0件を「出来事は年表へ9件」として繋ぐ（イベントページの空状態と同じ理屈）
- 更新日の表示: 更新日を持たない項目を「最新」としては出さない（改善方針 §7 の指示）
- やらないこと: 検索欄の設置（方向B の担当）・照合状態の表示（方向C の担当）
- 不利な点: 目的がある訪問者の近道にはならない

#### catalog-a（目録棚）
- 最も大切にする行動: 帳面を通読する。項目の並びそのものを読む
- 情報の優先順位: ID → 題 → 日付 → 状態。種別の列は省き、題の語感で分からせる
- 検索: 1欄のみ。絞り込みチップは置かない（帳面の体裁を優先）
- やらないこと: 種別棚の分割・関連項目の網・照合内訳の開示
- 不利な点: 種別で探すには向かない。横断の導線は無い

#### chara-a（人物一覧）
- 最も大切にする行動: じっくり読む。一覧を名簿として眺める
- 情報の優先順位: 名 → 役割 → 所属。外見の記述は詳細へ譲り、一覧では出さない
- 空の扱い: 題箋の紋様を細かくし字間を広げる。肖像がないことを隠さず、器として整える
- 外見の記述: 載せない（方向B と真逆の判断。名簿の余白を守る）
- やらないこと: 検索・並び替え・バッジの追加。13人なら絞り込みだけで足りる
- 絵が入ったら: 題箋の面を差し替えるだけ。比率は 3:4 を維持
- 不利な点: 探す速さは現行と同じ。横断の導線は無い

#### events-a（催事）
- 最も大切にする行動: 空の意味を誤解しない。「無い」を「準備中」と読ませない
- 空の扱い: 額縁として整え、隣の室への案内を短く添える
- 行き先: 年表・作品の2本。実在するページのみ
- やらないこと: 予告・予定・開催履歴の捏造。内容を無理に増やさない（改善方針 §7 の指示）
- 不利な点: このページ自体に情報は無い。探索の入口にはならない

#### work-a（作品詳細）
- 最も大切にする行動: 本文を読み切る。根拠は脚注で後から確かめる
- 紙面の型: 本文中心・脚注後置。表を本文の流れに入れない
- 出典の扱い: 脚注番号と確認済の明示。出典なしの記録も明記する
- やらないこと: 関連項目の網（方向B）・主張と根拠の対照表（方向C）
- 不利な点: 根拠の確認が後回しになる。横断はしない

### 方向B — 横断して探す索引

#### home-b（入口）
- 最も大切にする行動: 目的を持って引く・道を辿る
- 入口の型: 検索を正面、棚と道をその下に
- 0件の扱い: 催事0件を棚に「出来事の記録はこちら」として繋ぐ
- やらないこと: 額縁の装飾・展示室の比喩（方向A の担当）。照合状態（方向C の担当）
- 不利な点: 眺めて楽しむ導入には弱い。検索語が無い訪問者は棚へ降りる

#### catalog-b（目録棚）
- 最も大切にする行動: 横断する。作品から人物・用語・出来事へ道を辿る
- 情報の優先順位: 種別 → 題 → 関連。検証状態は方向C の担当
- 読み継ぎの根拠: works.characters・glossary.workId・history.workId（実在確認済み）
- やらないこと: 照合内訳の開示（データが無い接続を網で偽装しない）
- 不利な点: 関連列で表が広くなる。出典状態は出さないので根拠確認は後回しになる

#### chara-b（人物一覧）
- 最も大切にする行動: 探す・比べる・横断する。「あの役割の人」を最短で引く
- 情報の優先順位: 役割・所属 → 外見 → 出演作品。題箋より情報密度
- 読み継ぎ: 出演列 → 目録棚 → 作品。人物から作品・用語へ道が続く
- 肖像の扱い: 省く。絵が入ったら題箋列を復活させる形に戻せる（方向A が担当）
- やらないこと: 額縁の装飾の追加。索引では罫線のみ
- 不利な点: 「肖像画が並ぶ回廊」の見立てから離れる。絵が入った日の再設計は方向A に譲る

#### events-b（催事）
- 最も大切にする行動: 0件の面から、実在する記録へ移動する
- 0件の扱い: 空状態と代替の行き先を明確に分ける。催事と出来事は別物として併記しない
- 行き先の根拠: history.json 9件（実データ）。workId は全て実在
- やらないこと: 催事の告知の捏造。出来事を催事として見せかけない
- 不利な点: 「イベント」という名の面に年表が出る構造は、名と中身のねじれを残す

#### work-b（作品詳細）
- 最も大切にする行動: 作品を起点に横断する。次の記録へ迷いなく進む
- 接続の根拠: works.characters（人物3名）・glossary.workId（2件）・history.workId（1件）・series.workIds（実測済み）。推測の接続は載せない
- 本文の扱い: 詳細本文は最小。横断を主にする
- やらないこと: 脚注の論文面（方向A）・対照表（方向C）。人物→用語の道（データ無し）
- 不利な点: 本文を読む体験は薄い。リンクの数が多いと索引面になる

### 方向C — 根拠をたどる記録室

#### home-c（入口）
- 最も大切にする行動: 記録の信用の度合いを最初に把握する
- 入口の型: 現状の開示 → 記録室
- 数値の出所: このページの数値は sources.json・history.json・catalog.json を開いた時点の集計（実測・群8項14）。固定値を書かない
- やらないこと: 装飾（方向A）・検索（方向B）。データ課題の解決をデザインで偽装しない（改善方針 §4 層3）
- 不利な点: 入り口に数字が並ぶため、初見の訪問者には重く見える

#### catalog-c（目録棚）
- 最も大切にする行動: 根拠を読み解く。状態の裏にある照合の経路を確認する
- 情報の優先順位: 検証状態 → その内訳 → 題・日付
- 日付なし出典: 「出典なし」と同一視しない。日付の有無と照合可否を分けて表示
- やらないこと: 曖昧な一致の自動確認済化。日付の創作
- 不利な点: 開閉の操作が増える。一覧のSCAN性は方向A/B に劣る

#### chara-c（人物一覧）
- 最も大切にする行動: 根拠を確かめる。「この記録はどこに乗っているか」を一覧で判定する
- 情報の優先順位: 検証状態 → 出典 → 出演 → 名・役割。記録の器として並べる
- 検証の源泉: catalog.json の verify 値（照合結果）。出典数では判定しない
- 未照合の扱い: 「未照合（出典の群名から引けていない）」を出典欄に出す。静かに落とさない
- やらないこと: 外見の記述の追加（方向B の担当）。額縁装飾の強化（方向A の担当）
- 不利な点: カードが高く1画面の人数が減る。fixture では人物13人すべて未検証で、バッジの分布は本家データで変わる

#### events-c（催事）
- 最も大切にする行動: 出来事の出典まで辿る。照合の仕組みの差を見せる
- 0件の扱い: 空状態 → 出典つき記録 → 内訳、の3段
- やらないこと: 目録棚の verify を書き換えない。デザインでデータ課題を解決したように見せない（改善方針 §4 層3）
- 不利な点: 「催事」の面に出典の表が出るため、目的が入り組んで見える恐れ

#### work-c（作品詳細）
- 最も大切にする行動: 主張の根拠を確かめる。書かれていない根拠を見抜く
- 紙面の型: 記録 → 主張と根拠の対照 → 照合の内訳
- やらないこと: 脚注論文面（方向A）・読み継ぎの網（方向B）。曖昧一致の確認済化
- 不利な点: 表が増え、本文を読む体験は後回しになる
