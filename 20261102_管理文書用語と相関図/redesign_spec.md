# 相関図再設計仕様(redesign_spec)

- 作成日: 2026-11-02
- 状態: モック完成·ユーザー承認待ち(本仕様は承認後に実装レーンへ引き渡す)
- 対象: LNB管理手順書·PanaCIM管理手順書 共通の相関図(Stage5ベース·両冊同一図)
- 根拠: ユーザー指示「図に関しては、名称やジャンル、アイコンなど、必要最低限の情報に絞り、リストにしたうえで具体的にわかるように、なおかつ、十分な余白を持たせ、視認性を向上すること」·Nielsen 10ヒューリスティクスの静的図面への翻訳·多視点盲評価6役の結果(`評価_多視点_20261102.md`)

## 1. 目的と現状課題

現行の相関図(Stage5)は1頁に全情報(ノード詳細·備考·出典·接続条件)を載せるため、ラベルがノードから遠くに浮き、文字が小さく、備考欄が枠を突き破る。本再設計は情報を「図(概観)」と「リスト(詳細)」の二層に分離し、図は最低限の識別情報のみを持たせる。

現状からの変更点:

1. ノード枠内の詳細文·備考·出典を図から削除し、番号付きリストへ移す
2. 遠隔ラベルをE番号チップ+注記線でノード近傍に寄せる
3. 語中折り(セル内での単語途中改行)を解消する
4. 確定/推定/未確認を線種と枠様式で区別し、凡例に定義を集約する

## 2. 成果物構成(2頁構成)

| 頁 | 内容 | 判型 |
|---|---|---|
| 図頁(2-3) | NR4030様式ヘッダー+帯a/b+ノード19+エッジ18+凡例 | A4横 |
| リスト頁(2-4, 1/2) | 機器ノードリスト(N01〜N19)+運用注記(旧N05)+帯の定義 | A4縦 |
| リスト頁(2/2) | 接続リスト(E01〜E18·E11は未描画)+出典符(T1/T1b/T2/T3)の定義 | A4縦 |

- E11はX02-①持ち越し(会議確認事項)のため図に描画しない。リスト(2/2)に「未描画」であることを明記する
- 旧N05注記ボックスの内容は運用注記ブロックとしてリスト(1/2)へ移す(本文§2.1との重複整理は実装時に確認)
- 評1(作業者)は図とリストの同一紙面を求めたが、19ノード+18エッジ+凡例+様式ヘッダーを文字実効10pt以上で1頁に収めることはできない。このため別頁+番号相互参照(E番号·N番号のチップ)とする。**ユーザー承認を要する判断事項**

## 3. 図面様式

### 3.1 ノード

- 表記: 【分類】+名称 の1〜2行。詳細文·備考·出典は載せない
  - 例: 「【サーバ(VM)】PanaCIMアプリケーションサーバー」「【設備】アンドン/(状態表示)」
- (要確認)接尾辞は図タイトルに付けない。要確認は推定様式(枠の破線)+リストの要確認列が担う(N04·N13·N14に適用)
- N番号チップ: 各ノード左上に白抜き角丸チップでN番号を示す。リストの番号と一致する
- アイコン: Material Symbols。12pt以上で描画する
- 分類別の枠様式(パレットは現行図からの実サンプリング値):

| 分類 | 枠線色 | 塗り | 枠太さ | 線種 |
|---|---|---|---|---|
| サーバ系 | (128,100,162) | (235,222,247) | 1.0pt | 実線 |
| 端末系 | (155,187,89) | 白 | 1.0pt | 実線 |
| 設備系 | (160,82,70) | 白 | 2.25pt | 実線 |
| コンテナ(N01) | (128,100,162) | (235,222,247) | 2.25pt | 実線 |
| 推定 | (128,128,128) | (242,242,242) | 1.0pt | 破線 |
| 外部 | (127,127,127) | 白 | 1.0pt | 実線 |

- N07(LNB)は帯境界跨りを示すため設備系の太枠(2.25pt)を維持する

### 3.2 エッジ

- 実線黒=確定した接続 / グレー破線=推定(未確認)の接続
- 矢頭=データの向きが確定している接続のみ。矢頭位置は経路終端に一致させる(モック製作時に発見した座標系混在バグの教訓は§7に記載)
- E番号ラベル: 白ハロ付き9ptで経路近傍に置く。ラベルは必ず自経路の可視範囲内に置く
- E15/E16のような短い接続は番号タグ(8pt)のみを置く
- N09への問い合わせ線(E09「表示内容の由来?」)は推定(破線)+矢頭+N番号への注記で表現する

### 3.3 帯(ネットワークセグメント)

- 帯a: PanaCIM管理側ネットワーク — 上位網 192.168.30.xx / 帯b: ライン設備側ネットワーク — 内部網 192.168.10.xx/20.xx
- 帯はグレー破線の枠で表現し、帯タイトルチップ(濃灰地·白文字·ボールド)を帯内の空き領域に置く。帯bのチップは左下に置く(N07の帯境界跨り·E05/E06の帯越え線と重ならない位置)
- 帯の詳細なセグメント値·出典はリスト(1/2)の帯行に記載する

### 3.4 凡例

図頁下部に2行で記載する:

1. 実線=確定した接続 / グレー破線=推定(未確認)の接続 / 破線帯=ネットワーク帯 / 矢頭=データの向きが確定 / 枠の破線=推定機器(当Site未確認) / N番号·E番号=相関図リストの項目番号
2. 分類の色見本(サーバ系·端末系·設備系·推定·外部)

## 4. リスト様式(1/2)

- 列構成: 番号 / 名称(図の表記) / 詳細(図から移動) / 要確認
- 名称は図の表記と一致させる(【分類】+名称)
- 詳細列は現行図のノード内文·備考の出典付き全文を収録する。IP·運用条件·出典符(X02-⑪等)を失わないこと
- 要確認列は未確定事項とその台帳番号(X02-⑤⑦⑧⑩⑫等)を記載する。未確定事項を黙って省略しない
- 運用注記(旧N05)は3段落のブロックとしてリスト下部に置く
- 帯行: 帯a/bのセグメント値と出典(T1:-9-/-10-·T1b: ネットワークイメージ.pptx·2026-10-27)
- フッターに(2/2)への参照とNR4030番号を記載する
- 文字サイズ: 実効10pt以上を原則とする。モックの詳細列8.5ptは実装時に10ptへ引き上げ、収まりを見て改頁する

## 5. 白黒印刷への配慮(評1·3·4·6の条件)

分類は色だけに依存しない。次の4手段を併用する:

1. 【分類】接頭辞(テキストで分類を明示)
2. 枠太さの差(設備系2.25pt / その他1.0pt)
3. 線種の差(推定=破線·その他=実線)
4. アイコンの差(分類ごとに異なる図形)

実装時にグレースケールレンダを生成し、分類の判別が保たれることを確認する(§7)。アイコン15種の白黒区別性は評4が最重要未検証項目と位置づけた。白黒レンダで判別不能なアイコンがある場合、代替案(記号の重ね打ち·テキストラベル追加)を評価してから採用する。

## 7. 実装時検証項目

1. validator: HARD違反0(枠突き破り·文字欠け)を維持。交差指摘は現行10件から減少すること
2. 注記線: E番号ラベルのうち経路から離れるものに注記線を引き、結べないラベルは配置しない(評1·4·6条件)
3. 文字折れ: Stage6の残留指摘(語中折り)を全解消する
4. 白黒グレースケールレンダの生成と分類判別の確認(§5)
5. 文字実効10pt以上·アイコン12pt以上(モックの8.5pt部分を引き上げ)
6. NR4030様式枠内への収まり(図: A4横·リスト: A4縦)
7. 相関図_oldの扱い(評2): 承認後に旧図を差し替える際、記録欄の同時復元要否を規定してから実施する。**未決**
8. 版数·改訂履歴·承認記録欄(評5): 本件とは別に整備要。**未決**
9. リスト側の同期手順(評5): 図とリストの両方を更新する運用手順を記録に残す。**未決**

### 実装者向け技術上の注意(モック製作時に判明)

- 座標系の混在に注意: モックスクリプトでは図面座標(pt)→頁座標(pt)の平行移動→px変換の3段がある。矢頭呼び出しでpt座標を誤ってS(=3)除算し、矢頭が頁左上(様式ヘッダー部)に飛ぶ事故が発生した。実装では「座標変換は1か所で行い、描画関数には変換済み座標のみを渡す」こと
- Meiryoのttc index: `meiryo.ttc`のindex 1はItalicである(0=Regular·2=Meiryo UI Regular)。通常文はindex 0、ボールドは`meiryoB.ttc` index 0を使用する。モック初期版はindex 1を指定しており全文がイタリックになった。文字幅計測(tlen)は描画に使うフォントと同一の面で行うこと(相違するとチップ幅が不足する)
- 帯チップは文字幅計測+左右パッド12ptずつ。ラベルの白ハロは自経路·他経路·ノード罫線を背後に隠すため、ハロが本文字面を覆わない位置関係をvalidatorで確認すること
