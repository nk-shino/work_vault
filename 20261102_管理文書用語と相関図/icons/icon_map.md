## 1. スタイルの統一規則

| 項目 | 規定 |
|---|---|
| 書体·スタイル | Material Symbols Rounded / FILL=1(塗り)·GRAD=0·opsz=20·wght=400 |
| 色 | 全種ダークグレー #404040 の単色。背景透過 |
| 装飾 | グリフ単体。枠·影·グラデーションは付けない |
| ファイル形式 | 透過PNG 256×256px(300dpi 記録)。1種別1ファイル |
| 挿入手順 | Excelへ挿入後、縦横比を正方形のまま「図のサイズ」で推奨サイズ(pt)を指定する。引き伸ばしはしない |

スタイル判断の根拠:

- FILL=1(塗り)·opsz=20(小サイズ用の光学サイズ)は線が相対的に太く、12〜16ptへの縮小と白黒印刷で形状が残る。輪郭線のみのスタイルは細線が印刷で途切れる恐れがある
- Rounded はノードの角丸矩形·グレーのコネクタと丸みが揃う
- 色は単色とし、分類(青/黄/緑)はノードの塗り·罫線と【分類】接頭辞テキストが担う(理由は 2. )

## 2. 配色方針と理由

**判断: 全種ダークグレー(#404040)で統一する。分類色(青/黄/緑)に合わせたアイコンは作らない。**

理由:

1. 黄は白黒印刷でほぼ白飛びし、白地の上で消失する。青·緑も中間調に潰れ、3色の区別は印刷条件で保証できない
2. 分類(青=サーバ·表示系 / 黄=PC·操作端末 / 緑=設備·データ保存)は既にノードの色と【分類】接頭辞で伝わっている。アイコンで色を二重化すると、色覚·印刷条件に依存する情報が増えるだけである
3. アイコンの役割は機器種の瞬間認識の補助であり、15種を形状(シルエット)の差で区別する。濃グレー単色は白背景·白黒印刷の両方で最も安定する

ノード自体の配色·分類の割当(10 アクセスポイント·14 ネットワーク帯をどの分類に置くか)は本タスクのスコープ外で、現行図の凡例に従う。

## 4. 再書き出し手順(色·種別を変える場合)

フォントと作業スクリプトは作業用ディレクトリ配下に置いており成果物へは同梱していない。再書き出しは次の手順で行う。

1. フォント取得: `https://github.com/google/material-design-icons` の variablefont 配下から `MaterialSymbolsRounded[FILL,GRAD,opsz,wght].ttf` と同名の `.codepoints` を取得する
2. Pillow でコードポイントの文字をグリフ描画する。軸は FILL=1·GRAD=0·opsz=20·wght=400 に固定し、256×256px の RGBA で保存する
3. 分類色のアイコンが必要になった場合は色指定を変えるだけ(例: 青 #2E75B6·黄 #BF8F00·緑 #538135)。ただし白黒印刷での区別性は失われるため、適用前に 2. の理由を再確認する

## 5. drawio第一層(会議用 箱6+境界2)への転用可否 — 所見

- 可。本PNG(256px·透過·単色)は drawio の画像挿入でそのまま使える。会議用の草案尺度(箱6+境界2)なら縮小劣化は実用範囲内で、白黒印刷でも形状は識別できる
- ただしラスタのため drawio 側での再配色·線幅の変更は効かない。分類色に合わせる·大きく拡大する場合は手順 4. での再書き出しが必要
- 恒常的に drawio で運用するなら SVG 化(単色パス·fill指定)かフォントグリフのテキストシェイプ化の方が拡張性に優れる。実装は別レーンのため判断を委ねる
