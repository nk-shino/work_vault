# 相関図の再設計 第三案(C4モデル風 3図+2リスト)の適用提案メモ

- 作成: 2026-11-02
- 状態: モック完成·検証済み。ユーザー承認待ち
- 対象: PanaCIM管理手順書·LNB管理手順書(両冊)が共通で使う「相関図」の全面差し替え案

## 1. 経緯と要求

1. 現行(Stage5): 1枚のA4横に機器19·接続18を密載。評価の結果、文字·線の密度が高いことが課題になった
2. 第二案(1図+リスト1頁): 図を最低限表記に絞り詳細をリストへ移した。ユーザーの判断は「良くはなったが、まだ納得できない」だった
3. ユーザーの追加指示: 「文字·矢印が重なっている場合は再度作り直し。枠線·矢印·テキスト·アイコンが対象。重なりなしを確実に確認できるまで繰り返す」
4. 本第三案は、図を3枚に分けて密度を下げ、重なりの全排除を検証ツールと目視の両方で確認した案である

## 2. C4モデル記事からの採用ルール

出典: https://zenn.dev/nac/articles/n33467_c4model(C4モデルの解説記事)

採用した考え方と、相関図への翻訳:

| C4モデルの考え方 | 相関図での適用 |
|---|---|
| 図を関心ごとに分割し、1枚に1つの話題 | 全体の関わり(図①)·管理側の内部(図②)·設備側の内部(図③)の3枚に分離 |
| システムコンテキスト図で境界の外と内を区別 | 図①は管理者·作業者·上位システムと2システムの関わりのみ。内部は図②③へ |
| コンテナ図で内部の実行単位を描く | 図②はサーバー·端末と退避·出力先。図③は装置·端末とLNB中心のデータの流れ |
| 関係には番号と短い説明を付ける | E番号+短い説明のラベル。詳細条件はリスト(2/2)で引く |
| 記法の凡例を図の近置に置く | 各図頁の下部に凡例·分類チップ·略語の3行を置く |
| 人間(アクター)とシステムを別表記 | 【人】と【システム】の分類チップと塗り分け |

不採用とした点: C4記事の英語圏向け略語(C4/Cloud等)·ツール前提。様式NR4030の維持を優先した。

## 5. 重なり排除の検証記録

### 5.1 検証手段

生成スクリプト(c4_mock.py)内のチェッカーが、描画と同時に全要素の矩形を登録し、頁内の全組合せを検査する。検出対象は次のとおり。

- 線×線: 厳密な交差(端点の接触·重なりは検出しない)。交差は「許容」として件数表示する(第6節)
- 枠×枠·文字×文字·文字×枠·文字×線·矢頭×各要素·アイコン×各要素·帯境界線×各要素
- 文字がノード内に収まっている場合は可。ノードの枠に掛かる場合は不可
- 各要素の周囲に0.5ptの判定マージンを置く

### 5.2 今回解消した重なり

| 問題 | 解消方法 |
|---|---|
| E03×E14の交差(図③) | N11(LWS)を中段から上段へ移動。E03の横線をN11の下端とN14のチップ上端の間(y=134)に通し、E14を上段の専用レーン(y=76)へ配線 |
| 第1回修正で発生した3つの重なり | 帯境界の判定帯が±1.5pt·ノード番号チップがノード枠の上にはみ出す(上方向6.5pt)仕様を確認し、N11·N14·E03·E14·E13·E10を再調整 |
| 略語行とフッター「様式 NR4030-0300-A3」の文字重なり(全図頁·既存) | 凡例ブロックをy=523へ移動。帯bの下端を内容に合わせて12pt短縮し空間を確保 |
| E04ラベルとCIM-C PCの説明文の重なり(図②·既存) | ラベル描画の座標基準と検査用矩形の基準が一致していなかった不具合を修正(ラベルを指定点中心の描画に統一)。全ラベルの実位置が検査対象に乗った |

チェッカー自体の強化: 凡例3行とフッター3項目を検査対象へ登録した(修正前は検査対象外で、文字重なりが検出できない盲区間だった)。

### 5.3 検証結果

- チェッカー: 重なり0件。交差4件(すべて線と線。次節)
- 目視: 3図の全体表示と、交差部·ラベル周辺·帯境界·フッター周辺の部分拡大を確認

## 6. 残存交差4件の根拠(線と線のみ·許容と判断)

チェッカーの分類上、文字·枠·アイコンの重なりは0件で、残るは線どうしの交差のみである。各交差について迂回経路を検討した結果、次の理由で不可だった。

| 交差 | 位置 | 迂回不可の根拠 |
|---|---|---|
| 図② E02×E16 | (440,256)付近 | E02(N16→N02)とE16(N16→N19)は同じN16の上側から出る。N19の位置とN01コンテナの枠で、出発順の入れ替えや経路の外周化のいずれも他要素との重なりを生む |
| 図② E08×E17 | (556,74) | E08(N02→N10)の終端はN10の左縁のみ。右列の3ノード(N17·N18)へ伸びるE17·E18の縦線群はN02の右縁から扇状に出るため、終端20pt区間での横断が避けられない |
| 図② E08×E18 | (548,74) | 同上。E17·E18の縦線の間隔(8pt)よりラベルと矢頭の回避余地が小さい |
| 図③ E03×E10 | (306,164) | E03はN08の右縁(300,164)への進入が必要。E10の縦線(x=306)はN07の下端からN09への経路として、N08の存在で東側へ寄せるとN12·E14レーンと衝突する |

交差の許容判断は提案時点のもの。承認時に「交差を許さない」方針へ変更する場合は、ノード配置の段階から組み直す必要がある(工程の増加を見込む)。
