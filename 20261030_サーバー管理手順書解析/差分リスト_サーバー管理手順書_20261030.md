## 3. 想定記述ケース(取り入れる場合の書き方)

前提: 自文書の設計(章帯=節見出し・ラベル面=「項目」行・朱注記線=※注記・本文11pt・部分太字接頭辞)に当てはめた記述例。

### ケース1: 頻度別の確認項目(A1)

章立ては頻度を章帯の見出し語にする。既存章(5バックアップ/6復旧/7異常時)の内部に頻度を混ぜない。

```
[章帯] 毎日の確認
[ラベル面] 項目|確認内容|結果
本文: SQL Serverの起動確認
  services.msc で「SQL Server (MSSQLSERVER)」が「実行中」であること。
[朱注記線] ※「実行中」でない場合は 7章 異常時の対応 を参照。
```

### ケース2: しきい値判定(A2)

ラベル面の表ヘッダに合否区分を並べる。

```
[ラベル面の表ヘッダ] 項目|正常|注意|対応
本文行: データドライブ空き容量|20%以上|10〜20%(記録)|10%未満(7章へ)
[朱注記線] ※しきい値は設計値に基づく。根拠は別紙を参照。
```

しきい値の根拠(設計値・過去実績)を明示すると承認時に説明しやすい。

### ケース3: 緊急時の代替手順(A3)

異常時章の分岐の末尾に緊急手順ブロックを置く。

```
本文: 通常の復旧手順で回復しない場合は、緊急手順を実施する。
  ① 対象ファイルを緊急用フォルダへ複製する。
  ② 設定ファイルの参照先を緊急用フォルダへ変更する。
[朱注記線] ※実施後は、変更した設定を必ず元へ戻す。
```

時刻による分岐(当日の午前中/それ以外)は、フローチャートの判定ノードに置くか、見出しで2分割する。

### ケース4: 内部参照(A4)

見出しパスは「章 → 節 → 項」の順につなぐ。自文書の引用行(題目行の様式)に載せる。

```
本文: ■バックアップ → ●自動バックアップの確認 を参照。
```

### ケース5: 連携先の役割表(A5)

構成説明は本文の長文にせず、表形式に整理する。

```
[ラベル面の表ヘッダ] アプリケーション|役割|未起動時の対応
本文行: ベースアプリ|(役割)|APL監視アプリケーションから起動
```
