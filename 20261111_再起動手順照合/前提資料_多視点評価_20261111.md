# 前提資料: 管理書 §10-4 追記の多視点評価

## 1. 検討の位置づけ

Pana-CIM の異常時再起動手順について、現場で使われている旧PDF（17頁）と管理書 §10-4 を照合した。旧PDFのうち管理書に無い「起動後の確認3点」を追記し、古い版・ライセンス通知・印刷物の認証情報の扱いを明記した。この追記が現場で使えるか、管理上問題ないかを評価する。

## 2. 構想と方針

- 管理書はベータ版（0.15）。実機未検証。認証情報は本文に書かない。
- 旧PDFは2019年の画面。ESXi 6.7.0 Update 2（ビルド1361272）、PanaCIM Version 8.8.3.1。現在のESXiはビルド17167734（§4-3-1）。PanaCIMの版とライセンスは要確認。
- 追記の方針: 手順の骨格は変えず、起動後の確認3点を追加する。古い内容は手順にせず差異として説明する。印刷物の認証情報は事実だけ記し、値は書かない。

## 3. 対象

- 管理書 §10-4「異常時のサーバー再起動」の追記分（L737〜L768）、付録A-5（L1020〜L1032）、§14 No.37〜40（L942〜L946）、改訂履歴0.15（L53）。
- 読者: 現場作業者（非エンジニア）、管理責任者。

## 4. 現状

- 旧PDFの17頁と §10-4 の14手順を対応付けた。抜けは起動後の確認3点。
- 3点: (1) アプリの自動起動とサーバーマネージャーを閉じる、(2) タスクバーの緑表示は通常確認不要、(3) サービスコントローラは全緑、2箇所が緑でなくても問題ない、それ以外は再起動ボタン。
- 旧PDFの3・7・10・13頁に平文の認証情報がある。値は本資料にも管理書にも書かない。
- 実機検証は未実施。サービスコントローラの「2箇所」が現在も同じかは未確認。

## 5. 用語と未確定

- CIMC-SV: VMware 上の仮想マシン。CIM-A PC / CIM-C PC: 物理PC。
- ESXi: 仮想化基盤。メンテナンスモードの終了を忘れると仮想マシンを起動できない。
- 未確定: 現在のPanaCIM版、ライセンス契約、サービスコントローラの例外2箇所、旧PDF印刷物の配布範囲、実施者・判断者。

## 6. 運用手順（追記後）

停止（手順1〜6）: 全ライン停止 → CIMC-SVをシャットダウン → ペンギン確認 → メンテナンスモード → ホストシャットダウン → CIMA-SV電源OFF。

起動（手順7〜14）: 電源投入・3分待つ → CIMA-SVログオン → Firefox/ESXiログオン → メンテナンスモード終了 → CIMC-SVパワーオン → コンソールログオン → Route Editer。

起動後の確認（追記）: アプリ自動起動、タスクバー緑、サービスコントローラ全緑（2箇所例外）、再起動ボタン。

差異（追記）: ESXi版、PanaCIM版、ライセンス通知、印刷物の認証情報。

## 7. 技術・運用の制約

- 全ライン停止を伴う。停止判断者の承認が要る。
- 実機は1環境のみ。検証環境なし。
- 認証情報は別紙。印刷物に平文が残る。
- 管理書は Markdown。現場では紙で使う可能性がある。

## 8. 評価の出力形式（全評価者共通）

1. 対象が必要となる条件
2. 不要または不適切となる条件
3. 最大の懸念
4. 根拠と不足情報（推測は「仮定」と明記）
5. 結論を変える証拠
6. 暫定結論（進む／限定条件で進む／代替策優先／保留／不要）と、その条件

分量は600〜900字。多数決は想定しない。異論が残る場合は明記する。
