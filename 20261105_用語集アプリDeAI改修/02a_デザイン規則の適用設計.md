## 0. 7 規則の解釈と適用範囲

## 1. 余白・寸法（規則 1）

### 1.1 余白スケール

| トークン | 値 | 用途 |
|---|---|---|
| `--space-1` | 4px | 最小（タグ内・gap） |
| `--space-2` | 8px | 入力 padding・隣接間隔 |
| `--space-3` | 12px | 表セル横・カード縦 |
| `--space-4` | 16px | カード標準 |
| `--space-5` | 24px | セクション間・hero 横 |
| `--space-6` | 32px | 大きな区切り |
| `--space-7` | 48px | `.is-pending` の左余白（チェック欄分） |

02 の §8 候補（4/8/12/16/24/32/48）をそのまま採用する。**20px 段は設けない**: 現行の 19.2px（1.2rem）は文脈に応じ 16 か 24 へ寄せる（02 §1.1 の置換表どおり）で足りる。段を増やすと選択の揺れが生じる。

### 1.2 対象と対象外

- 対象: `margin`・`padding`・`gap`・`width`・`height`・`min-width`・`min-height`。02 §1.1 の 71 件の置換表を正本とする
- 除外: 罫線の太さ（1/2/3px）、`.sr-only`・`.skip` の画面外座標、`outline-offset`、履歴の点など記号の位置合わせ（-1.5rem・top 8px・点 12px へ丸めて採用。規律の対象外だが値は近傍のグリッド値に寄せる）
- `em` 基準の微細余白は px へ寄せる（02 §7-6 の回答）: `.nav-badge` margin-left 4px・min-width 20px、`.badge` padding `0 --space-2`、`.ai-chip` padding `0 4px`・margin-right 4px、`kbd` min-width 16px。理由: 機械確認（grep）を可能にするため。文字相対の余白は規則 1 の点検から外れる
- `.prop-check input`（一括処理のチェック欄）は 16px の図形とする（現行 16.8px から縮小）。当たり面の拡大はしない（j/k トリアージと Tab で到達できるため、02 §1.1 の 24px 候補より現状同等を採る）

### 1.3 文字スケールと行送り

行送り（line-height）は全要素で 4 の倍数 px に確定する。font-size は規則の対象外のため、現行の rem 値に近い px へ丸める（1px 級の差は許容）。

| 用途 | サイズ / 行送り |
|---|---|
| badge・chip・kbd・dir | 12 / 16 |
| 補助（hint・crumbs・src・tag・thead・メタ・notice） | 13 / 20 |
| 読み（`.reading`） | 14 / 20 |
| 本文・h3・リンク行・`.prev-body` | 15 / 24 |
| h2 | 17 / 24 |
| 定義（`.definition`） | 17 / 32 |
| h1 | 20 / 28 |
| hero の見出し語（`.hw-big`） | 現行 clamp 維持 / 行送り 40px |

コントロールの高さ: input・button は 40px（`min-height` で担保・境界 1px は対象外）。stamp 廃止後の評価ボタン・nav-badge など小型の部品は 32px 基準。

### 2.2 暗テーマの「面なし」設計（02 §7-8 の回答）

暗テーマでは色付きの淡色地を廃止し、状態表現を「面（surface-2）＋アクセントの文字＋アクセントの罫」で構成する。実装は、暗ブロックで `--kuchi-bg: var(--surface-2)` のように地を面値へ再定義し、罫トークンを前景色と同値にする。これにより明暗で同じ規則（`.warn`・`.badge`・diff の add/del）が共有され、テンプレート側の分岐が不要になる。warn・badge・diff add/del の文字は §2.7 の計算値で AA を満たす。

### 2.3 規則 7（パステル）の運用基準

OKLCH（概算値。実装時に自動点検で実測する）で次のように判定する。

| 区分 | 基準 | 判定 |

| a. 面の淡色地 | L ≥ 0.88 かつ C ≤ 0.06 | 明の roku-soft / shu-soft / kuchi-bg / matsu-bg / #d7e9e4 が適合 |

## 3. 文字（規則 6）

### 3.1 配信計画

- 入手元（一次資料・確認済み）: google/fonts `ofl/notosansjp/NotoSansJP[wght].ttf`（9,589,900 バイト・wght 100〜900・license OFL）— https://raw.githubusercontent.com/google/fonts/main/ofl/notosansjp/METADATA.pb 。代替として notofonts/noto-cjk release `Sans2.004` の `16_NotoSansJP.zip`（27,139,567 バイト・地域別サブセット OTF 日本語）— https://github.com/notofonts/noto-cjk/releases/tag/Sans2.004
- 自己配信の根拠: **Windows 11 に Noto は非搭載**（Yu Gothic は標準搭載・Meiryo は機能オンデマンド）— https://learn.microsoft.com/en-us/typography/fonts/windows_11_font_list 。CDN は使わない（訪問者の IP を第三者に渡さない・設計原則）
- 形式: 変数 TTF を woff2 に変換し `static/fonts/` へ 1 ファイル同梱。`@font-face { font-family: "Noto Sans JP"; src: url("/static/fonts/NotoSansJP-VF.woff2") format("woff2"); font-weight: 100 900; font-style: normal; font-display: swap; }`。変数フォントのためウェイト数は容量に影響せず、現行の bold（700）と通常（400）を使う（02 §7-2 の「400/700 の 2 種」候補に対する回答: 変数 1 ファイルで足りる）
- ライセンス: `static/fonts/OFL.txt` を同梱し、Reserved Font Name「Noto Sans JP」を保持する（フォント名を変更しない）
- フォールバック: `"Noto Sans JP", "Yu Gothic UI", "Meiryo", sans-serif`。フォント読込中の一瞬だけフォールバックが見える（swap）
- サブセット化: 任意とする（ローカルアプリで転送は初回 1 回・キャッシュ対象）。変換後のサイズは**未実測**（概算 3〜5MB。未決 4）
- **トークン**: `--font-ui` を上記スタックへ。`--font-mincho`・`--font-num` は廃止（使用箇所 6 種は `--font-ui` へ・数値は `font-variant-numeric: tabular-nums` に一本化）。`--font-mono` は §3.3

### 3.2 根拠となる未確認事項

- Noto Sans JP の `tabular-nums`（tnum）対応は**未確認**（未決 3）。非対応なら数値の桁揃え効果が消えるが、表の数値列は行頭揃え（§6）なので崩壊はしない。Phase 2 で確認する
  - **実測（2026-11-06）**: 配信する変数フォント（google/fonts・NotoSansJP[wght].ttf）の GSUB features は `aalt ccmp dlig fwid hist hwid jp78 jp83 jp90 liga locl nlck pwid ruby vert vrt2` で、**tnum は非搭載**。数値の桁揃えはフォント依存になるが、表の数値列は行頭揃えなので崩壊しない。`tabular-nums` の宣言は将来のフォント差し替えに備えて維持する（未決 3 は解消）

### 3.3 等幅（例外）

### 3.4 `palt` の廃止

### 4.3 配信方式

- `base.html` に inline の SVG スプライト（`<svg hidden><symbol id="i-*">…</symbol></svg>`）を置き、各所から `<svg class="ic" aria-hidden="true"><use href="#i-chevron-right"></use></svg>` で参照する。HTTP リクエストが増えず、単色化（currentColor）とラベル併記の規律（§4.4）を守れる

### 4.4 アイコンの規律

アイコンは必ず `aria-hidden="true"` とし、意味は隣接する可視ラベル（無い場合は `sr-only`）が伝える。装飾としてのアイコンの追加はしない（§5 の削除対象の置き換えに使う分だけに限定）。
