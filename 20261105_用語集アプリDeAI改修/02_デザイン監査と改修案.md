## 2. AI っぽさの監査

### 2.1 グラデーション

対象は 3 箇所（**確認済み**）: ヘッダー罫（:125-129）、body 背景（:91-94）、meter（:472）、favicon。すべて §1.7 のとおり**削除または単色化**。明テーマの地の「かすみ」は辞書の紙の演出だが、生成系 UI の典型的な装飾と読めるため、単色＋罫で構成し直す。

### 2.2 カードの影

`--shadow-1` がボタン・表・カード・統計帯・pager・stamp・review タブ等の**ほぼ全面**に掛かっている（**確認済み**: :271, 189, 222, 265, 291, 416, 484, 508, 521, 532）。影が部品の規格になるとテンプレート感が出る。**案**:

- 影は浮遊面だけに限定: `.bulk-bar`（:415）と `.busy`（:497）、フォーカス時の `--shadow-2`（:407 kcursor）のみ
- カード・表・ボタンは罫＋面の色差で階層を作る（DESIGN.md の「階層の基本は面の色と罫線」に返る）
- hover での浮き上げは無い（現行どおり。:8 の方針は維持）

### 2.3 角丸 10px の一律適用

`--radius: 10px` が hero・表・カード・bulk-bar・empty・confused・evaluate に共通適用（**確認済み**）。しかも 10px は 4px グリッドに乗らない。**案**: 3 種に整理 — 面（カード・表・帯）`--radius-card`、入力・小部品 `--radius-field`、チップ・バッジ `--radius-chip`。候補値 §8（8px/6px/4px）。`--r-pill 999px` は badge・nav・pager・stamp・busy・meter・notice に使われているが、**ピルは廃止**（§2.4）。meter のトラックのみ角丸を残すかは 02a。

### 2.4 ピル型バッジと stamp

- `.badge`（pill＋色点）→ **角丸 4px の小さなタグ**（枠＋淡い地＋文字）。色点は削除（§1.2）。状態色は pastel の kuchi/matsu 系を維持（**保護**: 状態の文字併記）

## 3. 実データで分かった UX の課題と対応案

実データ 14 語での全フロー確認（オーケストレーター記録）とスクリーンショットに基づく。**バックエンドの変更が要るものは「別課題」**と明記する。

### 3.1 語義の見出しに札が 4 つ並ぶ（複数語義で文脈が埋もれる）

現状: 語義見出し行に「状態バッジ・文脈・出どころ・採用者」が横並びし、375 幅では 2〜3 行に折れる（detail-tanaoroshi-dark-375 で**確認済み**）。棚卸＝経理／物流のように**文脈タグだけが語義の区別の決め手**の語で、文脈が他の札に埋もれる。

**デザイン対応（提案）**: 見出し行は「語義 N ＋ 状態タグ ＋ 文脈タグ」に絞り、文脈タグはアクセント色の枠タグで状態タグと視覚的に区別する。出どころ・採用者・AI チップはカード末尾の注記行（muted・小）へ移す。文脈タグが無い語義では行が短くなるだけ。

### 3.2 関連語の内部値「（human）」と関係の向き

- 表示の内部値（`queries.py:148` の `method`、`term_detail.html:88`・`proposals.html:75`）→ §2.8 のとおり日本語ラベルへ（LABELS 追加。web 層。Phase 2 可）
- **向きの誤り**: 関係は片側の語義から登録され、相手側の詳細画面では `relation_type` がそのまま出るため「上位概念→相手」という誤読が起きうる（`queries.py:143-149`）。**別課題**（domain: 読み出し時の向きの反転、または登録時の双方向展開）。表示側は反転後のラベル（broader↔narrower、abbrev_of↔「略語」）を前提に設計し、`synonym`・`related`・`confused_with` は対称表示。UI 単独での暫定対応は不可（誤りを正しく見せられないため、手を入れない）
  → **2026-11-06 適用**: domain の読み出し時反転で解消（`queries.py` に `INVERSE_RELATION_TYPES` を追加、to 側では key を反転）。テスト追加・検証 DB で実画面確認済み（表面実装↔リフロー）

### 3.3 提案キュー 1 頁目が採用できない関係の提案で埋まる

現状: スコア降順 20 件/頁（`app.py:329`・`PROPOSALS_PER_PAGE`）で、頁 1 は BGA ⇔ 不良 等の関係の提案が並び、両端が未登録で今は採用できない。採用を押すと error.html（「関係の両端の語に、先に語義を採用しておく必要がある」・**確認済み**）に遷移する。

**別課題（構造解決）**: ①提案の種類での絞り込みパラメータとフィルタ UI、②既定の並び（語義の提案を先にする等）、③採用失敗時に error.html ではなく提案キューへ理由帯付きで戻す。いずれも app.py 変更。①②の UI デザインは本書 §4.7 に受皿を用意した。
