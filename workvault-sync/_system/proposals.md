## P-011 拡張子の無いファイルの受け入れ手順が無い

**起票 2026-10-07 / 対象: rules.md §6（00_inbox）/ 状態: 未決**

| | |
|---|---|
| 現行 | §6 は「ToDo以外は移動先を決めて移す」のみ。**拡張子の扱いに触れていない** |
| 実体 | 2026-10-02 の `00_inbox` 整理で、**拡張子の無いファイルが8件**出た |

### 何が起きるか

**拡張子が無いと Obsidian がノートとして扱わない。**
リンクも検索も効かず、**保管庫に在るのに読めない状態になる。**

実際に出た8件のうち、`QA` という名前のファイルは中身が
「0確認マクロ 運用確定質問票」だった。**名前からは何か分からない。**
`kohdenGPTノート1`〜`6` は全件が同じ日・同じ主題の検討記録だった。

**社用PCからの持ち出しで拡張子が落ちるようで、今後も繰り返す。**

### 何を決めたいか

**00_inbox で拡張子の無いファイルを見つけたときの手順を §6 に足す。**

1. **中身を読む。**先頭の見出しかフロントマターを見る
2. **`.md` を付ける。**Markdown として読めるなら `.md`。読めないなら中身に合う拡張子
3. **見出しに合わせて改名する。**`QA` のように中身が分からない名前は、見出しの文言へ寄せる
4. **移動先は通常の分類ルール（§5）で決める**

**この作業は Tier A（統合の一部）とする。**拡張子を付けるのは中身を変えない操作で、
間違えても付け直せる。**承認を待つと、読めないファイルが受け皿に溜まる。**

### 根拠

**起票条件「同種の AD-HOC が3回以上」を、1回で8件という形で満たしている。**
`decision-log.md` の 2026-10-02 の行に AD-HOC として記録してある。

**持ち出し経路が変わらない限り再発する。**毎回その場で判断すると、
名前の付け方が人によって変わる。

### 想定副作用

**中身を読んでから改名するので、1件あたりの手間が増える。**
ただし**読まずに `.md` だけ付けると `QA.md` のままになり、問題は解決しない。**

### 推奨

**上の4ステップをそのまま受け入れる。**
**特に3（改名）を省かないこと。**拡張子だけ付けても、一覧から内容が分からない状態は残る。
上の4ステップをそのまま受け入れることを承認する。
