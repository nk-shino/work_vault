## 1. 先に止めたもの：スナップショットが8時間で56 GBに膨らんでいた

**これが今日いちばん急ぎだった。依頼には入っていないが、放置すると数日でD:が埋まる。**

| 項目 | 値 |
|---|---|
| 発見時のスナップショット総容量 | **56.1 GB** |
| 原因 | `参照のみ・読み込み後に削除` が10-07 18:13にでき、**除外に入っていなかった** |
| 太り方 | **世代あたり 6,574 MB。8世代で 52.6 GB** |
| このままの見込み | 60世代 × 6.5 GB ≒ **394 GB**。D:の空き496 GBをほぼ使い切る |

### 根本原因は設計のほう

`snapshot.ps1` の `$xf` は**外す拡張子を並べる拒否リスト**だった。
`.bak` `.whl` `.msi` `.cab` `.dat` `.exe` がどれも入っていなかった。

**拒否リストは「新しい形式が来たら漏れる」側に転ぶ。しかもエラーも警告も出ない。**
`pending.md` G節に「旧パスのままだと世代あたり2GB増えるがエラーは出ない。
黙って太るだけなので気づけない」と既に書いてあり、**同じ形で2度目が起きた。**

### 直し方：許可リストへ反転した

拾う拡張子を列挙する形にした。`.md` `.txt` `.canvas` `.drawio` `.bkp` `.svg`
`.py` `.ps1` `.bat` `.sh` `.bas` `.cls` `.yaml` `.yml` `.toml` `.ini` `.xml`
`.css` `.js` `.url` `.example` `.gitignore`。

**許可リストは「漏れたら拾わない」側に転ぶ。**
守りたいのは書き換わるノート本文なので、**拾い漏れて気づくほうが、黙って太るよりまし。**

| 検証 | 結果 |
|---|---|
| 新世代の容量 | **6,574 MB → 33 MB** |
| ノートの取りこぼし | **0件。**保管庫198 + Zettelkasten215 = 413 に対しスナップショット側も **413** |
| exit code | 0 |

控えは `snapshot.ps1.bak_2026-10-08` に取った。

**太った8世代（52.6 GB）は消していない。**
今日のH:側削除の復元元になっているため。**60時間で自然に世代落ちする。**

## 9. 抽出器のバグを1件直した

xlsxのセルを読む正規表現が `<c\b([^>]*)>(.*?)</c>` だった。
**空セルは `<c r="B3" s="5"/>` と自己閉じで来る。**
`</c>` を待つ形だけで拾うと、**自己閉じセルの属性が「次の本体を持つセル」の中身と組になり、
全体が1つずれる。**

結果 `t="s"` の判定が外れ、**共有文字列の添字が数字のまま出ていた**
