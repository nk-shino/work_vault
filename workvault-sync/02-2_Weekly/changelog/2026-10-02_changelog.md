## 7. 用語集の書式決め直しと新規作成

**既存が「AIっぽくて分かりにくい」との指摘を受けて、書式を決め直した。**

### 何がAIっぽかったか

| 症状 | 実例 |
|---|---|
| 絵文字 | **旧 `CCNA_Glossary.md` は236項目すべてに `🔹` が付いていた。**`rules.md` の「絵文字を使用しない」に反している |
| 免責の段落 | 「本ノートは学習用の整理です」「全定義を一次資料で個別検証済みという意味ではありません」が冒頭に3段 |
| 辞書の定義 | 「異なるIPネットワーク間でパケットを転送するL3装置」。**読んで分かる人は調べる必要がない** |
| 正式名称の欠落 | CCNAは `IPS` `NGFW` の展開すら無い。**AWSと生成AIパスポートには略語索引があった** |
| **直訳がどこにも無い** | **全7本に無かった。**本人の明示的な要求 |

### なぜ直訳を入れるのか

**技術用語が覚えられない理由は、それが意味のない文字列に見えているから。**
`Elastic Compute Cloud` を「EC2」として覚えると暗記対象が3文字の記号になるが、
「伸び縮みする・計算する・雲」と読めれば**名前そのものが機能の説明になる。**
`Elastic` を一度ほどけば `Elastic Block Store` も `Elastic Load Balancing` も
ただで読めるので、**1語ずつ覚えるより安い。**

### 決めた書式

項目ごとに **正式名称 / 直訳 / 意味 / 混同** の4行。表にしない（横に広がると直訳が削られる）。
規約は `06_Tools/用語集/_用語集の書き方と回し方.md`。

### 置き場の整理

**`06_Tools` 直下に学習用語集20件が混ざっていた**（§4で要検討としていたもの）。
`06_Tools/用語集/` を作って移した。**`06_Tools` はツール手順の置き場**なので、
直下に残るのはクローラー・リモート接続・個人フォルダ更新スクリプトの7件だけになった。
