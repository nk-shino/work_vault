# Daily Report 2026-09-07

## 今日の狙い
棚卸しの仕様書と図解を仕上げつつ、松井さん向けの確認事項を実際に送れる形に整える。あわせて、ヒアリング録音を自分で文字起こしできる環境を作る。

## やったこと

### 棚卸し作業全般のタスク設計
何を
- 倉庫移動SQLだけに閉じていた前回のタスク整理を、設備操作から棚卸し完了までの全工程に広げ直した。事前準備、上流データの確定、照合と失敗リスト処理、カウント、データ反映、後処理という骨格でまとめ、idouSQLはデータ反映の一工程として位置づけた。
結果
- 当日の着手順と、静かに事故りやすい箇所がひと目で追える形になった。移動先コードの確定を全工程の最優先に置いた。
成果物 [[固定テーブル棚卸し作業_全般タスク設計]]
状態 Done

### 仕様書・図解の矛盾点の洗い出しと修正
何を
- 仕様書と図解、実機の計算機で記述が食い違う箇所を突き合わせた。移動先コードは仕様書が202、実機シートが201、図解は食い違いを認めたまま、と三者で割れていた。SSMGという誤記、在庫cgiのホスト名の欠落も見つけた。
結果
- 移動先コードは製品ごとに異なるという前提が新たに出たため、固定値202をやめて対応表を参照する形へ改める方針にした。データフロー図と判断フローのidouSQL説明を、トランザクション安全化まで含めた粒度に揃えた。判断フローには、要確認BOXと例外パターンへ抜ける破線をPDF根拠で追加した。

### Whisperによる文字起こし環境の構築
何を。社用PCにfaster-whisperをローカルで入れ、ヒアリング録音を文字起こしできるようにした。仮想環境の有効化やモデル未定義など、いくつかのエラーを一つずつ潰した。固有名詞の置換辞書とinitial_promptを組み込み、竹渕さんの打ち合わせ録音を22分の最後まで通した。
結果。人名と専門用語の誤変換は残るが、話の骨格は追える精度になった。この録音から今後のテーマ分担の議事録を起こした。
成果物 [[議事録_今後のテーマ分担]]
状態 Done

## 決めたこと・決まっていないこと
確定
- 移動先コードは製品ごとに異なる前提とし、固定値ではなく対応表を参照する形に改める。
- idouSQLの改修はUPDATE本体を変えず、トランザクションとバックアップで安全化しただけで、破壊的変更はない。
- 0確認は棚卸しの一部として扱い、手順を仕様書へ明文化して誰でも実施できる状態にする。

保留
- 各製品の移動先コードの実値。資料に混在する201、202、208がどの製品に対応するかは未確認。
- テーブル番号14を除外する理由、TEC56が照合で在庫数列を参照していないか。詳細は [[07-1_棚卸/固定テーブル棚卸し_詳細設計・仕様書]] の未確定欄へ集約。
