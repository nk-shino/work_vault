# SMT・THTと可視化システム　基礎整理

## この資料の位置づけ

竹渕さんから渡された可視化システムのテーマ（[[議事録_今後のテーマ分担]] 2026-08-21）は、SMTとTHTの2本に分かれている。指示は「SMT側はほぼ完成形にしたい、THT側は工程情報の追加でこれからリニューアルが必要」だった。

着手する前に、この2つが何を指すのか、そしてなぜ片方だけ先に形になっているのかを押さえておく。結論から言うと、**工法の違いがそのままデータの有無になっている。** これが分かっていないと、THT側を「SMTと同じ作り方で追いつかせる」という方向に進んでしまう。

---

## SMTとTHTは、基板に部品を載せる2つの工法

### SMT（表面実装・Surface Mount Technology）

基板の表面にあるランドへはんだペーストを印刷し、その上に部品を置き、リフロー炉で一括して溶かして接合する。基板に穴を開けない。

- 部品はテープに巻かれたリールの状態で供給される。
- 実装機がノズルで1点ずつ吸着し、所定の座標へ置く。
- 小さく軽い部品ほど向く。高密度で速い。

### THT（挿入実装・Through-Hole Technology）

部品の足（リード線）を基板の穴に差し込み、裏面からはんだ付けして固定する。

- 機械的な強度が高く、熱と振動に強い
- コネクタ、大型の電解コンデンサ、トランスなど、力がかかる部品や背の高い部品に残る
- 手挿入か専用のインサータで行う。SMTのような汎用の実装機は使わない

SMTが主流になった今もTHTが消えないのは、この強度が理由。抜き差しされるコネクタをSMTで付けると、ランドごと剥がれる。

## なぜSMTだけ可視化が進んでいるのか

ここが今回の要点。

**SMTの実装機は、装着の1点ごとにカウンタを回している。** しかもノズル単位・フィーダー単位で。PowerBIフォルダにある実データの列がそれを示している。

### ノズル情報（18列）

|     | 列                                                               |
| --- | --------------------------------------------------------------- |
| 識別  | パス / レポート開始日 / 基板名 / 指図 / 品目 / 面 / 設備 / ヘッド / ノズル位置 / ノズルシリアル番号 |
| 計数  | 吸着回数 / 実装回数                                                     |
| 異常  | 吸着ミス / 厚みミス回数 / 認識エラー回数 / 実装エラー / 部品落下エラー停止回数 / 転写ユニット部品落下エラー   |

### フィーダー情報（21列）

| | 列 |
|---|---|
| 識別 | パス / レポート開始日 / 基板名 / 指図 / 品目 / 面 / 設備 / Z/PU番号 / フィーダーバーコード / 材料バーコード / 部品番号 / ベンダー / ロット番号 |
| 計数・異常 | ノズル情報と同じ8列 |

### 設備ステータス（11列）

号機×時間で、実稼働時間 / 部品切れ時間 / 設備エラーダウンタイム / 機種切り替え時間 / 前工程待ち時間 / 後工程待ち時間。

つまり「どのノズルが吸着ミスを出すか」「どのフィーダーで認識エラーが出るか」「どの号機がどの理由で止まっているか」を、**人が何も記録しなくても機械が勝手に残している。** 可視化はその集計にすぎない。`SMT設備データ可視化_作業用.pbix` が成立しているのはこのためで、作った人が偉かったからではなく、材料が最初から揃っていたからである。

**THTにはこれが無い。** ノズルもフィーダーも存在しない工法なので、同じ粒度のカウンタが出ようがない。手挿入なら、そもそも機械が数えていない。

竹渕さんが THT について「工程情報の追加でこれからリニューアルが必要」と言ったのは、ここを指していると読める。THT側は、**まず何をどこで記録するかを人が決めないと、可視化する対象そのものが存在しない。** SMT側の作り方をなぞっても追いつかない理由がこれ。

## 棚卸しの仕事と繋がりそうな点

フィーダー情報の10列目が「材料バーコード」、11列目が「部品番号」。

固定テーブル棚卸しでは、セットアップレポート取り込み後の9列目＝材料バーコード、10列目＝部品番号を突き合わせに使っている（[[07-1_棚卸/固定テーブル棚卸し_詳細設計・仕様書]] §4）。**同じ名前の列が、隣り合う同じ並びで出てくる。** どちらもPana-CIM由来なので、同一データの別出力である可能性が高い。

同じ識別子なら、実装機のフィーダーデータと在庫のシリアル照合を同じキーで繋げる。ロス情報をEGProへ戻す経路の調査（継続テーマ）とも接点ができる。

**要確認。** 名前が同じでも桁数や採番規則が違えば繋がらない。実データで突き合わせる。
