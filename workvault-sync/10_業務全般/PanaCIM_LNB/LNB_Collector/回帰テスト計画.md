# 回帰テスト計画・結果 — LNB Collector v6.5-review

## 1. 目的と運用シナリオ

v6.5-review の改修(6点)が**今回の運用(L1/L2/L3 端末での USB 収集)で壊れていないこと**を、
作業用PC(環境A)で実施可能な粒度で確認する。運用は次のシナリオを想定する。

| シナリオ | 運用での流れ | 環境Aで検証する範囲 |
| --- | --- | --- |
| S-1 初回USB準備 | `Register_USB.cmd` → 登録 → `PREPARE_USB.cmd` | CMD→PS1 の起動と終了コード伝播 |
| S-2 事前確認 | `TEST_LNB.cmd` → 自己テスト14ケース | 全ケース PASS・exit 0 |
| S-3 収集実行 | `Run_LNB.cmd` → YES → 収集 → XLSX → COMPLETE | 関数単位の正常系(収集は実機依存のため代替) |
| S-4 異常時 | USB交換/マーカー改変/出力先改変 → 停止・部分出力 | 異常系の拒否動作と COMPLETE.txt 非生成 |
| S-5 改修箇所の退行確認 | v6.4.3 で動いていた動作が v6.5 で同等に動く | 改修6点とその周辺 |

## 2. テスト項目

### T-1 自己テスト回帰(S-2)
`-TestOnly` の14ケースが全PASS(改修により退行していない)。**既合格(v6.5 改修直後に実施)**。

### T-2 CMD起動伝播(S-1)
4種のCMDが正しいスイッチでPS1を起動し、終了コードを伝播する。
- `Register_USB.cmd` / `PREPARE_USB.cmd` / `TEST_LNB.cmd` / `Run_LNB.cmd` の引数照合(静的)+実行時伝播(動的)

### T-3 CSV/安全化ユーティリティ回帰(S-3, S-5)
`Safe` / `CsvText` / `MruPath` / `DocPath` / `Suspicious` を実データ想定値で検証:
- ラベルxlsx風パス(通常/UNC/角括弧)、URL・ADS・機微名称の拒否
- MRU値 `[F0000001][T01ABCDEF]*C:\...\a.xlsx` の抽出
- 式注入(`=cmd`, `@x`, `+1`, `-1`)の防御
- 空DataTableのヘッダー保持

### T-4 出力サブシステム回帰(S-3, S-4)
疑似USBルート(NTFS一時ディレクトリ)を使い `EnsureSafeDir` / `PathHasReparse` / `WriteAllTextVerified` を検証:
- 正常作成(data\LNB_調査\L1_...の一段ずつ作成)
- ルート外脱出の拒否、出力内junctionの拒否
- 書込→読戻し一致、UTF-8 BOM 付与

### T-5 USB識別ロジック(S-4、環境Aで可能な範囲)
- スクリプトがUSBルート以外に置かれた場合の `GetUsbIdentity` 停止(疑似ドライブルートで模擬)
- マーカー書式の生成/検証(LNB-USB-ID-v1, GUID, DiskSerial, VolumeSerial, RootMarker)の正規表現一致

### T-6 依存検証ロジック(S-4)
- `ValidateDependency` の前提: manifest不在→throw、版不一致→throw、reparse→throw
- 環境Aでは ImportExcel 実体がないため、疑似モジュールフォルダで manifest 読取部のみ検証

### T-7 帳票構成の退行確認(S-3)
- 13シート構成定義(10収集+Metadata/SelfTest/Status)、列数定義、0件時ヘッダー保持
- `$metaCopy` に確定値(Finished/Completion)が入ること(改修#5)

## 3. 合否基準

- T-1〜T-7 の全ケースが期待結果であること(1件でも不一致なら不合格)
- 異常系は**必ず throw/exit で停止**し、完了扱い(COMPLETE.txt 相当)にならないこと

実行結果は `回帰テスト結果_20261013.md` に記録する。ハーネスは `regression_test.ps1`(環境A専用、本番USBに配置しない)。
