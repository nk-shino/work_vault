# マウントプログラム(DGS) 手順書の様式分析

**目的**: 既存の作成済み資料(Pana-CIM/LNB 管理手順書草案)を本資料に沿った形式へ当てはめるため、本資料で情報がどのような状態で扱われているかを抽出する。

**対象**: `02_参照元/マウントプログラム(DGS)/0494-913473 実装プログラム手順(DGS)_P1.xls`(表紙・付表1) と `0494-913473 実装プログラム手順(DGS)_P2.xlsx`(本文、2026-03-04 版)。`old/` は参考(旧版 5 件)。

## 2. シート分類と頁構成

| 分類 | シート | 形式 |
| --- | --- | --- |
| 導入 | はじめに | 【目的】【適用範囲】の 2 項目のみ(B7/B11 に 1〜2 行ずつ) |
| フロー図 | 試作フロー/設計変更_部品フロー/設計変更_改版フロー/新製品フロー | **図形(shape)とコネクタ(cxnSp)で描くフローチャート**。17/16・10/11・10/10・9/9 個。図形内にテキスト、遷移先はセル Z 列に「➡シート名」で併記 |
| 個別手順 | マウントデータ作成〜パーツ_その他設定の 29 シート | 手順番号付き本文+スクショ画像 |

- フロー図の分岐テキスト例: 「新しい基板？」(YES/NO 分岐)
- 1 シート=原則 1 頁。長い手順は **約 55 行ごとに改ページし、「作業内容」ヘッダ行(A 列=作業内容、G 列=シート題目)を再掲**して継続(改ページは row_breaks で明示。再掲間隔 54〜55 行)
- 例: マウントデータ補正角度確認(335 行)=ヘッダ再掲 6 回

- グリッド線は表示のまま。ズーム設定なし

## 4. 手順本文の記載規則(事実)

### 4.1 手順番号

- 形式: **「1．」全角読点区切り**の連番(A 列)。本文は同じ行の C 列〜へ続きを書く(例: A6=1．、C7〜C8=補足)
- 手順間は空行 1〜数行で間隔を空ける(行高 12.8pt のまま詰めない)
- 途中のページ(約 55 行)を跨ぐと番号は**通しで継続**(ダミーコード採番: 1,2,3,5,6 → 4 は画像のみの行が本文を兼ねる)
- 「はじめに」シートのみ手順番号なし

### 4.2 文体・表現

| 規則 | 例(実文) |
| --- | --- |
| 文末は**「します」で統一**(である調・だ調は不使用) | 「DGSコンソールアイコンをクリックします。」「ユーザー名に「admin」、パスワードに「pass」を入力し、ログインをクリックします。」 |
| 画面要素は**「」で括る** | 「データベースユーティリティ」→「バックアップ」 |
| UI の値入力は**「名前：」のコロン形式** | 「PCB名：に型式を入力し」 |
| 補足・条件は**行頭に「＊」または「※」** | 「＊既存の基板と同じ場合は、PCBを流用可とします。」「※型式のx以降は削除してください。」 |
| 注記の詳細は「※1〜※5」と番号付注 | 「※1　サイズ、極性位置、梱包仕様のわかるページを添付します。」 |
| 遷移先は**「➡シート名」** | 「➡マウントデータ作成」「➡ジョブ作成、SD作成」 |
| 別紙参照は「➡〇〇手順は別紙参照」 | 「➡差分出力手順は別紙参照」 |
| 完了条件を手順の最後に書く | 「8．以下のフォルダにファイルが作成されていれば完了です。」 |
| 例示は「例」ラベル+小表 | 例: 基板図番 ****-912345 ⇒ マウントデータ名 912345_00 |
| パスは**実パス(\\\\nksv250\\...)をそのまま掲載** | パス掲載シートは 14/34 |
| 全角数字の項番・全角括弧(ＤＧＳ)(Ｍ－ＢＯＭ)が混在 | 表紙・見出しで使用 |

### 4.3 表形式の使い方

- 「指示書作成、その他」シートに**条件別の必須/任意マトリクス表**がある(行=添付資料 9 種、列=試作フェーズ 5 種(維持改良 M**/コンセプト試作 C-**/量産試作 UT,UR/量産維持 R**)、セル値=必須/不要(×)/条件付き添付)
- 項目×条件のマトリクスでは、条件を**記号(M**/C-**/UT,UR/R**)**で表現
- セル内改行(Alt+Enter)で長い条件を折り返す

### 4.4 画像(スクショ)

- **PNG 147 枚+JPEG 7 枚=154 枚**が 28 シートに埋め込み(Openpyxl の images API ではカウントされない旧式アンカーを含む)
- 配置ルール: **手順番号の直下・手順本文の右脇(C 列〜)に該当画面のスクショを貼る**。手順テキストと画像が 1 対 1 で対応
- 手順 4 のように**画像のみで本文を兼ねる手順**がある(操作の見た目がすべての情報になる)
- 画像サイズ: 最小 0KB〜最大 633KB・中央値 54KB

### 4.5 フローチャート

- Excel 図形(四角形)+コネクタ(矢印)で描画。**セルに手順を書かず図形が主**
- 分岐判定は菱形テキスト「新しい基板？」+ YES/NO ラベル
- 各処理ボックスの下に「➡シート名」をセルに併記し、フロー→個別手順への導線を二重化

## 5. 印刷・ページ設定

| 項目 | 事実 |
| --- | --- |
| 用紙向き | **縦向き 33 シート/横向き 1 シート(現場立ち合いのみ横向き+fitToPage)** |
| 拡大縮小 | **スケール指定なし(fitToWidth/fitToHeight も未設定)**。縦向き A4 に約 55 行が入る行高設計(12.8pt) |
| 余白 | 左 0.87"/右 0.51"/上 0.59"/下 0.79" |
| フッタ | 左「　　NR4030」/中央「様式 NR4030-0300-A3」/右「&P(頁番号)」。右上に「日本光電」 |
| 改ページ | 手動改ページ(row_breaks)で約 55 行ごとに区切り、継続ヘッダ(作業内容+題目)を再掲 |

## 6. 版管理・変更管理の実務

- P1(表紙)に変更履歴を集約: 変更記号 01→02→03 はすべて「書替」(部分改訂ではなく全面書き替え)。適用は「089」「定期見直し」(管理 No と定期見直しの 2 種のきっかけがある)
- 初版枚数 55 枚 → 総枚数 93→118→119 枚とシート増加の履歴
- 本文(P2)側に改訂履歴を持たない。**現行草案の「改訂履歴シート」は本様式では P1 に相当**
- ファイル名の版慣習: `old/` に yyyymmdd_接頭辞付きの旧版(200527/200706/210701/260304)を保存。PDM→PLM への名称変更(旧 PDM照合/PDM設定 → 新 PLM照合/PLM設定)も版で反映

## 7. 情報の状態で特徴的な事実(移行時に留意)

1. **認証情報が平文掲載**(DGS起動 手順 2: ユーザー名・パスワード)。本書は限定的配布前提。**草案へ移す際は伏字方針(付録A と同じ扱い)を適用**
2. **社内サーバーの実パス**(\\\\nksv250\\富岡（株）_実装\\...)が手順の本体情報。環境依存の強い情報であり、草案では記載可否の判断が要る
3. 個人フォルダの表記は「##個人フォルダ##」とプレースホルダ化
4. 完了条件を明示する書き方(「〜していれば完了です」)が手順の締めの定型
5. 型名・管理番号欄は空欄運用(ZZZ-90000 は表紙のみ)。**欄の値をシートごとに書き換えない**運用

## 9. 判定できない事項(次回以降の確認)

- 「ＺＺＺ－９００００」の付番規則と管理番号 0494-913473 の関係(ZZZ-90000 は仮番か実番か)
- 変更履歴の「089」の意味(管理 No/製造 No/頁番号のいずれか)
- 横向き 1 シート(現場立ち合い)だけ fitToPage な理由(表の幅ゆれ対策か)

## 10. 一次根拠(分析に使った実測)

- シート数/行数: openpyxl 実測(P2: 34 シート、最大 544 行×70 列)
- フォント: Meiryo UI 16pt(A1)/10pt(本文)を複数セルで実測
- 列幅/行高: column_dimensions(A=1.9)/row_dimensions(2-4=33pt、6 以降=12.8pt)実測
- 罫線: ヘッダー枠外周 medium・内側 thin を A3/G4/AC2/AZ2 等で実測
- 画像: xl/media 154 ファイル(PNG147/JPEG7)、drawing アンカー実測(DGS起動: 手順直下の行 7/13/34 に配置)
- 図形: drawing XML の xdr:sp/xdr:cxnSp カウント実測(試作フロー 17/16)
- 文体: 手順文 24 シート分の行頭パターン(全角読点番号/＊/※/➡)を正規表現集計
- フッタ: oddFooter 実測(左 NR4030/中央 様式 NR4030-0300-A3/右 &P、右下 日本光電)
- 版差分: old/260304(32 シート)と現行(34 シート)のシート名集合差分実測(PDM→PLM 名称変更)
