# チェックシート 判定基準の持ち寄り案(2026-10-14 会議用)

**目的**: 会議記録 §12「チェックシート三項目の判定基準を持ち寄る」に応える案。
**注意**: しきい値の数値は実機画面を見て確定させるため、本書は「決め方の提案」であり確定値ではない。
(草案の方針「判定基準を創作すると、異常を正常と読む文書になる」を踏襲)

---

## 1. 稼働状態の確認(日次)

| 項目 | 提案 |
| --- | --- |
| 見るもの | 稼働モニタの表示、アンドンの表示 |
| 正常とみなす状態(案) | 稼働モニタ: (正常画面名を記入する枠)が表示されている。アンドン: 停止・予告の色が出ていない |
| 記入方法 | 正常なら「○」。異常があれば画面の文言をそのまま記入+不具合記録の番号 |
| 実機で決めること | ①稼働モニタの「正常と判定する画面名」②アンドンの色定義表 |

## 2. バックアップ結果の確認(日次)

| 項目 | 提案 |
| --- | --- |
| 見るもの | 最終実行日時と成否の表示 |
| 正常とみなす状態(案) | 「データベース完全バックアップに成功しました。」の表示があり、**最終実行日時が前日以内** |
| 異常とみなす状態(案) | 「4日以上前のバックアップが存在する(DBCleanBackup)」の表示 → **この時点で確認者へ連絡(運用としては1日でも遡ったら要確認としてよいが、まず実機の表示挙動を確認)** |
| 記入方法 | 最終実行日時(日時まで)+成否 |
| 実機で決めること | 遡りのしきい値(提案: 2日で注意、4日で異常連絡) |

## 3. 保存領域の確認(日次)

| 項目 | 提案 |
| --- | --- |
| 見るもの | 空き容量の数値と前回からの増加傾向 |
| 正常とみなす状態(案) | 空き容量が (しきい値を記入する枠)% 以上 |
| 異常とみなす状態(案) | しきい値を下回る、または1週間で急激な減少(数値は実機の増加傾向を見て決める) |
| 記入方法 | 数値をそのまま記入(○×にしない) |
| 実機で決めること | しきい値(%) |

---

## 4. 未決の論点(会議記録 §7「これ以外に検討する論点」への回答案)

| 論点 | 提案 |
| --- | --- |
| 復旧の確認 | 「取得できていても戻せるかは別」。戻す試験の手順と実施条件を §9 復旧で確定してからチェックシートに組み込む。初回は試験自体を「定期作業」として実施日を記録する欄だけ設ける |
| LNBの点検項目 | 相関図と並行して現行実施者へ聞き取り。まず「LNB接続状態の表示確認」を候補 Step 1 として置く(草案 §6) |
| 記録の確認者 | 日次は(実施者)が記入し(確認者)が翌営業日までに確認。確認者は管理体制が確定した時点で記入 |
| Windows更新後の扱い | RPA機と同じ「更新の翌日に再起動」を採用するか → **会議で決定すること(未決)**。採用する場合、月次チェックシートに「Windows更新後再起動」の行を追加 |
| 随時再起動 | 記入欄を設ける。月次チェックシートの下に「随時実施の記録」欄を追加(実施日時/実施者/同席者/発動条件/結果)。承認者の記入が無い行は実施していないものとして扱う(草案 §13-4 と同じ原則) |

## 5. 会議で確定すべきこと(持ち帰り)

1. 三項目のしきい値を**実機画面を見ながら**決める(日程を決める)
2. LNB の点検項目の聞き取りの担当と日程
3. Windows更新後の扱い
4. 随時再起動の記入欄の可否
