## 3. 用語

- **LNB**　社内での呼び名。**本書では、承認済みの L1〜L3 端末と、そこで稼働する LNB ソフトを対象とする。**
  **`iLNB` と同一であるとは断定しない。**製品資料に現れる LNB と iLNB の関係は要確認
- **iLNB**　統合ライン管理システム。**メーカー公開資料での製品名。**
  **社内で「LNB」と呼んでいるものが iLNB と同じかは確認できていない。**同じものとして扱わない
- **LWS**　**LNB 自体は GUI を持たないため、LNB に関する情報を確認するために設けられた GUI。**
  接続先URLの `/lws/` にあたる経路名と一致する。**ラインごとに LWS を持つ端末が1台ずつあることが実機確認で判明（2026-10-14 確定）。**

  正式な呼称は要確認
- **L1 / L2 / L3**　ラインの区分。**接続先がライン別に3つ存在することから、少なくとも3ラインが対象と判断できる**（§4-2）
- **設定情報の自動バックアップ**　**LWS 上に存在する機能（実機確認で確認済み・2026-10-14 確定）。**
  **現在時点では実行されていないことが確認されている。**有効化するかは要確認

  **新井さんがバックアップを取っていると推定。**大塚さんへの確認が未了【推定・要確認】

- **CIMC-SV**　Pana-CIM 側の再起動対象モニタ。**ESXiホスト画面（172.25.253.45）のナビゲータに「LNBマップ」が表示される**ため、LNB の構成確認の入口になりうる。**ただし LNB の管理対象に含めるかは要確認**

### 記入のきまり

**聞き取りの結果をこの形で埋める。**各項目を Step として並べ、1項目ごとに次の6点を書く。

| 書く欄 | 書き方 |
| --- | --- |
| やること | 何を見るか、どこで見るかを書く |
| 操作の種別 | **「読み取りのみ」か「状態を変える」のどちらかを書く。**曖昧にしない |
| 取り消し可否 | **「状態を変える」のときだけ書く。**戻せるなら戻し方も書く |
| 完了条件 | **数値か画面の状態で書く。**「問題なければ」とは書かない |
| 記録 | 残す値・画面・出力を書く。残さないなら「記録なし」と書く |
| 注意点 | 誤読しやすい表示があれば書く |

### なぜ「問題なければ」と書かないのか

**判定を実施者の感覚に預けると、人によって結果が変わる。**
文書の目的は、誰がやっても同じ判定になることなので、
**数値か画面の名前まで落とさないと文書として機能しない。**

Pana-CIM 側では、この基準づくりを「実機の画面を見ながら決める」としている。
**LNB も同じ進め方になる。**

### Step 1　LNB接続状態を確認する（候補）

**確定した点検項目ではない。**公式資料に「表示される」と書かれている項目なので、
**聞き取りの出発点として置く。**

| 項目 | 内容 |
| --- | --- |
| やること | **LNB接続状態**（無線スキャナーと LNB の接続状態）の表示を確認する |
| 操作の種別 | 読み取りのみ |
| 完了条件 | **要確認。**正常とみなす表示が分かっていない |
| 記録 | **画面名と表示されていた文言をそのまま書く。**「正常」「○」とは書かない |
| 注意点 | 出典は PanaCIM-EE 材料照合（サーバー無しタイプ）N7201A670J06 PDF通し19頁（付録A-1）。**自社の L1〜L3 に同じ表示があるかは未確認** |

**判定基準が決まるまでは、見たものをそのまま書く。**
○×で記録を始めると、基準を決めたあとに過去の記録が読めなくなる。

## 7. 定期管理

**頻度区分が未確定。**日次・月次・年次・随時のどれを置くかから決める。

Pana-CIM は月次再起動を SMT点検日に実施している。

### 7-1. 再起動は2種ある（実機確認・2026-10-14）

**LWS の「LNB再起動」ページには、実際には3つのボタンがある（§4-3）。**
再起動として扱うのは次の2つ。**「LNB-PC電源OFF」は再起動ではなく電源を切る操作なので、ここでは扱わない。**

## 15. 申し送り（認証情報の扱い）

**本書の作成中に、放置できない状態が見つかった。**

**LNB の接続用ショートカット3件に、利用者名とパスワードが URL のクエリとして
平文で埋め込まれている。** 置き場は
`11_USBミラー_E/buckup/15575/desktop/` の `L1_LNB.url` `L2_LNB.url` `L3_LNB.url`。

**値は本書に書かない。**以下は「なぜ急ぐか」だけを書く。

**2026-10-14 追記： LWS の「LNB構成情報」画面には「認証ID」の項目が表示される（§14 No.38）。
この値も本書には書かない。**スクリーンショットを共有するときは、認証IDが写らないよう注意すること。

### 何が起きているか

| 事実 | なぜ問題か |
| --- | --- |
| パスワードが URL のクエリ文字列にある | **ブラウザの履歴・プロキシのログ・サーバーのアクセスログに、そのまま残る。**見た人を特定できない |
| 通信が HTTP（暗号化なし） | 同じネットワーク上で読める。**ポート8080で平文** |
| 3ラインとも同じ利用者名・同じパスワード | **1つ漏れると3ライン全部に入れる。**どのラインから操作されたかも区別できない |
| この写しが業務用保管庫に入っている | **保管庫は Google Drive で同期している。**社内の共有フォルダに置いたのとは別の経路に、もう1部ある |

### 先に決めること

**本書の §14 No.17 より先に処理する。**点検手順を書く前の話。

1. **このショートカットを配っている範囲を確認する。**デスクトップに置いてあったものなので、同じ端末を使う全員が持っている可能性がある
2. **埋め込みをやめられるか**をベンダーまたは現行実施者に確認する。ログイン画面で入力する形に変えられるか
3. **変えられない場合でも、利用者名とパスワードを本書と手順書に転記しない。**保管場所だけを書く
4. **保管庫側の写しをどうするか決める。**`11_USBミラー_E` は USB の写しなので、**USB側を直さないと戻ってくる**

**こちらの判断で消していない。** 現物を消すと、
**現場でその経路しか知らない人が入れなくなる可能性がある。**
`rules.md` の削除は承認が必要という扱いにも合わせた。
