# 業務報告 改善方針と原稿の作り方

2026-09-18 の発表で受けた講評への対応。**次の10月報告で実施する。**

---

## 1. 講評の整理

### できていたこと（維持する）

声の大きさ、活舌、聞き手を見ること。**これらは意識から外してよい。**
直す対象に入れると、直すべきものに割く注意が減る。

### 指摘（9件）

| # | 指摘 | 根っこ |
| --- | --- | --- |
| 1 | 補足で同じ結論・言い回しを繰り返した | A |
| 2 | 結果として冗長になった | A |
| 3 | すべて説明しようとして簡潔にまとまらない | A |
| 4 | スライドの語句と口頭の語句が違い、違和感を与えた | B |
| 5 | 抽象と具体が混ざりすぎ。言い切る形で話すべき | B |
| 6 | いきなり今後の展開に入った。前段の継続を先に言うべき | B |
| 7 | 接続詞の活用に難がある | B |
| 8 | 具体的な数字が無く実証力が弱い | C |
| 9 | 内容の理解が浅い。自分の言葉で話せていない | D |

**9件は4つの根っこに畳める。**

- **A: 話す量を決めていない** — 全部言おうとするから冗長になり、同じ結論を繰り返す
- **B: 話す順番と語句を決めていない** — その場で言葉を選ぶから、スライドと食い違い、抽象と具体が混ざる
- **C: 数字を用意していない** — 「やりました」で終わり、規模が伝わらない
- **D: 原稿が無い** — 上の3つは全部ここに帰着する

**講評自身が結論を出している。「原稿を作るべき。」**

---

## 2. 質問されたことの意味

質問は「聞かれた」のではなく、**資料に書いていなかったから確認された。**

| 質問 | 書いていなかったこと |
| --- | --- |
| この実施前の確認はいつするのか | **具体的な日付**。「実施前」では時期が決まらない |
| B列在庫差異は厳密にはゼロになっていない。原因はこのパターンだけではない | **差異の種類**。1パターンだけを書いて全体のように見せていた |
| 生産一課と連携していた内容か | **何を指しているか**。主語と範囲が曖昧だった |

**3件とも「書けば聞かれなかった」もの。** 質問を減らす方法は、答えを準備することではなく、
**資料に日付・種類・範囲を書くこと。**

## 3. 10月報告に向けて取るべきデータ

Cへの対応。**作業しながら数えないと、後から出せない。**

### 必ず取る（数えるだけ）

| 項目 | 取り方 | 報告での使い方 |
| --- | --- | --- |
| **0確認の対象件数** | 取り込み実行時のメッセージ（現在 5,848件） | 「5,848件を対象に」と規模が言える |
| **0確認の消し込み結果** | ○件数 / 無し件数 / 未処理件数 | 「○○件を消し込み、残は△件」 |
| **B列反映の機種別内訳** | 更新 / 据え置き / 非掲載0化 / 警告 | **9月報告でAEDと送信機L2しか出せなかった箇所。**TEC1000・NKV・TEC5600を今度は埋める |
| **作成した文書の数** | 仕様書・手順書・設計書の本数 | 「仕様書○本、手順書○本」 |
| **所要時間** | 実行前後の時刻を控える | 「1回あたり○分」→ 年間の削減時間に換算できる |

### 取れたら強い

| 項目 | 取り方 |
| --- | --- |
| 改修前後の差 | 0確認を手作業でやった場合の想定時間との比較 |
| 対象部品の金額規模 | 単価が取れれば。**現状は取得元が未特定** |
| 差異の種類別の件数 | 質問2への直接の答えになる |

### 数字の出し方

講評の指示は「**何を何件やったか、目標数値、件数単価のいずれか**」。
**3つ全部は要らない。1テーマにつき1つで足りる。**

```
悪い例: 「不足部品リストへのEGPro在庫反映を行いました」
良い例: 「5機種に展開し、AEDで更新362件・据え置き4件・非掲載0化633件」
```

## 4. 原稿の作り方

Dへの対応。**スライドを作ってから原稿を書くのではなく、原稿を書いてからスライドを削る。**

理由は講評の4番。スライドの語句と口頭の語句が違うのは、
**スライドを先に作り、話すときに言い換えているから。**原稿を先に書けば、
スライドはその要約になるので、言葉が一致する。

### 1スライドの話し方の型

講評6番（いきなり今後の展開に入った）への対応。**この順を崩さない。**

```
1. いま何の話か        「Topics①、不足部品リストへのEGPro在庫反映です」
2. 前段の状態          「従来はEGPro在庫を取り込む処理がなく、」
3. やったこと          「Excelの数式とVBAを解析し、照合処理を追加しました」
4. 数字               「5機種に展開し、AEDで更新362件です」
5. だから次にどうする   「そのため、残るTEC1000・NKV・TEC5600の内訳を取得します」
```

**4を飛ばすと講評8番、2を飛ばすと講評6番になる。**

## 5. 資料作成・原稿作成プロンプト

`01_Templates` へ保存して再利用する。**次の月次でそのまま使えること**を狙う。

### 使い方

1. その月のデイリーレポートと成果物の一覧を集める
2. 下のプロンプトを貼り、材料を添付する
3. 出てきた原稿を**声に出して読む。** つかえた箇所が、まだ自分の言葉になっていない箇所

```
あなたは製造現場の業務報告を支援する書き手です。
月次の業務報告について、スライドの下書きと、読み上げる原稿を作ってください。

## 守ること

- **原稿が主、スライドが従。** 先に原稿を書き、スライドはその要約にしてください。
  スライドにある語句と原稿の語句を一致させてください。言い換えないでください。
- 1スライドあたりの原稿は、次の順で書いてください。順番を変えないでください。
  1. いま何の話か（見出しをそのまま言う）
  2. 前段の状態（何が問題だったか。「従来は〜」）
  3. やったこと（「〜しました」で言い切る）
  4. 数字（何を何件、目標に対していくつ、時間がどれだけ）
  5. だから次にどうするか（「そのため〜します」）
- **数字を必ず入れてください。** 材料に数字が無い項目は、
  「数字が取れていない」と明記してください。数字なしで流さないでください。
- **抽象的な表現と具体的な内容を混ぜないでください。** 言い切ってください。
  「〜と考えられます」「〜のような」は使わないでください。
- 同じ結論を2回書かないでください。補足は、前と違うことを言うときだけ入れてください。
- 接続詞は「そのため」「一方で」「ただし」を使い分けてください。
  「また」の連続を避けてください。
- 専門用語を使うときは、**その場で言い換えず、初出で一度だけ短く説明**してください。

## 分量

1スライドあたり、読み上げて40〜60秒。それを超える原稿は削ってください。
削るときは、5つの要素のうち「3. やったこと」を短くしてください。
数字と次の展開は削らないでください。

## 出力

### A. スライド下書き
見出しと箇条書きだけ。1枚あたり本文は5行以内。

### B. 読み上げ原稿
スライドごとに、上の1〜5の順で。話し言葉で。

### C. 想定質問と答え
資料に書いていないために聞かれそうなことを挙げてください。
特に次の3つは毎回確認してください。
- 日付や時期が具体的に書かれているか
- 「差異」「不具合」などの言葉について、種類が分かれるのに1種類だけ書いていないか
- 誰と連携した話なのかが書かれているか

答えを用意するのではなく、**Aに書き足すべき内容**として出してください。

## やらないこと

- 材料に無い数字を作らないでください。
- 「一般的には」で始まる説明を入れないでください。
- 作成ツールや生成に関する記述を残さないでください。
```

## 6. 次の報告までの手順

1. **作業しながら §3 の数字を控える。** 後から数えられないものが多い
2. 月末に材料（デイリーレポート・成果物一覧・数字）を集める
3. §5 のプロンプトで原稿とスライド下書きを作る
4. **原稿を声に出して読む。** つかえた箇所を直す
5. スライドを [[work-report-deck-format]] の社内様式（4:3・`09_NKbeacon-white`・Meiryo UI・3枚程度）へ流し込む
6. §5-C の想定質問を見て、**答えを用意するのではなくスライドに書き足す**
