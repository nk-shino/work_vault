# 容量確認とJob構成（TOOL.xlam 仕様）

`00_inbox/Todo.md` の「ジョブ作成時に容量確認（TOOLマクロ）を行うが、鹿島製品が来ると
テーブルに収まらなくなる可能性がある」への回答。

**2026-10-08 時点で、保管庫のノートに `TOOL.xlam` の言及は0件だった。**
**運用の中核にあるツールが一度も文書化されていない状態だった。**

実体は `参照のみ・読み込み後に削除/Job作成/マクロ等/bin/TOOL.xlam`（649 KB・2026-06-30）。
VBA を olevba で抽出して読んだ（6,649行）。

---

## 1. 結論：テーブルの「容量」は数字で決まっている

**「収まる／収まらない」は感覚ではない。スロット数の上限が3つ決まっている。**

| 区分 | 上限スロット | 何に使う |
|---|---|---|
| **3ノズルヘッド** | **90** | ノズルコードが1000超の部品 |
| **その他（8〜12ノズルヘッド）** | **300** | それ以外の部品 |
| **全体** | **390** | 90 + 300 |

**判定式はこれだけ。**

```
3ノズル側  :  Σ(フィーダーサイズ | ノズルコードのいずれか > 1000)  ≦  90
その他側    :  Σ(フィーダーサイズ) − 3ノズル側                      ≦ 300
```

**鹿島製品を足して、どちらかが超えたら「収まらない」。**
**全体390に余裕があっても、3ノズル側が90を超えれば収まらない。**ここが落とし穴である。

---

## 2. どこから数字を取っているか

**`TOOL.xlam` は自分でデータを持っていない。Access を読んでいる。**

```
Provider = Microsoft.ACE.OLEDB.16.0
Data Source = \\nksv523.ad.nkc.co.jp\第二工場実装課用\1係用\Job作成\部品リスト.accdb
con.mode = adModeRead   ← 読み取り専用で開く
```

| テーブル | 持っている列 | 役割 |
|---|---|---|
| `egproBOM` | 品目名, 部品名 | 品目 → 部品の展開 |
| `PartList` | 部品名, 供給種別, **ノズル**, **フィーダーサイズ** | 部品 → 占有スロット数 |

結合は `egproBOM.部品名 = PartList.部品名` の **LEFT JOIN**。

**`PartList` に無い部品は 供給種別・ノズルが空、フィーダーサイズ 0 として扱われる。**
**つまり未登録部品は容量0として通る。**ここが過小評価の入り口になる。
**鹿島製品を入れる前に `PartList` への登録漏れを潰す必要がある。**

実データは手元にもある。

- `Job作成/部品リスト.accdb`（15.5 MB・2026-10-07）＝ 上記DBの写し
- `Job作成/egproBOM.csv`（9.4 MB・2025-06-24）＝ `egproBOM` の書き出し

## 3. 3ノズルヘッドの振り分け規則

**`PartList.ノズル` はカンマ区切りの複数値。**

```vba
For Each str In Split(CStr(myBUHIN.ノズル), ",")
    If CLng(str) > 1000 Then
        DBG_3H = DBG_3H + CDbl(myBUHIN.フィーダーサイズ)
        Exit For
    End If
Next str
```

**いずれか1つでも1000超なら、その部品のフィーダーサイズ全量を3ノズル側に寄せる。**
**按分しない。`Exit For` で即抜ける。**

**つまり「3ノズルでも載る部品」は3ノズル枠を食う側に数えられる。**
3ノズル枠が逼迫しているときは、**ノズルコードの構成を見直すだけで枠が空く可能性がある。**
`PartList` の持ち方次第なので、**データ側の改善余地として残っている。**

## 4. テーブル禁止推奨数（「収まらない」の逆算）

**容量は固定ではなく、テーブルを止めると減る。**その余裕を数えているのがこの部分。

```vba
x = 0.8                                  ' 安全率80%
If (150 * x) >= (HINMOKU_SIZE - DBG_3H) Then T = T + 1
If (180 * x) >= (HINMOKU_SIZE - DBG_3H) Then T = T + 1
If (210 * x) >= (HINMOKU_SIZE - DBG_3H) Then T = T + 1
If (240 * x) >= (HINMOKU_SIZE - DBG_3H) Then T = T + 1
If (270 * x) >= (HINMOKU_SIZE - DBG_3H) Then T = T + 1
Msg_inv = "テーブル禁止推奨数 : " & T & "※禁止優先度 T8 > T6 > T4 > T2 > T10"
```

**読み取れること。**

| 事実 | 根拠 |
|---|---|
| **その他側300は「基礎150 + テーブル5枚」でできている** | しきい値が 150/180/210/240/270 と**30刻みで5段** |
| **1テーブル = 30スロット** | 刻みが30 |
| **安全率は80%** | `x = 0.8`。使用率80%を超える構成は「禁止できない」と判定する |
| **止める順番が決まっている** | **T8 → T6 → T4 → T2 → T10** |

**T10 が最後。**番号順ではない。**T10 だけ優先度が低い理由はコードに書かれていない。要確認。**

**鹿島製品を入れると `HINMOKU_SIZE - DBG_3H` が増え、T が減る。**
**T が 0 になった時点で「どのテーブルも止められない」＝余裕ゼロ。**
**この T が、段階的引き込みの判断に直接使える指標である。**

## 5. 共通部品率も既に出ている

**Todo の竹渕さんメールが「共通部品率、フィーダー使用率、ヘッド負荷率などの管理指標および
目標値を明確化し」と書いているが、指標のうち2つは既に出力されている。**

シート `Job作成` のA〜C列に書き出される。

| 列 | 見出し | 中身 |
|---|---|---|
| A | 選択品目とのスロット共有率%(スロット数換算) | `Round(共有スロット / 当該品目の全スロット * 100)` と `(共有スロット数)` |
| B | 選択品目と非共有のスロット数 | `当該品目の全スロット − 共有スロット` |
| C | (A〜C列は計画作成用) | 注記 |

**フィーダーサイズ0の品目は `0%(トレイ?)` と出る。**トレイ供給の判別がここに出ている。

### 既にあるもの／無いもの

| 指標 | 状態 |
|---|---|
| **共通部品率** | **ある。**A列のスロット共有率がそれ |
| **フィーダー使用率** | **ある。**`【ALL】 n/390` `3Noz: n/90` `Other: n/300` |
| **ヘッド負荷率** | **ある（部分的）。**3ノズル／その他の2分類まで。ヘッド個別の負荷は見ていない |
| **目標値** | **無い。**安全率80%が実質の上限だが、明示された目標値はどこにもない |

**作るべきは指標ではなく目標値である。**
**指標は動いている。「何%までを可とするか」が決まっていない。**
これが品目選定システム改修の最初の論点になる。

## 6. 実行の入り口

| 入口 | 何 |
|---|---|
| `部品確認_手動実行用()` | 手で回すとき |
| `Buhinkakunin_btn(r As IRibbonControl)` | リボンのボタン |
| `BuhinKakunin_ADO(s, e, msgFlag)` | 本体。既定 `s=1, e=300, msgFlag=False` |

**`msgFlag = False` が既定。つまり既定では数字をダイアログに出さない。**
**A〜C列への書き出しだけが行われる。**
容量の数字（`【ALL】 n/390`）を見たいときは `msgFlag = True` で呼ぶ必要がある。

**`e=300` の既定は処理行数の上限。**選択範囲が300行を超えると扱いが変わる可能性がある。**要確認。**

### 実行前に開かれるもの

```vba
Workbooks.Open "\\nksv523.ad.nkc.co.jp\第二工場実装課用\1係用\SMTData\実装状況表2.xlsx"
```

**「高速化の為実装状況表を開きます」** と確認ダイアログが出る。
`Job_BaseCreate` 側の処理で、**`実装状況表2.xlsx` が開いていないと遅い。**

## 7. 鹿島引き込みに向けた具体的な手順

**Todo と竹渕さん・茂木さんのメールに対して、こう進められる。**

1. **鹿島品目を `egproBOM` / `PartList` に登録する**
   → 未登録はフィーダーサイズ0で通るので、**登録漏れがあると容量が過小に出る**
2. **候補のJob構成を選択して `BuhinKakunin_ADO(msgFlag:=True)` を回す**
   → `3Noz: n/90` と `Other: n/300` を見る
3. **`T`（テーブル禁止推奨数）を見る**
   → T が 1 以上残る構成なら、現行のテーブル運用のまま入る
   → **T = 0 なら、そのJob構成では入らない**
4. **入らない場合、A列の共有率で品目を組み替える**
   → 共有率が高い品目同士を同じJobに寄せるとスロットが減る
5. **それでも入らないなら、フリーJOBを2件以上に増やす話になる**
   → 茂木さんが「手動による複数フリーJOBの計画作成」と書いているのはここ

**2と3は既存ツールだけでできる。改修は要らない。**
**改修が必要になるのは5の「フリーJOBを2件以上」からである。**

**茂木さんが天野さん宛に「段階的に進めることをご検討いただけないでしょうか」と
書いているのは正しい。**段階ごとに T を見れば、どこで止まるかが事前に分かる。

## 8. 同梱されているもので注意が必要なもの

### 8-1. `un.bas` は VBA プロジェクトのパスワード解除

```vba
Public Sub unprotected()
Private Function GetPtr(ByVal Value As LongPtr) As LongPtr
Private Function Hook() As Boolean
Private Function MyDialogBoxParam(...) As Integer
Private Sub RecoverBytes()
```

**`DialogBoxParam` を API フックしてパスワード入力ダイアログを無効化する手口である。**
VBAプロジェクトの保護を外すためのもので、**容量確認とは無関係。**

**ver2 としてまとめるときは、この1モジュールの扱いを決める必要がある。**
**残すなら「何のために入っているか」をコメントに書く。**
佐藤（勇）さんが保護付きのブックを触るために入れたものと推測できるが、**確認が取れていない。**

### 8-2. 参照しているライブラリ

`RegExp`（VBScript RegExp）、`FileSystemObject`（Scripting Runtime）、
`Dictionary`（Scripting Runtime）、`ADODB`（ActiveX Data Objects）を**事前バインドで使っている**。
`Microsoft.ACE.OLEDB.16.0` も要る。

**別PCへ持っていくと参照が外れて動かない。**
`00_backup` 等の旧版と入れ替えるときも同じ。**参照設定を先に見る。**
