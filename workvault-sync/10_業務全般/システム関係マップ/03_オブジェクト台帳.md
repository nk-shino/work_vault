# オブジェクト台帳

関係マップに登場するノードと関係の定義。**語彙の正本はこのノート。**
図(01/02)やタグ(台帳スクリプト)で新しい名前を使うときは、先にここへ追加する。

表記は [[00_関係マップMOC]] の約束に従う(【確定】【暫定】【未確認】)。

---

## 1. ノード種別

| 種別 | 記号 | 意味 |
|---|---|---|
| `EQ` | 設備 | 実装機など、現場の装置 |
| `SYS` | システム | サーバ上で動く業務システム |
| `APP` | アプリ | 利用者が画面で操作するアプリケーション |
| `DB` | データ | テーブル、ファイル群 |
| `IF` | 連携 | システム間のインターフェース |
| `TOOL` | ツール | Excelマクロ、スクリプト、RPA |
| `HOST` | ホスト | サーバ、端末、仮想基盤 |
| `STORE` | 保管場所 | ファイルサーバ共有、同期フォルダ |

## 3. 関係の種別

図で使う辺の意味。**これ以外の意味を線に持たせない。**

| 関係 | 読み | 使う場面 |
|---|---|---|
| `feeds` | データを供給する | 設備 → システム、システム → システム |
| `reads` | 参照する(書き換えない) | LNB → PanaCIM |
| `writes` | 書き換える | idouSQL → T_在庫データ |
| `operates` | 画面を操作する | マクロ → 倉庫管理アプリ |
| `hosts` | 載っている | ESXi → CIMC-SV |
| `stores` | 保管している | nksv523 → 仕様書 |
| `derives` | 生成物の元になる | セットアップレポート → 計算結果 |

## 5. 名寄せが要るもの(命名が揺れている)

**同じ対象を別名で呼んでいる。台帳で機械的に集計すると二重になる。**

| 正とする名前 | 揺れている表記 | 判断 |
|---|---|---|
| PanaCIM | Pana-CIM / PanaCim / PANACIM / **Pana-SIM** | `Pana-SIM` は WinActor シナリオ名の表記。**同一かは【未確認】** |
| LNB | iLNB | **同一とは断定しない**(W41 で決定) |
| EGPro | EG Pro / EG-Pro / EGプロ | 同一【確定】 |
| セットアップレポート | セトレ / SETUPREPORT | 同一【確定】 |
| 移動先コード | 棚卸し用倉庫コード | 同一【確定】。**208 は廃止コード** |

## 6. 既知の落とし穴(図に書き込む前に読む)

| # | 内容 | 根拠 |
|---|---|---|
| 1 | **定義書の「⇒Panasonic」「←Panasonic」は SAP/MES 側から見た向き。**EGPro 視点では逆になる | 【確定】 |
| 2 | **`DB.WHCSV` と `DB.TANACSV` を取り違えない。**Tanaoroshi は在庫が全件0扱い | 【確定】 |
| 3 | **件数 29,246 / 6,884 / 5,848 は意味が違う。**別日時のCSVで同じ値にならない。期待値として使い回さない | 【確定】 |
| 4 | **idouSQL の `WHERE` は現在ロケーションを見ない。**A55 の移動先コードを誤ると正しい件数を誤った倉庫へ動かす | 【確定】 |
| 5 | **トランザクション運用は v1.0 から無改修。**「不要になった」は誤り。**変更点ではなく「変えていない点」として書く** | 【確定】 |
| 6 | **PanaCIM の再起動手順は2種類。**月次計画再起動と、異常時の14ステップ。**取り違えると生産を止める** | 【確定】 |
| 7 | **異常時14ステップは停止(1〜6)と起動(7〜14)の2段。**手順6で中断すると生産を再開できない | 【確定】 |
| 8 | **BARCODE.BarCodeCtrl.1 は 32bit Office 前提。**64bit 移行時に影響 | 【確定】 |
| 9 | **リールバーコードでメーカーラベルを誤読することがある。**0確認の件数が合わない原因になりうる | 【確定】課題管理表 |
