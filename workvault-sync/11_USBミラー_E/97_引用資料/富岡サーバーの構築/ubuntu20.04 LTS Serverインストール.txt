nksv559のLinux環境について(Ubuntu 20.04.3 LTS)

1. Ubuntu本体のインストール
	－ブートデバイスをDVD-ROMドライブに設定、インストールDVDを起動
	　(F2やF12を押すことでブートデバイスの選択に移行。)
	　●Language (言語設定)
		↑↓キーで English を選択し enter
	　●Installer update available
		何も入力せずに [ Done ] にカーソルがある状態で、enter
		(最新版にインストーラをアップデートしない)
	　●keyboard (キーボード配列)	
		tabキーで  Layout:[  ]に移動、enter後↑↓キーで Japanese を選択
		自動的に Variant:[ Japanese ] になるので、tabキーで [ Done ] に移動し、enter
		([ Identify keyboard ]は操作が面倒)
	　●Network connection (ネットワーク設定)
		NICにより表示内容が異なる。適切な NIC に対して
		【固定ipの場合】
		ケーブルがつながれたNICの [ enp0s25 eth -   ] を選択し、enter
		サブメニューで Edit IPv4 を↑↓キーで選択し、enter
		ウィンドウが開いて IPv4 Method: [ Automatic (DHCP) ] となっているので、
		↑↓キーで Manual を選択し、enter
		ウィンドウが本Methodに対する設定値編集に変わって、以下を設定
		Subnet:		172.25.201.0/24		を入力(セグメントアドレスをCIDR形式)
		Address:	172.25.201.11		を入力(自ipアドレス)
		Gateway:	172.25.201.254		を入力(デフォルトゲートウエイ)
		Name servers:	172.30.30.2,172.24.1.2　を入力(DNS名。1stと2ndの間は " , ")
		Search domains:	ad.nkc.co.jp	を入力(ドメイン名)
		内容を確認して [ Save ]を↑↓キーで選択し、enter
		画面が戻って、NIC表示の下に "Static" と共に ip アドレスが表示される。
		【DHCPの場合】
		NIC表示の下に "DHCP" と表示され、取得されたipアドレスが表示される。
		tabキーで [ Done ] まで移動し、enter
	　●Configure proxy (プロキシサーバの設定)
		何も入力せずに [ Done ] にカーソルがある状態で、enter
	　●Configure ubuntu archive mirror (ubuntuのミラーサーバの選択)
		表示されたままで [ Done ] にカーソルがある状態で、enter
	　●Guided storage configuration (HDDの設定)
			Use an entire disk (全領域を使用) の ( ) にカーソルを合わせ、spaceバー
				→ "X"が表示される
			Set up this disk as an LVM group の [ ] にカーソルを合わせ、spaceバー
				→ "X"が表示される
			Encrypt the LVM group with LUKS の [ ] は空白のまま
		内容を確認して [ Done ] にカーソルを移動させ、enter
	　●Storage configration (設定の確認)
		内容を確認して [ Done ] にカーソルがある状態で、enter
		Confirm destructive action (破壊的操作の確認) が表示されたら
		[ Continue ] にカーソルを移動して(カーソルが赤表示に変わり) enter
	　●Profile setup (サーバ名、アカウントの設定)
			Your name:		 	administrator を入力(ログイン後のプロンプトに表示される)
			Your server's name:	nksv559 を入力
			Pick a user name:	administrator を入力(ログインアカウント名に使用される)
			Choose a password:	いつものパスワードを入力
			Confirm your password:	パスワードを再入力
		内容を確認して [ Done ] にカーソルを移動させ、enter
	　●SSH setup (SSHサーバの設定)
			Install OpenSSH server の [ ] にカーソルを合わせ、spaceバー
				→ "X"が表示される
			Import SSH identity: 以降は、何もしない。
		内容を確認して [ Done ] にカーソルを移動させ、enter
	　●Featured Server Snaps (追加のサーバ機能の設定)
		何も入力せずに [ Done ] にカーソルを移動させ、enter

	　………　インストールが始まる　………

	　●Installation complete! (システムの再起動)
		インストールが完了すると、最下段の表示が [ Reboot Now ] になるので、
		インストールメディアを抜いて [ Reboot Now ] にカーソルを移動させ、enter
		ブートが完了してコンソールにログインプロンプト( login: )が表示されたら、

			処理途中、ディスク容量を喰うが進めてよいか？"Y/n"の入力を促されるので、"Y"を入力。
			sudo reboot

4. SSLリバースプロキシの構築
	－sslディレクトリの生成
		以下を実行してroot:rootのフォルダを作る。
			sudo chmod 755 /etc/ssl/private		# 755にしないとmkdirできない
			sudo mkdir /etc/ssl/private/newcert
			sudo mkdir /etc/ssl/private/oldcert
			sudo chown root:root /etc/ssl/private/*
	－～.key(秘密鍵),～.csr(公開証明書署名要求)ファイルを生成する
		以下を実行してファイルを生成する。
			cd /etc/ssl/private/newcert/
			sudo openssl req -new -newkey rsa:2048 -nodes -keyout server.key -out server.csr
		要求されるパラメータを入力する
			Country Name (2 letter code) [AU]:JP
			State or Province Name (full name) [Some-State]:Tokyo
			Locality Name (eg,city)[]:Shinjyuku-ku
			Organization Name (eg, company) [Internet Widgeits Pty Ltd]:NIHON KOHDEN CORPORATION
			Organization Unit Name (eg, section) []:Admin. Dept.
			Common Name (e.g. server FQDN or YOUR name) []:nktomioka.nkc.co.jp
			Email Address []:.
			A challenge password []:.
			An optional company name []:.
		この結果で/etc/ssl/private/newcertディレクトリに生成される
			server.key(秘密鍵ファイル)
			server.csr(公開証明書署名要求ファイル)
		のうち server.csr をCA(証明機関)に送付し、
			～.crt(公開鍵ファイル)
			～.ca-bundle(中間証明書ファイル)
		を取得する。(nktomioka_nkc_co_jp.crt、同.ca-bundle は、SECTIGO(旧COMODO)から取得した場合のファイル名)
	－または、生成済秘密鍵、発行済証明書を元サーバ(nksv560)から、以下のファイルをコピーする
			nktomioka_nkc_co_jp.crt
			nktomioka_nkc_co_jp.ca-bundle
			server.key
			(これらファイル群をコピーすることで、証明書は継続利用可能。)
	－証明書を結合する
		公開鍵・中間証明書の順にファイルを結合する
			sudo cat nktomioka_nkc_co_jp.crt nktomioka_nkc_co_jp.ca-bundle > nktomioka_nkc_co_jp.pem
		結果、以下のようなディレクトリ、ファイル構成となる。
		ディレクトリ構成(グループ:オーナー、権限)
		/etc/ssl(755)/private(711)/	nktomioka_nkc_co_jp.crt(644)			# サーバ証明書(CAから提供)
				↑			↑		nktomioka_nkc_co_jp.ca-bundle(644)		# 中間証明書(CAから提供)
			root:root	root:root	nktomioka_nkc_co_jp.pem(644)			# サーバ証明書+中間証明書
									server.key(644)							# 秘密鍵(下記newcert/server.keyと同じ)
									oldcert(655) /	nktomioka_nkc_co_jp.crt			# 旧サーバ証明書
													nktomioka_nkc_co_jp.ca-bundle	# 旧中間証明書
													server.key						# 旧秘密鍵
									newcert(655) /	server.csr		# 生成された署名要求ファイル(中間認証機関に送る)
													server.key		# 生成された秘密鍵
	－設定ファイルの生成
		/etc/nginx/site-available/default をバックアップしておく
			sudo cp /etc/nginx/site-available/default /etc/nginx/site-available/default_bak
		ファイル default を、以下を実行して修正する
			sudo vi /etc/nginx/site-available/default
		設定内容は以下のとおり
			##
			# Default server configuration (reverse proxy)
			server {

			# SSL configuration
					listen 443 ssl default_server;						# ポート443についてのみ応答
					listen [::]:443 ssl default_server;					# ip:portでも指定
					server_name nktomioka.nkc.co.jp;					# 自URL

			# SSL certificate
					ssl_certificate /etc/ssl/private/nktomioka_nkc_co_jp.pem;	# 証明書ファイル
					ssl_certificate_key /etc/ssl/private/server.key;	# 秘密鍵ファイル

			# SSL comm
					ssl_session_timeout 5m;								# セッションタイムアウト時間が5分
					ssl_protocols TLSv1.2;								# TLSバージョン1.2以上を使用
					ssl_ciphers HIGH:!aNULL:!MD5;						# 暗号化強度がHIGH(>128bit)、認証の無いものは使用不可、MD5 は使用しない。
					ssl_prefer_server_ciphers on;						# 

			# target location
					location / {
							proxy_pass http://nksv560.ad.nkc.co.jp/;	# proxy先URI
							proxy_http_version 1.1;						# httpバージョン1.1以上
							proxy_set_header Upgrade $http_upgrade;		# 
							proxy_set_header Connection keep-alive;		# 
							proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
							proxy_set_header Host $host;				# 
							proxy_cache_bypass $http_upgrade;			# 
					}
			}
		編集後、以下のコマンドで文法をチェックする
			sudo nginx -t
		応答：
			nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
			nginx: configuration file /etc/nginx/nginx.conf test is successful
			(証明書の結合順が違うとき)
			nginx: [emerg] SSL_CTX_use_PrivateKey("/etc/ssl/private/server.key") failed (SSL: error:0B080074:x509 certificate routines:X509_check_private_key:key values mismatch)
			nginx: configuration file /etc/nginx/nginx.conf test failed
	－証明書の更新
		約1年で証明書の有効期限が切れるので、その度ごとに ～.csr (署名要求ファイル)を認証機関に送り、証明書を取得する。
		控えとして、旧証明書ファイルはすべて /etc/ssl/private/oldcert/ に移動し、以降は新規と同じ方法でふぁいるを配置する。
	－nginxの再起動
		以下を実行してnginxの再起動を行う
			sudo systemctl restart nginx
	ー動作の確認
		ブラウザで以下のURLをアクセスし、接続が拒絶されることを確認する。
			http://nksv559.ad.nkc.co.jp/ 
		ブラウザで以下のURLをアクセスする
			https://nksv559.ad.nkc.co.jp/ 
		証明書名前が違うことが表示され、警告が表示されることを確認する。
		さらに「強制的に接続」させると、URLアドレスに
			nksv559.ad.nkc.co.jp
		が表示されたまま、
			nksv560.ad.nkc.co.jp/index.html
		の内容が表示されるのを確認する。
　		さらに、外部の確認サイトからSSLの稼働を確認する。
		例）http://www.cman.jp/network/support/ssl.html
		をアクセスして動作を確認する。
