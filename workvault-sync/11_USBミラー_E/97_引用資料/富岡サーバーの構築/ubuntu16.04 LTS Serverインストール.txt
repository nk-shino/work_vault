　●起動対象プログラムの設定
　－参照順序
		/var/spool/cron/crontabs(初期属性:1730,root:crontab)の中にある「ユーザ名(例：administrator)」のファイル内容を実行する
		(本ファイルは、初期属性では閲覧・編集不可。下記方法で本ファイルが編集される)
　－homeディレクトリに作るファイルによる編集(追加)
	ユーザのホームディレクトリに適当な名前の設定ファイルをvi等で作成
		例）administratorのhomeディレクトリ下で、vi crontab_scheduled
	書式(参考URL：http://x68000.q-e-d.net/~68user/unix/pickup?crontab)
		分 時 日 月 曜 コマンド(行末にreturn必要…かも知れない)
		20 1 * * * cd /var/www/html/cgi/scheduled/; perl BOSS_SQL.cgi;(return)
		(毎日1:20AMにカレントディレクトリを"/var/www/html/cgi/"に移動して"perl BOSS_SQL.cgi"を実行)
		*/3 * * * * ～
		(3分毎に～)
		0,10,20,30,40,50 * * * * ～
		(毎時00,10,20,30,40,50分に～)
		パスを変数に置いて（例： root_DIR='/var/www/html/cgi/' として）、
			root_DIR='/var/www/html/cgi/scheduled'
			20 1 * * * cd $root_DIR; perl BOSS_SQL.cgi;
		としても良い。
	これをcrontabsに組み込むことで有効化される
		crontab crontab_scheduled
　－crontabsの直接編集
		crontab -e
		で編集("-r"は全消去なので注意…)
		完了し閉じると、
		crontab: installing new crontab
		を表示。
　－crontabの内容確認
		crontab -l
　－実行時のログ
		*/30 * * * * /bin/sh /home/hoge/fuba.sh 1>>/tmp/analog.log 2>>/tmp/analog-err.log
	として、1>> は標準出力先、 2>> は標準エラー出力先で取得可能
	実行できない時は、実行時のエラー発生に注意。
	wide characters in ～等のwarningエラーはmailによってadminに通知される。
　－root権限でcrontabを実行
	suになって、crontab -e でファイルを編集。
	例）
	# シェルとパスを設定。
		SHELL=/bin/sh
		PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin
		# 毎週月曜日、午前0時に"perl /root/del_tempFiles.pl"を実行。
		0 0 * * 1 perl /root/del_tempFiles.pl 1>>/root/del_tempFiles.log 2>>/root/del_tempFiles-err.log
	エディタ閉じると crontab: installing new crontab を表示して終了。
　－crontabの停止(全消去)
	crontab -r (当該ユーザの全crontabを消去するので注意)
	【補足】
	"-r"オプションの誤使用対策
	~/.bashrcに-iオプション付加のaliasを設定
		sudo vi ~/.bashrc
		alias crontab = 'crontab -i'
		source = ~/.bashrc
	crontab -r を入力すると
		crontab: really delete ~'s　crontab?
	を表示

	/var/www/html/index.htmlが無いとき、Forbiddenが表示されることで確認。
	【参考】<Directory>ディレクティブの記述
	<Directory (path)>～</Directory>間に記載。(pathのディレクトリに対して作用)
	Options FollowSymLinks:シンボリックリンクをたどる。
	Options Indexes:index.htmlが無い時ディレクトリ表示する。
	Require all denied:アクセス全禁止、granted:アクセス全許可
	Require ip (ip):ipからのアクセスを許可(ip:172(172.～全部)、172.25(172.25.～全部))
	複数条件のRequireの場合、RequireAll(AND条件) / RequireAny(OR条件) / RequireNone(NOR条件)を使用

5. Perlモジュールのインストール
5.1 リポジトリからのインストール(apt-get < apt,aptitude RedHat は yum)
　－組み込み済モジュールの一覧
	find `perl -e 'print "@INC"'` -name '*.pm' -print
　－モジュールの検索
	sudo apt-cache search ^(必要なモジュール名).*-perl
	(例：)sudo apt-cache search ^libcrypt.*-perl
	(例：)sudo apt-cache search ^libSpreadsheet.*-perl
　－インストール
	　sudo apt update で最新のパッケージリストを取得
	　sudo apt upgrade でアップグレードを適用
	　sudo apt install (package name1) (package name2) (package name3) ・・・
	～::～ は ～-～に置き換える。
	例えば必要モジュールが、Config::Simple の場合、モジュール名は libconfig-simple-perl
	(例：)sudo apt install libimage-size-perl libfile-spec-perl libdbi-perl libdbd-mysql-perl libhtml-parser-perl libwww-perl libsoap-lite-perl libfile-temp-perl libimage-magick-perl libstorable-perl libcrypt-openssl-dsa-perl libmime-base64-perl libxml-atom-perl libarchive-tar-perl libarchive-zip-perl libio-compress-perl
	(例：)sudo apt install libcrypt-rc4-perl			→ Crypt/RC4.pmが@INC内に生成される
	(例：)sudo apt install libspreadsheet-xlsx-perl		→ Spreadsheet/XLSX.pmが@INC内に生成される

11.1 Apacheの設定変更
　－エディタでdefault-ssl.confファイルを以下のように修正する。
	(nktomioka_nkc_co_jp.～ファイル名は、SECTIGO(旧COMODO)からのCAの場合)
		sudo vi /etc/apache2/sites-available/default-ssl.conf
	(3行目)管理者メールアドレス
		ServerAdmin webmaster@nksv560.ad.nkc.co.jp
	(32行目)公開鍵ファイルの場所とファイル名
		SSLCertificateFile      /etc/ssl/private/nktomioka_nkc_co_jp.crt
	(33行目)秘密鍵ファイルの場所とファイル名
		SSLCertificateKeyFile   /etc/ssl/private/server.key
	(42行目)中間証明書ファイルの場所とファイル名
		SSLCertificateChainFile /etc/ssl/private/nktomioka_nkc_co_jp.ca-bundle
　－default-ssl.confの編集を有効にする。
		sudo a2ensite default-ssl
　－sslを有効にする(初回のみ…sites-enabledディレクトリにdefalt-ssl.confへのリンクを生成) 
		sudo a2enmod ssl
11.2 ディレクトリの構築
　－/etc/ssl/フォルダに移動し、private/newcert,oldcertフォルダを作る
		cd /etc/ssl/
		sudo mkdir private/newcert
		sudo mkdir private/oldcert
		sudo chown root:root private/*
	ディレクトリ構成(グループ:オーナー、権限)
	/etc/ssl(755)/private(710)/		~.crt(644)			# 公開鍵(CAから提供)
		  ↑root:root(デフォ)		~.key(640)			# 秘密鍵(下記フォルダ)
				  ↑root:ssl-cert	~.ca-bundle(644)	# 中間証明書(CAから提供)
									/oldcert(655) /	~.crt
													~.key
													~.ca-bundle
									/newcert(655) /	server.csr	# 生成される署名要求ファイル
													server.key	# 生成される秘密鍵
11.3 csrファイル(証明書の秘密鍵)の生成
　－/etc/ssl/private/newcertフォルダに移動、opensslを起動
		cd /etc/ssl/
		sudo chmod 655 private		# 655にしないとCDできない
		cd private/newcert/
		sudo openssl req -new -newkey rsa:2048 -nodes -keyout server.key -out server.csr
　－要求されるパラメータを入力する
		Country Name (2 letter code) [AU]:JP
		State or Province Name (full name) [Some-State]:Tokyo
		Locality Name (eg,city)[]:Shinjyuku-ku
		Organization Name (eg, company) [Internet Widgeits Pty Ltd]:NIHON KOHDEN CORPORATION
		Organization Unit Name (eg, section) []:Admin. Dept.
		Common Name (e.g. server FQDN or YOUR name) []:nktomioka.nkc.co.jp
		Email Address []:.
		A challenge password []:.
		An optional company name []:.
　－この結果で/etc/ssl/private/newcertディレクトリに生成される
		server.key(秘密鍵ファイル)
		server.csr(公開証明書署名要求ファイル)
	のうち server.csr をCA(証明機関)に送付し、
		～.crt(公開鍵ファイル)
		～.ca-bundle(中間証明書ファイル)
	を取得する。(～:nktomioka_nkc_co_jp のファイル名は、SECTIGO(旧COMODO)から取得した場合)
　－モードを戻す
	cd /etc/ssl/
	sudo chmod 710 private
11.4 crtファイル(証明書の公開鍵)のインストール
　－/etc/ssl/に移動、古い証明書は /etc/ssl/private/oldcertに移動
		cd /etc/ssl/
		sudo mv nktomioka_nkc_co_jp.crt private/oldcert/
		sudo mv nktomioka_nkc_co_jp.ca-bundle private/oldcert/
		sudo mv server.key private/oldcert/
		sudo chown root:root private/oldcert/*
　－ベンダーから提供された
		～.crt(公開鍵ファイル)
		～.ca-bundle(中間証明書ファイル)
	先に生成した
		～.key(秘密鍵ファイル)
	の3ファイルを/etc/ssl/private 配下に移動する。
		sudo mv /home/share/nktomioka_nkc_co_jp.crt private/
		sudo mv /home/share/nktomioka_nkc_co_jp.ca-bundle private/
		sudo mv /etc/ssl/private/newcert/server.key private/
		sudo chown root:root private/*
		sudo chmod 644 private/*
		sudo chmod 640 private/server.key
　－Apacheの設定再読み込み
		sudo systemctl reload apache2		# 接続を維持しながら設定を反映
	または
		sudo service apache2 restart		# 切断して再起動
	または
		sudo systemctl restart apache2		# 切断して再起動
