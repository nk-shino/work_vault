# 多視点盲評価（役割別の独立評価）

複数の役割を与えたAI評価者を独立に動かし、相互参照のない評価を集め、進行役が統合する方法。2026-10-28 の投票機能必要性検討（独立盲評価8件）で実績のある手順の一般化である。

## 前提と禁止事項

- この評価は実利用者調査・専門家承認ではない。報告書・記録には必ず「AIによる役割別評価である」旨を明記する
- 「8視点すべて一致」のような一致の多さを、真偽や承認の根拠にしない。AI評価者は結論が寄りやすく、一致は論点の整理に使う
- 権威づけに使わない。「専門家の視点で評価済み」といった記述はしない（authority-claim-verification スキルの基準に従う）
- 進行役（統合する本体）は評価者を兼ねない

## 手順

### 1. 対象と問いの確定

- 評価対象（機能・提案・文書・設計）と、答えたい問いを一文で確定する
- 不足情報がある場合は質問を最大5件に絞り、評価の前にユーザーへ提示する

### 2. 前提資料を1枚にまとめる

評価者は次の構成の前提資料のみを読む。関係資料の要約と引用で作り、数値や仕様には出典を付ける。

1. 検討の位置づけ
2. 構想と方針（構想の主の言葉は転載）
3. 対象（システム・文書の対象一覧）
4. 現状（実測・ユーザー回答の要約）
5. 用語の定義と未確定事項
6. 運用手順（現行・予定）
7. 技術・運用の制約
8. 評価の出力形式（各評価者共通・下記）

### 3. 役割リストの設計（5〜8役）

評価対象の利害関係者を網羅する。既定の例であり、対象に合わせて差し替える。

- 一般の利用者・読者
- 専門家・検証担当（ファクトチェックなど）
- 運営者・管理者
- 評価対象の影響を受ける側（作成者・提供される側）
- 法務・プライバシー
- セキュリティ・不正対策
- アクセシビリティ・少数意見の保護
- 費用対効果・プロダクト

### 4. 盲評価の実施

- 1役につきサブエージェント1体。全役を同じターンで並列起動する
- 新規セッションで起動する。セッション再利用は過去の文脈を持ち込み、盲評価でなくなる（再利用が拒否されたら新規セッションで代替する）
- 渡すものは前提資料のパスのみ。評価者にファイルを作成・編集させない
- 起動プロンプトは下の雛形を使い、役割の部分だけ変える

### 5. 各評価の出力形式（前提資料§8に書き、全員で共通化）

1. 対象が必要となる条件
2. 不要または不適切となる条件
3. 最大の懸念
4. 根拠と不足情報（推測は「仮定」と明記）
5. 結論を変える証拠
6. 暫定結論（進む／限定条件で進む／代替策優先／保留／不要）と、その条件

分量の目安は600〜900字。多数決を想定しない。異論が残る場合は明記させる。

### 6. 統合（進行役）

- 一致点: どの視点が一致したか ID（評1〜）を添えて列挙する
- 対立点と残る異論: 多数決で潰さない。少数意見の扱い（保留・条件化）まで書く
- 最も強い反論: 各評価の反論を1文に統合する
- 原文は改変せず、付録に全文収録する

### 7. 成果物

- 記録ファイル（例: `評価_多視点_YYYYMMDD.md`）: 評価方法の説明＋「ID／役割／暫定結論」の表＋比較分析（一致点・対立点・最も強い反論）＋各評価の全文
- 報告書に組み込むときは、本編に統合結果のみを置き、AI評価である旨と未確認事項を分離して書く。全文は付録へ

## 起動プロンプト雛形（各評価者）

```text
あなたは「{役割}」の立場から評価する。他の評価者の存在や結論は知らない前提で、自分の視点だけから評価する。

- 前提資料: {前提資料のパス} のみを読む。外部の一般知識は使えるが、推測は「仮定」と明記する
- 立場: {立場の具体的説明と、対象との関係}
- 特に見るべき点: {その立場が見落とせない関心事}
- ファイルの作成・編集はしない。回答は本文だけで返す
- 出力は前提資料§8の6項目どおり。多数決を想定せず、異論が残る場合は明記する
```

## 実例

ワークスペースの `20261028_投票機能必要性検討/` を参照する。

- `前提資料.md`: §1〜§8 の構成例。§8 に出力形式
- `評価_多視点_20261028.md`: 8役の暫定結論表・比較分析・各評価の全文
- `報告書_投票機能必要性検討_20261028.md`: 報告書への組み込み方（§7 多視点評価・付録1 原文）
- `実行ログ_20261028.md`: 2回目以降の実施（計画文書への4視点評価）の運用

## 連携するスキル

- decision-memo: 評価結果を意思決定メモへ整理するとき
- authority-claim-verification: 評価結果の記述の権威づけ点検
- deai-writing: 報告書・記録の文体点検
- security-review: セキュリティ点検は本スキルではなくこちら
- evidence-and-change-review: 変更の完了判定は本スキルではなくこちら
