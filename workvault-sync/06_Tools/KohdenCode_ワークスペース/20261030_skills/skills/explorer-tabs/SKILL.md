# Explorer Tabs (成果物をエクスプローラーのタブで前面表示)

## 何をするか

指定された成果物のパス群を、**1つのエクスプローラーウィンドウに新しいタブとして追加**し、そのウィンドウを**前面**に出す。既存のタブは操作せず、追加のみ行う。既存のエクスプローラーウィンドウがあればそれを再利用し、なければ最初のパスで新規起動する。

## トリガーの判断

「展開して」だけでなく、「前面に表示してほしい」「エクスプローラーのタブで開いて」「成果物を並べて見せて」など、**成果物をエクスプローラーで見せること**を意図した依頼すべてで使う。ファイルを関連アプリ(Excel·メモ帳など)で開く依頼、1フォルダを開くだけの依頼は対象外(通常の Invoke-Item / explorer.exe で足りる)。

## 手順

1. **対象の確定**(優先度順):
   - a. 指示の中に明示されたパス·ファイル名
   - b. 現在のセッションで作成した成果物(実行ログの「成果物」行·直近の成果物フォルダ)
   - c. 判断できない場合は question ツールで確認(対象候補が多い·セッションに成果物が無いときのみ。少ない候補で推測して勝手に開かない)
   - 複数あるときは作成順(古い→新しい)でタブにする。目安として8タブ以内
2. **ファイルは親フォルダをタブで開く**。エクスプローラーのアドレスバーにファイルパスを入れて Enter すると関連アプリが起動するため。開いたフォルダ名と対象ファイル名を最後にチャットで明示する
3. **対象パスを1行1パスのUTF-8テキストファイルに書き出す**(write ツール)。日本語パスをコマンド引数で渡すとエンコードが崩れる恐れがあるため、必ずファイル経由にする。リストファイルはテンポラリ(`C:\Users\ss80751\AppData\Local\Temp\kohden-code\` 配下)に置く
4. **スクリプト実行**(ワークスペース外の実行のため sandbox_permissions: require_escalated + justification が必要):

   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File "<スキルのBaseDirectory>/scripts/expand_tabs.ps1" -ListFile "<リストファイル>"
   ```

   別ウィンドウを新しく立てたい場合は `-NewWindow` を付ける。
5. **結果の確認と報告**: 出力は 1行1対象で `OK(tab): <パス>` / `OK(opened with window): <パス>` / `SKIP(focus failed): <パス>`。SKIP があれば「ウィンドウにフォーカスが取れなかった対象」として報告し、再実行するかをユーザーに任せる。日本語パスはコンソール出力上で文字化けして見えることがあるが、パスの解決とタブ作成は正常に行われているため動作には影響しない。

## 動作の前提と注意

- Windows 11 のエクスプローラータブ(22H2 以降)を前提。Win10 では「タブ追加」キーが新規ウィンドウ扱いになるが、致命的ではない
- スクリプトは `^T`(新規タブ)→`^L`(アドレスバー)→`^V`(貼り付け)→`Enter` を、**フォアグラウンドが対象ウィンドウであることを確認してから**送る。それでも、ユーザーが別アプリで入力している最中の実行は衝突の恐れがあるため、ユーザーが待機しているタイミングで実行する
- クリップボードは一時使用後に元の内容(テキスト)へ復元する
- 開くのはローカルの成果物パスに限る。UNC 等の外部パスが混ざるときは実行前にユーザーへ確認する

## 失敗時

- ウィンドウが現れない: スクリプトは新規起動を試みて失敗時にエラーを返す。その場合はユーザーにエクスプローラーを1枚開いてもらい、もう一度実行する(再実行は安全)
- フォーカス奪取の失敗(SKIP)は再実行で回復する可能性が高い
