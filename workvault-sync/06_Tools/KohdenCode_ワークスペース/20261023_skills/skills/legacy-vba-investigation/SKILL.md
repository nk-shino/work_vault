# legacy-vba-investigation

## 起動条件

- マクロの不具合・再実行時の停止問題
- 入力条件やデータ書式の変更対応
- 開発PCと現場PCで動作が異なる問題

## 手順

1. **構造の把握**: ブックのシート構成、モジュール(Module1/2など)の一覧、呼び出し関係、処理の開始条件と終了条件を整理する。
2. **データ条件の確認**: 入力データの種類、見出し、列の意味、桁数、空白、数量上限などの条件を確認する。
   - **空白・桁数を一律に整形しない**。識別子の空白や桁数が意味を持つケースが多い。変更前に現行の保持条件を記録する。
3. **内部処理と外部操作の分離**: Excel内部の処理と、外部アプリ(EGPro等)の画面操作(ウィンドウタイトル、座標、待機判定)を分けて扱う。
4. **変更範囲の限定**: 必要最小限のみ変更する。要件(例: 数量上限の任意入力化)は既存フローに乗せる形で実装する。
5. **検証**: コンパイル、境界値、処理済みデータの再実行、異常終了時の挙動を確認する。
6. **診断支援**: 動かない場合は、ウィンドウタイトル、座標、待機判定(WaitMain等の戻り値)、最終行などの診断情報取得コードを提示して切り分ける。

## 再解析・再検証(既存解析物があるとき)

1. **ハッシュ照合を最優先**: 対象ブックのSHA-256を前回解析のREADME/manifestと突合する。一致なら再解析は不要で、検証(再実行+証跡diff)に切り替える。不一致なら差分箇所(シート・VBA・接続)を特定してから解析する。
2. **スクリプトのパス依存を先に潰す**: 再利用する解析スクリプトは対象パスを第1引数または環境変数で受ける。既存スクリプトが絶対パス直書きの場合、最初に一括置換し `grep` で旧パス0件を確認してから実行する(保管庫フォルダ改名で全壊する実害あり)。
3. **証跡diff**: スクリプト再実行→前回証跡とdiffし、IDENTICAL/DIFFを全件列挙する。DIFFが出たら後処理(マスク表記・NUL清掃等)起因か、実データ変化かを確認してから判定する。
4. **出力の実在確認**: リダイレクト/cp等のファイル生成は直後に同一コマンド内で実在とサイズを確認する(消失事故 ERR-20261022-001 の再発防止)。

## 出力

- モジュール別の変更後コード
- 変更差分(変更前後比較)
- テスト結果と未検証項目
- 現場PC向けの実行手順(起動から終了まで)

## 注意

- 開発PCにEGProがない等の環境差を前提にし、開発環境だけで成立する対策にしない
- 実環境で未実行なら明記する
- 本番データ操作は別途許可を確認する
