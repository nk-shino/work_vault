# evidence-and-change-review

## 起動条件

- 既存資料・コードの調査を依頼されたとき
- 仕様書・手順書の更新を伴う変更のとき
- コード改修の完了を報告する前

## 手順

1. **実在確認**: 対象ファイルと版を実在パスで確認する。ファイル名だけでなく内容・適用条件から正本を判断する。更新日時だけで正本を決めない。
2. **根拠の分類**: 情報を次に分けて扱う。
   - 事実(実在するファイル・ログ・実行結果)
   - 推定(根拠はあるが未確認)
   - 提案(自分が提案しただけ)
   - 決定(本人が明示的に承認したもの)
   - 未確認
3. **変更の整理**: 変更前後の差分と影響範囲を一覧化する。変更していない箇所も明記する。
4. **検証の区分**: 実施した検証と未実施の検証を分ける。開発PCで通っても現場PC/本番で未確認なら「実環境で未実行」と明記する。
5. **引き継ぎ情報**: 次の作業に必要な前提・制約・残課題を残す。

## 出力形式

- 根拠一覧(どのファイル・ログのどの部分か)
- 変更差分
- 検証結果(実施済み/未実施を明示)
- 残課題

## 禁止事項

- AI回答だけの確認で本番成功を認定しない
- 未実施テストを完了と表現しない
- 根拠のない断定をしない
