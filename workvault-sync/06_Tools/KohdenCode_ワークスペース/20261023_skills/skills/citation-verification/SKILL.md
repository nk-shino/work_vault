# Citation Verification — 出典付き生成と出典確認の標準運用

管理文書に載せる数値・日付・型番・規格番号・引用は、元資料の原票で確認して初めて発行できる。
本スキルは東京弁護士会 LIBRA の実務手順（判例DB照合を義務づける運用）を製造現場の文書作成に置き換えたもので、
第3次調査（`10_業務全般/PanaCIM_LNB/03_記録/AI生成文問題の解決策_第3次調査_2026-10-14.md` §4.3・優先2）に基づく。

**根拠資料:**
- 保管庫: `01_Templates/プロンプト/DeAIプロンプト.md` §5（生成指示の定型・受入れ基準）
- 保管庫: `01_Templates/プロンプト/出典付き生成_参照範囲限定RAG_セットアップ手順.md`（セットアップ・月次点検）
- 総務省ガイドブックの実測: 根拠資料を参照させると探索時間が約25%削減（https://www.soumu.go.jp/main_content/000820109.pdf）

## 1. 生成時に適用する指示（プロンプト定型）

生成AIへ資料に基づく記述を依頼するとき、次の4点を指示に含める。

- 根拠を社内資料（規格・手順書・過去の指図書）の該当箇所で示させる。**資料名・版・節番号まで**書かせる。「どこかに書いてあった」では不足
- 該当する記述が資料になければ「該当なし」と答えさせる。推測で補わせない
- 数値・日付・型番・規格番号は参照資料の記載値をそのまま写させる。換算・丸め・要約をさせない
- 出典を示せない記述は書かせない（60秒ルールの生成側の対応。数値のない方が捏造より良い）

## 2. 生成後の確認（受入れ基準）

生成物を受け入れる前に、次を確認する。deai-writing スキル §2 の「2回目・事実確認」と併用する。

- 出典として示された資料名・節番号が**実在し、該当箇所に記載がある**ことを原票で確認する。出典番号の見た目だけで通さない
- 出典の実在が確認できない記述は書き直しまたは削除の対象。「原票に戻して確認」できない記述は残さない
- 参照範囲限定型ツールを使う場合も、出典番号クリック→原票ジャンプの到達を初回・月次で確認する。ジャンプ先が期待した節と違えば参照範囲の設定を見直す
- 社外提出文書では、確認日・確認者・照合元資料の3点を文書の冒頭または末尾に記す

## 3. 社内資料 RAG の運用（ツールを選ぶ前・選んだ後の共通要件）

参照資料は版管理され正本が一意に定まるものだけに絞る。個人情報・顧客情報を含む資料と未確定のドラフトは入れない。
外部 SaaS への投入は情報取扱規程の確認または承認を得てから行う。

採用条件は7項目（参照範囲の限定・出典提示と原票ジャンプ・アクセス権・改版追従・ログ・学習への非利用・退出可能性）。
詳細とセットアップ手順・月次点検の記録様式は `出典付き生成_参照範囲限定RAG_セットアップ手順.md` を参照。

**改版時の必須操作**: 資料の改版があったら、旧版を参照範囲から削除して新版を投入する。
旧版と新版の混在は、生成物が旧版の記述を「正」として出典づけする原因になる。

## 4. 適用の判断

- **常に適用**: 数値・日付・型番・規格番号・引用・URL を載せる文書すべて（仕様書・設計書を含む）。
  deai-writing と異なり仕様書にも適用する。文体の基準は関係せず、事実の根拠のみを扱うため
- **軽減してよい**: 個人メモ・ドラフト（ただし発行段階で本スキルの確認を通す）
- 関連スキル: deai-writing（文体と多パス点検）・authority-claim-verification（権威づけ主張の検証）。
  役割分担: 生成指示と出典照合は本スキル、文体点検は deai-writing、「会議で決定」等の権威づけ主張は authority-claim-verification
