# inventory-package-maintenance

## 起動条件

- 棚卸準備・棚卸セットの更新
- 関連仕様書・マクロの見直し
- 棚卸セット ver2 のような次版の作成

## 前提

- 基準は**現行運用で実際に使っているコピー**(共有OneDriveからコピーしたもの)。新しい版や提案資料を基準にしない。
- 先に記録してから変更する。

## 手順

1. **台帳の整理**: 保管庫内のファイル一覧を作り、各ファイルの役割(本番/テスト/旧版/仕様書)を整理する。散在する仕様書も探索対象にする。
2. **正本の照合**: ファイル名だけでなく、内容と適用条件から最新・適切な資料を判断する。候補が複数ある場合は本人に確認する。
3. **恒久/回次の分離**: 恒久手順(マクロ・手順書)と回次固有データ(対象データ・数量上限・日付)を分けて扱う。回次固有の値をコードに埋め込まない。
4. **工程の点検**: 改修から実際の棚卸実施までの流れを追い、工程間の入力・出力と不足資料を確認する。抜けがあれば明示する。
5. **チェックリスト反映**: 改修結果を実施用チェックリストへ反映する。

## 出力

- 構成一覧(ファイル台帳)
- 作業フロー(改修→テスト→配置→実施)
- 差分(現行からの変更点)
- 実施前確認表

## 注意

- **現行運用への配置と変更案の作成は別工程**にする。勝手に本番配置しない。
- テストデータを作ったら削除漏れを確認する。
- コード変更後はデバッグ・簡易テスト・結果報告までを一組で行う。
