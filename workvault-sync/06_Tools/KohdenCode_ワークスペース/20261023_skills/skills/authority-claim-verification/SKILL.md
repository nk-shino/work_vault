# authority-claim-verification

## なぜこのスキルが要るか

「会議で決定した」という一行が文書に入ると、読んだ人は確認を省略し、後続の判断がその上に積み上がる。
実際に起きた失敗(2026-10-13): 調査方針(Excel MRUとWindows Recentから利用実態を逆算)について
「会議で決定」と記載したが、会議の実在すらなく、方針は作成者の独断だった。
「決定」という語一つで、未合意の提案が合意済みのように扱われ、テスト計画の前提が崩れた。

権威づけは疑われにくい。だからこそ、書く側の責任で根拠を添える必要がある。

## 起動条件

- ユーザーの発話・貼り付け資料に「会議で決定」「承認済み」「決議」「合意」「確定済み」等の権威づけがあるとき
- 自分が報告・計画書・仕様書に権威づけ表現を書こうとしているとき
- ユーザーから「虚偽」「それは違う」「決定していない」と指摘を受けたとき(是正モード)
- 過去文書の再検証を依頼されたとき

## 手順

### 1. 主張を聞いたら: 根拠を確認する

「会議で決定」には必ず根拠が伴うはず。確認する順序:

1. **議事録の実在**: 保管庫の会議記録ノートに該当件があるか(キーワード検索)
2. **日時と出席者**: 主張の中身と一致するか
3. **決議文言**: 「方針決定」なのか「検討事項として持ち帰り」なのか

確認できない場合の判定は一律ではない:

| 状況 | 扱い |
|---|---|
| 作業を進めるうえで影響がない | 「未確認の主張」として先へ進む(いちい止めない) |
| 計画・仕様・報告書の前提になる | **書き込む前にユーザーへ確認**。「会議で決定された件として進めます。議事録の所在は確認できますか」等 |
| 自分が提案した方針を権威づけしようとしている | 禁止。提案は「提案」と書く(下記 禁止事項) |

### 2. 書き込むとき: 事実と提案を分離する

報告書・計画書の背景欄・前提欄は虚偽が混入しやすい。書き分け:

```
× Excel MRUとRecentから利用実態を逆算する方針が会議で決定
○ Excel MRUとRecentから利用実態を逆算する方針(案)。**作成者の提案であり、
  会議等での決定はまだ**。実施前にレビュー担当者・関係者の合意を得ること
```

| 語 | 使ってよい条件 |
|---|---|
| 決定/確定/承認済み | 議事録・承認記録を特定でき、文言と一致するとき |
| 検討中/未決 | 合意手続きがこれから。この語を増やすのは安全 |
| 提案/案 | 自分が出しただけのもの。根拠不要だが「提案」と明記 |
| 独断 | 提案に承認がなく、かつ誰の提案か明記した上で |

### 3. 指摘を受けたら: 虚偽の是正(是正モード)

「これは虚偽です」は記録の汚染を意味する。次の順で是正する:

1. **全量走査**: 該当キーワード(例: 「会議で決定」「MRU」「逆算」)で保管庫・ワークスペースの全文検索。文書種別は .md/.txt ほか、関連する成果物すべて
2. **2種類の虚偽を区別する**:
   - **直接の虚偽**: 「会議で決定」という記載そのもの。訂正文に置換し、訂正の痕跡(版号更新・訂正日付)を残す
   - **随伴する虚偽**: それを前提にした記述(「要件は会議で確定済み」→ 確定手続きの未了)。これを残すと直接の虚偽を直した意味が消える
3. **訂正の記録**: 訂正した文書は版を上げ、訂正内容を版ヘッダや変更記録に書く。decision-log にも一行記録する
4. **再走査**: 訂正後に同じキーワードで再検索し、残存が無いことを確認して報告する

訂正文の形(直接の虚偽を「正しい情報+出典」に置換するだけでは足りない場合、虚偽だったことを明示する):

```
× (単に削除)
○ ~~会議で決定~~ → **訂正(2026-10-13)**: 会議での決定は無かった。
  本方針は作成者の独断(提案)であり、合意手続きは未了
```

### 4. 過去文書の再検証を依頼されたら

1. 対象期間・対象フォルダを決めて全量走査(部分走査で「無かった」と結論しない)
2. 権威づけ語を抽出: 決定/確定/承認/合意/決議/採用済み/確定済み/全员/現場確認済み
3. 各箇所で根拠を探す(議事録・記録ノート・コミット)。見つからなければ一覧化してユーザーに確認
4. 是正要否をユーザーの判断に委ね、勝手に歴史を書き換えない(訂正の同意を取る)

## 禁止事項

- 議事録等の一次根拠を確認せずに「会議で決定」等と書くこと
- 自分の提案を「決定」「承認済み」と表現すること
- 虚偽指摘の際、該当1箇所だけ直して走査を省略すること
- 訂正時に訂正の痕跡(版・日付)を残さず無かったことにすること
- 「確認済み」を、確認していないにもかかわらず便宜上使うこと

## 出力形式(是正モードの報告)

```
## 再検証の結果
| ファイル | 虚偽記載 | 是正 |
(箇所ごとに訂正前→訂正後)

## 検証で虚偽なしと確認できたもの
(根拠つき)

## 再発防止
(learnings への記録 ID と promotion 状況)
```
