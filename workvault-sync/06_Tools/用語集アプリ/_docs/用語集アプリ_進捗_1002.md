## 送る直前のマスキングの中身

| 用語集の DB に残すもの | LLM へ送る文での扱い |
|---|---|
| 必要書類の URL | `<URL>` に置き換える |
| 共有フォルダのパス（`\\nas-01\...` の形） | `<PATH>` に置き換える |
| 役割と一緒に出る人名（〇〇部長・〇〇さんが担当） | `<PERSON>` に置き換える |
| 「担当：〇〇」「窓口は〇〇」の名前 | `<PERSON>` に置き換える |

- 設定は `config\llm_send_masking.yaml`。ルールの書き方は、DB 側のマスキング（`masking_rules.yaml`）と同じ
- **DB に残す用例は変えない。** 置き換えるのは LLM に渡すプロンプトの中だけ
- **モック以外の LLM へは、この送信用マスキングを通さずに送れない**ようにした（通さずに呼ぶとその場で止まる）。設定ミスで素のまま送ってしまう事故を防ぐため
- テストで、LLM に届く文から NAS 名・社員名・URL が消えていること、DB の用例にはそれらが残っていることを確かめた

**これで決まったわけではないこと：** マスキング済みの抜粋そのもの（業務の文面）は、伏せたあとも送られる。pending E節の論点1（社内の文を外部 API へ出してよいか）は、引き続き規程側の判断が要る。
