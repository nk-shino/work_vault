# 用語集PoC：マスキングの方針（2026-09-24 決定）

「用語集PoC_判断結果_0924」の続き。マスキング（用例を保存する前に、個人の情報を記号に置き換える処理）で、**伏せないもの**を決めた。

## 決まったこと

- **必要書類の URL や共有フォルダのパスは伏せない。** 用語集で「その書類がどこにあるか」を引けないと、引継ぎの役に立たないため
- **役割と一緒に出る人名は伏せない。** 「〇〇部長の承認」「〇〇さんが担当」「窓口は〇〇さん」のような名前は、誰に聞けばよいかという情報そのものだから

## 実際の動き

| 文 | 保存される形 |
|---|---|
| 申請書は https://example.invalid/forms/123 から | そのまま |
| 様式は \\nas-01\共有\申請書 にある | そのまま |
| 星見部長の承認が必要 | そのまま |
| 雲居さんが担当している | そのまま |
| 担当：田中 | そのまま |
| 昨日、雲居さんに確認した | `<PERSON>`さんに確認した |
| 窓口は 000-1234-5678 | 窓口は `<PHONE>` |

「役割と一緒に出る」の判定は次のとおり。
- 名前の直後に役割の語がある（部長・課長・係長・主任・社長・担当・責任者・窓口・管理者）。間に「さん」や「が／の／は」があってもよい
- または、同じ行の直前に「担当：」「窓口は」などがある

前の行の「担当」は次の行の名前には効かない。関係の無い名前まで残してしまわないため。

メールアドレス・電話番号・金額・シリアル番号は、これまでどおり伏せる。

## 気を付けること

- 伏せないと決めた名前は、**誰でも見られて、消せない用語集に残る**（物理削除をしない設計のため）。本人が載ってよいと思っている役割の名前に限るのが前提
- 役割の語は `config/masking_rules.yaml` の `role_after` と `role_before` に並べてある。社内で使う呼び方（「リーダー」「当番」など）があれば、ここに足せばコードを変えずに効く
