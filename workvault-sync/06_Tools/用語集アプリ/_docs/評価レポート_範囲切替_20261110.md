# 評価レポート: 用語集 単語データ追加（範囲切替コーパス・2026-11-10）

## 1. 概要

用語集アプリの単語データを増やすため、収集範囲を切り替えた第3弾のデータ投入を実施した。前回までの対象はデスクトップ data フォルダだったが、今回は保管庫 Work_Vault とワークスペース kohden-code-workspace の md/txt を対象にした。ディレクトリ除外後の対象は1,010文書（保管庫649・ワークスペース361）で、マスキングと安全性検査を通過した636文書をコーパスとして採用した。

個人情報の扱いを最優先した。認証情報を含むおそれのあるディレクトリ・ファイル名を除外し、人名等を規則でマスクした。データの出典は元パスを含まない不透明IDで管理しており、元パスとの対応表は保存していない。

## 2. 方法

処理は次の順で行った。各段階の詳細は `前処理統計_20261106.md`（v1〜v4節）を参照。

1. 収集。保管庫とワークスペースから md/txt を集め、認証情報を含みうるディレクトリ（98_Pass 等）とファイル名パターンを除外した。98_Pass 配下の内容は開いていない。
2. 前処理。YAMLフロントマターの除去、45,000バイトでのキャップののち、マスキングを行った。メール用のクリーニングは資料には適用しない設計に従い、「〜書きました」行や罫線で本文が失われないようにした。
3. マスキング。アプリの設定を恒久変更せず、今回専用の上書き設定を用いた。役割語に隣接する人名、URL・file://・UNC共有パスもマスク対象とした。マスク件数は計7,859（URL 892、共有パス126、人名系6,008、シリアル396、金額306、電話122、メール9）。
4. 漏えいゲート。7桁以上の連続数字を含む文書、マスク後もメール・電話・URL・パスが残る文書を除外した。採用636文書の全行走査では、これらの残存は0件だった。
5. 候補抽出と採点。SudachiPy による名詞連結・略語・カタカナ語の抽出、専門性フラグ、文書分散（df）によるスコア計算は前回確定した仕様のままである。
6. 登録前検査。候補語ごとのプライバシー検査に加え、DBへ保存する用例（抜粋）にも同じ水準の安全性検査を適用した。疑わしい抜粋は保存せず除外した。

## 5. 留意点

1. 登録した定義はすべてモックによる仮定義である。実運用の前に全件のレビューが必要であり、自動採用は発生していない。
2. ストップワードを48語補足した。本次元の上位候補に並んだ汎用語（ユーザー・成果物など）は今回で除外済みだが、将来の入力で新たな一般語が上位に来る可能性があるため、ドライラン上位語の点検を続ける。
3. パスワード・認証情報は、定義対象としての価値が低く記録保持も望ましくない分野としてストップワードに入れた。
4. 用例検査の敬称・役職語リストは候補検査と単一の共有定数に統合した。「ちゃん」「監査役」は本次元の抜粋には現れなかったが、共有リストにより今後の入力でも同じ水準で検出される。
5. 7桁以上の連続数字のゲートは、日付形式（YYYYMMDD）も除外する。v1の計測では除外358文書の大半が日付らしい8桁だったが、v4での内訳は未計測である。本次元ではゲートを緩和していない。
6. CSV には合格を含む採点結果の全行を書いたが、プライバシー検査に当たった語の行は書いていない。

## 6. 承認経緯

- Gate 1 レビュー（attempt 1）で material 指摘5件（未マスクミラーの廃止・専用マスキング設定・採点出力の非出力化・メール用クリーナーの停止・採点スクリプトの引数化）を受け、ミラー廃止と原典からの再処理で v2 として再生成した。
- attempt 2 で、DB用例への人名疑い検査（R1）とコミット前件数検証（R2）を指摘され、抜粋の安全性検査・トランザクション内検証・入力内容ハッシュ照合を実装して v3 として再確定した。
- attempt 3 で、候補検査と用例検査の敬称群の不一致（ちゃん・監査役の欠落）を指摘され、敬称・役職語を共有定数に統合し、反例回帰テストと承認済み入力ハッシュの固定照合を追加して v4 として確定した。回帰テストは11項目すべて合格。
- 本番DBへの4,580件pending登録は例外レビュー（ora-1）で承認された。条件は、修正版コードと v4 確定入力の使用、承認ハッシュの保持と `--commit` 単独実行、登録対象が4,580から変わる場合の停止、コミット前件数検証の通過である。条件はすべて満たした。
