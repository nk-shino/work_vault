# 社内用語集

社内の用語を、定義と用例（実際に使われている文）つきで貯めて引けるようにするアプリです。引継ぎ資料やメールから用語を拾って自動で判定・登録し、人は登録後の評価と訂正に回ります（2026-09-28 の設計方針：件数が多く、全件を人が事前に承認する運用は続かないため）。

**既定では外部に一切接続しません**。LLM は既定でモック（仮の文）で、モックの定義は自動採用しません（定義は人が書きます）。社内の LiteLLM を使う設定にしたときだけ、LLM が定義案を書き、条件を満たしたものが自動で採用されます（下の「LiteLLM を使うとき」）。

## 使い方

Python 3.11 以上があれば動きます（社用PCの 3.14 用の wheel も揃うことを確認済み）。make・Docker・PowerShell スクリプトは使いません（社用PCにある保証が無いため）。

**フォルダは OneDrive などの同期フォルダの外（例：`C:\work\用語集アプリ`）に置いてください。** 仮想環境の数千ファイルを同期が掴んで、準備が途中で失敗しやすいためです。同期フォルダの中で実行すると注意が出ます。

### はじめて使うとき

`python tasks.py`（引数なし）か `start.bat` を実行するだけです。初回は準備（仮想環境の作成と依存の導入、DB の作成）をしてから起動します。VS Code の実行ボタンでも同じです。

pip が社外に出られない PC では、下の「pip が社外に出られない PC では」の手順で入れます。

### ふだんの使い方

1. **起動する：** `start.bat` をダブルクリックする（または `python tasks.py`）。ブラウザで http://127.0.0.1:8000 が開きます。自分の PC からしか開けません
2. **用語を登録する：** 画面上の「用語を登録」から、見出し・定義・用例（その語が実際に使われている文）を入れます。同じ見出しが既にあれば、2つ目の語義として足されます
3. **引継ぎ資料やメールから候補を拾う：** 資料のフォルダを指定して取り込みます。フォルダの下の `.md` / `.txt`（メモ・手順書）と `.eml` / `.csv` / `.jsonl`（メールのエクスポート）をサブフォルダまでたどって読みます

   ```
   python tasks.py import "C:\資料\引継ぎ"
   ```

   よく出てくる語を、自動判定が次の3つに振り分けます（しきい値は `config/adoption.yaml`）。

   - **用例の追加：** 登録済みの語なら、まだ無い用例を足す。定義は変えない（人が直した定義を上書きしないため）
   - **自動採用：** 新しい語で、用例2件以上・出典2種類以上・LLM の確からしさ 0.7 以上・「用例が定義を支えている」のすべてを満たすとき
   - **保留：** それ以外。「提案キュー」に理由つきで残るので、定義を書いて「修正して採用」する。モックの定義文は必ず保留になる
4. **調べる：** 「用語一覧」で見出し・読み・英語・略語から検索できます。検索条件は URL に残るので、リンクを人に渡せば同じ一覧が開きます
5. **評価する：** 語義ごとに「正しい/修正が必要/判断できない」「役に立つ/役に立たない」のボタンがあります。評価は定義を書き換えず、押した時点の版に結び付きます（定義が直されたら、旧版への評価は数えない）。ログインが無いので、件数は押された回数であって人数ではありません。「見直し」の画面で、修正が必要・意見が割れている・自動採用のまま未評価の語義を拾えます
6. **直す・つなぐ：** 用語の詳細から、定義の編集、読み・英語・略語の編集、関連語（混同注意・同義・略語の元 など）の追加ができます。誰でも、誰が作った項目でも直せます。直すときは理由が必須で、履歴にすべて残ります
7. **配る・残す：** 「CSV出力」で用語集を CSV（Excel でそのまま開ける形）で書き出せます

用語集の中身は `data/glossary.db`（1ファイル）にあります。バックアップはこのファイルをコピーするだけです。消したい用語は削除ではなく「アーカイブ」にします（誤って消した用語を取り戻せなくならないように、削除の機能は作っていません）。

### 開発・確認用

```
python tasks.py demo         # 架空メール50通で 取り込み → 提案 → 一部採用 まで通す（data/demo/ に別の DB を作る）
python tasks.py serve --db data/demo/glossary-demo.db
python tasks.py check        # lint・型チェック・テストをまとめて
```

個別の段階は `preprocess` / `extract` / `propose` / `test` / `lint` / `typecheck` / `evaluate DIR` / `fixtures`。一覧は `python tasks.py -h`。

### LiteLLM を使うとき

社内の LiteLLM ゲートウェイは OpenAI 互換の API です（2026-09-29 に管理画面で確認）。使うときは、実行する前に環境変数を入れます。値はこのフォルダのどのファイルにも書かないでください。

```
set LLM_BACKEND=litellm
set LITELLM_BASE_URL=https://（ゲートウェイの URL）/v1
set LITELLM_API_KEY=（発行された鍵）
set LITELLM_CHAT_MODEL=（例：gpt-5.4-mini）
python tasks.py import "C:\資料\引継ぎ"
```

呼び出しは標準ライブラリの urllib で行います（会社の証明書ストアをそのまま使うため）。https 以外の URL は受け付けません。

実LLM のときは、草案とは別の呼び出しで「定義が用例に裏付けられているか」を再度確かめます（正誤判定の二段構え）。裏付けがなければ自動採用せず保留にし、判定理由を提案キューに表示します。

「修正が必要」の評価が付いた定義は、改稿案を LLM に作らせられます。採用は人の確認を待ち、元の語義は残ります。

```
python tasks.py revise --limit 5
```

**LiteLLM へ送る文には、送る直前にもう一段マスキングをかけます**（`config/llm_send_masking.yaml`）。用語集の DB には、必要書類の URL・共有フォルダのパス・役割と一緒に出る人名を残していますが、これは社内の用語集に残す前提での判断で、社外の API へ送るなら前提が変わるためです。送る文からだけ URL・パス・人名を伏せ、DB の中身は変えません。この送信用マスキングを通さずに、モック以外の LLM へ送ることはできないようにしてあります。それでも、マスキング済みの抜粋自体は送られます。送ってよい範囲かは先に確かめてください。

### pip が社外に出られない PC では

ネットに出られる PC で wheel を集め、フォルダごと運びます。`--python-version` は社用PCの Python に合わせます。

```
python tasks.py wheelhouse wheels --python-version 3.11   # ネットに出られる PC で
python tasks.py setup --wheelhouse wheels                 # 社用PCで（ネット不要）
```

USB で持ち込む場合は、このフォルダごと（`.venv` と `data` を除く）と `wheels/3.11`〜`wheels/3.14` を運び、社用PCの Python に合う版を指定します。

```
python tasks.py setup --wheelhouse wheels/3.11
```

依存の版は `requirements-lock.txt` に固定してあります。3.11 / 3.12 / 3.13 向けの wheel がすべて揃うこと、揃えた wheel だけで新しいフォルダに入れてテストが全部通ることを確認済みです（合計およそ 100MB。うち SudachiPy の辞書が約 70MB）。

## ディレクトリ構成

```
tasks.py                    コマンドの入口（make の代わり）
alembic.ini                 英数字のみ（alembic はこのファイルを cp932 で読むため）
config/
  masking_rules.yaml        マスキングのルール。コードを変えずに追加できる
  cleaning_rules.yaml       署名・引用・あいさつ・免責文の除去ルール
  stopwords.txt             候補語から外す語
migrations/versions/        DB スキーマの正本（制約・トリガーはここにだけある）
src/glossary/
  ports.py                  コアが依存してよい抽象（SourcePort / LlmPort / RawDocument）
  factory.py                環境変数でアダプタを選ぶ唯一の場所
  settings.py               環境変数の読み取り
  adapters/source/          export_file_adapter（完成）/ knowledge_api_adapter（スタブ）
  adapters/llm/             mock_adapter（既定）/ litellm_adapter・local_embedding_adapter（骨格）
  preprocess/               除去 → マスキング → マスキング済みのものだけを書き出す
  stats/                    形態素解析・候補語・名寄せ・TF-IDF・共起・PMI（LLM は使わない）
  propose.py                候補語から提案を作って提案キューへ
  db/models.py, guards.py   ORM と、アプリ層の書き込みガード
  domain/                   sense_writer（語義を書く唯一の場所）/ proposals / review / queries
  web/                      レビューUI（FastAPI + Jinja2 + 素の JavaScript）
  evaluation/metrics.py     評価指標
eval/templates/             人手ラベルの CSV テンプレート（BOM 付き UTF-8。Excel で開ける）
fixtures/mails/             架空の業務メール 50 通（scripts/make_fixtures.py で再生成できる）
tests/                      テスト一式
data/                       前処理・解析の出力と DB（git 管理外）
```

## 切り替え

| 環境変数 | 値 | 既定 |
|---|---|---|
| `SOURCE_BACKEND` | `export` / `knowledge_api` | `export` |
| `LLM_BACKEND` | `mock` / `litellm` / `local` | `mock` |
| `EXPORT_DIR` | エクスポートファイルのフォルダ | `fixtures/mails` |
| `DATABASE_URL` | SQLAlchemy の URL | `sqlite:///data/glossary.db` |

変数の一覧は `.env.example`。値（接続先・キー）はリポジトリに書きません。

取り込めるのは `.md` / `.txt`（資料。更新日時を出典日時にする）と `.eml`、`body, thread_id, occurred_at, source_ref` の列を持つ CSV / JSONL を読みます。CSV は BOM 付き UTF-8 と cp932 のどちらでも読めます。時差の無い日時は日本時間とみなします。

## データの約束事と、どこで守っているか

片方だけだと抜け道が残るので、アプリ層と DB 層の両方で止めています。

| 約束事 | アプリ層 | DB 層 |
|---|---|---|
| 用例の無い定義は保存しない | `sense_writer.create_sense` が拒否 | `(first_evidence_id, id) → evidences(id, sense_id)` の遅延外部キー。コミット時に「自分の用例を1件以上指している」かを確認する |
| 語義へ書く経路は、提案の受理とレビュー画面の2つだけ | `before_flush` のガード＋`tests/test_write_paths.py` の静的検査 | （DB からは呼び出し元を区別できないので、アプリ層で担保） |
| 物理削除しない | `before_flush` が削除を拒否。アーカイブ（`archived`）へ移すだけ | 全表に `BEFORE DELETE` トリガー。マイグレーションの downgrade も用意していない |
| 更新時は必ず履歴を残す | `after_flush` で自動追記。編集理由が無ければ保存しない | 履歴は `BEFORE UPDATE` トリガーで追記専用 |
| 楽観ロック | 画面を開いた時点の版と照合し、違えば 409 で差分を見せる | `version_id_col` による `WHERE revision_number = 旧値` |
| 自分自身への関係・存在しない語義への関係 | 受理時に拒否 | `CHECK (from <> to)` と外部キー |
| 用例の長さ（400字） | 受理時に拒否 | `CHECK (length(excerpt) <= 400)` |
| メール本文の全文を保存しない | 保存するのはマスキング済みの抜粋と出典キーだけ | メール由来の用例は `masked = 1` でなければ入らない |

マスキング前の本文はメモリ上でしか扱わず、ディスクへ書き出すのはマスキング済みのものだけです。書き出す前に同じ正規表現でもう一度検査し、残っていれば止めます。

## 運用の決定事項（2026-09-24）

- 提案は採用した時点で「確定」にする
- 誰でも、誰が作った項目でも編集できる
- 編集者の欄は置かない。DB の `editor_name` / `reviewed_by` は将来ログインを入れるときのために残してあり、今は常に空
- マスキングで、必要書類の URL・共有フォルダのパスと、役割と一緒に出る人名（〇〇部長・〇〇さんが担当・担当：〇〇）は伏せない
- 手で登録した用例はマスキングしない（人が選んで書いたものなので）。取り込んだメール・資料の用例はマスキングする

## 運用の決定事項（2026-09-28 設計方針より）

- 全件の事前承認をやめ、自動判定が採用・登録まで行う。人は登録後の評価・保留の確認・訂正を担う
- 自動採用も「確定」。ただし自動採用か人の採用かは語義ごとに記録し（`adopted_by`）、未評価のものを確認済みとして見せない
- 自動でも人でも、書き込みは `proposals.accept` → `sense_writer` の同じ経路を通る。用例必須・履歴・楽観ロックは同じにかかる
- 評価は追記のみ（DB のトリガーで書き換えと削除を止める）。評価だけで定義を変えたり消したりしない
- 書き込み（POST）は同じ画面から来たものだけ受け付ける（別のサイトからの送信は 403）

## テスト

`python tasks.py test`。テスト中は、自分自身（127.0.0.1）以外への接続と名前解決を conftest が遮断します。Windows の asyncio が内部で自分自身への接続を使うので、そこだけは通しています。遮断した試みが1件でもあればテスト全体を失敗にします。LLM はモック以外を選ぶとその場で止まります。
