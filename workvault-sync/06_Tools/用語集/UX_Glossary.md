# UX用語

書式は `_用語集の書き方と回し方.md` のとおり。**正式名称・直訳・意味の3点。**

**UXの用語は、作った人が意味を込めて名付けたものが多い。**
だから直訳が効く。`affordance` は「与える」から来ていて、
**物がこちらに何を許しているか**という話だと分かれば、定義を暗記しなくて済む。

**エンジニアから入る人向けに書いた。**「無視すると何が壊れるか」を添えてある。

---

## 1. いちばん混ざるもの

### UX

- **正式名称**: User Experience
- **直訳**: 使う人の・経験
- **意味**: **製品に触れる前から後までの、その人に起きたこと全部。**画面の見た目だけでなく、届くまでの時間・問い合わせの返事・値段の分かりやすさも入る
- **混同**: **UI は UX の一部でしかない。**画面を綺麗にしても、手順が7段あるなら経験は悪い

### UI

- **正式名称**: User Interface
- **直訳**: 使う人との・境界面
- **意味**: **人と機械が触れ合う面。**ボタン・文字・音・振動
- **混同**: **「境界面」という直訳が本質。**UIは物ではなく**面**で、そこで情報が行き来する。片方向しかないならUIとして足りていない

### ユーザビリティ

- **正式名称**: usability
- **直訳**: 使える・度合い
- **意味**: **決まった目的を、どれだけ速く・間違えずに・学びやすく達成できるか。**測れる
- **混同**: **UXは良い悪いの話、ユーザビリティは測る話。**「使いやすい」と言うだけでは何も改善できない。**何秒かかったか、何人が失敗したかを出す**

---

## 2. 物が何を許しているか

### アフォーダンス

- **正式名称**: affordance
- **直訳**: （afford = 与える・許す から）与えているもの
- **意味**: **物の形そのものが「こうできる」と示している性質。**取っ手は握れる、平らな板は押せる
- **混同**: **「見た目のヒント」ではない。**それは下の signifier。アフォーダンスは**実際にできるかどうか**。押せない飾りのボタンはアフォーダンスが無い

### シグニファイア

- **正式名称**: signifier
- **直訳**: 示すもの・記号
- **意味**: **「ここを押せる」と気づかせるための手がかり。**影・下線・カーソルの変化
- **混同**: **フラットデザインで一番壊れたのがここ。**押せるのに押せると見えないボタンは、アフォーダンスはあるがシグニファイアが無い状態

### 発見可能性

- **正式名称**: discoverability
- **直訳**: 見つけられる・度合い
- **意味**: **その機能があることに、人が気づけるか**
- **混同**: **機能を作ることと、使われることは別。**「隠してあるが説明書に書いてある」は、発見可能性ゼロ

### メンタルモデル

- **正式名称**: mental model
- **直訳**: 頭の中の・模型
- **意味**: **その人が「これはこう動くはずだ」と思っている仕組みの絵。**実際の仕組みと違っていても、人はそれに従って操作する
- **混同**: **作った人の模型と、使う人の模型は必ずずれる。**自分が分かるから大丈夫、が通らない理由

## 3. 人の限界

### 認知負荷

- **正式名称**: cognitive load
- **直訳**: 認識する・積み荷
- **意味**: **一度に頭で抱えられる量には上限がある。**その上限を超えると、間違えるか諦める
- **混同**: **情報を減らすことだけが対策ではない。**まとめる・順に出す・覚えなくて済むようにする、も対策

### 段階的開示

- **正式名称**: progressive disclosure
- **直訳**: 段々に・開いて見せること
- **意味**: **最初は必要最小限だけ見せ、求められたら詳細を出す**
- **混同**: **隠すのとは違う。**入口に「詳細」があるのが段階的開示、どこにも無いのが隠蔽

### Fittsの法則

- **正式名称**: Fitts's law
- **直訳**: （人名）フィッツの法則
- **意味**: **押す対象までの距離が遠いほど、小さいほど、時間がかかる。**式で表せる
- **混同**: **画面の隅は速い。**マウスは画面外に出ないので、隅は「無限に大きい的」になる。だからタスクバーやメニューバーは端にある

### Hickの法則

- **正式名称**: Hick's law
- **直訳**: （人名）ヒックの法則
- **意味**: **選択肢が増えるほど、決めるのに時間がかかる**
- **混同**: **選択肢を減らすのが常に正しいわけではない。**よく使う3つを出して残りを「その他」に入れるのは、減らさずに速くする手

## 4. 調べる

### ペルソナ

- **正式名称**: persona
- **直訳**: （ラテン語で）仮面・役柄
- **意味**: **調査から作る、代表的な利用者の像。**名前・仕事・困っていることまで決める
- **混同**: **想像で作ったペルソナは害になる。**「仮面」なので、誰かが被らないと意味がない。**調査データが無いなら作らない**

### ジャーニーマップ

- **正式名称**: customer journey map
- **直訳**: 客の・旅の・地図
- **意味**: **目的を果たすまでの道筋を時間順に並べ、各段で何を思ったかを書く**
- **混同**: **画面の遷移図ではない。**画面に出ない部分（人に聞く、紙に書く、諦めて電話する）が入るのが要点

### Jobs to Be Done

- **正式名称**: Jobs to Be Done（JTBD）
- **直訳**: 片付けられるべき・仕事
- **意味**: **人は機能が欲しいのではなく、用を済ませたい。**「ドリルが欲しい人は、穴が欲しい」
- **混同**: **要望をそのまま作ると外れる。**「Excelに出力したい」の裏にある用（上司に見せる・金額を照合する）を見ると、別の解が出る

### 考えを声に出す法

- **正式名称**: think-aloud protocol
- **直訳**: 声に出して・考える・手順
- **意味**: **操作してもらいながら、思っていることを全部口に出してもらう。**どこで迷ったかが分かる
- **混同**: **こちらから助けないのが肝。**手を出した瞬間に、その人の経験ではなくなる

### カードソート

- **正式名称**: card sorting
- **直訳**: 札の・分類
- **意味**: **項目を書いた札を、利用者自身に分類してもらう。**メニューの区切り方を決めるのに使う
- **混同**: 作る側の分類と利用者の分類は違う。**「システム的に正しい分類」はよく外れる**

## 5. 測る

### ヒューリスティック評価

- **正式名称**: heuristic evaluation
- **直訳**: 経験則による・評価
- **意味**: **既にある原則の一覧に照らして、専門家が問題を洗い出す。**利用者を集めずにできる
- **混同**: **利用者テストの代わりにはならない。**原則違反は見つかるが、**その人が実際に困るかは分からない**

### SUS

- **正式名称**: System Usability Scale
- **直訳**: 仕組みの・使える度合いの・尺度
- **意味**: **10問の質問票で、使いやすさを点数にする。**他と比べられる
- **混同**: **点数だけでは何を直せばいいか分からない。**原因は別に調べる

### NPS

- **正式名称**: Net Promoter Score
- **直訳**: 差し引きした・推薦する人の・点数
- **意味**: 「人に薦めるか」を0〜10で聞き、**薦める人の割合から薦めない人の割合を引く**
- **混同**: **「差し引き」が直訳の要点。**9〜10だけが推薦者で、7〜8は数に入らない。**いい点を付けても中立扱いになる**ので、平均点とは別物

### A/Bテスト

- **正式名称**: A/B test（split test）
- **直訳**: AとBの・試験
- **意味**: **2つの案を同時に出して、実際の行動で比べる**
- **混同**: **差が出ても、人数が足りないと偶然と区別できない。**何人必要かを先に計算する

## 6. 作る

### ワイヤーフレーム

- **正式名称**: wireframe
- **直訳**: 針金の・骨組み
- **意味**: **色も画像も入れず、何がどこにあるかだけを描いたもの**
- **混同**: **骨組みの段階で色の話をすると、配置の議論が止まる。**わざと灰色で描く

### プロトタイプ

- **正式名称**: prototype
- **直訳**: 最初の・型
- **意味**: **触れる試作。**押すと次の画面に行く程度でよい
- **混同**: **作り込むほど捨てにくくなる。**試すために作ったものを、惜しくて本番に使うのが一番多い失敗

### デザインシステム

- **正式名称**: design system
- **直訳**: 設計の・体系
- **意味**: **部品と規則をまとめたもの。**同じボタンが画面ごとに違う、を防ぐ
- **混同**: **部品集だけではシステムにならない。**いつどれを使うかの規則が無いと、結局ばらける

### 空の状態

- **正式名称**: empty state
- **直訳**: 空っぽの・状態
- **意味**: **データが1件も無いときの画面。**初めて使う人が必ず最初に見る
- **混同**: **ここを作り忘れると、初回の体験が真っ白になる。**一覧画面を作ったら必ず0件を見る

## 7. 誰でも使えるか

### アクセシビリティ

- **正式名称**: accessibility（a11y）
- **直訳**: 近づける・度合い
- **意味**: **目・耳・手・認識に制約があっても使えるか**
- **混同**: **特別な人のための話ではない。**明るい屋外・片手がふさがっている・騒がしい場所は、誰にでも起きる

### WCAG

- **正式名称**: Web Content Accessibility Guidelines
- **直訳**: ウェブの・内容の・近づきやすさの・指針
- **意味**: 国際的な基準。**A・AA・AAA の3段階で、実務の目標は AA**
- **混同**: **「対応した」と言うには、どの版のどの等級かを言う必要がある**

### コントラスト比

- **正式名称**: contrast ratio
- **直訳**: 対比の・比率
- **意味**: 文字と背景の明るさの差。**AAは通常の文字で 4.5:1 以上、大きい文字で 3:1 以上**
- **混同**: **薄いグレーの文字は、綺麗に見えても読めない人がいる。**感覚ではなく数値で見る

### 代替テキスト

- **正式名称**: alternative text（alt text）
- **直訳**: 代わりの・文章
- **意味**: 画像の代わりに読まれる文。**画面を見ない人に、その画像が何かを伝える**
- **混同**: **飾りの画像には空にする。**「装飾」と読み上げられるほうが邪魔。**入れるか空にするかの判断が要る**

## 8. 悪い方の名前

### ダークパターン

- **正式名称**: dark pattern（deceptive design）
- **直訳**: 暗い・型 ／ 人を欺く・設計
- **意味**: **わざと分かりにくくして、利用者の意図と違う選択をさせる作り。**解約をわざと遠くに置く、同意ボタンだけ目立たせる
- **混同**: **知らずにやってしまうことがある。**「このまま続ける」だけ大きくするのは、意図が無くてもダークパターン

### 同意疲れ

- **正式名称**: consent fatigue
- **直訳**: 同意の・疲れ
- **意味**: **何度も同意を求められると、人は読まずに押すようになる**
- **混同**: **同意を取った記録があっても、理解されたとは限らない**

## 9. 覚える順番

1. **UX / UI / ユーザビリティの線引き。**ここが混ざると全部混ざる
2. **アフォーダンスとシグニファイアの違い。**この2語でUXの半分が説明できる
3. **認知負荷と2つの法則（Fitts・Hick）。**理由が数字で言える武器になる
4. 調べる手段（§4）。**1つだけ選んで実際にやる。読むだけでは身に付かない**
5. 測る（§5）、アクセシビリティ（§7）

**エンジニアから入るなら §7 を早めに読む。**
**仕様として書けて、数値で確認できるのはここだけ。**残りは判断が入る。
