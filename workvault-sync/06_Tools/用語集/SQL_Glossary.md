# SQL・データベース用語

書式は `_用語集の書き方と回し方.md` のとおり。**正式名称・直訳・意味の3点。**

**倉庫移動SQL（idouSQL）に寄せてある。**あの処理は `UPDATE` と
`COMMIT` / `ROLLBACK` が中心で、取り消せない操作を含む。
**一般的なSQL入門とは重みが違うので、そこを厚く書いた。**

---

## 1. SQL そのもの

### SQL

- **正式名称**: Structured Query Language
- **直訳**: 構造を持った・問いかけの・言葉
- **意味**: データベースに対する命令の言葉。**「問いかけ」という名前だが、読むだけでなく書き換えも消去もできる。**名前から受ける印象より危険
- **混同**: 「シークェル」とも「エスキューエル」とも読む。**どちらでも通じる**

### DDL / DML / DCL

- **正式名称**: Data Definition / Manipulation / Control Language
- **直訳**: データを・定義する／操る／制御する・言葉
- **意味**: SQLの命令は3種に分かれる。**定義（`CREATE` `ALTER` `DROP`）、操作（`SELECT` `INSERT` `UPDATE` `DELETE`）、制御（`GRANT` `REVOKE`）**
- **混同**: **多くのDBで DDL は暗黙に確定する。**`CREATE TABLE` を打った時点で、`ROLLBACK` しても戻らない。**`ROLLBACK` が効くのは DML だけだと思っておく**

## 2. 取り消しに関わるもの

**倉庫移動SQLで一番大事な節。**

### トランザクション

- **正式名称**: transaction
- **直訳**: 取引・やりとり
- **意味**: **複数の操作を「全部やるか、全部やらないか」のひとまとめにする枠。**倉庫Aから引いて倉庫Bへ足す処理で、引いた後に落ちたら在庫が消える。**それを防ぐために両方を1つの取引にする**
- **混同**: **枠を開いていなければ、1文ごとに確定する。**`UPDATE` を5本流して3本目で落ちたら、2本は確定済みで戻らない

### COMMIT

- **正式名称**: commit
- **直訳**: 委ねる・確定させる
- **意味**: トランザクションの中でやったことを**確定する。これ以降は取り消せない**
- **混同**: **`COMMIT` の後に「間に合わなかった」は無い。**流す前に対象件数を数える

### ROLLBACK

- **正式名称**: rollback
- **直訳**: 巻き戻す
- **意味**: トランザクションの中でやったことを**全部捨てて、開始前に戻す**
- **混同**: **`COMMIT` 済みのものは戻せない。**`ROLLBACK` は「まだ確定していない分」だけを巻き戻す。**取り消せる窓は `COMMIT` までの間しかない**

### 自動コミット

- **正式名称**: autocommit
- **直訳**: 自動の・確定
- **意味**: 1文流すたびに自動で `COMMIT` される設定。**多くの接続ツールの既定がこれ**
- **混同**: **これが入っていると `ROLLBACK` は何も戻さない。**トランザクションの枠を自分で開いたつもりでも、設定が勝つことがある。**流す前に、その接続が自動コミットかを確認する**

### ロック

- **正式名称**: lock
- **直訳**: 錠
- **意味**: **誰かが書き換えている最中の行や表を、他から触らせないようにする仕組み。**無いと、2人が同じ在庫を同時に引いて、片方の減算が消える
- **混同**: **ロックは待たせる。**夜間バッチが長いトランザクションを開いたまま走ると、昼間の端末が止まる。**`COMMIT` を遅らせるほど、他を止める時間が伸びる**

### デッドロック

- **正式名称**: deadlock
- **直訳**: 死んだ・錠
- **意味**: AがBの錠を待ち、BがAの錠を待って、**どちらも永久に進めなくなる状態。**DB側がどちらかを強制的に失敗させて解く
- **混同**: **「たまたま失敗した」ように見える。**同じ処理が成功したり失敗したりするときは、これを疑う。**対策は、複数の表を触る順番を全プログラムで揃えること**

### 分離レベル

- **正式名称**: isolation level
- **直訳**: 切り離しの・水準
- **意味**: **他のトランザクションの途中の状態が、どこまで見えてしまうかの段階。**厳しくすると正確になるが、待ちが増える
- **混同**: **既定の水準はDB製品ごとに違う。**同じSQLが別のDBで違う結果を出す原因になる

## 3. NULL

**仕様書に4回出てくる。バグの発生源として扱う。**

### NULL

- **正式名称**: null
- **直訳**: 無効・何も無い
- **意味**: **「値が入っていない」という状態。0でも空文字でもない。**在庫数が `0` は「在庫を数えて0だった」、`NULL` は「数えていない」
- **混同**: **ここが一番事故る。**次の2点を覚える

### NULL の比較

- **意味**: **`NULL = NULL` は真にならない。**「分からない値」と「分からない値」が等しいかは、分からないため。判定は `IS NULL` / `IS NOT NULL` を使う
- **混同**: `WHERE 倉庫 <> 'A'` は**倉庫が `NULL` の行を拾わない。**除外したつもりの行が残り、残したつもりの行が消える。**`WHERE 倉庫 <> 'A' OR 倉庫 IS NULL` と書く**

### NULL の計算

- **意味**: **`NULL` を含む計算は `NULL` になる。**`在庫 + NULL` は `NULL`。合計を出すと、1件の未入力で全体が消える
- **混同**: `COUNT(列)` は `NULL` を数えないが、**`COUNT(*)` は数える。**件数が合わないときはここを見る

## 4. 取り出し

### SELECT

- **正式名称**: select
- **直訳**: 選び出す
- **意味**: データを取り出す命令。**書き換えないので、流して確認するのに使える**
- **混同**: **`UPDATE` を流す前に、同じ `WHERE` で `SELECT` して件数を見る。**これが取り消せない操作に対する唯一の予防

### WHERE

- **正式名称**: where（句）
- **直訳**: どこで・どういう場合に
- **意味**: 対象を絞る条件。**`UPDATE` と `DELETE` では、ここが命綱**
- **混同**: **`WHERE` を書き忘れた `UPDATE` は全行を書き換える。**エラーにならない。`ROLLBACK` できる窓の中でしか助からない

### JOIN

- **正式名称**: join
- **直訳**: 繋ぐ・結合する
- **意味**: 複数の表を、共通の列で横に繋いで1つの表として扱う。**部品番号で部品マスタと在庫を繋ぐ、など**
- **混同**: **繋ぎ方で件数が変わる。**`INNER` は両方にある行だけ、`LEFT` は左の全行を残して右が無ければ `NULL` を入れる。**件数が増えたら、繋ぎの列が片方で重複している**

### DISTINCT

- **正式名称**: distinct
- **直訳**: 区別された・重複の無い
- **意味**: 重複する行を1つにまとめる
- **混同**: **`DISTINCT` で件数が合うようになったら、それは解決ではない。**重複が出る原因（JOINの繋ぎ列）が残っている

### GROUP BY / HAVING

- **正式名称**: group by / having
- **直訳**: ～でまとめる ／ ～を持つものに限る
- **意味**: 列の値でまとめて、合計や件数を出す。`HAVING` は**まとめた後の結果に対する条件**
- **混同**: **`WHERE` はまとめる前、`HAVING` はまとめた後。**「合計が100を超えるものだけ」は `HAVING`。`WHERE` には書けない

## 5. 構造

### 主キー

- **正式名称**: Primary Key（PK）
- **直訳**: 主たる・鍵
- **意味**: **その行を1件に特定できる列。**重複も `NULL` も許さない
- **混同**: **主キーが無い表は、同じ行が2件入っていても気づけない。**`UPDATE` の対象が1件に絞れず、巻き込みが起きる

### 外部キー

- **正式名称**: Foreign Key（FK）
- **直訳**: 他所の・鍵
- **意味**: 別の表の主キーを指す列。**存在しない部品番号の在庫を作れなくする**
- **混同**: **設定されていないことが多い。**無いと、マスタから消えた部品の在庫が孤立して残る

### インデックス

- **正式名称**: index
- **直訳**: 索引
- **意味**: 本の索引と同じ。**全ページめくらずに目的の行へ飛べるようにする。**同じSQLが何十倍も速くなる
- **混同**: **書き込みは遅くなる。**索引も一緒に書き換えるため。大量 `INSERT` の前に外して後で付けるのは、この理由

### 正規化

- **正式名称**: normalization
- **直訳**: 標準の形にすること
- **意味**: **同じ情報を1か所にしか持たないように表を分けること。**部品名を在庫の全行に書くのをやめて、部品マスタ側だけに持つ
- **混同**: **分けるほど JOIN が増えて読みにくくなる。**実務では意図的に崩す（非正規化）こともある。**崩したなら、どこが二重持ちかを記録に残す**

### ストアドプロシージャ

- **正式名称**: stored procedure
- **直訳**: 蓄えられた・手続き
- **意味**: **DB側に保存しておく処理のまとまり。**端末から呼ぶだけで中の複数のSQLが流れる
- **混同**: **コードがDBの中にあるので、ファイルを検索しても出てこない。**「どこにこの処理があるか分からない」の原因になりやすい

## 6. 繋ぎ方

### ODBC

- **正式名称**: Open Database Connectivity
- **直訳**: 開かれた・データ置き場への・つながり
- **意味**: **どのDBにも同じ書き方で繋げるようにする中間層。**Excel や Perl から EGPro を叩けているのはこれ
- **混同**: **32ビットと64ビットで設定が別々に存在する。**Excelが32ビットなら32ビット側の設定が必要

### ADO / ADODB

- **正式名称**: ActiveX Data Objects
- **直訳**: 能動的な部品としての・データの・もの
- **意味**: **VBAからDBを触るための部品。**`ADODB.Connection` `ADODB.Recordset` の形で使う
- **混同**: **接続を閉じないと、サーバー側に残る。**`Close` と `Set ... = Nothing` を書く。残り続けると接続数の上限に当たって、他の人が繋げなくなる

### プレースホルダ

- **正式名称**: placeholder / parameterized query
- **直訳**: 場所を・押さえておくもの
- **意味**: SQLの中に値を直接書かず、`?` を置いて後から渡す書き方。**値に `'` が入っていても壊れない**
- **混同**: **文字列の連結でSQLを組むと、値の中身でSQLの形が変わる。**部品名に `'` が1つ入っているだけで失敗する。悪意が無くても起きる

## 7. 流す前の確認

**仕様書どおりに流すときの手順。覚える対象ではなく、毎回見る対象。**

1. **同じ `WHERE` で `SELECT COUNT(*)` を取る。**想定件数と合うか
2. **その接続が自動コミットかを確認する。**自動なら `ROLLBACK` は効かない
3. **トランザクションを開く**
4. 流す。**影響件数が手順1の数と一致するか**
5. 一致していれば `COMMIT`、違えば `ROLLBACK`

**手順4で止まれるようにするのが、トランザクションを使う唯一の理由。**
確定してから数えても、もう戻せない。
