# 用語集の書き方と回し方

既存の用語集が「AIっぽくて分かりにくい」ので書式を決め直した。
**あわせて、読むだけで終わらせないための道具を調べて組み込んだ。**

---

## 1. なぜ直訳を入れるのか

**技術用語が覚えられない一番の理由は、それが意味のない文字列に見えているから。**

`Elastic Compute Cloud` を「EC2、AWSの仮想サーバー」として覚えると、
**暗記する対象が3文字の記号になる。**忘れたら戻ってこない。
一方「伸び縮みする・計算する・雲」と読めれば、**名前そのものが機能の説明になる。**
`Elastic` が付く理由（必要なときだけ増やして減らせる）まで名前に書いてある。

もう一つ効くのは、**同じ語が別のサービスでも使われること。**
`Elastic` を一度ほどけば `Elastic Block Store`・`Elastic Load Balancing`・
`Elasticsearch` が全部ただで読めるようになる。**1語ずつ覚えるより安い。**

これは試験対策としても効く。選択肢に見たことのない略語が出ても、
**展開して直訳すれば、だいたい正解の方向が分かる。**

### 直訳と意訳は分ける

直訳は**意味を取らずに語をそのまま置き換える。**
`Availability Zone` は「可用性ゾーン」ではなく **「使える状態・地帯」。**
「可用性」はもう日本語の専門用語になっていて、**訳したことにならない。**
分からない語を分からない語に置き換えるのが、既存の用語集が読みにくかった原因。

## 2. 書式

1項目はこの4行で書く。**表にしない。**横に広がると直訳が削られる。

```markdown
### 用語（見出しは日本語か、定着している略語）

- **正式名称**: 英語のフルスペル（略語は展開する）
- **直訳**: 語をそのまま日本語に置き換えたもの
- **意味**: 何をするものか。**なぜそれが必要になったのかまで書く**
- **混同**: 間違えやすい相手があるときだけ書く。無ければ行を消す
```

### 守ること

**絵文字を使わない。** 旧 CCNA 用語集は236項目すべてに `🔹` が付いていた。
情報を持たない記号が項目数ぶん並ぶと、**どれが重要か分からなくなる。**

**冒頭に免責の段落を置かない。** 旧版には「本ノートは学習用の整理です」
「全定義を一次資料で個別検証済みという意味ではありません」が並んでいた。
**誰も読まないし、読んでも何も変わらない。**
版や出典が重要なものは、**その項目の中に1行で書く**（試験範囲の改訂日など）。

**「意味」で辞書の定義を繰り返さない。**
「異なるIPネットワーク間でパケットを転送するL3装置」は正しいが、
**それを読んで分かる人は、もう調べる必要がない。**
「なぜルーターが要るのか（VLANをまたぐと誰かが橋渡しをしないと届かない）」を書く。

**知らないことは空欄にする。** 埋めるより、嘘がないほうが使える。

## 3. Claudeで学習するときの道具

調べて使えると判断したものだけ。

### 学習スタイル（claude.ai）

入力欄の左下のプラス → **「スタイルを使用」→「学習」**。

**答えを直接出さず、先に今の理解度を聞いてくる。**
段階的に説明して、そのあと理解を確認する質問を投げる。
**自分の言葉で答えさせる形になっているのが要点で、**
用語集を読む（入力）だけでは起きない出力が発生する。

**用語集と組み合わせる使い方:** 用語集を貼って
「この中から5個選んで、学習スタイルで順に聞いてほしい」と頼む。
読み返すより、**答えられなかった項目が特定できる**ぶん速い。

出典: [クラスメソッド](https://dev.classmethod.jp/articles/claude-learning-style-guide/)

### 一問一答をスキルで作る（`/mq` の型）

Google Cloud の資格勉強で、**1問ずつ作って蓄積するスキル**を組んだ例がある。

- 問題を分類する → 公式文書を調べる → 回答を作る → 保存先へ追記する → **進捗を `state.json` に書く**
- **1問ずつにするのが肝。**まとめて大量生成すると質が落ちて、結局やらない
- 時間を食っていたのは「公式文書の調査」と「保存先への書き込み」の2つ

**この保管庫ではNotionの代わりに用語集そのものを保存先にできる。**
MCPの追加もいらない。下の §4 がその実装。

出典: [電通総研テックブログ](https://tech.dentsusoken.com/entry/google-cloud-certification-claude-code-skill)

### やらないと決めたもの

**過去問をアプリ化する手法**は見つけたが、**今は要らない。**
アプリを作る時間のほうが、用語を覚える時間より長くなる。
用語集が埋まって、**問題演習の段階に来てから考える。**

**Anki などの外部の分散復習ツールも入れない。**
**同じ内容を2か所で持つと、必ず片方が古くなる。**
この保管庫の中で完結させて、間隔は下の「最終確認日」で見る。

## 4. 回し方

### 1日分の手順

```
/glossary-quiz CCNA
```

スキルが用語集から**最終確認日が古い順に5問**出す。
答えたら、`最終確認: 2026-10-02` の行だけが書き換わる。
**間違えた項目には `要復習` が付いて、次に優先して出てくる。**

**紙でも回せる。**「最終確認」が古い順に見出しを拾って、
正式名称と直訳を隠して言えるか試すだけ。

### なぜ最終確認日を項目に持つのか

**別ファイルで管理しない。**用語集を手で直したときに進捗だけ取り残されて、
**どちらが本当か分からなくなる。**項目と同じ行にあれば、それが起きない。

### 試験範囲が変わったとき

**用語を消さない。** 範囲外になった項目には `範囲外: v2.0〜` と書いて残す。
**消すと「前は出たのか」が分からなくなり、同じ調査をやり直すことになる。**
