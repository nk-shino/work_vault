# Azure用語

書式は `_用語集の書き方と回し方.md` のとおり。**正式名称・直訳・意味の3点。**

**AWS を先に学んでいる前提で書いた。**同じ概念に別の名前が付いているだけのものが多く、
**対応が分かれば覚える量が半分になる。**§1に対応表を置いた。

**サービス名も値段も変わる。**このノートは考え方の対応を押さえるためのもので、
受験や設計のときは公式の最新を見る。

---

## 1. AWS との対応

**名前が違うだけで役が同じもの。**ここを先に通すと、残りは差分だけになる。

| Azure | AWS | 役 |
|---|---|---|
| サブスクリプション | アカウント | 請求と権限の入れ物 |
| リソースグループ | （近いものが無い） | **Azure独自。**まとめて消せる単位 |
| Microsoft Entra ID | IAM + Identity Center | 利用者の名簿 |
| 仮想ネットワーク（VNet） | VPC | 自分専用の網 |
| ネットワークセキュリティグループ（NSG） | セキュリティグループ | 通信の許可／拒否 |
| 仮想マシン（VM） | EC2 | 仮想サーバー |
| マネージドディスク | EBS | VMに付ける円盤 |
| Blob Storage | S3 | 置くだけの倉庫 |
| Azure SQL Database | RDS | 面倒を見てもらうDB |
| App Service | Elastic Beanstalk | アプリを置くだけで動く場 |
| Azure Functions | Lambda | 呼ばれたときだけ動く関数 |
| AKS | EKS | Kubernetes の面倒見 |
| Azure Monitor | CloudWatch | 監視と記録 |
| Key Vault | KMS + Secrets Manager | 鍵と秘密の保管 |
| ARM / Bicep | CloudFormation | 構成をコードで書く |
| Azure Policy | SCP + Config | やってはいけないことを決める |
| Front Door | CloudFront | 入口と配信 |
| ExpressRoute | Direct Connect | 専用線 |

### 対応しないもの

**リソースグループは AWS に相当物が無い。**ここが最大の差なので §2 で厚く書く。

## 2. 入れ物の階層

**Azure を分かりにくくしているのは、入れ物が4段あること。**

### サブスクリプション

- **正式名称**: subscription
- **直訳**: 定期購読・加入
- **意味**: **請求と上限がまとまる単位。**「定期購読」という名前なのは、月額で使い続ける契約という捉え方から。AWSのアカウントに近い
- **混同**: **リソースの上限（クォータ）がここに付く。**上限に当たったとき、サブスクリプションを分けるのが解決策になることがある

### リソースグループ

- **正式名称**: resource group
- **直訳**: 資源の・組
- **意味**: **まとめて作って、まとめて消すための箱。**Azureのリソースは必ずどれか1つに属する。**検証環境を作って片付けるとき、グループごと消せば残骸が出ない**
- **混同**: **AWSに同じものが無いので最初につまずく。**AWSではタグで擬似的にやることを、Azureは構造として持っている。**逆に、グループを跨いで整理し直すのは手間がかかるので、最初の切り方が効く**

### 管理グループ

- **正式名称**: management group
- **直訳**: 管理の・組
- **意味**: **サブスクリプションの上に置く階層。**組織全体に一括でポリシーを当てるときに使う
- **混同**: リソースグループとは層が違う。**上から 管理グループ → サブスクリプション → リソースグループ → リソース の4段**

### リソース

- **正式名称**: resource
- **直訳**: 資源
- **意味**: VM・ディスク・DBなど、実体のあるもの1つ1つ
- **混同**: **Azureでは全てが「リソース」として同じ仕組みで管理される**（ARM、下記）。この統一があるので、構成をコードで書ける

## 3. 利用者と権限

### Microsoft Entra ID

- **正式名称**: Microsoft Entra ID（旧 Azure Active Directory / Azure AD）
- **直訳**: Entra は造語（entrance = 入口 から）。ID は識別情報
- **意味**: **クラウド側の利用者の名簿。**Microsoft 365 と同じものを使う
- **混同**: **2023年に Azure AD から改名された。**古い教材・古い画面・古いコマンド（`AzureAD` モジュール）には旧名が出る。**同じものだと分かっていないと、別のサービスだと思って二重に覚える**
- **混同2**: **社内の Active Directory とは別物。**社内ADはサーバーの名簿、Entra IDはクラウドの名簿。繋ぐには同期の仕組みが要る

### RBAC

- **正式名称**: Role-Based Access Control
- **直訳**: 役割に・基づく・近づくことの・制御
- **意味**: **「誰に」「どの役を」「どの範囲で」の3点で権限を決める。**役は所有者・共同作成者・閲覧者など
- **混同**: **範囲は階層を下へ継承する。**管理グループで与えた権限は、配下の全サブスクリプションに効く。**「ここだけのつもり」が広く効いていることがある**

### マネージドID

- **正式名称**: Managed Identity
- **直訳**: 面倒を見てもらう・身分
- **意味**: **VMやアプリ自身に身分を持たせる仕組み。**これを使うとコードに鍵を書かなくて済む
- **混同**: **これが使える場面でキーをコードに書いているのは、設計の問題。**鍵の置き場を悩む前に、マネージドIDで済むかを見る

## 4. 置き場所

### リージョン

- **正式名称**: region
- **直訳**: 地域
- **意味**: データセンターがまとまっている地理的な場所。**日本なら東日本・西日本**
- **混同**: **サービスによって使えるリージョンが違う。**新しいサービスは一部のリージョンだけで始まる

### 可用性ゾーン

- **正式名称**: Availability Zone（AZ）
- **直訳**: 使える状態の・地帯
- **意味**: **1つのリージョンの中で、電源と回線が分かれている区画。**片方が止まってももう片方が生きる
- **混同**: **「可用性ゾーン」と訳しても何も分からない。**要は**別の建物**。だから片方の停電が波及しない

### リージョンペア

- **正式名称**: region pair
- **直訳**: 地域の・対
- **意味**: **Azureがあらかじめ決めている相方のリージョン。**更新を同時に当てない、災害時の復旧を優先する、といった扱いを受ける
- **混同**: **AWSに無い概念。**自分で選ぶのではなく、Azure側が決めている

---

## 5. 計算と保存

### 仮想マシン

- **正式名称**: Virtual Machine（VM）
- **直訳**: 仮想の・機械
- **意味**: 物理サーバーの上に作る、OSごと丸ごとの計算機
- **混同**: **止めても課金が続くものがある。**ディスクとIPアドレスは、VMを止めても残る。**消すまで払う**

### スケールセット

- **正式名称**: Virtual Machine Scale Set（VMSS）
- **直訳**: 仮想機械の・規模の・組
- **意味**: **同じVMを必要な数だけ自動で増減させる仕組み**
- **混同**: 可用性セット（下記）は**壊れないようにする**仕組み、スケールセットは**数を変える**仕組み。目的が別

### 可用性セット

- **正式名称**: Availability Set
- **直訳**: 使える状態の・組
- **意味**: **同じ役のVMを、物理的に別のラックや電源へ散らす設定。**メンテナンスで同時に落とされないようにする
- **混同**: **1台だけで可用性セットに入れても意味が無い。**散らす先が無い

### ストレージアカウント

- **正式名称**: storage account
- **直訳**: 保存の・口座
- **意味**: **Blob・ファイル・キュー・テーブルをまとめて入れる器。**この単位で冗長構成や接続の鍵が決まる
- **混同**: **S3のバケットとは層が違う。**ストレージアカウントの中にコンテナーがあり、その中にBlobが入る。**S3のバケット ≒ Azureのコンテナー**

### Blob Storage

- **正式名称**: Blob Storage（Binary Large Object）
- **直訳**: 大きな・ひとまとまりの・もの
- **意味**: 画像・動画・バックアップなど、**中身の構造を問わず置くだけの倉庫**
- **混同**: アクセス層（ホット・クール・アーカイブ）がある。**アーカイブは取り出しに時間が掛かる。**安いが、すぐ要るものを入れると困る

## 6. 構成をコードで書く

### ARM

- **正式名称**: Azure Resource Manager
- **直訳**: 資源の・管理者
- **意味**: **Azureの全操作が通る一枚の層。**ポータルもCLIもここを叩いている。だから操作が統一されている
- **混同**: ARMテンプレート（JSON）は読み書きが辛い。**今は Bicep を使う**

### Bicep

- **正式名称**: Bicep（上腕二頭筋）
- **直訳**: 力こぶ
- **意味**: **ARMテンプレートを書くための、読みやすい言葉。**書いたものはARMテンプレートに変換されて実行される
- **混同**: 名前の由来は **ARM（腕）を動かすもの**という洒落。覚えやすさのために作られた名前で、機能の説明ではない

### Azure Policy

- **正式名称**: Azure Policy
- **直訳**: 方針
- **意味**: **やってはいけないことを先に決めて、作ろうとした時点で止める仕組み。**「タグの無いリソースを作らせない」「指定外のリージョンを使わせない」
- **混同**: RBACは**誰ができるか**、Policyは**何を作れるか**。所有者権限を持っていても Policy には勝てない

## 7. 監視

### Azure Monitor

- **正式名称**: Azure Monitor
- **直訳**: 監視するもの
- **意味**: 指標と記録を集める入口
- **混同**: 中身が複数に分かれている。**指標（メトリック）は数値の時系列、ログは文章。問い合わせ方が別**

### Log Analytics

- **正式名称**: Log Analytics workspace
- **直訳**: 日誌の・分析（の作業場）
- **意味**: **ログを集めて問い合わせる置き場。**KQL という専用の言葉で検索する
- **混同**: **置き場を作らないと、ログの保存先が無い。**監視を有効にしただけでは何も溜まらない

### KQL

- **正式名称**: Kusto Query Language
- **直訳**: Kusto（開発時の呼び名）の・問いかけの・言葉
- **意味**: Log Analytics を検索する言葉。**`|` で繋いで絞り込んでいく形**
- **混同**: **SQLとは別物。**似ているが構文が違う。SQLの知識はそのままでは使えない

## 8. お金

### 予約インスタンス / 節約プラン

- **正式名称**: Reserved Instances / Savings Plans
- **直訳**: 予約された・実例 ／ 節約の・計画
- **意味**: **1年か3年使うと約束して安くする仕組み**
- **混同**: **使わなくても払う。**止めても戻らない。検証環境には向かない

### スポット

- **正式名称**: Spot Virtual Machines
- **直訳**: その場・現物
- **意味**: **余っている容量を安く使う。**ただしAzure側の都合で止められる
- **混同**: **止められて困る処理には使えない。**途中から再開できるバッチ向け

---

## 9. 覚える順番

**全部を一度に見ない。この順で足場が組める。**

1. **サブスクリプション → リソースグループ → リソース**の3段。**これが分かるまで次へ行かない**
2. **Entra ID と RBAC。**権限が分からないと何も作れない
3. **VNet と NSG。**繋がらない原因の大半がここ
4. **VM と ストレージアカウント。**実体のあるものを1つ作る
5. **ARM / Bicep。**手で作ったものをコードに起こす
6. 監視とお金

**AWSで同じ順にやっているなら、§1の対応表を見るだけで 1・4・5 は飛ばせる。**
