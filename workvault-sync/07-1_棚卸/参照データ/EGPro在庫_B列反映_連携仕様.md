# EGPro在庫→B列反映 連携仕様

不足部品リストのB列へEGPro在庫を反映するとき、
**セットアップレポートとEGProのどちらから何を取るか**を定める。

出典は B列修正タスク時の松井さんへの聞き取り（実施日は下表）。
聞き取りで確定した内容であり、資料から読み取った推測ではない。

| 機種 | 聞き取り日 |
| --- | --- |
| TEC10 | 08-17 |
| TEC56 | 08-17 |
| AED | 08-12 |
| 送信機 | 08-13 |

---

## 1. 2つのデータをどう使い分けるか

**役割が違う。片方で両方を賄わない。**

| データ | 役割 |
| --- | --- |
| L3セットアップレポート | **L3に取り付けられているリールを特定する**ために使う |
| EGPro | **特定したリールの現在の在庫数を取得する**ために使う |

セットアップレポートは在庫数量を取るためのものではない。
「どのリールが載っているか」だけを答える資料として扱う。

---

## 2. 照合のしかた

セットアップレポートの次の2つを、EGProの**シリアル番号**と突き合わせる。

- 材料バーコード
- スプライシングリール

**2つを文字列として連結しない。** それぞれを独立したリール番号として扱い、
EGProのシリアル番号に一致するものをそれぞれ検索する。

- スプライシングリールが空欄なら、材料バーコードのみで照合する
- **「スプライシングリール2」「スプライシングリール3」は対象に含めない**

---

## 3. 数量をどこから取るか

**セットアップレポートの「初期数量」を現在在庫として使わない。**
初期数量は積んだ時点の数であって、いま残っている数ではない。

現在の数量は **EGProの「在庫数」** を使う。

**EGProのロケーションは「設備(L3)」に限定しない。**
照合対象のシリアル番号が一致すれば、ロケーションに関係なくEGProの在庫数を採用する。
L3から降ろされて別の場所にあっても、そのリールの在庫はそのリールの在庫として数える。

### EGPro CSV の列

| 列 | 意味 |
| --- | --- |
| 2列目 | 品番 |
| 6列目 | 在庫数 |
| 8列目 | ロケーション名称 |

---

## 4. 不足部品計算シートへの反映

同じ部品番号に複数のリールが該当する場合は、**照合した各リールのEGPro在庫数を合計する。**

```
部品番号ごとの取付済在庫
  ＝ 材料バーコードに一致するリールのEGPro在庫数
  ＋ スプライシングリールに一致するリールのEGPro在庫数
```

---

## 5. 特採部品（T付）の扱い

ここが最も取り違えやすい。**EGProとBOSS/MESで品番の持ち方が違う。**

| 問い | 回答 |
| --- | --- |
| EGProでは、Tを外した元品番として在庫計上されているか | **別品番として在庫保持している。**T付きは別レコード |
| T付部品を実装で消費したとき、在庫はどの品番から引き落とされるか | **T付用の在庫から引き出している** |
| BOSS/MESとEGProで、T付品番の持ち方は一致しているか | **一致していない。BOSS/MES上はT無し、EGProだけTが付く** |

### なぜこれが効くか

**同じ部品を、システムによって別の品番で見ていることになる。**
EGPro側の在庫を品番で集計してBOSS/MES側と突き合わせると、
T付きぶんが別品番として分かれているため、数が合わない。

T付の管理は**指図ごと**に行われている。
BOSS/MES上では、T部品は**10桁の発注番号**で特別採用か代替部品かを管理している。

**指図ごとのT付管理と、10桁発注番号による特別採用／代替部品の区別を記録に残したい。**
