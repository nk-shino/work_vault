# 0確認マクロver2 運用手順

この文書は、[[0確認マクロ_運用確定質問票]] の Q1〜Q35 の回答（松井さん・現場責任者）を運用の形に整えたものである。書く範囲は、回答から確定する運用規律・未決事項・xlsm への実装事項の3点。根拠は質問票の回答行のみとし、回答に無い判断は「提案」として区別する。反映日は 2026-10-15。

## 1. 確定した運用（回答から直ちに確定するもの）

### 1.1 ブックと保存

- 正式版は `0確認マクロ_ver2.xlsm` に修正して運用する（Q1）。
- 保存場所は共有 `\\nksv569.ad.nkc.co.jp\Share\mnt\DGS-SV\◎棚卸し`（Q2）。
- ブックの変更は原則だれでもできる（Q3）。VBA も現場責任者の判断で変更できる（Q4-C）。
- 旧来の方針「現場責任者には VBA を編集させない」（[[0確認マクロ 運用・改修・記録 一枚集約]] §1.2）は、この決定によって置き換わる。変更時は VBA 変更記録と試験記録を残す（Q31）。

### 1.2 実行者と立会い

- 実行者は現場責任者（松井さん）と、松井さんが指名した担当者。新人は松井さんが教える。手順書は共有する（Q5-B）。
- ラベル消去の承認は不要（Q6-D）。現在実行するのは松井さんまたは係長の茂木（由美子）さん。
- 初回実行は設計者と現場担当者が立ち会う（Q7-C）。初回以降は正常運用が確認できるまで立会いが必要（Q8-B）。

### 1.3 実行タイミングと準備

- 実行時間帯は棚卸作業時間中に限定する（Q9-C）。棚卸は半年に一度。
- 実行前に他の担当者の EG-Pro 操作を停止する（Q10-A）。
- 使用する CSV は取得した当日中のもの（Q11-A）。

### 1.4 新規実行と取込

- 新規実行時に B 列が空でない場合は、別シートか別ブックへ退避してから空にする（Q12-B）。
- B 列が残っていても、過去結果を保存した後なら新しい CSV の取込を許可する（Q13-B）。
- 取込後は Q14 の全項目（A〜I）を確認する。マクロで記録できる範囲は新規マクロを追加し、実行毎にログを記録する（§3 の実装1）。
- 少数件試験を省略し、最初から全件処理する（Q15-B）。前提は、設計段階でコンパイルエラーがなくカーソル位置等が変わっていないこと。事前チェックを念入りに行う。合格判断は現場責任者と設計者の両者で行う（Q17-C）。

### 1.5 結果の意味と扱い

- 「○」は消し込みが可能なもの、つまり在庫ゼロという意味である（Q18-E）。
- 「無し」は「在庫ゼロである？という意味」との回答で、確定に至っていない（Q19 → §2）。
- 「無し」は正常結果として記録し、次へ進む（Q20-A）。
- 完了件数は「該当箇所の記録でよい」（Q21）。明確化が要る（§2）。

### 1.6 停止・復旧・再開

- 次の場合は即時停止する（Q22 a〜g はい）：中断メッセージ・前面タイトル変化・別アプリ前面表示・クリック位置の外れ・B 列の異常値・EG-Pro 反応停止・A/B 列対応の疑い。h（実行中の他者操作）は単一端末の限定的な画面のため起こりにくいと判断され「いいえ」。
- 異常時の最初の連絡先は松井さん（Q23-B,C）。
- 現場責任者が独自に行ってよい復旧操作は A〜G の全部：状態確認・画面記録・別名保存・同行情からの再実行・VBA 変更・クリック座標変更・再起動（Q24）。VBA 変更と座標変更を行ったときは、Q31 の「変更時」記録（H・I）を残す。
- 再開は中断した現場責任者が行う（Q25-A）。
- 再開時は新しく取得した CSV へ入れ替える。現場在庫 CSV は流動的でリアルタイムに変化しているため（Q26-B）。
- 再開前には A〜H のすべて（中断時のブック・CSV・最終正常行・最終正常シリアル・B 列最終結果行・EG-Pro 側の対象状態・前面タイトルとクリック位置・再開確認）を確認する（Q27）。
- 中断した行はもう一度処理する（Q28-A）。

### 1.7 完了判定と記録

- 完了条件は A〜H のすべて：件数一致・B 列が「○」か「無し」のみ・未処理行なし・未解決の中断なし・EG-Pro が通常画面へ復帰・結果ブック保存済み・実行記録保存済み・現場責任者の完了確認（Q29）。承認（I）は Q6 より設けない。
- 完了確認は実行した現場責任者が行う（Q30-A）。
- 毎回保存するもの：使用 CSV・実行前ブック・実行後ブック・実行チェックシート。異常時：中断記録・画面記録。変更時：VBA 変更記録・試験記録。承認記録は不適用（Q31・Q6）。
- 記録の保存場所は、共有 ◎棚卸し に新規で記録用の CSV か何かを付与する方向。回数が多くないためシートを増やす方式が安牌か、と回答されている（Q32 → §2）。
- 実行記録の形式は Excel のチェックシート（A）を検討中（Q33 → §2）。
- 保存期間は期限を設けず保管し、動作が重くなる件数になったら削除する（Q34-D）。

## 3. xlsm への実装事項（回答から必要とされる修正）

1. 実行ログ記録マクロ（Q14・Q31）。取込件数・A 列先頭と末尾の値・先頭空白の有無・B 列空確認・ライン別件数・在庫数別件数を実行毎に記録する。
2. 取込件数の選択機能（Q35-C）。「個数を選択して○個以下を取り込み」が実装可能なら追加する。CSV に単価列は無いため、判定基準は在庫数（6 列目）である。
3. 記録先（Q32・Q33）。共有 ◎棚卸し の記録用 CSV か、ブック内シート増設か。未決 2 件の決定後に実装する。

これらの修正要否の判断：修正は必要である。Q14（全項目確認をマクロで記録）と Q35-C（個数選択取込）が直に xlsm の変更を要求する。実施は VBA 編集を伴い、コンパイルと少数件での動作確認を要するため、実機での作業として次回に回す。

## 4. 旧方針から変わる点（矛盾の解消）

- 「現場責任者は VBA を編集しない」（一枚集約 §1.2・推奨案 A）→ Q3・Q4-C により、原則だれでも変更可・現場責任者の判断で変更可となった。条件として Q31 の変更時記録を伴う。
- 「50円以下フィルターは単価取得元が未特定のため別課題」（一枚集約 §0）→ Q35 で A（9 個以下で正式版にする）と C（別機能として後日追加）の併用が確定。単価列は無いため、追加機能は在庫数基準の個数選択として実装する。

## 5. 止まる条件

- 「無し」の意味（§2 の1）が確定するまで、B 列の「無し」を消し込み完了の証拠として扱わない。
- 実行記録の保存方式（§2 の3・4）が決まるまで、Q31 の毎回記録は仮置きの場所へ保存する。
- xlsm の修正（§3）が適用・コンパイルされるまで、本手順の「新規マクロでログを記録」の部分は運用開始条件に含めない。
