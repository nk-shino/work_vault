## 0. 結論

本運用は、次の分担を前提とする。

- 設計者は、VBAの改修、コンパイル、版管理、技術試験、障害解析を担当する。
- 現場責任者は、完成済みツールを使い、対象の妥当性判断、実行可否判断、定型操作、中断・再開、結果確認を担当する。
- 現場責任者はシステム内部を理解する必要はないが、想定外の動作を独自に修正せず、停止して設計者へ戻す。
- CSV取込はExcelのA列だけを変更する可逆処理である。一方、EG-Proのリール消費によるラベル消去は不可逆であるため、両工程を分離する。[4][5]
- 現状は「CSV取込機能の技術仕様はほぼ確定」「EG-Pro消し込みは条件付き運用可能」である。
- 本番運用前に、A列とB列の整合、`○`と`無し`の意味、Enter送信の影響、停止・再開方法を確定する。
- 50円以下フィルターは単価情報の取得元が未特定のため、本件に混在させず別課題とする。[4][5]

## 1. 前提条件

### 1.1 確定事項

- 対象ブックは`0確認マクロ_ver.2.xlsm`である。[4]
- A列にはシリアル番号を格納する。
- B列には`○`または`無し`を記録する。
- B列の最終使用行が、次回実行時の開始位置を決める基準である。[2][3]
- 入力CSVはUTF-8 BOM付き、カンマ区切り、11列である。[4][5]
- 判定に使う列は次のとおりである。
  - 1列目「シリアル番号」
  - 6列目「在庫数」
  - 8列目「ロケーション名称」
- 抽出条件は次の両方を満たす行である。
  - 8列目が`0確認`で始まる。
  - 6列目の在庫数が9以下である。9を含む。
- `0確認(L1)`、`0確認(L2)`、`0確認(L3)`を一括対象とする。[5][7]
- 取込時は`Trim(cols(0))`を使用し、シリアル番号の左右の空白だけを除去する。シリアル番号途中の空白は残す。[4][8]
- 取込前にA列を`ClearContents`する修正がある。[4][8]
- 指定CSV`2026_09_25_113916_EGProWhereHouse.csv`に限り、次が期待値である。[4][8]
  - 総行数：29,246行
  - 取込件数：5,848件
  - A列1行目：`160096C100792`
  - A列5,848行目：`T9000031021100011`
- クリック位置は前面ウィンドウ左上から横180、縦69の固定オフセットである。記録上の実測値は、左上`99,248`、入力欄`279,317`である。[1][2]
- マクロは前面ウィンドウへ`SendKeys`とマウス操作を送る。[2]
- `Application.Goto Cells(i + 3, 1)`は表示位置を3行先へ動かす処理であり、処理対象を3行飛ばす処理ではない。[2]
- VBAの既知の不具合は次のとおりである。
  - `PtrSafe`が不足している。
  - Module1とModule2で`coordinate`と`GetCursorPos`が衝突している。
  - シリアル番号の先頭空白が残る。
  - 前回より取込件数が少ないとA列下部に旧データが残る。
- Module1とModule2の宣言修正、`Trim(cols(0))`、A列初期化を適用し、VBAプロジェクト全体をコンパイルする必要がある。[4][8]

### 1.2 操作者の前提

- 操作者は、前任者に次いで現場情報に詳しい現場責任者とする。
- 現場責任者は次を判断できるものとする。
  - 対象件数が現場状況と整合するか。
  - 対象シリアル番号や品番の偏りが異常か。
  - 当日の設備状態で実行可能か。
  - 現場要因による異常時に続行、保留、中止のどれを選ぶか。
- 現場責任者にはVBAの編集、API宣言の変更、座標値の変更、障害解析を行わせない。

### 1.3 役割分担

| 役割 | 担当内容 |
|---|---|
| 設計者 | VBA改修、コンパイル、版管理、技術試験、座標変更、障害解析 |
| 現場責任者 | CSV選定、対象妥当性確認、実行可否判断、定型実行、中断・再開、結果確認 |
| 承認者 | 不可逆な消し込みの実行承認、例外時の再開承認 |
| システム管理側 | EG-Proの権限、画面仕様、操作結果、ログ取得方法の確認 |

現場責任者自身が消し込みを承認できるかは要確認とする。

## 2. 必須要件

### 2.1 ツール側

- 正式版ブックを一つに定め、旧版および試験版と区別する。
- Module1とModule2の宣言を修正する。
- VBEの「デバッグ」「VBAProjectのコンパイル」でエラーが出ないことを確認する。
- CSV取込時にシリアル番号の左右の空白を除去する。
- 取込前に前回データが残らないようにする。
- A列とB列の行対応を維持する。
- 前面ウィンドウタイトルが想定値でない場合は処理を続けない。
- マクロ開始前の無限待機を避けるため、待機時間上限または手動停止方法を設ける。現行コードは対象タイトルになるまで待ち続けるため要対応である。[2]
- 異常時に、行番号、シリアル番号、画面タイトルを記録して停止できるようにする。
- `Cells`、`Rows`、`Columns`の参照先を対象ブックおよび対象シートへ固定することを検討する。現行コードはアクティブシートに依存するため要確認である。[2]

### 2.2 運用側

- 新規実行と中断後再開を分ける。
- 使用CSV、使用ブック、実行日時、実行者を記録する。
- 実行前に入力CSVと取込結果を照合する。
- 少数件で画面挙動を確認した後に全件へ進む。
- 実行中は他のウィンドウを操作しない。
- 通知、ポップアップ、別アプリケーションが前面へ出た場合は停止する。
- 中断後は原因と最終正常行を確認せずに再実行しない。
- 完了時に対象件数と結果件数を照合する。
- 不可逆処理の前後で記録を保存する。
- ツール、CSV、ログ、結果の保存先を固定する。
- 同時に複数人または複数端末から同じ対象を処理しない。

### 2.3 本番実行の開始条件

次のすべてを満たすまで、EG-Proの消し込みを開始しない。

- 正式版ブックが確定している。
- VBAのコンパイルが成功している。
- 入力CSVが正式な取得元から得られている。
- CSVのファイル名、取得日時、総行数を記録している。
- 取込件数、A列先頭、A列末尾が期待値と一致している。
- B列の事前状態が、新規実行または再開の条件と一致している。
- クリック位置が入力欄に合っている。
- 前面タイトルが`リール消費【倉庫管理アプリケーション】`である。
- 少数件試験が完了している。
- 消し込みの承認権限が確認されている。
- 中断方法と連絡先が確認されている。
- 実行ログの保存先が決まっている。

## 3. 推測

次はコードまたは残存データから読み取った推測であり、確定事項として扱わない。

- `○`は、Enter送信後にリール消費画面へ戻ったことを示すが、業務上の「正常消去」「在庫なし」「処理済み」のどれを意味するかは要確認である。[2][3]
- `無し`は、入力後に前面タイトルが`倉庫管理アプリケーション`へ変わったことを示すが、何が「無し」なのかは要確認である。[2][3]
- Enterを3回送る処理は、EG-Pro上で確認、消費、画面復帰などを行っている可能性があるが、それぞれが確定する内容は要確認である。
- 固定座標`180,69`は当時の画面配置では入力欄に一致したが、別端末、解像度、表示倍率でも一致するとは限らない。
- B列の最終行を再開基準とする設計は、A列とB列が同じ処理単位のまま維持されることを前提としている。
- 指定CSVでの5,848件は確定した期待値だが、別日時のCSVにも同じ件数を期待してよいわけではない。
- 過去ファイルでB列がほぼ`○`であることだけでは、`○`の正式な業務意味は確定できない。[1][3]

3. アクティブブックおよびアクティブシート依存を確認する。
4. 新規実行と再開を操作上分離する。

   - `○`になるケース

8. 試験結果を承認し、正式版として固定する。

## 7. 相対解決性

ここでいう相対解決性とは、一つの課題を解決したときに、関連課題がどこまで解消または緩和されるかを示す。

| 解決する課題 | 直接効果 | 同時に緩和される課題 | 解決されず残るもの |
|---|---|---|---|
| 正式版を確定する | 旧版誤使用を防ぐ | 試験結果と実行ファイルを対応付けられる | 実機上の操作誤り |
| コンパイルを通す | マクロを実行可能にする | 「0件」と「未実行」を区別できる | 業務ロジックの正しさ |
| A列とB列の仕様を直す | 開始位置のずれを防ぐ | 再開時の重複、未処理漏れを減らす | EG-Pro側の処理状態 |
| `○`と`無し`を定義する | 結果を正しく判断できる | 完了判定と例外処理を定められる | 誤クリックなどの入力事故 |
| Enterの影響を確定する | 不可逆操作の発生点が分かる | 停止可能地点と承認地点を定められる | 既に実行した操作の取消し |
| 座標とタイトルを確認する | 誤画面入力を減らす | SendKeysの誤送信を緩和する | 通知や遅延による途中の画面変化 |
| 少数件試験を行う | 本番前に実機挙動を確認できる | 待機時間、タイトル、座標の問題を検出できる | 全件処理中だけ発生する障害 |
| 実行ログを残す | 経緯を追跡できる | 中断再開と事後確認が容易になる | 不可逆操作そのもの |
| 現場責任者を実行者にする | 現場妥当性をその場で判断できる | 異常件数や対象偏りを早期発見できる | VBA・Windows APIの技術障害 |
| 設計者へ技術判断を限定する | 無断修正を防ぐ | 版管理と再試験を維持できる | 設計者不在時の復旧遅延 |
| 単価元を確定する | 50円以下を判定可能にする | 低額品の抽出を自動化できる | 9個以下条件との優先関係、単価更新時点 |

優先順位は次のとおりとする。

1. 不可逆処理の発生点と結果の意味を確定する。
2. A列とB列の不整合を解消する。
3. 正式版、入力CSV、版管理を確定する。
4. 停止、再開、ログを確定する。
5. 少数件試験を行う。
6. 現場責任者による本番運用へ移す。
7. 50円以下フィルターを別課題として進める。

## 8. 追加した不足前提・必要項目

ユーザーの考えに追加して管理すべき項目は次のとおりである。

- データ鮮度
  - CSV取得から実行までにEG-Pro在庫が変化した場合の扱い。
  - 許容できる取得日時との差は要確認。
- 重複実行防止
  - 同じCSVや同じシリアル番号を再実行しない識別方法。
- 排他管理
  - 実行中に他者が同じ対象を変更しない運用。
- 実行環境固定
  - 端末、Excelのビット数、画面解像度、表示倍率、対象シート。
- 通知対策
  - メール、チャット、Windows通知、更新画面などが前面へ出ることへの対策。
- タイムアウト
  - EG-Proが応答しない場合に待ち続けない上限。
- 再実行境界
  - 中断行を処理済みとみなすか、未処理とみなすか。
- 重複シリアル
  - CSV内に同じシリアル番号が複数ある場合の扱い。
- 空白行と異常値
  - シリアル番号空欄、在庫数非数値、列不足を記録する方法。
- 保存失敗
  - Excel結果を保存できなかった場合の退避方法。
- 変更凍結
  - 本番期間中にVBA、画面配置、抽出条件を変更しないルール。
- 完了判定
  - `対象件数 = ○件数 + 無し件数`だけでなく、中断、未処理、異常が0であること。
- 証跡保全
  - 使用CSV、実行前ブック、実行後ブック、試験結果、承認記録を同じ実行IDで関連付ける。
- 連絡体制
  - 現場異常、EG-Pro異常、Excel異常の連絡先を分ける。
- リカバリー限界
  - Excel側は復元可能でも、消去済みラベルは元に戻せないことを明記する。

## 10. 現場責任者の停止条件

次のいずれかに該当した場合は、原因を推測して続行せず停止する。

- コンパイルエラーが出る。
- CSV取込件数が表示されない。
- 指定CSVで5,848件にならない。
- A列先頭または末尾が期待値と異なる。
- B列に前回結果が残っている状態で新しいCSVを取り込んだ。
- クリック位置が入力欄から外れている。
- 前面タイトルが想定値と異なる。
- 別ウィンドウまたはポップアップが前面へ出た。
- `中断`が表示された。
- B列へ`○`または`無し`以外が入った。
- A列のシリアル番号とB列の結果の対応が疑わしい。
- 対象件数と結果件数が一致しない。
- EG-Proの反応が通常より遅い、または画面が戻らない。
- 同じ対象を別担当者が処理している可能性がある。
- CSV取得後に対象在庫が更新された可能性がある。
- 実行ログまたは結果を保存できない。

## 11. 完了条件

次のすべてを満たした場合だけ完了とする。

- 正式版で実行した。
- 使用CSVを一意に特定できる。
- 対象件数と処理済み件数が一致する。
- `対象件数 = ○件数 + 無し件数`が成立する。
- 未処理件数が0である。
- 未解決の中断がない。
- A列とB列の対応が維持されている。
- EG-Proが通常の画面状態へ戻っている。
- 結果ブック、入力CSV、実行ログを保存している。
- 不可逆処理の範囲が承認内容と一致している。
- 現場責任者または承認者が完了を確認している。
