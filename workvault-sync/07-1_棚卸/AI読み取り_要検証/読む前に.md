# このフォルダのデータを棚卸しの実績として使わないこと

`棚卸し票_AI読み取り_2026-04-01.xlsx`（元の名前は `gemini.xlsx`・16.5 MB・2026-04-01）は、
**手書きの棚卸し票をAIに読み取らせた結果**である。

**隔離した理由は、ファイル自身が「読めていない」と申告しているため。**

---

## 1. ファイル自身が書いている判読不能

備考列にそのまま入っている。

| 行の例 | 備考 |
|---|---|
| `9000027864` | **シリアルに括弧、数量に斜線あり（判読不確実）** |
| `9000070824` | **数量が文字化け（判読困難）** |

シリアルの値が `(0`、数量が `πιο` になっている行がある。

## 2. Z軸が壊れている

**テーブル列とZ軸列が混ざっている。**しかも混ざり方が行ごとに違う。

```
部品        テーブル  Z軸
9000059184     1      100011      ← 正しく分かれている
9000027864            1100072     ← テーブルの1がZ軸に食い込んでいる
9000066596            1 100172    ← 空白で繋がっている
9000069249            100181 1    ← 後ろに付いている
9000069921            100022 1
```

**「テーブル列が空で、Z軸が7桁」になっている行は、先頭か末尾の1がテーブル番号である。**
ただし**どちらに付いているかが一定でない**ので、機械的に切り出せない。

**先頭の3行だけテーブル列が埋まっていて、残りは全部空。**
**つまりテーブル番号は実質失われている。**

## 3. シート構成

| シート | 中身 |
|---|---|
| `Sheet1` | **読み取り生データ。**上記の崩れが入っている |
| `校正後` | 手で直したもの。**どこまで直したかは未確認** |
| `印刷` / `印刷(2)` / `印刷(3)` / `印刷(4)` | 印刷用の版 |
| `T1` / `T5` / `T9` / `T13` | テーブル別。**T1・T5・T9・T13 の4枚だけ** |

**`T1/T5/T9/T13` がテーブル別に分かれているので、Z軸の崩れはここで解消している可能性がある。**
**ただし未検証。**生データと突き合わせていない。

## 4. 使ってよい使い方

| 用途 | 可否 |
|---|---|
| **在庫数・シリアルの実績として使う** | **不可。**判読不確実が混ざっている |
| **棚卸し票にどの項目が書かれていたかの確認** | 可。列構成は読める（部品/テーブル/Z軸/使用数/保管場所/シリアル/数量/備考） |
| **保管場所の体系の確認** | 可。`11-10-5-1` の4段形式が見える |
| **AI読み取りの精度の実例** | 可。**手書き票の自動読み取りは、この精度では実務に出せないという材料になる** |

## 5. 確認が要ること

| # | 内容 |
|---|---|
| 1 | **`校正後` シートはどこまで直したのか。**全件か、一部か |
| 2 | **`T1/T5/T9/T13` の4枚で足りるのか。**T2〜T13の残りはどこか |
| 3 | **この読み取りは何のために行ったのか。**2026-04-01。棚卸し本番との関係 |
| 4 | **原本の手書き票は残っているか。**残っていれば再読み取りか手入力の判断ができる |

**4が決まらないと、このファイルを直す意味があるかが判断できない。**
原本が無ければ、崩れた分は復元できない。
