# 棚卸しツール一覧

**`棚卸しセット` フォルダにある道具と、手順書との対応を1枚にしたもの。**

作った理由は2つある。

**1つ目は、どれが現役か分からなかったこと。** フォルダに12本のxlsmがあり、
`old` の中にも入っていて、**手順書に名前が出るものと出ないものが混ざっている。**

**2つ目は、同じコードが複数のファイルに写されていたこと。**
0確認の処理が3本のファイルに別々に入っていて、**片方だけ直った状態が実在した。**

## 2. 同じコードが写されていた箇所

**0確認の処理が3つのファイルに入っている。**

| ファイル | 入っている処理 | 相手の画面 |
|---|---|---|
| `0確認マクロ_ver2.xlsm` | ゼロ確認 | リール消費【倉庫管理アプリケーション】 |
| `リール消費マクロ.xlsm` | **ゼロ確認・外部出庫** | リール消費 / 外部出庫【ラベル発行アプリケーション】 |
| `ラベル再発行マクロ.xlsm` | **ラベル再発行・ゼロ確認・外部出庫** | 発行履歴 / リール消費 / 外部出庫 |

**`リール消費マクロ` の中の「ゼロ確認」は、名前が0確認だが実際はリール消費画面を相手にする。**
0確認マクロから流用したまま名前が残っている。**取り違えると、消費を計上する処理を
「確認だけ」と思って走らせることになる。**

ver.2 では**1本のモジュールに統合し、画面の指定を設定で切り替える形**にした。
写しが無くなるので、片方だけ直る事故が起きない。

## 3. ver.2 で直した欠陥

**実物のVBAを読んで確かめた分だけを書く。**推測は「疑い」と明記した。
抽出は `olevba` で、`リール消費マクロ.xlsm` 259行・`ラベル再発行マクロ.xlsm` 336行。

| # | 旧版の状態 | 何が起きるか | 確認 |
|---|---|---|---|
| 1 | **Module1 と Module2 が両方 `Type coordinate` と `GetCursorPos` を公開宣言** | **コンパイルが通らない。**「名前が適切ではありません」 | コードで確認 |
| 2 | **`GetCursorPos` `SetCursorPos` `mouse_event` に `PtrSafe` が無い**（上の4つには付いている） | **64bit版Excelでコンパイルが通らない。**32bitなら通る | コードで確認 |
| 3 | **毎回 `GetForegroundWindow` でタイトルを読む** | **他のアプリの通知が前に出た瞬間に、別の窓のタイトルで分岐する。**リール消費は取り消せないので最も危ない | コードで確認 |
| 4 | **再開位置の判定が `End(xlUp).Row = 1` だけ** | **B1に何か入っていてB2以降が空のとき、1行目をもう一度処理する。**リール消費では二重計上 | コードで確認 |
| 5 | **窓を待つ `Do ... Loop` に上限が無い** | 画面が出ないと永久に回る。**Excelを落とすしかない** | コードで確認 |
| 6 | **`Cells(...)` にシート指定が無い** | **設定シートなどを開いたまま実行すると、そちらへ結果を書く** | コードで確認 |
| 7 | **送る値に `.Text` を使っている** | **列幅が狭いと `###` が返る。**シリアルが文字列なら通常は出ないが、数値と解釈された列で起きる | コードで確認（疑い） |
| 8 | **A列が空でも送信して Enter を打つ** | **入力欄に残っていた前の値が確定される余地がある** | コードで確認 |
| 9 | **固定の `Sleep`** | ラベル再発行は1件あたり合計5.6秒。**5,848件で約9時間。**短いPCでは打ち漏らす | コードで確認 |
| 10 | **タイトルが変わらない場合を「在庫あり」として扱う** | **送信漏れと在庫ありを区別していない。**打てていないのに ○ が付く | コードで確認 |
| 11 | **外部出庫はクリックも前面確認もせず SendKeys だけ** | 入力欄に焦点が無ければ全部空振り。**それでも ○ が付く** | コードで確認 |
| 12 | **中断したとき B列の ○ しか残らない** | 何が見えて止まったのかが分からず、再現できない | コードで確認 |

### 仕様書の記述に誤りが2件あった

**既存の `リール消費マクロ_Excelデータ仕様書.md` と
`ラベル再発行マクロ_Excelデータ仕様書.md` の訂正。**

| 記述 | 実際 |
|---|---|
| 「三行下へ送る」 | **`Application.Goto Cells(i + 3, 1)` は画面のスクロールで、行を飛ばしていない。**`For` は1行ずつ進む。3行飛ばしていると読むと、件数の計算が合わなくなる |
| リール消費のゼロ確認は「末尾に完了メッセージを表示する点が加わっている」 | **`MsgBox "完了"` は無い。**`Next i` のあと何も表示せずに終わる |

### `#If Win64` について

旧版は `#If Win64` で分岐している。**これは0確認マクロで私が誤って
「原因」と報告した箇所だが、こちらには実在する。**

ただし**これ自体は不具合ではない。**32bit版では `PtrSafe` 無しの `Declare` でも動く。
ver.2 で `#If VBA7` に変えたのは、**32bit版でも `PtrSafe` と `LongPtr` を使えるようにして、
分岐を1本に減らすため。**

`めも.txt` の「現場PCは32bit版Excelの可能性がある」を満たしている。
**`LongPtr` は VBA7 なら32bitで `Long`、64bitで `LongLong` になる。**
VBA6（Office 2007以前）は `#Else` 側に落ちる。

## 4. ver.2 の構成

`解決課題/棚卸しセット_ver2/`

| ファイル | 役割 |
|---|---|
| `modWinAuto.bas` | **Win32 API を触るのはここだけ。**窓のつかみ方・タイトルの読み方・前面にする・クリック・キー送信 |
| `modTanaoroshi.bas` | 繰り返し処理と4つの入口（リール消費・ラベル再発行・外部出庫・ゼロ確認） |
| `ver2_変更仕様書.md` | 変更点と、なぜ安全といえるか |

**窓の取っ手を `modWinAuto` の外へ出していない。**公開関数の引数に `LongPtr` を使うと、
VBA6 の環境で宣言ごと作り直しになる。モジュール内に閉じれば起きない。

### 設定シートで変えられるもの

**座標をコードに埋めていない。**解像度や拡大率が変わると実測しなおしになるため、
`設定` シートに置いた。シートが無ければ初回実行時に既定値つきで作られる。

| 項目 | 既定 |
|---|---|
| リール消費_作業画面 | リール消費【倉庫管理アプリケーション】 |
| リール消費_ずらしX / Y | 180 / 69 |
| ラベル再発行_作業画面 | 発行履歴【ラベル発行アプリケーション】 |
| ラベル再発行_ずらしX / Y | 281 / 90 |
| 外部出庫_作業画面 | 外部出庫【ラベル発行アプリケーション】 |
| 窓を待つ上限ms | 30000 |
| 1手を待つ上限ms | 5000 |
| 印刷を待つms | 3000 |
| 開始行 | 1 |
| **件数の上限** | **1** |
| **試し実行** | **はい** |

**既定を「試し実行・1件」にしてある。**リール消費が取り消せるかは未確認なので、
**何もしないほうへ倒した。**全件を流すには設定を2箇所変える必要がある。

### 座標の測り直し

`座標を測る` を実行すると、窓をつかんでから**窓の左上からのずらし幅を直接表示する。**
旧版の `getMouseCoordinate` は画面の絶対座標しか出さなかったので、
**窓の位置を別に調べて引き算する必要があった。**

ラベル再発行の仕様書にある「281と90を別環境で使う場合の再測定手順」がこれで埋まる。

## 5. 残っている確認事項

| # | 内容 |
|---|---|
| 1 | **リール消費で計上した内容が取り消せるか。**ここが決まらないと全件を流す判断ができない |
| 2 | ラベル再発行と外部出庫が棚卸しのどの局面で使うか。**手順書に出てこない** |
| 3 | 現場PCのExcelが32bitか64bitか。**ver.2はどちらでも通る形にしたが、実機でのコンパイル確認が要る** |
| 4 | ラベル発行の印刷完了が画面に出るか。**出るならタイトル待ちに変えられる。**今は固定で3秒待っている |
| 5 | 旧版が Enter を3回送っていた理由。**ver.2 では画面の遷移を見て必要な分だけ送る形にしたが、画面側に3段階の確認がある可能性がある** |
| 6 | 相手アプリが管理者権限で動いていないか。**動いていると SendKeys が届かない。**その場合はこの方式自体が使えない |
| 7 | `EGPro使用実績訂正メンテツール`（名前に「本番環境」とある）の扱い |
