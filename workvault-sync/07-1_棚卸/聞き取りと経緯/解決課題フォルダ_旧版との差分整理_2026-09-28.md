## 2. 旧版にしか無かったもの

### 2-1. idouSQL の改修内容そのもの（最重要）

9/25時点で「**倉庫移動SQLの仕様書が無い**」を唯一の穴として記録していたが、
**中身は 9/04 の旧版HTMLに揃っていた。** 章「idouSQLマクロ改修 変更内容」に、
改修9項目と安全性の根拠が書かれている。

改修で足されたのは、いずれも**UPDATE本体ではなくその周り**。

| 追加された安全策 | 何を防ぐためか |
| --- | --- |
| 移動先A55が空欄・非数値なら停止 | 不正な移動先コードのまま更新が走るのを防ぐ |
| シリアル内の引用符を二重化 | 引用符入りシリアルでSQLが壊れる／意図しない条件で更新されるのを防ぐ |
| 対象0件なら停止 | 実データが入らない状態での空振りを防ぐ |
| 実行前に移動先と件数を表示して確認 | 担当者が想定と一致しているか目視してから流せるようにする |
| 更新前の状態をバックアップテーブルへ退避 | COMMIT後に誤りへ気づいても元の値へ書き戻せるようにする |
| `SET XACT_ABORT ON` + `BEGIN TRAN`、更新件数表示、COMMIT/ROLLBACKはコメント状態で出力 | 異常時に自動で巻き戻し、確定前に件数を見て確定か取消を選べるようにする |
| 末尾に切り戻しSQLをコメントで添付 | 確定後の切り戻しをすぐ実行できるようにする |
| SQL組み立てを行継続の連結から一行ずつの追記へ | 組み立て途中の崩れを防ぎ、生成SQLを追いやすくする |
| ファイル番号の固定をやめ、実行パスを引用符で囲む | 実行競合を避け、空白を含むパスでも動くようにする |

**SQL本体のロジックは変えていない。** 所在の付け替え、`M_ロケーション` からの
ステータス引き当て、ラインNo・設備No・Z軸NoのNULL化、シリアル列挙による絞り込みは
改修の前後で同一。**破壊的変更なし。**

→ 反映先: [[倉庫移動SQL_idouSQL_仕様書]]（2026-09-28 に正本化）

### 2-2. 見出し1件問題（実際に発生した事故）

**0件判定は空欄だけを対象外にする。** そのため現場部品リストの `D2` に
「シリアル」という見出し文字が残っていると、**有効値とみなして通る。**
対象が見出し1件だけで実データが一件も入らない出力が、実際に出たことがある。

`0件なら停止` という安全策があっても、**この事故は防げない。**
必ず `GenbaList` を先に実行し、D列に実データが並んでいることを目視してから流す。

00_inbox に置かれていた新しい仕様書2本（v2.0・更新版）には、**どちらにも記載が無かった。**

→ 反映先: [[倉庫移動SQL_idouSQL_仕様書]] §9-2

`倉庫移動SQL.md` と新版仕様書が要確認として挙げていた4件のうち、**3件は
2026-09-04 の時点で判断が済んでいた。**

| 項目 | 現行ノートの記載 | 旧版にある実際の判断 |

| バックアップテーブルの保管期間・削除ルール | 未確定 | **一時退避の位置づけで保管期間は定めない** |
