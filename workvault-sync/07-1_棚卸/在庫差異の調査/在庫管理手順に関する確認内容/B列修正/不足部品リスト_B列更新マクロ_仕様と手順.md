# 不足部品リスト作成(AED)_ver7 B列更新マクロ 仕様と手順

- 作成日: 2026-10-30
- 対象: `不足部品リスト作成(AED)_ver7.xlsm` の「不足部品計算」シート・B列更新ボタン
- 根拠: モジュール `modEGProB列更新`(2026-10-30版)の実コード、および実データによるprobe検証22項目
- 版の位置づけ: ver1 = 2026-08-12版 / ver2 = 2026-08-21版 + 2026-10-30改修(本書はver2について記述する)

## 1. 目的

生産計画に対する不足部品リストの作成ブック。EGPro(在庫管理システム)とL3セットアップレポート(セトレ)を照合し、「不足部品計算」シートのB列(取付済在庫)を実在庫へ更新する。B列更新ボタンはこの照合と更新を1回の操作で行う。

同構造のブックが機種別に6冊ある(AED / NKV / TEC1000 / TEC5600 / 送信機 / 原本)。本書の記述はAEDで確認した内容であり、他機種への転記は未確認(§10)。

## 2. 「不足部品計算」シート

| 列 | 内容 |
|---|---|
| A列 | 部品番号(実部品377件・部品番号「0」のプレースホルダ行622件を含む) |
| B列 | 取付済在庫。**B列更新ボタンの更新対象** |
| E〜R列 | 部品 / テーブル / Z軸 / リール情報 / スプライシング必要になる残数 / 使用数 / 不足数 / 不足リール数 / 保管場所 / チェック / 差引在庫数(生産品目考慮)など |

- A列の「0」行はプレースホルダ(B列=0)。更新対象外(§4)。
- R列以降の列定義の詳細は未確認(§10)。

## 3. B列更新ボタンの処理フロー

1. ボタン(`B列更新_Click`)→ `EGPro在庫をB列へ反映` を呼び出す。
2. CSV選択ダイアログが2回出る。順に **L3セットアップレポートCSV(セトレ)** → **EGPro在庫CSV**。
3. 読み込み: セトレはヘッダ照合(材料バーコード / 部品番号 / スプライシングリール)。EGProは1列目シリアル / 6列目在庫数 / 8列目場所(固定位置)。
4. セトレ掲載部品についてEGProシリアルを突合し、部品ごとに判定(§4)を付ける。
5. 件数確認メッセージ →「はい」で **B列更新前の退避** → B列書込 → 再計算 → 保存。
6. 完了メッセージに件数と退避先を表示する。

確認で「いいえ」を選んだ場合、CSV選択をキャンセルした場合は、**B列とりれきは変更されない**。ただし「EGPro照合結果」シートはCSV読み込みの時点で一度クリアされ、選択を中止しても前回の照合結果は戻らない(消える)。

## 4. 判定区分

| 区分 | 条件 | B列の扱い | 現場での対応 |
|---|---|---|---|
| 更新 | セトレ掲載・EGPro照合済(未照合リールなし) | EGPro在庫合計に置換 | そのまま使用する |
| 据え置き | セトレ掲載・EGPro未照合リールを含む | 変更しない | 棚卸で数量を調整する |
| 0化 | セトレ非掲載 | 0に置換 | 倉庫へ照会する |
| 警告 | ①EGProシリアル重複 ②セトレ行の部品番号空欄(材料バーコード等が入力あり) | **全行中止(B列未変更)** | 照合結果シートを確認し担当者へ連絡 |

- **0化とは**: セトレ(生産計画側のセットアップレポート)に部品番号が載っていない部品。生産で使わないため在庫を0にし、不足リストに残さないための処理。
- **据え置きとは**: EGPro側で照合できなかったリールを含む部品。在庫を確定できないため現状値のままにし、棚卸で調整する。
- 部品番号「0」(半角/全角)の行は判定・更新・りれき一覧のいずれにも含めない(§9の発見と修正)。

## 5. りれきへの記録(ver2で追加)

1回の実行 = 1ブロック(横書き・空列1つを挟んで右へ追加)。

| 行 | 内容 |
|---|---|
| 1 | 見出し「EGPro在庫反映」+ **末列マーカー「判定」**(ブロックの最終列位置を示す。次ブロックの開始位置計算に使う) |
| 2〜4 | 実行日時 / セトレCSV / EGProCSV |
| 5〜9 | 件数サマリ: 更新件数 / 据え置き件数 / 0化件数 / 警告件数 / 合計(数値・3桁区切り) |
| 11 | 一覧ヘッダ: 部品番号 / 変更前→変更後 / 判定 |
| 12〜 | 対象部品の全行(「0」行・空行を除く) |

- 警告で中止した場合も記録する。見出し「EGPro在庫反映(中止)」+ 末列マーカー「結果」+ 実行日時 / セトレCSV / EGProCSV / 警告件数 / 結果。明細は書かない。
- 連続して実行しても前のブロックは上書きされない(行1の末列マーカーで次の開始列を決めるため。probeで連続2回成功+中止の3連続実行を確認済み)。
- りれきの使用幅が79列を超えると、不足部品リスト印刷(main)など在庫更新系マクロの実行時に左側の列から削除される(最新79列のみ残す)。B列更新単独では削除しない。古いブロックはこの仕組みで消える。削除の境界はブロックの途中になることがある(従来の2列ブロックと同じ挙動)。

## 6. ver1 → ver2 の変更点

| 項目 | ver1(2026-08-12版) | ver2(2026-08-21版 + 2026-10-30改修) |
|---|---|---|
| B列更新前の退避先 | 保存先フォルダ配下 | 固定UNC `01_buckup_B列更新前_ver7`(フォルダ自動作成・保存エラー処理を追加) |
| りれき記録 | 変更明細のみ | **件数サマリ+判定列を追加** |
| 警告中止時の記録 | なし | **中止記録を追加** |
| 判定用語 | 「保留(据え置き)」「0へ更新」 | 「据え置き」「0化」に統一 |
| 部品番号「0」行 | 除外の意図が実装上効いていない(全角化のため全件0化対象に入っていた) | **除外を実効化(半角/全角とも対象外)** |
| 検証用の入口 | なし | `EGPro在庫をB列へ反映Impl(CSVパス, CSVパス, silent)` を追加(ボタン経路は変更なし) |

- ver1→ver2の8月版差分: 退避先の固定UNC化とエラー処理が主体。2026-10-30改修はその上に記録機能と「0」行除外の修正を重ねたもの。
- 「ここまでの改修はver2のものとして観測する」: 本書ではver2 = 2026-08-21版 + 2026-10-30改修とする。

## 7. 実行手順

1. EGPro在庫CSVをダウンロードする。**「0確認を含まない」方**を取得する。
2. L3セットアップレポートCSVを取得する。
3. 「不足部品計算」シートの **B列更新ボタン** を押す。
4. セトレCSV → EGProCSV の順に選ぶ。
5. 件数確認メッセージで「はい」→ 退避・B列更新・保存まで自動。
6. 「りれき」シートで件数を確認する。区分の意味は「修正対応」シートI列以降に記載してある。
7. 警告が出た場合: B列は更新されていない。「EGPro照合結果」シートの警告一覧を確認し、重複シリアルの担当部門へ確認する。りれきに中止記録が残る。対応後、再実行する。
8. 元に戻す場合: 退避フォルダの該当日時ファイルから復元する。

## 8. 制約・注意

- 実行のたびにブック自身が保存される(エクセルの閉じる操作とは別)。
- 退避はB列書込の直前・確認「はい」の後に行う。退避先に同名ファイルがある場合の上書き可否はBackupABの実装に従う(タイムスタンプ名のため原則衝突しない)。
- EGPro CSVのシリアル重複は全中止とする(安全側の設計)。
- 本番ブックは共有フォルダにある。改修・検証はInboxコピーとdevコピーで行い、本番への配備は別手順とする。
- 検証用の入口 `EGPro在庫をB列へ反映Impl(CSVパス, CSVパス, True)` は確認と退避を省略してB列を書き換え・保存する。**本番ブックでは実行しない**(devコピー専用)。

## 9. 検証記録(2026-10-30)

- 方法: Inboxコピーからdevコピーを作成し、実部品377件の実データで合成CSV2種(正常・警告)により**28項目を検証し28/28 PASS**(連続2回成功+中止の3連続実行を含む)。
- 独立レビュー(reviewサブエージェント)の指摘7件のうち、BLOCKER1件(連続実行で前ブロックの判定列を上書き)を末列マーカーで修正し回帰テスト追加、MINOR3件(silent無音化・文言修正・警告発生源の記載)を修正、NOTE3件(diff再生成・削除境界の注記・配備前確認)を反映。
- 主要確認: 件数サマリ(更新1/据え置き1/0化375/合計377)・一覧の判定列・B列の3区分の実値・中止記録とB列未変更・他モジュール16個のハッシュ一致・silent実行で本番退避フォルダに増減なし。
- **発見と修正**: 現行ver2ベースでは部品番号「0」行622件が全角化(HeaderKeyのStrConv)により0化対象に混入し、0化件数が997件と表示されていた(B列の値は元々0のため実データへの影響なし)。ユーザー確認のうえ、ver2で除外を実効化した(0化=375件になる)。

## 10. 未確認事項

- 他機種ブック(NKV等)への同モジュール配備は未実施。AEDのみ確認済み。
- 「不足部品計算」R列以降の列定義は帳票側の元資料で確認していない。
- main実行時のりれき79列ローリングがB列更新ブロックを削除する頻度は、実運用での観察が必要。
- EGPro CSV / セトレCSVの取得元の手順書は本書の範囲外(既有の手順に従う)。
