# セットアップレポート計算機v2.0 変更記録・試験記録(2026-10-22)

⑧スプライシング部品リスト印刷が作っていたバーコードデータは、印刷後にS1(印刷入力)のシリアル列とS2(印刷)のQRオブジェクトがどちらも削除されるため、作成データが残らなかった。この対策として、「取付部品シリアル」とその二次元バーコード(QR)をCSVとPDFで保存する新規ボタンを追加した。プロトタイプ扱いのため、ボタンは「マクロ実行」シートの最下部に置く。

## 1. 変更の対象と根拠

- 対象ブック: `\\nksv569.ad.nkc.co.jp\Share\mnt\DGS-SV\★個人フォルダ\篠原\固定テーブル棚卸作業\99_検証記録_ver2セット\review_20260915\セットアップレポート計算機原本_v2.0.xlsm`(変更前 979,617バイト・2026-10-22 14:39保存)
- バックアップ: 同フォルダの `セットアップレポート計算機原本_v2.0 - コピー.xlsm`(14:39作成、変更前と同一ハッシュ c3095f462b88be79ca6781a3382fdd42 を確認済み)
- 根拠: 2026-10-22 の追加指示。「⑧で作成されるデータの所在が不明。印刷後に削除されるなら保存される仕様に変更すること。取付部品シリアルとその二次元バーコードを必要データとする」

## 2. 変更内容

### SpliceBarcodeSaveモジュール(新規・224行)

- `SaveSpliceBarcode`: ボタン用の入口。確認ダイアログを出してから本体を呼ぶ。
- `SaveSpliceBarcode_Core(interactive)`: 本体。⑧(PrintSplice)と同じ条件(計算結果_整形 の J列・O列が空白でなく、H列テーブル番号が14以外)で絞り込み、表示行のL列「取り付け部品シリアル」を収集する。
- `WriteSerialCsv`: CSV出力。ヘッダー「取付部品シリアル」+1行1シリアル。文字コードはCP932。`Open For Output` なので同名ファイルは自動で上書きになる。カンマ・引用符を含む値だけ引用符で囲む。
- `ExportBarcodePdf`: PDF出力。S2(印刷)シートを一時ラベル領域として使い、既存存⑧⑨のShukkoと同じレイアウト(1ページ40件=4ブロック×5列×2段、QRは61×61pt、`BARCODE.BarCodeCtrl.1` のStyle=11)で展開し、`ExportAsFixedFormat` でPDF化する。20行ごとに手動改ページを入れて1チャンク=1ページに揃えた。
- 出力先はモジュール先頭の定数 `SAVE_DIR` で決める。既定は空文字=ブックと同じフォルダ。ファイル名は固定で `取付部品シリアル_バーコード.csv` / `.pdf`。実行のたびに上書きされる。
- PDF出力の前後で、S2の上下マージンだけ一時的に0.25インチへ縮めて戻す。テンプレートの20行(732pt)がA4の印刷可能高さ(約734pt)とほぼ等しく、マージンが0.75インチのままだと自動改ページが割り込んで空白ページが挟まるため。
- 出力後の後片付けで、QRのOLEオブジェクト・書き込んだセル値・追加した改ページを全て削除する。データはCSV/PDF側に残るので、S2は実行前の空の雛形に戻る。セルの書式・行高・罫線は触れていない。

### マクロ実行シート

- 最下部(A61〜C63)にフォームボタン `btnSpliceBarcodeSave`(表示名: 取付部品シリアル_バーコード保存、割当: SaveSpliceBarcode)を追加。
- A60に見出し「EX)取付部品シリアル_バーコード保存」、D60に注記「●ブックと同じフォルダへCSV/PDF出力(上書き保存)」を追加。

### 変更しなかったもの

- 既存の全マクロ(Module1・PrintBarCode)と⑧〜⑨の動作。⑧はこれまで通り印刷後に一時データを破棄する(保存は新ボタンの役割)。
- S1・S2のテンプレート書式、ブックの「読み取り専用を推奨」設定(fileSharing readOnlyRecommended=1 は変更後も保持)。

## 3. 試験

## 4. 確定・保留事項

- 確定: 実装・ボタン配置・上書き保存仕様。原本への反映は2026-10-22 15:16(反映後、vbaProject.bin内のモジュール存在・VMLのFmlaMacro・A60/D60の文言を再読込して確認済み)。

# 第2次変更: ⑥⑦⑧⑨の印刷→PDF書き出し化とPDF印刷機能(2026-10-22 午後)

## 6. 変更の対象と根拠

- 対象ブック: 第1次変更反映後の同一ブック(反映後 1,010,853バイト・ハッシュ 1E10522A4D981565C12DEFA152090DE8)
- 根拠: 2026-10-22 の追加指示。「印刷する機能をPDFデータとして書き出す機能に変更。印刷機を設定する機能を、各ボタンの名称に沿った命名のPDF出力に変更。加えてフォルダ指定でPDF一括印刷・選択したPDF1種のみ印刷の機能を追加。要件確認から段階実装・デバッグを含む」
- 確定要件(ユーザー回答): PDF化対象は⑥⑦⑧⑨の4ボタンのみ(印刷入力シートの入庫用/出庫用ボタンは現状の紙印刷のまま)。⑦⑧の「バーコードも出力」は既存の `取付部品シリアル_バーコード.pdf` と共用。出力先はブックと同じフォルダに統一。全PDF固定名・上書き。一括/単体印刷は既定のプリンタ・印刷後もPDF削除なし。

## 7. 変更内容

### PdfExportUtilモジュール(新規・95行)

- `SAVE_DIR`(全PDF共通の出力先定数。空=ブックと同じフォルダ。第1次の SpliceBarcodeSave.SAVE_DIR から移管し1箇所化)
- `OutputDir` / `OutDirError`: 出力先の取得と妥当性確認。
- `VisibleLastRow`: フィルタ後の表示最終行(J列基準)。使用範囲がA1:T1000まであるため、出力時に印刷範囲を A1:T最終行 へ一時設定して空ページの連発を防ぐ。
- `ExportListToPdf`: 計算結果_整形を `ExportAsFixedFormat` でPDF化。印刷範囲が未設定のときだけ一時設定し、正常・エラーのどちらでも元へ戻す。

### Module1(⑥⑦⑧⑨のPDF化。プロシージャ単位で置換)

- 各ボタン用SubはMsgBox表示のみにし、本体を `*_Core(interactive)` 関数へ分離(結果メッセージを戻り値に。テストは interactive=False で無音実行可能)。
- ⑥FaildSetUp → `セットアップ情報取得失敗リスト.pdf`。フィルタ条件・追加の列非表示(12/15/19/20)は元の紙印刷と同一。確認ダイアログを出力先付き文言に変更。
- ⑦FaildSplice → `スプライシング切り替え失敗部品リスト.pdf` +「バーコードもPDFに出力しますか?」で `取付部品シリアル_バーコード.pdf`。
- ⑧PrintSplice → `スプライシング部品リスト.pdf` + 同上のバーコード。
- ⑨ManualNyuko → `手動入庫処理バーコード.pdf`(S1へ集めたシリアルを NyukoPdf へ渡す)。
- プリンタ設定ダイアログ(xlDialogPrinterSetup)と PrintOut を対象4ボタンから全廃。
- 未変更: FaildSplice_OK、取込系(tana/GenbaList/idouSQL/Utf8ToSjis/各Import等)、印刷入力シートの入庫用/出庫用ボタン(Nyuko/Shukko の紙印刷)。

### PrintBarCodeモジュール(NyukoPdf追加・314行)

- `NyukoPdf(pdfPath)`: S1!A列のシリアルを Nyuko と同じレイアウト(1ページ20件、上段=シリアルのQR、下段=SUBSTITUTEで空白を除いたコードのQR)でPDF化。エラー時はS2を雛形へ戻してメッセージを返す。

### SpliceBarcodeSaveモジュール(改修・266行)

- `ExportBarcodePdf` を Public 化(⑦⑧から共用)。
- `ExportBarcodeFromFilter(ws)` 追加: 指定シートのフィルタ結果からL列シリアルを集めてバーコードPDFを出力(⑦⑧の「バーコードも出力」から呼ぶ。S1を経由しない)。
- 出力先判定を PdfExportUtil へ移管。

### PdfPrintモジュール(新規・163行)+ ボタン2個

- `PrintAllPdfs` / `PrintAllPdfs_Core(interactive, folder, dryRun)`: フォルダ選択→`*.pdf`列挙(上限500)→確認→ShellExecute の print 動詞で順に印刷(1ファイルずつ1秒待ち)。失敗ファイルは一覧で報告。
- `PrintOnePdf` / `PrintOnePdf_Core(interactive, filePath, dryRun)`: PDFファイル選択→確認→1件印刷。
- `dryRun=True` は列挙と確認まで行い印刷しない(テスト用)。
- `btnPrintAllPdfs`(A66〜C68・「PDF一括印刷」)、`btnPrintOnePdf`(A71〜C73・「PDF選択印刷」)、A65/A70に見出し、D65/D70に注記。
- 前提: PDF印刷はWindowsの「既定PDFアプリの印刷」に依存。動作PCでは Acrobat DC に print 動詞が登録済み(`HKCR\Acrobat.Document.DC\shell\print\command` = `Acrobat.exe /p /h "%1"`)を確認済み。

### OLE削除方法の変更(防御的)

- S2からQRのOLEオブジェクトを消す処理を For Each から後ろからのインデックス削除へ変更(列挙中削除の飛び防止)。ExportBarcodePdf と NyukoPdf の後片付け。

## 10. 実装時の記録(第2次)

- 計算結果_整形 は横方向・1ページ幅(FitToPagesWide=1)設定で、列A〜G/K/M-N/P-R は元々非表示。PDFは紙印刷と同じ列構成になる(⑥は12/15/19/20列を追加で非表示)。

- PS の COM 経由では `OLEObjects.Count` が全シートで1を返す等の偽値がある。実数は Shapes の Type=12(ActiveX)で数える。
