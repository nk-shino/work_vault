# リール消費マクロ等 リファクタリング記録

実施日: 2026-10-21。対象: `★リール消費マクロ等ver2/` にコピーした運用中4ブック(リール消費・ラベル再発行・個別出庫・外部出庫)。元コードは DGS-SV `★リール消費マクロ等` の 2026-06-26 版ほか。

## 1. 方針

運用実績のある動作を一切変えないことを最優先した。Sleep 値・SendKeys のキー列・クリック座標・記録内容・MsgBox の有無はすべて既存どおり。迷った箇所はすべて既存を採用し、判断の根拠をコメントとして残した。

## 2. 生成物

| ファイル | 内容 |
|---|---|
| Module1_リール消費マクロ_リファクタ.bas | ゼロ確認(主処理)+外部出庫+共通部 |
| Module1_ラベル再発行マクロ_リファクタ.bas | ラベル再発行+ゼロ確認+外部出庫+共通部 |
| Module1_個別出庫マクロ_リファクタ.bas | 個別出庫+ゼロ確認(記録なし)+共通部 |
| Module1_外部出庫マクロ_リファクタ.bas | ゼロ確認(外部出庫画面版)+共通部 |
| Module2_共通_リファクタ.bas | getMouseCoordinate(診断用) |

## 3. 検証結果

- 文レベル照合: 4ブックの元コードとリファクタ版を、Sleep 値・SendKeys・座標・記録内容・MsgBox・画面タイトルの網羅照合にかけ、動作に関わる差分ゼロを確認した(差分は待ちループの共通化による重複解消と Module2 分離のみ)。
- コンパイル検証: 元ブックの複製に Module1/Module2 を差し替えてインポートし、VBE のコンパイルを 4 ブックとも実行。全ブックでエラーなし(PASS)。
- 検証環境: Office 16.0(x86)、AccessVBOM=1。

## 4. 変更内容

1. モジュールヘッダの新設: 目的・使い方(画面を前面→実行→A列順送信→記録列で再開)・注意(実行中はPCを操作しない、Sub名はボタン割当があるため変更しない)を各 Module1 の先頭に記載。
2. 繰り返しパターンの括り出し(動作同一): 左クリック(3行のクリック操作)、画面を待つ(前面切替待ち+0.5秒安定待ち)、再開行を求める(記録列の最終行の次)。元コードで各Subに重複していた部分。
3. 機能コメントの追加:
   - 在庫あり確認後の ENTER 3回 = 判定取りこぼし対策の冗長送信(仮説B)。実B)。実績があるため維持。
   - Sleep 値 = 実績値。ラベル再発行の 3 秒待ちは印刷完了待ち。
   - 中断検知 = 前面画面が想定外に変わったら即停止する誤送信防止。
   - 再開 = 記録列の最終行の次から始めるため、中断しても記録済み行を送り直さない。
   - Application.Goto Cells(i+3,1) = 処理中の行を見せる進捗表示。
   - ブック間の同名 Sub の差異(案内/完了MsgBoxの有無、記録の有無、記録列、○/◯ の記号の揺れ、外部出庫マクロのゼロ確認は画面も座標も別物)を明記。
4. 宣言の整理: Win64/Win32 の二重宣言の意図をコメント化。マウスAPIとTypeを Private にして局所化(Module2 との名前衝突の潜在リスクを除去)。
5. Module2 の修正: 元コードの `Declare Function GetCursorPos`(外部出庫マクロ側で PtrSafe 無し)は 64bit Excel でコンパイルできないため PtrSafe を付与。Type/宣言を Private 化。

## 5. QCD の評価

- Q(品質): 意図不明点の解消と64bit対応により、誤送信時の切り分けと引き継ぎが容易になった。コンパイル検証済み。
- C(コスト): 実行時間は不変(Sleep・キー列を既存採用)。コード重複の括り出しにより、修正時の変更箇所が減った。実行時間の短縮は ver2(modTanaoroshi/modWinAuto)の状態待ち設計(ver2_変更仕様書 §7)で扱う。
- D(確実性): 中断時の再開条件が文書化され、誰が止めても次の人の続行方法が分かる。

## 6. 導入手順(実ブックへの適用)

1. 適用前に元ブックの複製を取る。
2. VBE で Module1・Module2 を削除し、対応する .bas をインポートする(Module1 は各ブック専用、Module2 は共通)。
3. VBE のデバッグ→コンパイルでエラーがないことを確認して保存。
4. Sub 名は変更していないため、ボタン割当・マクロ一覧はそのまま使える。

## 7. 既存採用とした見送り事項

Sleep の短縮、ENTER 送信回数の削減、待ちループへのタイムアウト追加、窓タイトルの表記ゆれ対応。いずれも動作が変わるため、本リファクタでは手を付けず ver2 設計(状態待ち・30秒上限)で扱う。
