## 1. 設備に付いたままの部品を、倉庫へ戻す

**棚卸しでは部品がテーブルに付いたままカウントする。**
**しかし EG-Pro 上はステータスを倉庫に戻す必要がある。**

> 部品がテーブルに付いたままカウントを実施するが､EG-Pro上はステータスを倉庫に戻す必要がある｡
>
> 最終Job生産終了後､EG-Pro在庫検索の倉庫ロケーションで【設備([ライン名])】となっているものがあるか確認する｡
>
> ある場合､対象ラインにあるEG-Proを操作し､用意してあるダミーのJobを読み込ませる｡(000001-DMY/000002-DMY/000003-DMY)
>
> **生産開始を押し､すぐにキャンセルを押す｡これで倉庫ロケーションが外しに切り替わる｡**

### 要点

| 項目 | 内容 |
|---|---|
| いつ | **最終Jobの生産終了後** |
| 何を見るか | EG-Pro 在庫検索の倉庫ロケーションが **【設備(ライン名)】** になっているもの |
| ダミーJob | **`000001-DMY` / `000002-DMY` / `000003-DMY`**（ラインごとに1本と見える） |
| 操作 | **生産開始 → すぐキャンセル** |
| 結果 | 倉庫ロケーションが **「外し」** に切り替わる |

**「生産開始を押してすぐキャンセル」が肝。**
実際に生産するのではなく、**EG-Pro にジョブの読み込みを認識させて
ロケーションの状態遷移だけを起こしている。**

**要確認:** ダミーJob の3本がライン L1/L2/L3 に対応するのか、
`000001-DMY` がどのラインかは本メモに書かれていない。

## 2. 0確認はここから始まる

> 倉庫検索で0確認となっている部品を抽出してExcel出力し､0確認マクロを実行する｡

**0確認マクロの前工程が、これで確定した。**

```
EG-Pro 在庫検索
  ロケーションに 0確認(L1) / 0確認(L2) / 0確認(L3) を指定
      ↓ 条件表示
  抽出結果
      ↓ Excel出力
  CSV / Excel
      ↓
  0確認マクロ（A列へ貼り付け → 実行）
```

**在庫検索の画面には「在庫数」の検索条件が無い**（`棚卸セットver2_実物同定と初期調査_2026-10-07.md` §2-2）。
**「在庫数9以下」で絞るのは Excel 出力した後。**
`0確認マクロ` の期待値 5,848件が Excel 側の絞り込みであることと整合する。

## 3. 必要なリストの作成手順

> まず､Pana-CIMよりセットアップレポートを出力する｡
>
> 次に､**EG-ProのサーバーPCから全部品情報を出力する｡**
>
> セットアップレポートマクロに上記2つと､**固定部品のマスター配列データ(Job作成マニュアルで作成済みのもの)** を貼り付ける｡
>
> スプライシングされている部品だけをフィルターで絞り､印刷する｡
>
> バーコードは**バーコード作成マクロ**を使用して印刷する｡

### 入力は3つ

| # | 入力 | 出所 |
|---|---|---|
| 1 | セットアップレポート | **Pana-CIM** |
| 2 | **全部品情報** | **EG-Pro のサーバーPC**。保管庫に記載が無かった |
| 3 | 固定部品のマスター配列データ | **Job作成マニュアルで作成済みのもの** |

**3つを「セットアップレポートマクロ」に貼り付ける。**
これは `セットアップレポート計算機` の `SETUPREPORT_Import` / `HAIRETSU_Import` に対応すると見える。
**ただし「全部品情報」が計算機のどのシートへ入るかは未確認。**

**「固定部品のマスター配列データ」が Job作成マニュアル由来**という点も、
既存文書では「★固定マスタから取る」としか書かれていなかった。
**作成元が Job作成側にある。**

## 4. 不具合対応

**現物とシステムが食い違ったときの分岐。**保管庫に記載が無かった。

### 4-1. バーコードが2つ貼られているが、スプライシングテープが見当たらない

```
① Pana-CIM端末でステータスチェックを実施する
   └ スプライシングされている → スプライシング解除する
② 剥がせる方のバーコードが、EG-Proの倉庫検索でシリアルが存在するか確認する
   └ 存在する → 剥がせる方のEG-Proバーコードに対して【リール破棄処理】を実施する
```

### 4-2. バーコードが1つしかないが、スプライシングテープがあり、穴も塞がれている

```
① Pana-CIM端末でステータスチェックを実施する
   └ スプライシングされている
       → スプライシング前のシリアルが EG-Pro の倉庫検索で存在するか確認する
           └ 存在する   → 貼り付け漏れのため再発行して貼り付け直す
           └ 存在しない → 同じ注番でシリアルを発行し、Pana-CIM上でスプライシングし直す。
                          発行したラベルは部品にテープで貼り付ける（剥がせる状態）
   └ スプライシングされていない
       → スプライシング前のシリアルを頑張って探す。
         再カウント時の未カウントのリストにあれば、それの可能性が高い。
         どうしても特定できない場合、スプライシング前の部品を全て破棄する
```

### ここで使う操作

| 操作 | 場所 | 保管庫での記載 |
|---|---|---|
| **ステータスチェック** | Pana-CIM 端末 | **無し** |
| スプライシング解除 | Pana-CIM | 言及はあるが手順は無し |
| **リール破棄処理** | EG-Pro | **無し。取り消せない操作の可能性が高い** |
| シリアル再発行 | EG-Pro（ラベル再発行マクロ？） | マクロはあるが、この文脈での記載は無し |

**「リール破棄処理」は名前からして取り消せない。**
`0確認マクロは取り消せない` と同じ扱いが要る。**実施の判断者が未確認。**

## 5-2. ロケーション名称の実値（倉庫検索シートから）

**`倉庫検索` シートに28,884行の実データが入っていた。**列は次のとおり。

| 列 | 値の例 |
|---|---|
| シリアル番号 | `154468A100006` |
| 品番 | `154468A` |
| 受入数 / **在庫数** | 5000 / 238 |
| ステータス名称 | **貯蔵 / 生産終了 / 出庫** |
| **ロケーション名称** | **棚 / ハズシ(L2) / 0確認(L1) / 1ライン倉庫 / 2ライン倉庫** |
| 棚 | `01-01-01-01` |
| **新品かどうか** | **新品 / 中古品** |

### ここで §1 のダミーJob手順が裏付けられる

**§1 に「倉庫ロケーションが外しに切り替わる」とあったが、その行き先が `ハズシ(Lx)`。**

```
【設備(ライン名)】 ──ダミーJob読み込み→生産開始→即キャンセル──> ハズシ(Lx)
```

**`0確認(Lx)` と `ハズシ(Lx)` は別のロケーション。**取り違えない。

### 「新品かどうか」の列がある

**この列が §5-3 の工数差の根拠になっている。**
在庫検索の画面（`棚卸セットver2_実物同定と初期調査_2026-10-07.md` §2-2）には
この列が見えていないので、**Excel出力後に付与されるか、別の出力に含まれるかは未確認。**

## 5-3. 工数の実測値（部品数シート）

**これまでどの文書にも無かった数字。**見積もりに直接使える。

| 区分 | 本数 | 1本あたり | 合計時間 | 人日 | 1日あたり必要人数 |
|---|---|---|---|---|---|
| **新品** | **18,351** | **15秒** | 76.5時間 | 25.5 | 3.64 |
| **中古品** | **10,532** | **77秒** | **225.3時間** | **75.1** | **10.73** |
| 総計 | **28,883** | — | 約302時間 | 約100 | — |

### 読み取れること

**中古品は新品の5倍かかる（77秒 対 15秒）。**
本数は中古品のほうが少ない（10,532 対 18,351）のに、
**時間は中古品が3倍近くを占める**（225時間 対 76時間）。

**工数を減らすなら、中古品の1本あたりを縮める以外にない。**
新品を速くしても、全体の25%にしか効かない。

**中古品が遅い理由は本メモに書かれていない。**
ただし §4 の不具合対応（バーコードが2つ／1つしかない、スプライシングテープ）は
**すべて中古品で起きる種類の問題。**ここが時間を食っている可能性が高い。**要確認。**

### 総計 28,883 と 28,884 行について

**倉庫検索シートは見出し1行＋データ28,883行。**部品数シートの総計と一致する。
**`0確認マクロ` の 29,246行とは別のデータ。**取得日時が違う。混同しない。
