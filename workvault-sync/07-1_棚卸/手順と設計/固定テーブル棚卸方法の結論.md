結論：固定テーブル棚卸は
「設備の現状（実物）が示す所在情報を、EG‑Pro（在庫DB）の所在 / ステータス情報と一致させる」ための一連の作業。
数量（在庫数）を直接書き換えることが目的ではない。

■要点
- 設備側（Pana‑CIM）
    - 役割：設備のセットアップ状態を出力する「[[セットアップレポート-テーブル設計書]]」を出す。これが現物の状態を示す一次データになる。
- 事務PC（セットアップレポート計算マクロ）
    - 役割：セットアップレポート＋[[EG‑Pro在庫CSV(0確認を除く)-仕様書]]＋[[配列データ]](固定製品毎)を照合し、現場部品リスト（GenbaList）を生成。idouSQL（倉庫移動SQL）を生成して更新候補を作る。
    - 備考：[[セットアップレポート計算機]](FaildSplice_OK等)のマクロは Excel 内の取込済みシートを書き換えるだけで、EG‑Proや現物は変えない。
- EG‑Pro（在庫管理DB / サーバ）
    - 役割：最終に所在（ロケーションコード / ステータス / ライン・設備・Z軸フラグ / 更新日時）を更新される対象。[[idouSQL]] で生成した SQL を人が実行して反映する運用になっている。在庫数量は更新対象外。
- 倉庫 / 現場（物理側）
    - 役割：実物（リール）を棚卸し用倉庫（ロケーションコード 201・202など）へ移す為の物理操作が伴う場合がある。
- 実行者（人）
    - 役割：生成された倉庫移動SQLを実行する (@@ROWCOUNTで確認して COMMIT / ROLLBACK を選ぶ / 作業ログを残す)

確定事項まとめ

- 目的は「所在（ロケーション / ステータス等）の整合」であり、在庫数の直接修正は目的外。
- データフローは「設備 → Pana‑CIM（セットアップレポート）→ Excel（GenbaList / idouSQL）→ 人がSQL実行 → EG‑Proロケーション更新」　の流れ。

要確認事項（運用で確認すべき点）
- 棚卸後に別プロセスで在庫数量を是正する運用があるかは明記されていない。
