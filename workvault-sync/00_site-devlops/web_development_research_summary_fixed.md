## 概要

このチャットでは、個人による一般的なWeb開発を想定し、開発工程に沿ったツール検討、料金・ライセンスやリスクの確認、SNS投稿データ利用の規約確認、AI開発支援製品の比較を順に行った。対象を広く調べた後、SNSはXとYouTubeに絞り、AI開発時の支援ツール費用を比較した。

現時点での主な結論・整理は次のとおり。

- 期間は半年（試算上30日×6か月＝180日）。利用者の「100人/日」はWebサイトへのアクセス人数の前提であり、APIで読む投稿数、投稿量または課金対象件数を意味しない。
- AIツール費用の検討対象は開発時のみ。本番サービスでのAI実行やRAGは含めない。人件費も除外する。
- X APIの通常投稿読取について、調査時点の料金情報を用いて、課金対象となる投稿リソース数を別途仮定した費用例を作成した。アクセス人数からAPI費用を直接算出することはできない。
- YouTube Data APIは標準クォータ内の利用料を$0として整理した。クォータ増枠は申請・審査が必要で、承認や運用負荷を確定事項として扱わない。
- SNSの削除・保持条件はプラットフォームごとに異なる。Xの24時間は削除後に許される猶予期間ではなく、所定の削除要求を受けた後の対応期限として整理した。YouTubeの30暦日更新・削除条件も、対象データや例外と区別する。
- 既存のClaude Code Proを継続することを優先案とし、ほかの有料製品を最初から重ねない案を提示した。これは提案であり、ユーザーが最終採用を確定したものではない。
- 「GPT Astra」は製品名が特定されていない。GPT-6 Astraを指す可能性は確認したが、同一製品と確定していない。
- ノートは過去のやりとりで更新・確認済みとされた。今回の依頼ではノートを編集していない。

## X APIの従量費試算

### 会話内の調査で確認した単価と課金上の扱い

- X APIの通常投稿読取は、会話内の調査結果では **返却された課金対象リソース1件あたり$0.005**。
- 同一UTC日内の同一投稿の再取得は、原則として重複課金されない扱い。ただし翌日以降の再取得には再課金され得る。重複排除はsoft guaranteeとして説明されており、無条件の請求上限とはみなさない。
- 他のリソースやAPI操作には別単価があり、この試算の単価を全APIに適用しない。
- 試算は人件費・税・為替・ほかのAPIリソース費用を含まない。

### 定常的な1日あたり課金件数を置いた例

| 課金対象投稿リソース数/日 | 30日換算 | 180日換算 |
|---:|---:|---:|
| 100件 | $15 | $90 |
| 1,000件 | $150 | $900 |

計算式は「日次課金対象件数 × $0.005 × 日数」。例として100件/日なら100×0.005×30＝$15/月、100×0.005×180＝$90/半年となる。

この件数は、同一UTC日内の重複取得を除いた後の課金対象数が毎日同程度であるという仮定である。新規投稿だけでなく、既存投稿を翌日以降に再取得する分も課金対象になり得る。蓄積した全件を毎日再確認する設計では、実際の課金対象数が時間とともに増えるため、この単純試算を上回り得る。**100人/日のWeb閲覧数を100件/日のX API読取と読み替えてはならない。**

### YouTube Data API

会話内の整理では、YouTube Data APIは標準クォータ内ならAPI利用料を **$0** とした。標準枠の増枠には申請・審査が関係するため、承認済みの追加容量や無制限利用を前提にしない。クォータ超過を避けるには、実際に使用するメソッドのクォータ消費と日次上限を実装前に照合する必要がある。本記録では詳細な検索クォータ消費量を数値で推測していない。

### 製品間の利用枠・認証の区別

- Claude CodeはVS Codeの無料版でも利用できる。Claude CodeをCursor内で使う場合の認証・利用枠と、Cursor AgentからClaudeモデルを使う場合の利用枠は同一ではない。
- Cursor AgentでClaudeモデルを選ぶ利用はCursor側の枠に関係する。Claude Codeの利用枠をそのまま流用するものではない。
- BYOK（自分のAPIキー）を使う場合はAnthropic APIの別料金となり、Claude Proの定額枠をAPIに転用できない。
- CodexのChatGPTプラン内利用とOpenAI APIの従量課金も別物として扱う。

## 提案と判断の留保

### 会話内で提示した提案

1. まず既存のClaude Code Proを継続し、Claude Codeを使うためだけにCursorの有料プランを追加する必要はない。
2. Codex Freeを独立したレビュー・比較用途で試す。
3. Cursor Hobbyで補完やGUI上の作業体験を評価し、Proが必要かは実際の利用枠不足・機能価値を確認してから決める。
4. 手作業やIDE統合の価値が大きい場合は、優先順位をCursor側に入れ替えて評価してよい。
5. 最初から複数の有料プランを同時契約せず、足りない機能・利用量を確認してから一つずつ追加する。Claude側の利用量が不足する場合は、別製品追加とMaxへの変更も比較する。
6. モデルの一般的な性能順位を断定しない。ここでの比較軸は、開発環境との統合、機能の重複、利用枠、追加費用、実作業での価値とする。

### この提案の位置づけ

これらは検討を進めるための提案であり、ユーザーが最終決定・契約した事実ではない。実際のプロジェクトで、コーディング、レビュー、GUI操作、利用上限のどこが律速になるかを試してから再評価する。性能ベンチマークに基づく製品ランキングは、この会話では検証していない。
