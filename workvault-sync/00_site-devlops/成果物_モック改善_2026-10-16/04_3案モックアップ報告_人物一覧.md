## 5. 3案の設計（§6）

### 案A — 既存を活かす最小改善（`chara-a.html`）

| 項目 | 内容 |
|---|---|
| 想定場面 | いまの利用のしかたを続ける。操作の再学習をしない |
| 最も改善したい課題 | 欠損キーで「undefined」と表示される欠陥（前ラウンド発見・修正済み）を画面で確定させる |
| 既存との違い | **ほぼ無い。**「情報が欠けた欄を（未記録）と明示」1点のみ。現状維持を正式な案として扱う（§6-案A の指示） |
| 使用部品 | `.card` `.plate` `.chips`（すべて現行流用） |
| 参考にしたページ | 現行 chara.html |
| 実データとの対応 | characters.json 13人・6キー。欠損時は（未記録） |
| 必要な変更 | 取り込み時: chara.js へ text() ヘルパー1関数を移植するだけ |
| 不利な点・保守コスト | 13人横断の比較は面倒のまま。出典導線なし。保守負担は増えない |

### 案B — 作業効率を優先（`chara-b.html`）

| 項目 | 内容 |
|---|---|
| 想定場面 | 「あの役割の人は誰か」「聖堂の人物一覧」を最短で引きたいとき |
| 最も改善したい課題 | 題箋3:4の大きな枠が13人分の縦幅を占有し、一覧性が低い（肖像が無いあいだ特に） |
| 既存との違い | カード格子 → **行形式の表**。題箋を外し、appearance（外見の特徴）を行内に載せる。検索・並び替え3種（登録/五十音/所属）を追加 |
| 使用部品 | `table`・`input[type=search]`・`select`・`.chips`・`.empty` |
| 参考にしたページ | catalog.html の検索・絞り込み・0件 |
| 実データとの対応 | characters.json の id/name/role/affiliation/appearance。appearance は未使用のままだった既存キーを初めて一覧に出す |
| 必要な変更 | chara.js の render を表形式へ置換。並び替え関数を追加（~40行） |
| 不利な点・保守コスト | 「肖像画が並ぶ回廊」（手引き §4 の見立て）から離れる。**絵が入った日に再設計が要る**——絵が入ったときの案と分けて扱う（§6-3 論点2） |

### 案C — 理解と根拠確認を優先（`chara-c.html`）

| 項目 | 内容 |
|---|---|
| 想定場面 | 「この人物の記録は出典が乗っているか」を、詳細を開く前に知りたいとき |
| 最も改善したい課題 | 一覧に検証状態・出典への導線が無く、根拠確認が詳細ページを開いてからになる（改善案 指摘6の内容を一覧へ前倒し） |
| 既存との違い | カードに **検証バッジ・出演作品（時系列）・出典リンク** の3行を追加。カード=肖像の器 から 記録の器 へ構造を変える |
| 使用部品 | `.card` `.plate` `.badge`（VERIFY対応表）・catalog.json/sources.json の照合 |
| 参考にしたページ | work-detail.html（主張と根拠の3列）・catalog.js のバッジ |
| 実データとの対応 | 検証=catalog.json の verify 値（**出典数で判定しない**）。出演=works.json の characters + released で時系列ソート。出典=catalog の ref → sources の群名 |
| 必要な変更 | fetch 対象が1→4ファイルに増える。照合ロジック ~30行 |
| 不利な点・保守コスト | カードが高くなり1画面の人数が減る。fetch が増える分、失敗時の扱い（未実装）が課題になる。**fixture では人物13人すべて未検証**なので、バッジの分布は本家データで変わる（本家の検証状態を置き換えない） |

### 3案に共通する構造上の違いのまとめ

配色・角丸・フォントは3案とも同一（トークンは同じ）。
違いは **情報の優先順位（肖像 vs 記録）、レイアウト（格子 vs 行）、導線（詳細後出し vs 一覧で前出し）**。

**守った分離の約束（§7 の箇条書き）:**
- 公開日時・取得日時・確認日時は混同していない（モックが扱うのは作品の released のみ）
- API（fetch）の成功を真実性と扱っていない。検証は verify 値（照合結果）を出す
- 出典の数で確認済みを判定していない（verify 値を直接見る）
- 同じ原典の転載を独立した裏付けとして数えていない（出典は群名の表示のみ・点数化しない）
- 矛盾・訂正・未確認は隠していない（未検証バッジ・出典なし表示が見える）
- fixture の検証状態（未検証13人）を本家の検証状態と誤認させないよう、ページ foot に注記
