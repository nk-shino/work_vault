### 着手前に調べたこと

**Void が何か分からなかったので先に当たった。** Cloudflare が 2026-10-15 に公開した
デプロイ基盤で、Vite を土台にしている。Vite の開発元を Cloudflare が買収した流れのもの。

公式の記述で確かめた点：

| 確かめたこと | 結果 |
|---|---|
| フレームワーク無しの静的サイトを扱えるか | 扱える。「existing frameworks and static sites」と明記 |
| Vite の設定ファイルが要るか | `inference.appType: "static"` なら不要。build を実行して outputDir を上げるだけ |
| 設定ファイルの名前と項目 | `void.config.ts`。`inference` / `routing` / `worker` / `cloudflare` |
| ヘッダーの指定方法 | Workers の静的配信は `_headers` を読む（Cloudflare 公式ドキュメントで確認） |

**第三者の記事に「v1 では静的サイトは fail closed」という記述があったが、公式側で裏が取れなかった。**
断定せず、素の wrangler で上げる手順も併記した。

### 実施

#### 1. 配信物の切り出し（`tools/build-site.js` 新規）

**リポジトリの根をそのまま配ると、APIキーを扱う別アプリも、下書きの入ったフォルダも一緒に外へ出る。**
10-19 のセキュリティ確認で「tools は webroot 外へ」と指摘したのと同じ話が、本家にそのまま当てはまった。

拾う側だけを並べる方式にした。外す側を並べると、新しいフォルダを足した日に黙って混ざる。

配る直前に2つ検査し、合わなければ終了コードを立てて止まる。

- HTML 内のリンクと `src` が、配信物の中に実在するか
- `<head>` のインラインスクリプトを全部ハッシュに取れたか（開いたタグの数と突き合わせる）

#### 2. 配信ヘッダー（`dist/_headers` を自動生成）

**「外部リクエストはゼロ」は、これまでコードを読む人が守る決まりだった。**
CSP を付けるとブラウザが止める。うっかり外部CDNを足しても本番で読み込まれない。

ハッシュを手で書き写さないのが要点。スクリプトを一文字直した日に、そのページだけ
テーマの先読みが黙って死ぬ。**罫線トークンの件（10-18）と同じ「複製された根拠の片修正」の型。**

#### 3. 404 ページの新設

本家に 404 の行き先が無かった。**どのURLに対しても返るページなので、中のパスを全部 `/` 始まりにした。**
相対にすると `/pages/` の下で返ったときに全部外れる。

#### 4. `void.config.ts`

公式の項目名に沿って書いた。**実デプロイでの検証は未実施**（パッケージを導入していないため。
公開6日のパッケージなので、導入前に本人の判断を仰ぐ）。

### 分かったこと（デプロイ条件）

**ドメインの根にしか置けない。** 共通パーツもデータも `/` 始まりで読んでいるため、
`example.com/site/` のような途中の階層に置くと**中途半端に壊れる**。
CSSは当たるのでページは正しく見えるのに、ナビとデータだけが出ない。

`README.md`・`docs/project-rules.md`・`package.json`・`.gitignore`（追記）
