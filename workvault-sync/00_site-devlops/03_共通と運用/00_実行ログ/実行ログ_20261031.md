### 実装1 ── `npm run watch` が立体演出のJSを壊す欠陥

**何が起きていたか（実測で再現した）。**

変換の設定が2本ある。`tsconfig.json`（`module: none`・出力先 `js`）と
`tsconfig.hero.json`（`module: ES2022`・出力先 `js/hero`）。
ところが `tsconfig.json` の `include` が `src/**/*.ts` で、**`src/hero` まで拾っていた。**
出力先は両方とも `js/hero/ambient.js` に重なる。

`npm run build` は2本を `&&` で続けて走らせるので、**後に走る hero 側の出力が残り、たまたま正しくなる。**
しかし `npm run watch` は `tsconfig.json` だけを走らせる。実際に走らせたところ、

```
変更前: import * as THREE from "three";
変更後: const THREE = require("three");
```

`<script type="module">` で読み込んでいるブラウザに `require` は無い。**読み込んだ瞬間に落ちる。**

**直し方。** `tsconfig.json` に `"exclude": ["src/hero"]` を足した。
これで出力先の重なりが消え、`npm run build` も**順番頼みでなくなる。**

ただし `extends` は `include` だけでなく `exclude` も引き継ぐので、
そのままでは hero 側が「No inputs were found」で何も変換しなくなる（これも実測で確認した）。
`tsconfig.hero.json` に `"exclude": []` を足して打ち消した。

**監視の穴。** 上の修正で `npm run watch` は壊さなくなったが、hero を見なくなる。
`src/hero/ambient.ts` を直しても画面が変わらない、という別の落とし穴になるので、
`"watch:hero": "tsc -p tsconfig.hero.json --watch"` を足した。hero を触るときは2つ目を走らせる。

`tsc -b`（ビルドモード）で1コマンドにまとめる案も試して動くことは確かめたが、
`.tsbuildinfo` がリポジトリの根に増えること、出力を消しても「最新」と判断して何もしない場合があることから、
**道具を増やさない側**を採った。

| 確認 | 結果 |
|---|---|
| `npm run build` の後、`js/hero/ambient.js` が `import` のまま | **合格** |
| `tsc -p tsconfig.json` を単体で走らせても壊れない | **合格**（控えと byte 単位で一致） |
| ブラウザで HOME を開いて立体演出が出るか | **合格**（canvas 1513x1140 が生成・コンソールのエラー0件） |
