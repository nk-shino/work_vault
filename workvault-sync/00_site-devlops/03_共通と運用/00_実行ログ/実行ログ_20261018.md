# 実行ログ 2026-10-18

## エントリ1：罫線トークンの一本化 → **変更不要。こちらの誤りだった**

### 依頼

バックログの「罫線トークンが2系統ある（新48箇所／旧29箇所）。置換が途中で止まっている」を
片付ける、という指示。**判断を待たずに進められる作業として、こちらが提案していたもの。**

### 着手前に調べたこと

仕様書 §3-3 の置換表が**部分的**（6セレクタ＋据え置き2つ）で29箇所を網羅していなかったため、
全件を属するセレクタ付きで洗い出した。

```
--border-accent 29箇所の内訳
  3px 見出しの縦罫          7     仕様は「変更なし」
  2px 額縁・引用の縦罫       3     仕様は「変更なし」（額縁は主役）
  1px リンクの下線           8
  1px 押せるもの（ボタン・タブ・チップ）  4
  1px バッジ・ラベル         5
      太さ指定なし           2
```

**置換表が想定していた「一覧の区切り線」は1つも残っていなかった。**
残っているのはリンクの下線・ボタン・チップ・バッジ、つまり**アフォーダンス**だった。

そこで新しい体系が何に使われているかを数えた。

```
--rule* 48箇所の内訳
  区切り線   21
  枠・面     22
  リスト区切り 3
  押せるもの   1
```

### 決め手

**`css/style.css` の `:root` に、使い分けの理由がコメントで書いてあった。**

> 罫線の階層。`--border-accent` 一本で表・リスト・額縁・見出しを全部兼用していると、
> 深紅の線が画面中に散らばってうるさくなる。**ここぞという強調だけ `--border-accent` を残し**、
> `--rule` と `--rule-strong` は飾りの線で、**薄さは意図したもの**。
> 線が無いと構造が読めない場所（表の行区切りなど）には `--rule-solid` を使う。

**設計だった。負債ではなかった。**

### 置換していたらどうなったか

`--rule` はライトで `--accent` の12%、ダークで `--foil` の16%。

**リンクの下線8箇所・ボタンとタブとチップの枠4箇所・バッジ5箇所が、12%の線になる。**
縁がほぼ見えなくなる。掃除ではなくアフォーダンスの破壊だった。

### 唯一の混在候補も別部品だった

`.chip`（`--border-accent`）と `.catalog .chip`（`--rule-strong`）。

| | `.chip` | `.catalog .chip` |
|---|---|---|
| 角丸 | 4px | 0 |
| 下限の高さ | 指定なし | **44px**（指で触れる大きさ、とコメントあり） |
| hover | なし | `--blue` |

別の部品。揃えるかは設計の判断であって、トークンの掃除ではない。

### 結論

**変更不要。コードには一切触っていない。** 作業ツリーはきれいなまま。

## 再発防止

**件数を数えただけで「途中で止まっている」と判断したのが原因。**
同じファイルの `:root` に理由が書いてあったのに、読んでいなかった。

**トークンの使用数に差があるときは、先に定義側のコメントを読む。**
数の偏りは、未完了の証拠にも、意図的な使い分けの証拠にもなる。

このセッションで同じ型の誤りは2件目。
1件目は「動画の概要欄に番号表記は無い」と、動画を見ずに出典の記載だけから判断したもの。
**数えた／引いた、だけで結論を出さない。**
