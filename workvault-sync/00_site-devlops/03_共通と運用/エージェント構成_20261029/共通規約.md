# エージェント構成 共通規約（全役共通の前提）

各担当プロンプト（agent/*.md）は、この規約を参照して重複を避ける。各プロンプトは「共通規約を先に読む」を第一手順とする。

## 1. 参照する正本（着手前に確認する所在）

| 記録 | 所在 |
| --- | --- |
| サイト開発コンテキスト | `~/.config/kohden-code/skills/site-dev-context/SKILL.md`（所在一覧・失敗記録・方針・未決） |
| 開発方針（正本） | 保管庫 `00_site-devlops/03_共通と運用/開発方針.md` |
| 自律開発ガイド（差分） | 保管庫 `00_site-devlops/03_共通と運用/autonomous-development-guide.md` |
| 実行ログ | 保管庫 `00_site-devlops/03_共通と運用/00_実行ログ/実行ログ_YYYYMMDD.md` — 指示1件＝エントリ1件 |
| 質問台帳 | 保管庫 `00_site-devlops/03_共通と運用/質問一覧_サイト側.txt` |

## 2. 承認境界（開発方針 §2 ＋自律開発ガイド §2 を要約）

- 明示承認が必要: 実API呼び出し（GETも含む）・実データ収集・スクレイピング・キー発行・OAuth同意・アカウント作成・課金・外部投稿・Webhook・デプロイ/公開・本番変更・依存の追加・破壊的マイグレーション・公開範囲の緩和・基盤移行・commit/push・秘密情報へのアクセス
- 過去の承認を無期限の許可として再利用しない。承認待ちでも、影響調査・設計案・テスト作成など独立して安全な作業は続ける
- 質問は各確認ラウンドで最大5件、理由・選択肢・推奨案を添える。自律実行中は、安全に決定できる範囲は推奨案を選び進め、重大な未確定事項は BLOCKED として記録する

## 3. 秘密情報と通信

- 秘密値（トークン・キー・PIN・認証情報）を閲覧・出力・文書化・外部送信しない。`.env`・秘密鍵ファイルを不用意に開かない。環境変数名と用途のみ調べる
- 公開資料の読み取り専用閲覧と、実API再実行・投稿・素材ダウンロード・外部送信を区別する。検証は外部通信を防止したローカル設定・モックで行う

## 4. 記録と証跡の分離

- テスト結果は PASS／FAIL／BLOCKED／NOT RUN を区別する。過去の記録・今回の実測・モック・実API・本番を混同しない
- 変更しなかった範囲も報告に含める。変更不要も完了判定に含める（根拠付き）
- 実施していない検証を実施済みと表現しない。「後で実行する」予定を実施済み報告に含めない

## 5. セッション切断への対策（チェックポイント規約）

- 長文を一括生成して最後にだけ保存しない。調査・判断・設定ファイル・検証の各区切りで保管庫へ保存する
- 区切りごとにチェックポイントを残す: タスクID／状態（完了・進行中・保留・BLOCKED）／変更ファイル／確認済み事項／未完了／次の1手
- 再開時は保管庫の実行ログと Git 差分を再確認し、既存の実装・保存を重複実行しない。タイムアウト時は成功/失敗を推測せず、実際の保存・変更状態を確認する
- 再試行は回数制限を付け、部分失敗を分離する。同時編集を避け、再実行は必要最小限に限る
- 切断したセッションが自動継続するとは保証しない

## 6. 同時編集の回避と引き継ぎ

- 同じファイルを複数担当が同時に編集しない。進行管理がファイル単位の担当割当を記録し、担当変更時は引き継ぎメモ（変更前後・根拠・次の1手）を残す
- 引き継ぎメモの様式: 日付／担当（旧→新）／対象ファイル／状態／変更済み内容／未完了／次の1手

## 7. 媒介と報告

- ユーザーとのやり取りは保管庫のノート（めも・対象ノート）を介する。セッション上の報告は最小限とする
- 成果物・根拠・判断・変更差分・検証結果は保管庫へ出力する。ワークスペース側の実行ログも同日に書く
