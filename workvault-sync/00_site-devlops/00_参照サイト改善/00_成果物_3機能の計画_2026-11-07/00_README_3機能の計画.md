## カーソル

### 何を作ったか

人物の札と作品の札に指を乗せると、**カーソルそのものが金の輪と芯に替わる。**
32×32 の SVG を CSS の `cursor` に渡すだけで、OS が描くので遅れは無く、JS も新しいファイルも要らない。

### 模型のままにしなかった理由

模型のカーソルは、点が指に付き、輪がばねで少し遅れて追い、札の上で「ひらく」の字を出す作り。
2026-11-06 に「わざと遅れて追う動きは素早いに反する」として採らなかったもの（ui-design-spec §9）。
実測でも、輪が止まるまで0.38秒、速く動かすと指から100px以上遅れる。輪の大きさの変化も0.35秒で、上限0.32秒を超える。
さらに OS のカーソルを全部消して自前で描くので、ポインタを大きくしている人の設定や、入力欄の縦棒も消える。

### 2026-11-08 の見直し（運営者「ストーリーやモックアップ版を考慮して最適な形を」）

物語と模型の意図を読む担当・ブラウザの制約を調べる担当・案を2つ（物語重視／模型重視）出す担当・採点して1つにまとめる担当で見直した。
**結論は「金の輪と芯を、記録の札にだけ」のまま。直したのは描き方だけ。**

- 物語の上での意味: 札に指を乗せると、その位置に灯りが当たる。輪はその灯りの中心、芯は押す一点で、押すとそこから次のページが丸く開く。炎は描かない（光源は画面の外にある決まり）
- 模型から引き継いだもの: 模型の中で OS のカーソルでは言えなかった唯一の区別（記録を1件開く札／部屋を移るだけのリンク）。「ひらく」は金の輪に、「すすむ」は OS の指の形に置き換えた。指に遅れず付いていた5pxの点は芯になった
- 寸法: 見える外径 26→25px、金の芯 4→5px、絵の中心 16→16.5（OS が押す点に使う画素のまん中。芯と押す点が半画素ずれていたのが無くなった）
- 採らなかった案: 炎・蝋燭・ランタン（光源の決まり、ランタンはジャック1人の持ち物）／紋章や目（32pxでは照準や瞳に見える。「観測者」は世界観の中で定義が無い）／人物と作品で絵を分ける（札の形が既に区別している）／テーマで色を替える（ライトの深紅は血の赤と色相差5°）／字を焼き込む（等倍で潰れ、読み上げに届かない）／輪をナビやボタンにも広げる（灯りが当たるのは札だけ。全部に付けると柄になる）
- 比べた絵は `画像/カーソル_4案の比較.png`、決めた形は `画像/カーソル_決定版.png`（明暗・札・額縁の色の上に、等倍・4倍・表示倍率125/150/200%）

### 確かめたこと

配信ヘッダー（CSP）を付けた配信で、見えない Chrome を動かして16項目すべて合格:
人物・作品の札で金の輪になる／指を乗せた後も同じ／札以外のリンクは指の形のまま／テーマを替えても同じ／
CSP違反0件／絵が32×32として読める／検索欄は縦棒のまま／強制カラーでは指の形に戻る／動きを減らす設定でも同じ／エラー0件。
動きの28項目も、カーソルを入れた後に全部合格のまま。
**OS のカーソルそのものは見えない Chrome では見えないので、見た目は運営者の目視が要る**（S-32）。

## 二面性

### これまでに決まっていること

暗い表示（灯を落とした状態）が主軸／データは `characters.json` の `duality` 欄／押印は詳細ページ（S-19）／呼び名「灯の相・煤の相」は仮置き。
**ただし、どれも試作の模擬人物（c001〜c013、別の模擬サイトの人物）に対して決めたもの。** 本番の13人の誰に付けるかは決まっていない。

### 本番で決まっていないこと（S-31）

- 誰に付けるか、裏の顔に何を出すか。中身を創作しない決まりがあるので、出典のある項目から選ぶ必要がある
- 候補（出典あり）: ジャネットの「人間 → 吸血鬼」、サリアの「変異後の姿（サキュリア）」
- ヴァンの黒猫は使わない。黒猫がヴァンだというのは、サイト自身が「推測」と書いている

### 作るときの形

- 仕組みは、データが無い間は画面が今と1文字も変わらない作りにする
- 切り替えは0.32秒以内・段差なし。模型のノイズが走る演出（案3、0.46秒・色相をずらす）は上限と「ネオン・ツヤを使わない」原則に当たるので入れない
- 隠れている側の顔は、読み上げとページ内検索から外す
- 仮の呼び名「灯の相・煤の相」は画面に出さない（公開すると確定した呼び名のように見える）

## 肖像

### 分かったこと

- **切り抜きは CSS がもう済ませている。** 額は縦横3:4で、絵は `object-fit: cover` で収まる
- 試作の道具（`crop_pipeline.py`）は本家に入れない方がよい。Python と OpenCV（5未満）が要り、実行中に顔検出のモデルをネットから取り、
  幅と高さを別々に切り詰めるので6枚中3枚が縦横比の崩れたまま書き出される
- **評価に使った8枚はすべて生成画像**（来歴データ入り）で、名前も作り物。どこにも出せない
- 本家に足りないのは、画像の置き場（`assets/` を配る一覧に入れる）と、許可とクレジットの欄だけ。どちらも「許可を記録できた本物の絵」が来てから足す

### 先に入れたもの

`npm test` に「配る画像と、データ・ページが指す画像が一対一で揃っている」を足した（いまは0枚・0参照で合格）。
試しに置いた画像や生成画像が、どこからも指されないまま配られるのを止める。
逆に、データに画像を書いても `assets/` が配る一覧に無ければ落ちる。
わざと壊して、両方向とも落ちることを確かめた。

### 決まっていないこと（J-02）

誰の絵を、どこからの許可で載せるか。その許可に「顔の周りだけを見せる切り抜き」を含められるか。
推奨は、許可（誰が・いつ・どうやって・どんな条件で）を記録できた絵から1枚ずつ手で置き、J-02 は「道具は使わない」で閉じること。
13人の規模なら手作業で足りる。

## 検証道具の置き場

配信ヘッダーを付けて配る道具と、見えない Chrome を動かす道具は、試作フォルダ（`20261104_動き最大活用モック/` など）と同じ場所の `20261107_検証道具_CSP配信とCDP/` へ写した。
消える作業場所にしか無かったため。本家には入れていない。
