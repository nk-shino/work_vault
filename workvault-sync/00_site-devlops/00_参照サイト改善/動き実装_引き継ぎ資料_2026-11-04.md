## デザイン意図と視覚仕様（site-design）

この節は、追加層方式（`css/motion.css`・`js/motion.js` の2本＋フック属性）を実サイトへ適用するときに、デザイン判断を再現・保護するための基準である。実測の根拠は `20261104_動き実データサンプル/` の実物（コミット077fe01）と `設計判断の記録_20261026.md`（§2 方向A）に置く。動きの語彙の出典調査の正本は保管庫 `00_site-devlops/00_参照サイト改善/モーション参照リンク一覧_2026-11-04.md`。

### 1. トーンの判断軸

- 基準線は「静かな資料館」：文字主体・明朝セリフ（line-height 1.85）・額縁（二重罫 `.frame`）・題箋（`.card .plate`・3:4）で構成する。罫線は区切りでなく絵を飾る枠、という style.css 冒頭の定義を変えない
- 動きは内容の補助で、主役にしない。index の lead に「ヒーロー演出は割愛」と記録済みのとおり、ヒーロー級の演出を持ち込まない
- 出現は「一度きり・据わり」に限定する。常時運転（ループ・常駐のスクロール連動・パララックス）は現行トーンでは採用しない
- 静止状態（読み込み完了後・アニメーション終了後）の色・額縁・題箋・3:4枠の見た目を、既存 style.css と1ピクセルも変えない

### 2. 採用済み4+1パターンの意図と適用箇所

採用理由の共通項：①既存 DOM に載る（属性を足すだけで新構造を作らない）②一度発火したら終わる ③hover は既存の色変え応答の延長で種類を増やさない ④追加層として剥がせる。読み込み幕は使わない（前ラウンドで明示的に外した）。

| # | パターン | フック | 適用箇所 | 起点と方向 |
|---|---|---|---|---|
| ① | 1文字リビール | `data-motion="chars"` | index の h1「回廊の記録」・chara-a の h1 | 初視認時（IO threshold 0.2）。1文字ずつ下から 0.6em 立ち上がり＋フェード。1頁1箇所（h1 限定） |
| ② | セクション出現 | `data-motion="reveal"` | index「入り口」セクション・chara-a の絞り込み＋注記セクション（計3箇所） | 画面下20%の線で一度だけ（観察後 unobserve）。フェード＋24px 上昇 |
| ③ | stagger | `data-motion="stagger"`（`#grid`） | chara の13カード（初回描画のみ） | fetch 描画後に1枚ずつ 16px 立ち上がり。チップ絞り込みの再描画は即時表示 |
| ④ | 控えめhover | 属性不要（motion.css のセレクタで効く） | 全9ページの nav とカード類 | nav は下線スイープ（左から 1px・`aria-current` は対象外）。カードは枠一段濃く＋背景うっすら色づけ |
| ⑤ | 行マスク | `data-motion="lines"` | chara-a のリード文1箇所のみ | GSAP SplitText（mask: lines）。yPercent 100→0・power3.out。未読時は単純フェードへフォールバック |

- 出現の方向は「下から上」に統一する。左右・ズーム・回転は使わない
- stagger が chara のみで index に無い理由：13件の名簿の並びそのものが内容のため、一覧の成り立ちを1度だけ示せば足りる。絞り込みのたびに再生すると操作感を壊すため、初回限定が仕様
- ⑤だけが外部ライブラリ依存。フォールバック込みで頁が完結する（§6 参照）

### 3. イージングと距離感の基準（定量）

値はすべて motion.css の `--m-*` 変数で実在する。変更する場合はこの節の意図（控えめさの上限）を超えないこと。

| 項目 | 基準値 | 意図 |
|---|---|---|
| 移動量 | 文字 0.6em／stagger 16px／IO出現 24px | 読みの始点をずらさない。変化は不透明度が主、移動は従 |
| 時間 | 文字・カード 600ms／フェード 700ms／IO移動 900ms | 単発でゆっくり。hover は既存 `--dur-base`（240ms）を使い速度感を分ける |
| 単位遅延 | 文字 60ms／カード 70ms | 13枚で最終カード開始が 840ms・全体収束を約1.5秒以内に置く |
| 発火位置 | IO `rootMargin: 0px 0px -20% 0px`（画面下20%の線）・chars は threshold 0.2 | 視界に入ってから発火。巻き戻しで再発火しない |
| イージング | フェード系 `--m-ease-o: cubic-bezier(0.33,1,0.68,1)`（ease-out-cubic 相当）・移動系 `--m-ease-t: cubic-bezier(0.22,1,0.36,1)`（ease-out-quint 相当）・hover は既存 `--ease`（0.2,0.6,0.2,1）を再利用 | 不透明度と移動で別曲線。既存 `--ease` の上書きはしない |
| hover の色づけ | `--m-tint`：ライト rgba(124,29,36,0.045)（深紅 #7c1d24 基準）／ダーク rgba(201,161,39,0.05)（金 #c9a13b 基準） | 各テーマの `--accent` 値から導いた rgba を直書き。`--accent` 変更時は同期が必要 |
| hover の枠 | `border-color: var(--rule-strong)` の一段のみ | scale・影・持ち上げは追加しない（額縁の構えを保つ） |

### 4. フックの命名規約と「剥がせる」構造の守り方

- HTML 側は `data-motion` 属性のみ。値は空白区切りのトークン（`chars`／`reveal`／`stagger`／`lines`）で、CSS は `[data-motion~="..."]` で照合する。既存のクラス名・id には触れない
- JS が付与するもの（HTML に書かない）：`<html>` へ `.js-armed`、要素へ `.m-chars-on`／`.m-on`／`.m-lines-armed`／`.m-lines-fallback`、文字 span へ `.m-char`＋`aria-hidden`＋`--index`、stagger コンテナへ `.m-stagger`＋`data-motion-state`（`first` → 再生完了後 `done`）
- 隠し状態（`opacity: 0` 等）は例外なく `.js-armed` 配下に置く。`.js-armed` は motion.js が reduced-motion でないときに付ける唯一のグローバル合図で、JS が動かなければ何も隠れない（noscript 安全）
- 出現は animation（backwards fill）で付け、transition は hover のみに使う。既存・将来の transition 設定との競合を避けるための分離
- 変数は `--m-*` 接頭辞で既存トークンと分離。時間の語彙は既存 `--dur-base`・`--ease` を再利用する
- 読み込み順：既存頁用 js →（chara-a のみ GSAP 2タグ）→ motion.js 最後。バニラ JS・即時実行・fetch なし・モジュールなし
- 剥がし手順：`<link rel="stylesheet" href="css/motion.css">` 1行・`<script src="js/motion.js">` 1行・`data-motion` 属性を外せば元に戻る。`css/style.css`・既存 js 6本・data 11本の無変更がこの前提。もし既存側を編集しないと実装できない変更が見えたら、それは追加層の失敗なので実装せず、設計判断の記録に新しい判断として上げる

### 6. 実装時の注意

- 文言は後で整える前提。h1・lead・フッター注記はモック用の仮置き。motion 層は文言非依存（`setupChars` が実文を `aria-label` に退避するため、差し替えても JS/CSS は無変更でよい）。空白は text node のまま残す実装のため、語間も崩れない。ただしフッターの外部リクエスト表記は、実際の読み込み構成と一致させる
- 意図を壊す改変（flatten）の禁止例：
  - `.js-armed` の外へ隠し状態を出す（JS 無効環境で空白が出る）
  - 出現を transition へ置き換える（既存 transition と競合する）
  - 対象の横展開（全見出し・全セクションへ chars/reveal を足す）。適用範囲は §2 の対応表どおり
  - stagger の再発火（絞り込みのたびに再生）
  - hover への scale・影・持ち上げ追加
  - 読み込み幕の持ち込み
  - `style.css`・既存 js・data への改変
- GSAP CDN（chara-a・jsdelivr 2タグ）は現行方針（CDN 不使用・T-04 外部通信 0）への既知の例外。本番適用時に ①2ファイルの自己ホストへ切替 ②例外を承認区分つきで記録、のどちらかを確定させる。フォールバック設計のためタグを外しても行マスクが単純フェードに落ちるだけで頁は完結する
- hover 層はセレクタで効くため、`header.masthead nav a` と `.card` が存在する本番の全ページに及ぶ。頁集合に乗せる前にこの点を確認する。stagger は `#grid`＋`.card`（li）構成の頁に限る
- アクセシビリティの下限：既存 `focus-visible` の outline は変更しない。hover の識別は色のみに頼らない（枠の濃さ＋背景の併用）。文字 span は `aria-hidden`＋親に `aria-label` で SR は原文を読む。reduced-motion は二重安全（style.css の全般停止块＋motion.js が発火前で停止）。キーボード操作経路に触れない
- テスト基準値への影響：T-05 の件数基準（chara 13 等）は DOM 件数を変えないため不変。T-03（console 0）は3ページで検証済み。T-04 は chara-a の CDN で不合格になる（上記の決定事項）。T-08 は `--m-tint` の明暗切替を含めて確認。T-10（JS 無効）は構造上合格するが一度実機確認。加えて reduced-motion エミュレーションと絞り込み共存（2026-11-04 検証済み手順）を smoke に含め、変更後は T-12 一式を再実行する
- file:// では既存 js の fetch がブロックされる（既存挙動・追加層と無関係）。13カード stagger の目視確認は HTTP 経由で行う

## セキュリティと安全の確認項目（site-security）

検査日: 2026-11-04。方法: 両フォルダのHTML・CSS・JS・data JSONの静的点検（実読とgrepによる全量照合）。動作の実測は本点検では行わず、既存の検証記録（`20261104_動き実データサンプル\実行ログ_20261104.md`）を引用した。事実は「事実:」、評価は「評価:」として区別する。確認できなかった事項は末尾の残余リスクに記す。

### 1. 外部CDN依存（重大度: 高 — 本番適用の前提条件）

- 事実: 本番候補でCDNを読むのは `chara-a.html` のみ（chara-a.html:59-60、`cdn.jsdelivr.net` の gsap.min.js と SplitText.min.js の2タグ）。残り8ページは外部リクエスト0。
- 事実: この2タグに integrity 属性・crossorigin 属性はない（全HTML・CSSをgrepしSRI関連の記述0件）。バージョン指定はメジャーのみ（`gsap@3`）で、マイナー・パッチの解決は jsdelivr 側に委ねられている。CSP（meta・_headers相当）の記述も両フォルダに存在しない。
- 評価: このページを開いた訪問者のブラウザは jsdelivr へ直接リクエストを送る。訪問者のIPアドレス・User-Agent・Refererは、サイト管理者ではなくjsdelivr側のログに残る。サイト全体が通信0でも、この1ページだけで訪問者と第三者との通信が発生する。
- 評価: SRI未使用のままのCDN参照は、サイト側に改ざん検知の手段がない状態を意味する。メジャー指定は、サイト側の変更なしに配信内容が更新されうることも意味する。CDNを継続するなら integrity（sha384）＋`crossorigin="anonymous"`＋パッチまでの固定が最低条件。ただしSRIは不一致時に読み込みを遮断する仕組みであり、ページが動き続ける保証にはならない。
- 事実: CDN不通時のフォールバックは追加層に実装済み。`window.gsap && window.SplitText` の存在を確認し（motion.js:116）、try-catchで例外も吸収して行マスクを単純フェードに置換する（motion.js:115-124、135-138）。2スクリプトの片方だけ失敗しても、両者の存在を見てから分岐するためガードは成立する。
- 注意: このフォールバックはコード確認まで。CDN遮断状態でのブラウザ実測は未実施（既存の検証記録は通信可能な状態のもの）。下記チェックリスト4を本番判断の前に実施すること。

### 2. 動的描画の注入耐性

- 事実: 描画を行う既存js6本（chara.js・chara-a.js・chara-b.js・chara-c.js・works.js・catalog.js）は、json由来の文字列を esc()/text()（`& < > "` を実体参照へ置換、chara.js:9-10）に通してから innerHTML に渡す。属性値へのデータ埋め込み箇所は現状ない（テンプレートは要素内容のみ）。
- 情報（低）: esc() はシングルクォートを置換しない。現行の埋め込み箇所では影響が出ないが、将来 single-quoted 属性へデータを流す場合は規約の拡張が必要。
- 事実: 追加層 motion.js に innerHTML 系APIの使用はない（grep 0件）。1文字span化は textContent の読み取り→createElement/createTextNode/textContent での再構築（motion.js:36-58）で、元テキストにHTMLらしき文字列が混ざってもテキストノードとして扱われる。元文は親要素の aria-label へ退避し、span側は `aria-hidden="true"` のため読み上げが1文字ごとに分断されない。
- 事実: motion.js の他の処理はクラス付与・`style.setProperty`・dataset操作のみ。最大活用モック scenes.js:119 の `innerHTML: [0, end]` はanime.jsの数値カウントアップ構文で、`end` は `data-count` 属性を `Number(...) || 0` で数値化した値（scenes.js:116）。文字列が経路に入らず、注入箇所には該当しない（実読確認）。
- 事実: fetch はすべて相対パスの同梱json（chara.js:35、chara-a.js:36、chara-c.js:69-72、works.js:24、catalog.js:50）。外部APIへの問い合わせと、応答を直接信頼する経路は存在しない。
