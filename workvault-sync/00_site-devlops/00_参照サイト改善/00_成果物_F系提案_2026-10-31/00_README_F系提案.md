## 一手目は `setup.ps1` の処分

**提案の中身より先に、これを片付けること。**

リポジトリ直下の `setup.ps1`（4,032バイト・git 追跡下）は、`Set-Content` 18行で
主要ファイルを**確認なしに**骨組みへ戻す。走ると `css/style.css` が 3,355行から十数行に、
`data/glossary.json` が `[]` になる。**追跡下でも全部は戻せない**（未コミットの差分が消える）。

同じ種類の危険がもう1つある。**`tools/assign-source-ids.js` と `tools/link-sources.js` が git に入っていない。**
`npm run check` の2本目と3本目がこの2本で、1回の `git clean -fd` で検査が動かなくなる。

詳細と着手順は 00 の §4。

## 作り方と、信頼してよい範囲

起草 → **一次情報での引用照合** → **横断検証（矛盾・既決との衝突・実行可能性）** → 改訂 → 保存。
照合と検証は起草とは別の担当が行い、**リポジトリの実物を読んでいる。**

### 検証で実際に出たもの

初版は**5本とも「このままでは出せない」判定**だった。理由は提案の筋ではなく、
**実物を読まずに書いた前提**にほぼ集中していた。出た指摘のうち重い例:

- 「第32条は翻訳までしか認めていない」の根拠に**第32条を挙げていた。** 根拠は第47条の6第1項第2号で、本文に一度も出てこなかった
- 「ウェブアーカイブの複製を認める条文は第43条**一本だけ**」が誤り。第47条の5第2項がある。しかも**同じ資料の出典表に自分でその条文を挙げていた**
- 02 に**出典表が1つも無かった**（条文を20件以上引いているのにURLが1件もない）
- 03 の3行手順を実行すると **`npm run check` が赤くなる**（検証者が隔離コピーで再現した）
- 01 が足そうとしていた列は、既存の2欄から**100%導出できた**。しかも `js/sources.js` が既に同じ3分岐を描いていて理由までコメントにある
- 「機械が気づかない」に対し、`tools/verify-links.js` が**既に24項の題と投稿者を照合していた**
- **5本とも `setup.ps1` に一度も触れていなかった**
- 「起因タグ」が**1語で4つの別物**を指していた

**178件を直し、65件は理由つきで直していない。**

### 一次情報で裏が取れたもの

照合で**123件が原文どおり**と確認された。施行規則の数値4本、相談ダイヤルの番号と受付時間、
総務省の指定一覧（事業者名の欄が「個人」の行まで）、EDPBガイドラインの版歴、
Cloudflare のプライバシーポリシーの発効日など。**捏造は出ていない。**

条番号の移動も確認してある。現行施行版と2026-11-02施行版を比べ、引用した条番号はどれも動いていない。
令和8年改正が全部施行される段階では一部が変わるので、公開後に当たり直すこと（04 §7）。

### 残っている弱点

- **確定版そのものへの独立検証は行っていない。** 直した結果が正しいかは確かめていない
- `npm run verify` は外部へ接続するため走らせていない（共通規約 §2 の明示承認対象）
- 取得できなかった一次情報がある。GDPR 本文（EUR-Lex が応答しない）、
  最判平成9年9月9日の原文（同判決を引用する最判平成16年7月15日から写した）、
  令和8年改正の解説ページ、各種の政令・総務省令。**各資料の「未確認」の節に全部挙げてある**
- **これは法的助言ではない。** 専門家に相談するときの材料と、相談前でも安全側に倒せる運用案である
