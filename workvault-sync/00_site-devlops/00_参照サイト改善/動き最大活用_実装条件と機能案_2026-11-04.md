## 2 実装条件（最大限活用するために満たすべき条件）

### 2.1 共通の固定条件

- JS無効で全内容を表示する。隠し状態は `.js-armed` 配下のみに置く（JSが動かなければ何も隠れない）。
- prefers-reduced-motion で全停止する。style.css 側の全般停止と JS 側の発火前停止の二重構えを維持する。
- 参照パターンはコード非転載の自作再現に限る。ICS MEDIA 等 All Rights Reserved の源からの転載を行わない。
- 1文字span化は `aria-hidden`＋親要素への元文 `aria-label` 退避の契約を守る。SR は原文を読む。
- 一覧・年表・数字は実データの静的埋め込みにする（noscript・file:// でも内容が見える。fetch に依存しない）。

### 2.2 ライセンス条件

- GSAP: 3.13.0 以降は全プラグイン無償（Standard 'no charge' license）。バージョンはパッチ番号まで固定する（`@3` のメジャー指定は使わない）。
- anime.js: v3.2.2（MIT）固定。現行 v4 は破壊的変更があるため、移行する場合は別途判断する。
- easings.net: 曲線の cubic-bezier 値（事実値）のみ採用する。サイトのコード流用は GPL-3.0 が及ぶため行わない。
- Aceternity UI・Magic UI: 無料分の利用条件は明記がない。React コンポーネントのコードは使わず、パターンの自作再現に限る。
- LottieFiles: ライセンスが2層。復活時は無料公開アニメ（Simple License・商用可）に限るか、Team 以上の契約を前提にする（Free/Individual プランの制作物は商用禁止）。

### 2.3 通信とCDNの条件

- 本番リポジトリの現行方針は CDN 不使用・外部通信0（T-04）。最大活用の構成を採る場合、GSAP 2ファイル（gsap.min.js・SplitText.min.js）と anime.js 1ファイルの自己ホスト化が必須条件になる。
- 自己ホスト時は各ファイル先頭のライセンス・著作権ヘッダを削除しない。バージョン固定と更新手順は引き継ぎ資料 §4（site-techwatch）を参照。
- 本番で CSP を設定する段階では、CDN 継続は `script-src` への許可追加を生む。自己ホストならこの追加が不要になる。

### 2.4 縮退の条件（実測で確認済みの型）

- CDN不達: 隠し処理を行わず静的表示に落ちる（scenes.js の prep 先頭ガード・curtainReveal の !HAS_GSAP 分岐）。合格基準は pageerror 0件と本文可視の実測。幕を運転する処理は gsap 参照の前にガードを置く。
- View Transitions 非対応: 筆ワイプ幕へフォールバック（CSSViewTransitionRule 検出）。Safari 18.2+ を拾う検出条件の見直しは採用時に行う。
- scroll-driven 非対応: `@supports` 括りの外は静的表示。`animation-timeline` は `animation` 短縮形の後ろに書く書き順を守る。
- カーソル: `pointer: fine` のみ。JSが動くまで通常カーソル。reduced-motion で停止。
- VT の座標受け渡し: cross-document では遷移元の CSS 変数が遷移先へ伝わらないため sessionStorage で受け渡す（4秒有効・到着側で消費）。

### 2.5 検証条件

- 引き継ぎ資料 §5（site-review）の受け入れ条件に加え、縮退テスト（CDN遮断・route abort で4タグ遮断 → pageerror 0件・幕残存なし）を smoke に含める。
- 出発側の遷移幕は中間状態の実測で確認する（200ms〜400ms時点の visibility と layer の transform）。完了後の状態測定だけでは視認の証拠にならない。

### 2.6 トーンの条件

- 静かな資料館のトーンを基準にする。常時運転は scroll-driven の控えめな動きと spring カーソル（pointer:fine の補助）まで。
- 読み込み幕と pin＋scrub は上限確認の位置づけ。本番採用は別途判断する（採用の判断と公開の承認は分離）。
- 出現は一度きり。左右・ズーム・回転の出現は使わない（モック内の不採用記録と同じ基準）。

## 3 機能案の提案

### 3.1 今回実装・実測合格した2件

- **spring カーソル**（未検討ギャップ → 対応表#13）: React Spring の物理イージングの概念を vanilla の rAF spring 積分（K=170・DAMP=22・ζ≈0.84 の微小アンダーダンプ）で再現した。加速と減速の手応えが lerp と異なることを16サンプルの実測で確認。依存追加なし。
- **VT Circle リビール**（対応表#14）: クリック地点中心の clip-path circle で新画面が広がる。遷移中の `vt-circle-in` 運転を `document.getAnimations()` で捕捉し、c001 共有要素遷移との並走を確認。座標は sessionStorage ブリッジで受け渡す。

### 3.2 本番採用の候補（優先度順・前提条件つき）

1. **本番候補の4+1パターン**（1文字リビール／IO出現／stagger／控えめhover＋行マスク）— 第一候補。GSAP CDN の扱い（自己ホスト化 or 対象外）の決定が前提。
2. **spring カーソル** — `pointer: fine` 限定で本番候補の motion.js に追加する形。トーンとの相性を実機で確認してから判断する。
3. **VT 系（共有要素遷移・Circle リビール）** — 本番の画面構成に遷移対象となる要素の組が生まれたときに再検討する。
4. **横型タイムライン・動画ヒーロー等** — 対応する素材と画面構成の前提が揃ったときの再検討。

### 3.3 不採用13件の復活条件

出典対応表の不採用リストに対応する復活条件は次のとおり。

- 燃焼遷移: canvas マスクのコストを許容できる特設ページが生まれたとき。
- 横型タイムライン: 年表が一覧性を求める規模になったとき。
- stagger random: 秩序より賑やかさを求める場面が生まれたとき。
- typewriter: 読みの速度を演出したい特別な箇所ができたとき。
- scale 入口系・スクロール単語リビール: 出現語彙の統一を意図的に崩す判断をしたとき。
- Anime.js v3 timeline API: anime.js だけで完結する演出群を作るとき。
- WebGL・3D・動画ヒーロー・絵本型めくり・Linear 型・VT Pagination: 対応する素材・画面構成・機能が生まれたとき。
- Lottie: 無料公開アニメの活用か Team 以上の契約が現実になったとき（§2.2 のライセンス条件）。
- TANE-be: 実装要素ではなく実装依頼のプロンプト形式として利用する。
