# 変更履歴ノート：情報更新と改修の記録

情報整理シート（`01_開発者向け情報整理シート.md`）とセットで使う。**情報の更新**と
**コード・文書の改修**を同じ形式で区別して記録する。提案・承認・実施・検証を混同しない。
失敗や部分反映も記録する。

## 再利用の検討

既存の履歴系ノート（実行ログ・decision-log・changelog）は**ラウンド単位の作業記録**であり、
「対象・根拠・影響先・承認・反映・検証」を1件ごとに追える粒度ではない。このため §8 の指示に従い
別途このノートを作った。実行ログの役割（指示1件＝エントリ1件）は変わらない。

## 記録のルール

- 変更ID は CH-xxx（文書内の管理ID。アプリ・データの ID ではない）
- 変更前後は「何が変わったか」が分かる粒度で書く。「修正した」「改善した」で終わらせない
- 過去履歴の訂正は、誤記を無言で消さず訂正記録として追記し元記録を関連付ける
- git の差分が参照できる場合のみハッシュ等を書く。実行していない commit・存在しないハッシュを書かない
- このノート自体も同期ドライブ上にある。2台で同時に開かない（05ノート下部の注意と同じ）

## 変更記録テンプレート

```
### CH-xxx

- 変更ID：
- 記録日時：
- 変更実施日時：
- 種別：情報追加／訂正／別称追加／改名／統合提案／分割提案／撤回／文書更新／コード改修／検証のみ
- 関連する対象ID・確認ID：
- 対象ページ・ファイル：
- 変更理由：
- 根拠・関連判断：
- 変更前：
- 変更後：
- 影響先：
- 承認状態：
- 反映状態：
- 実施した検証：
- 結果：PASS／FAIL／未実行
- 未反映・未検証の範囲：
- 戻し方・訂正方法：
- 残る注意事項：
- 次の対応：
```
