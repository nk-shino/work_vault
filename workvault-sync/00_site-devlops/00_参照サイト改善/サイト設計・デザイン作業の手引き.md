# サイト設計・デザイン作業の手引き

**リポジトリを開けない場所から、設計・要件定義・デザイン改善を進めるための資料。**
この1枚で完結するように書いてある（他のノートを開かないと分からない、という形にしない）。

数値はすべて 2026-10-16 時点の実測。推測で書いた箇所には「未確認」と付けてある。

## 0. この資料でできること／できないこと

| やりたいこと | この資料だけで | 理由 |
|---|---|---|
| **設計の要件定義** | **できる** | 決まっていること・開いている論点を §5〜6 に全部書いた |
| **デザイン改善の検討・比較** | **できる** | 原則・トークン・実装の現在地が §4〜5 にある |
| **情報設計の見直し** | **できる** | ページとデータの対応が §2 にある |
| **デバッグ** | **できない** | 再現にコードと実行環境が要る。症状の切り分けと仮説立てまでが限界 |
| **CSS/JSの具体的な書き換え** | **半分** | 方針と差分案は作れる。**当てて確かめるのは手元でやる** |

**できないことを「できた」として扱わないこと。**
画面を見ていない状態で「崩れが直った」「コントラストが足りている」とは書けない。

## 1. サイトの概要

ある音楽プロジェクトを扱う**非公式の資料サイト**。公開はしていない（private）。

- **読者**は、作品を追っていて「設定や年表を確かめたい」人
- **最優先は記録性。** 何がどこに書いてあるか、その出典は何かを追えること
- 演出が可読性や出典表示を邪魔するなら、**演出を捨てる**

この順で優先する。

1. 情報の正確さ、不確かさの明示、出典をたどれること
2. 権利・プライバシー
3. 保守性
4. 作業効率
5. 見た目

### 画像 ── **1枚も無い状態で動いている**

ここを知らないと、デザインの前提を取り違える。

| 対象 | 実測 |
|---|---|
| 人物の立ち絵 | `characters.json` に `image` キーはあるが、**13人全員が空。** 全員「イラスト準備中」が出ている |
| 作品のジャケット | **`works.json` に画像のフィールドがそもそも無い** |
| サイト内の画像ファイル | **0枚**（別アプリ側に雛形のSVGが5枚あるだけ） |
| 「準備中です」を出しているページ | 4ページ（二次創作・グッズ・切り抜き・人物の一部カテゴリ） |

**描画側のコードはもう用意してある。** `image` に値が入れば、一覧も詳細も画像を出す作りになっている。
空のときだけ差し替え表示に落ちる。**つまり足りないのは絵であって、実装ではない。**

**なぜ空のままか。** 素材方針で縛っているため。

- **生成画像で代用しない。** 公式ビジュアルと誤認される恐れがある
- **ファンアートは作者の許諾を得て、クレジット付きで**載せる
- 非公式である以上、**公式と誤認させる表記やロゴを使わない**
- 外部サービスの埋め込みは訪問者のIPが相手に渡る。動画は Cookie を置かない配信元を使う

**デザイン上の意味。** 一覧は本来「肖像画が並ぶ回廊」として設計されているのに、
いまは**文字と罫線と余白だけで成立させている。**
絵が入る前提の案を出すと、当分のあいだ使えない。
**いまの見た目を良くする案と、絵が入ったときの案は、分けて出すこと。**

## 3. 変えてはいけない制約

**ここに反する案は、どれだけ良くても採用できない。**

| # | 制約 | 理由 |
|---|---|---|
| 1 | **公開されるのは素の静的ファイルだけ** | サーバー処理を使わない。TypeScript は開発時のみで、変換後の `.js` を置く |
| 2 | **外部リクエストはゼロ** | ライブラリをCDNから読まない。**訪問者のIPを第三者に渡さないため。** この一点は動かさない |
| 3 | **色の16進数を直接書かない** | 必ずCSS変数を使う。直書きするとダークモードで破綻する |
| 4 | `@media (max-width: 768px)` ブロックの**閉じ忘れを確認してから追記** | 過去に表示崩れを起こしている |
| 5 | **`js/home.js` を直接編集しない** | 生成物。`src/home.ts` を直す |

## 4. デザインの決まりごと

### 雰囲気 ── どういう「場所」のつもりか

**古い書庫に置かれた、一冊の記録。** これが全体の見立て。

扱っている題材がダークファンタジー寄りで、**血・異端・封印**といった語がついて回る。
一方でこのサイト自体は**資料**なので、物語の激しさをそのまま見た目に出すと読めなくなる。
**静けさで受ける**という方針で折り合いをつけている。

| | 何に見立てているか |
|---|---|
| ライトテーマ | **深紅。** 血、異端、封印 |
| ダークテーマ | **金。** 燭台の灯、箔押し |
| 罫線・枠 | 額縁。絵を飾る枠であって、区切りの線ではない |
| 背景の粒子 | 紙の繊維。ツヤではなく、かすれ |
| 動き | 灯りが揺れる程度。跳ねない、弾まない |

**色は多用すると安くなる。** 赤も金も、効かせどころを絞る。

### 原則（この5つに反するものは採用しない）

1. **静けさが最上位** — 動きは「灯りが揺れる」程度。跳ねる・弾む動きは使わない
2. **余白は書庫の空気** — 詰めない。行間1.8、セクション間64px以上
3. **赤は血、金は灯り** — ライトは深紅、ダークは金。多用すると安くなる
4. **紙と箔の質感** — ツヤ・ネオン・グラデーションは使わない。使うのは「かすれ」「粒子」「箔の反射」
5. **記録性が最優先** — 演出が可読性・出典表示を邪魔したら、演出を捨てる

### 使う／使わない

| 使う ○ | 使わない × |
|---|---|
| Grain / Noise（紙の粒子） | Glassmorphism（すりガラス） |
| 額縁・罫線 | Bento Grid（タイル） |
| Spotlight Glow（燭台の灯） | ネオングロー |
| Vignette（四隅の落ち） | 3D Tilt（傾くカード） |
| 文字の遅延出現 | 無限スクロール |

### デザイントークン

`:root` に約40個。主なもの。

```
色      --bg --text --text-sub --accent --foil --blue --blood
罫線    --rule --rule-strong --rule-solid        ← 新しい体系
        --border-accent                          ← 古い体系（§7 参照）
余白    --space-1 〜 --space-4
動き    --dur-fast --dur-base --dur-slow --ease
質感    --noise-fine --noise-coarse --noise-hero --grain --glow
面      --bg-raise --bg-sink
```

## 6. 開いている論点（要件定義の対象）

### 6-1. キャラクター別ストーリーボード（未設計・起票済み）

**要件:** 人物ごとに、関わった作品を**左から右へ時系列で並べて追えるようにする。**

縦のリストでも順番は出せるが、**横に流すと「進んでいる」という形そのものが順番を説明する。**
矢印や番号を足さなくても左が先だと分かる、という狙い。

**追加のデータ入力は要らない。** 既存の `works.json` と `characters.json` で組める。

| 必要なもの | どこにあるか |
|---|---|
| 誰が出ているか | `works.json` の `characters` |
| 時系列 | `works.json` の `released`（**13件すべて埋まっている**） |
| 作中の序列 | `works.json` の `order` / `orderLabel` |
| 並べる単位 | `characters.json` 13件 |

**決めること。**

| # | 論点 | 補足 |
|---|---|---|
| 1 | **並べる軸。** 発表日か、作中の序列か | **この2つは一致しない可能性がある。** 推奨は発表日を既定にして切り替え可能にすること。「いつ出たか」は事実、「作中の何番目か」は解釈 |
| 2 | 1コマに何を出すか | 画像＋題だけか、キャッチコピーまで載せるか |
| 3 | 置き場所 | 専用ページか、人物詳細の中に埋めるか |
| 4 | 未発表作を置くか、省くか | |

**実装の注意。** 横スクロールはスマホで嫌われやすい。画面幅に収まらない横並びは、
縦スクロール中に指が引っかかって誤爆する。**スクロールスナップでコマ単位に止める。**
**矢印キーだけでも読めるようにする。**

### 6-2. 空のデータを持つ3ページの扱い

`events` `tools-fanart` `tools-kirinuki` は**いま0件を描いている。**

決めること。「まだ無い」のか「募集中」なのか「準備中」なのかで、見せ方が変わる。
**0件のまま公開するなら、空状態は本番のデザインであって例外ではない。**

### 6-3. 絵が無いあいだの見せ方

**13人全員が「イラスト準備中」で並んでいる。** これが当分続く前提で決めること。

| # | 論点 | 補足 |
|---|---|---|
| 1 | 差し替え表示を**どう見せるか** | いまは文字で「イラスト準備中」。枠だけ残す／紋様を置く／そもそも枠を出さない、で印象が変わる |
| 2 | **絵が無い前提で一覧を組み直すか** | 肖像画が並ぶ想定の配置を、文字主体の配置へ寄せるか。絵が入ったとき戻せる形にしておけるか |
| 3 | 絵の**縦横比を先に決めるか** | 決めておけば、後から入れても並びが崩れない。決めないと入った日に全部ずれる |
| 4 | 作品側に画像の**フィールドを足すか** | `works.json` にはキー自体が無い。足すなら人物側と同じ扱いにそろえる |

**2 が本体。** いまの見た目を良くする案と、絵が入ったときの案は**別物として出す。**
片方だけ出すと、もう片方で破綻する。

### 6-4. 目録棚のIDが題を鍵にしている

`catalog.json` の採番は「種別＋題」を鍵に引き継ぐ作りで、**題を1文字直すとIDが振り直される。**
IDは資料に固定する決まりなので、題の修正が採番を壊す。

いまは `node tools/make-catalog.js --check`（`npm run check`）が
「消えたID」を見つけて止めるようにしてあるが、**作り自体は直っていない。**

## 8. 持ち出さないもの

**この資料に書いていないものは、書いていない理由がある。**

| 対象 | 理由 |
|---|---|
| ある返礼品の書籍の本文・読み取り結果 | **転載・公衆送信・第三者への譲渡が禁止**されている。ページ番号と事実の記録は別の非公開ノートにあり、そちらも外へ出さない |
| 非公開のコミュニティから取った未公開情報 | 出典を読者がたどれないものは、サイトにも資料にも断定で書かない |
| アカウント名・リモートURL・資格情報 | 設計の検討に要らない |

**固有名詞を伏せること自体が目的ではない。** 権利と出典の都合で出せないものを出さない、というだけ。

## 9. 依頼文のひな形

この資料を渡したうえで、次のどれかを添える。

### 要件定義

```
添付の手引きを読んで、§6-1「キャラクター別ストーリーボード」の要件定義をしてください。

決めるべき論点が4つ挙がっています。それぞれについて、
- 選択肢を2〜3案
- 各案の利点・欠点・実装の重さ
- このサイトへの推奨（一般論としての最良ではなく）
を出してください。

制約は §3 です。反する案は出さないでください。
既存データで組める前提なので、データの追加入力が要る案は、その旨を明記してください。
受け入れ条件（何ができたら完成か）も書いてください。
```

§6-2（空データのページ）、§6-3（絵が無いあいだの見せ方）も同じ形で頼める。
**§6-3 を頼むときは「いまの見た目の案」と「絵が入ったときの案」を分けて出すよう指定すること。**
混ぜると、どちらでも中途半端なものが返ってくる。

### デザイン改善

```
添付の手引きを読んで、<ページ名> の改善案を出してください。

**§5「実装の現在地」を必ず先に読んでください。** 設計仕様のチェックボックスは
更新されておらず、大半は実装済みです。できているものを再提案しないでください。

案は2〜3つ比較してください。
A. 現行を生かした最小修正  B. 発見・比較を重視  C. 根拠・確認状態を重視

各指摘は「観察した問題 → 利用者への影響 → 根拠 → 改善案 → 確認方法」の形で。
**画面を見ていないので、コード上の推定と実画面の観察を混ぜないでください。**
実測していない改善率や工数を事実として書かないでください。
```

### デバッグ（切り分けまで）

```
添付の手引きを読んで、次の症状の原因候補を挙げてください。

症状: <何が、どの画面で、どう見えるか>
再現条件: <ブラウザ / 画面幅 / ライトかダークか / 操作手順>

**コードを見ていない前提で、推測であることを明示してください。**
原因候補を可能性の高い順に並べ、それぞれについて
「手元でどう確かめるか」を1コマンドか1操作で書いてください。
確かめずに「これが原因です」と断定しないでください。
```

## 更新するとき
