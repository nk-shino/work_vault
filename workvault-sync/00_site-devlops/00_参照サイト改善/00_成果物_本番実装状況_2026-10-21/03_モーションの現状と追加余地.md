# モーションの現状と追加余地

**「何を足せるか」の前に「何が既に在るか」と「何が禁じられているか」。**
仕様書の実装ロードマップはチェックが実態と合っていないため、**このシートはコードを測った値で書いてある。**

固有名称は伏せてある。

**先に読むこと:** `01_実装状況_本番リポジトリ.md`

---

## A. 守る線（仕様の正本。提案の前にここを通す）

### A-1. 動きを速さで3層に分ける

| 層 | 速さ | 何に使うか |
|---|---|---|
| **気配** | 45〜75秒 | 入口の図形と灯りの明滅。振幅20px以内・回転4度以内。**無限ループが許されるのはここだけ** |
| **呼吸** | 720ms | 見出しやカードの出現。**10px上へ、不透明度0→1のみ** |
| **応答** | 160〜320ms | ホバー・フォーカス・押下。**浮きは2pxまで** |

**遅いものは動いてよく、速いものは動いてはいけない。** 1周に1分近くかけるので、
見ている間は動いていると気づかない。これが「静か」の定義になっている。

### A-2. 禁止事項

| 禁止 | 入口の主役部分だけ解除（2026-08-25） |
|---|---|
| `scale()` による拡大 | 解除 |
| 20pxを超える移動 | 解除 |
| 視差（パララックス） | 解除 |
| 擬似3Dの傾斜・回転 | 解除 |
| 無限ループ | 気配の層のみ |
| **バウンス系の跳ね返り** | **入口でも禁止のまま** |

**記録のページは静けさを保つ。** ここが緩むと、演出が可読性と出典表示を押しのけ始める。
バウンスだけは解除されていない。賑やかさの問題ではなく、世界観の問題として扱われている。

### A-3. あえて採用しないもの（理由つきで却下済み）

横スクロールの区画／無限に流れる帯／3D傾斜カード（入口以外）／
ガラス風の半透明／整列タイル／仮想スクロールのライブラリ。

**提案に含めると、理由ごと説明し直すことになる。** 先にこの一覧を見ること。

### A-4. 動きを減らす設定

**全ページで必須。** 入口も含む。例外は無い。

## B. いま動いているもの（実測）

### B-1. 繰り返し再生されるもの（9種）

| 動き | 速さ | 層 | 置き場所 |
|---|---|---|---|
| 紋章の線が描かれる | 900ms・1回 | 呼吸 | 入口の読み込み幕 |
| 題字が現れる | 700ms・950ms遅延・1回 | 呼吸 | 同上 |
| 行が下から現れる | 720ms・1回 | 呼吸 | 横断目録の各行 |
| 見出しが現れる | 720ms・0.2s遅延・1回 | 呼吸 | 入口の文字 |
| 年表の灯りのゆらぎ | 4.5秒・**無限** | 気配 | 年表の各点 |
| 灯りの明滅 | 9秒・**無限** | 気配 | 入口 |
| 図形の漂い（3種） | **46〜72秒**・無限 | 気配 | 入口の図形12個 |

**入口の図形12個は、1つずつ違う周期を持っている。** 揃えると群れが同時に動いて機械に見えるため。
**これは意図的な不揃いであって、整理されていない状態ではない。**

**年表の灯りは、記録のページで唯一の無限ループ。** コードに「燭台の灯りそのものなので例外扱い」と
理由が書いてある。**数が合わないからといって消さないこと。**

### B-2. 状態の変化に付く動き

`transition:` が**29箇所**。ホバーの色・枠、額縁の浮き、開閉、不透明度の切り替えなど。

### B-3. 画面の切り替え

`@view-transition` が全ページに入っている。**一覧の額と詳細の額が繋がる仕組み。**
一覧側のJSが、押された1枚にだけ目印を付ける。

> **同じ目印が同時に2つあると、遷移そのものが中止される。** ここは崩さないこと。

### B-4. JSが動かしているもの

| 場所 | 何をしているか |
|---|---|
| 年表 | 画面に入った項目に印を付ける（一度出たら戻さない）／スクロール位置に応じて縦線を伸ばす |
| 横断目録 | 行ごとに遅延を少しずつずらす（最大480ms） |
| 用語集 | 絞り込みの前後で容器を薄く消して戻す（0.15秒） |
| 入口 | 立体の層を1周64秒で回す |
| 共通 | 読み込み幕の開閉・テーマ切替の一括変化（400ms） |

### B-5. 動きを減らす設定への対応（実測）

| 層 | どう止めているか |
|---|---|
| 全体 | すべての要素の再生時間と遷移時間を強制的にほぼ0にする |
| 遅延 | **一括指定では遅延を打ち消せない。** 待ち時間のある4つを個別に0へ戻している |
| 画面の切り替え | 別途まとめて停止 |
| JS側 | 年表の縦線は最初から全長／入口の立体は停止 |

**遅延を個別に戻しているのが要点。** 戻さないと、動きを止めた人には
「1秒以上なにも出ない画面」になる。**止めると速くなるのではなく、止めると何も起きなくなる。**

> **ただし、個別に戻しているのは4つのセレクタだけで、取りこぼしがある。**
> **JSが要素に直接書き込んでいる遅延は、どれも0に戻っていない。**
> 横断目録の行（最大480ms）、人物一覧と作品一覧の出現（1件あたり50〜60msずつ）がこれにあたる。
>
> その行や札は、遅延のあいだ**不透明度0のまま置かれる**指定になっている。
> つまり**動きを減らす設定にしている人ほど、何も映らない時間が残る。**
> 動きを止めたいという申告に対して、**止まるのではなく、消えている時間だけが残る。**
>
> 直すときは、CSSの一括指定に遅延のゼロ化を足すだけでは届かない。
> **要素に直接書き込まれた値のほうが強い**ので、書き込む側（JS）で設定を見る必要がある。

## C. 使える資産 ── **これが実相**

### C-1. アニメーション用ライブラリ2本が、同梱済みで未使用

| ファイル | 大きさ | 読み込んでいる画面 |
|---|---|---|
| アニメーション本体 | 71 KB | **0枚** |
| スクロール連動の拡張 | 44 KB | **0枚** |
| 立体表示 | 671 KB | 入口の1枚のみ |

**合計115KBが、配信物に入ったまま一度も使われていない。** 全HTMLの読み込みタグ、
全JSの取り込み、動的な差し込みまで走査して0件だった。型定義の参照が1箇所残っているだけ。

**ここが提案にとって重要な事実。**

- **新しいライブラリを足す必要はほぼ無い。** スクロール連動も、時間軸の組み立ても、
  既に手元にある。承認が要るのは「使うかどうか」であって「入れるかどうか」ではない
- 逆に、**使わないと決めるなら115KBを外せる。** どちらかに倒す判断が要る
- 仕様書の表は「使っている」前提の記述になっている。**どちらに倒しても表の更新が要る**

### C-2. 既に在る装飾の部品

四隅の飾り／単角の印／尖塔の形／章扉の黒帯／箔のかすれた罫／擦れの質感／
散る小花／傾ける指定／読み上げ専用の隠し文字。

**いまはどれも静止している。** 動かすなら、新しく作るより先にここを見ること。

## D. 接続先の制限とモーションの関係（**最初に踏む落とし穴**）

2026-10-21 から、配信時に**接続先を同一オリジンに限定する宣言**が付いている。
**これはモーションの作り方を変える。** 動くかどうかが技法によって分かれる。

| 技法 | 使えるか | 補足 |
|---|---|---|
| CSSの繰り返し再生（`@keyframes`） | **使える** | 制限の対象外 |
| CSSの状態変化（`transition`） | **使える** | 同上 |
| **JSから要素の `style` を書く** | **使える** | **よく誤解される。** 見た目は同じでも、これは制限の対象外 |
| JSからCSS変数を書き換える | **使える** | 上と同じ扱い |
| ブラウザ標準のアニメーションAPI | **使える** | |
| **HTMLに `style="..."` を書く** | **使えない** | 止まる |
| **JSで `<style>` 要素を差し込む** | **使えない** | 止まる |
| 同梱したライブラリ | **使える** | C-1 の2本はここ |
| **外部配信のライブラリ** | **使えない** | そもそも元の決まりでも禁止 |
| **外部から取る動画・JSON形式のアニメ** | **使えない** | 同上 |
| 画面の切り替え | **使える** | |

**「JSから `style` を書くのは使えるが、HTMLに `style=` を書くのは使えない」が肝。**
見た目には同じことをしているので、ここで必ず引っかかる。
既存のコードは前者で書かれているので、**その書き方に合わせれば問題は起きない。**

## E. 現状の問題（実測。提案より先に直す候補）

### E-1. 横断目録が、入力のたびに全行を作り直して出現から再生し直す

**実測で確かめた。**

| 測ったこと | 結果 |
|---|---|
| 全件の行数 | 61 |
| 入力後、同じ行の要素が残っているか | **残っていない（毎回作り直し）** |
| 作り直された行に付いている動き | 行が下から現れる動き（720ms） |
| 最後の行の遅延 | **480ms** |

**一文字打つたびに、最大61行が消えて作り直され、全体が落ち着くまで約1.2秒かかる。**
手が止まってから0.12秒待つ処理は入っているので連打では走らないが、
**打つのをやめるたびに全部出直す。**

絞り込みは「減った」ことが分かればよいのに、**毎回ゼロから現れ直している。**

### E-2. 同じ「絞り込み」を、2画面が別のやり方で見せている

| 画面 | やり方 | 重さ |
|---|---|---|
| 用語集 | 容器ごと薄く消して戻す（0.15秒・1要素） | 軽い |
| 横断目録 | 行を1つずつ出し直す（720ms＋最大480msの遅延・最大61要素） | 重い |

**用語集のやり方が、そのまま横断目録に使える前例として同じリポジトリの中に在る。**

### E-3. 時間の指定が、トークンと直値で混ざっている

| | トークン使用 | 直値 |
|---|---|---|
| 状態変化（29箇所） | 16 | **13** |
| 繰り返し再生（18箇所） | 2 | 16 |

**繰り返し再生の16のうち12は、入口の図形の周期（46〜72秒）で、意図的に不揃い。**
残りは900ms・700ms・4.5秒・9秒。

> **これを「統一されていない負債」と即断しないこと。**
> 2026-10-18 に、罫線のトークンで**件数だけ数えて「置換が途中」と誤った判断をした前例がある。**
> 実際には役割で分けてあり、揃えていたら画面が壊れていた。
> **直値にも理由があるかもしれない。先に定義側のコメントを読むこと。**

### E-4. 出現の時間差が、ゆっくり読む人ほど効かない

人物一覧と作品一覧は、札が画面に入るたびに少しずつ遅らせて浮かび上がらせている。

**遅れの量に使っている番号が、「その一度に渡ってきた分の中での順番」になっている。**

| 読み方 | 一度に渡ってくる数 | 結果 |
|---|---|---|
| 速くスクロールする | まとめて多数 | 時間差が付く |
| **ゆっくり読む** | **1枚ずつ** | **番号が常に0。時間差がまったく付かない** |

**狙いと逆になっている。** 急いでいる人には演出が出て、じっくり読む人には出ない。
一覧全体での通し番号を使えば直るが、**横断目録のほうは既に通し番号で書かれている。**
同じリポジトリの中に正しい書き方がある。

### E-5. 入口の立体の揺れが、画面の滑らかさで変わる

位置を**毎回足し込む**書き方になっていて、経過時間で割っていない。
**描画が滑らかな画面ほど動く量が増える。**

CSS側の図形には「振幅20px以内・回転4度以内」という上限がコメントで宣言されているが、
**立体側はその上限を守る作りになっていない**（足し込みなので、上限そのものが決まらない）。

### E-6. 読み込み幕の秒数は、見た目だけの値ではない

**入口の幕が閉じる合図は、題字の出現アニメーションが終わったこと。** JSがそれを待っている。

**題字の秒数を変えると、幕が閉じる条件そのものが動く。**
「少し速くしたい」と短くしたつもりが、読み込みの待ち方を変えてしまう。
触る前にJS側を読むこと。

### E-7. 測れなかったもの

**読み込み時に要素が飛ぶかどうか（CLS）は未測定。** 仕様書にも未実装の項目として残っている。
**動いているものを足す前に、ここを測るのが順番として先。**

## F. 追加できるもの

**「意味を運ぶ動き」を上に、「飾りの動き」を下に並べてある。**
記録性が最優先という原則からすると、上から順に価値が高い。

### F-1. 絞り込みが効いたことを示す ── **E-1 の修正でもある**

| | |
|---|---|
| 何のため | 「条件を変えたら結果が変わった」を伝える。いまは毎回ゼロから出直すので、変化が読み取れない |
| どこ | 横断目録の一覧 |
| 技法 | 用語集と同じ、容器の淡い切り替え（CSSの状態変化のみ） |
| 守る線 | 応答の層。160〜320ms |
| 受け入れ条件 | 全件→絞込→全件で行の要素が作り直されても、出現が再生し直されないこと／動きを減らす設定で即時に切り替わること |
| 重さ | **軽い。** 既存のやり方を移すだけでライブラリも不要 |

**最初の一歩として、これが一番費用対効果が高い。**

### F-2. 検証状態を色の変化で示す

| | |
|---|---|
| 何のため | 根拠の強さは**このサイトの中身そのもの。** 一覧で目に入る価値がある |
| どこ | 一覧の検証状態の印。本番は未検証52・確認済6・出典なし2・要補足1 |
| 技法 | 状態変化のみ |
| 守る線 | 応答の層。**案内の色（青）と記録の色を混ぜない**（配色の決まり） |
| 受け入れ条件 | 色だけに頼らず文字でも区別が付くこと／コントラスト比を再測すること |
| 注意 | **「確認済」を目立たせすぎると、未検証が少なく見える。** 分布は逆（52対6） |

### F-3. 一覧と詳細のつながりを強める

| | |
|---|---|
| 何のため | どれを押してどこへ来たのかを、矢印や文言なしで示す |
| どこ | 人物一覧→人物詳細、作品一覧→作品詳細 |
| 技法 | **画面の切り替え（既に全ページに入っている）の拡張** |
| 守る線 | 240ms・淡い切り替え |
| 受け入れ条件 | **同じ目印が同時に2つ存在しないこと**（存在すると遷移ごと中止される） |
| 重さ | **軽い。** 仕組みは既に在る |

### F-4. 読み込み中であることを示す

| | |
|---|---|
| 何のため | **いまは読み込み中の表示が無い。** データが出るまで空欄で、失敗と区別が付かない |
| どこ | データを読む全画面 |
| 技法 | 状態変化＋読み上げへの通知 |
| 守る線 | 気配の層にしない。**回り続ける印は無限ループにあたる**ので、層の決まりと衝突する。短い淡い表示に留める |
| 受け入れ条件 | 読み込みが速いとき**ちらつかないこと**（遅れて出す）／失敗の表示と見分けが付くこと |
| 関連 | 2026-10-21 に「失敗」と「0件」は分けた。**残るのは「読み込み中」との区別** |

### F-5. 件数が変わったことを数字で示す

| | |
|---|---|
| 何のため | 絞り込みの手応え |
| どこ | 一覧の件数表示 |
| 技法 | 数を順に変える（JSから要素を書き換える） |
| **慎重にすべき理由** | **件数は記録であって演出ではない。** 数が転がっている途中の値は、一瞬とはいえ**事実でない数字を画面に出すことになる** |
| 判断 | **見送りを推す。** 掲載方針（裏付けのない記述を断定形で書かない）と相性が悪い |

### F-6. 0件のときに近い候補へ導く

| | |
|---|---|
| 何のため | 行き止まりを作らない。**候補を出す機能は既に在る**が、静かに差し替わるだけ |
| どこ | 用語集と横断目録の0件表示 |
| 技法 | 状態変化 |
| 守る線 | 呼吸の層。10px・不透明度のみ |
| 関連 | 設計論点2（0件の見せ方）と同じ範囲。**論点2の判断が先** |

### F-7. 見送りを推すもの

| 案 | 理由 |
|---|---|
| 一覧の横スクロール | 却下済み（A-3）。**データ的にも成立しない**。作品数が1件の人物が13件中10件 |
| 外部から取るアニメーション | 接続先の制限と元の決まりの両方に反する |
| 入口以外での視差・立体傾斜 | 記録のページは静けさを保つ（A-2） |
| 回り続ける読み込み表示 | 無限ループの扱いになる（F-4 参照） |

## G. 依頼を出すときに必ず添えること

1. **仕様書の実装ロードマップのチェックは実態と合っていない。** 読むと、できている作業をやり直す
2. **ライブラリ2本は既に同梱されている。** 新規導入としてではなく「使うかどうか」として扱う
3. **接続先の制限が入った。** D の表を先に渡す
4. **動きを減らす設定での停止は全ページ必須。** 遅延は一括では消えない
5. **色の16進数を直接書かない。** 必ずCSS変数
6. 受け入れ条件（何ができたら完成か）を必ず付ける
7. **「変更しない」が最適なら、根拠付きでそう書く。** それも結論として扱う
8. **実測していない改善率や工数を、事実として書かない**
