## 7. 並べ方の型

`display: grid` 9箇所、`display: flex` 32箇所、`inline-flex` 1箇所（計42宣言）。繰り返し現れる型は次の**10**（型A〜型J）で、新規はどれかに乗せれば済む。

### 型A 自動列のカード棚（最頻・5箇所）

`display: grid` ＋ `grid-template-columns: repeat(auto-fill|auto-fit, minmax(Npx, 1fr))`。列数を書かず、1枚の下限幅だけ決めて並ぶ数は画面に任せる書き方。

| セレクタ | 下限 | 関数 | `gap` | 768以下 |
|---|---|---|---|---|
| `.gate-grid` | 240px | `auto-fit` | `var(--space-4)` | 変更なし |
| `.work-grid` | 220px | `auto-fill` | `var(--space-3)` | 変更なし |
| `.chara-grid` | 180px | `auto-fill` | **生の `24px`** | 140px / `20px 16px` |
| `.clip-grid` | 260px | `auto-fill` | `28px 20px` | `1fr`（1列） |
| `.fanart-grid` | 180px | `auto-fill` | **生の `24px`** | 140px / `20px 16px` |

`auto-fit` は `.gate-grid` の1箇所だけで、残りは `auto-fill`。**新しいカード一覧を作るならこれが型。** 列数のメディアクエリは書かず、下限値だけを768pxで下げる。
`gap` の書き方は棚ごとに違う。5箇所のうちトークン経由は2つだけで、残り3つは生の値である。**隣に置く既存の棚と同じ書き方に合わせる**（§15-2-3）。

### 型B 固定2列 → 1列（1箇所）
`.catalog-filters`：`1fr 1fr` ＋ `gap: var(--space-4)` → 768pxで `1fr`。

### 型C 行グリッド（1箇所）

## 9. 縦横比と領域予約

中身が後から入る箱は、先に高さを取っておくのがこのサイトの型。取らないと、データが届いた瞬間に下の内容が押し下げられ、読んでいる行や押そうとしたリンクが動く。

## 12. 画像の扱い

**HTMLに `<img>` は1つも無い。** すべてJSが文字列として組む。`<img>` を出すのは4ファイル。

| ファイル | `loading` | `decoding` | `width/height` | `alt` |
|---|---|---|---|---|
| `js/chara.js`（一覧の札） | **なし** | なし | なし | 人物名 |
| `js/chara-detail.js`（下層の額） | **なし** | なし | なし | 人物名 |
| `js/tools-fanart.js`（二次創作） | `lazy` | `async` | なし | 題名＋作者名 |
| `js/tools-kirinuki.js`（切り抜きのサムネイル） | `lazy` | なし | `480×360` | **`alt=""`**（隣に題名があるため意図的な空） |

CSSの `img` 規則は2組だけ。

- `.chara-plate img, .chara-frame-inner img` → `width:100%` `height:100%` `object-fit:cover` `display:block`
- `.clip-thumb img` → 同じ4つ ＋ `transition: opacity .3s`、`.clip-thumb:hover img { opacity: .7 }`

収まっているのは器（`.chara-plate` / `.chara-frame-inner` / `.clip-thumb`）が `aspect-ratio` ＋ `overflow:hidden` を持ち、中の `img` が `100%` ＋ `object-fit:cover`（器いっぱいに拡げて、比の合わない分は切り落とす）だからである。`cover` にしてあるのは、人物の絵も切り抜きのサムネイルも縦横比が揃っていないため。`contain`（全体を収める側）だと器の中に余白の帯が出て、棚の列ごとに絵の大きさが変わる。溢れた分を切る代わりに、どの札も同じ面積で並ぶ。**器の外に画像を置くと素のまま出る**（§1-5）。新しい画面で画像を扱うなら器ごと流用する。

絵が無いときの代替：`.chara-noimage`（縦書き `writing-mode: vertical-rl`・11px・明朝・`letter-spacing:.5em`）。`:has(.chara-noimage)` で親の背景を放射グラデ＋暗めの地に差し替える。`index.html` の額でも同じクラスを使い回している。一覧側は絵の代わりに `.chara-plate.is-daisen`（題字札）を組む：`flex-direction:row` ＋ `align-items:flex-end` ＋ `space-between`、縦書きの名前（`clamp`）を右、1項目だけを左下。

動画の埋め込みは押されるまで `iframe` を作らない（`.clip-thumb` が `<button>`、再生後は `.clip-thumb-playing { cursor: default }` に切り替わる）。ただしサムネイル画像は押す前から外部ドメインを叩く行が残っており、配布版の `img-src` がそれを許していない（§1-13）。**この1行が `npm test` を1本落としている**（§14）。

質感のノイズはすべてSVGを `data:` URI でCSS変数に書き込んでおり（`--noise-fine` `--noise-coarse` `--noise-hero` ＋ `body::before` に直書き1つ）、画像ファイルは増えていない。

## 14. 配布・データ・検証

CSSの話ではないが、**ここを知らないと新しい画面は手元でだけ動く。**

### 配るものは列挙してある

`tools/build-site.js`（172行）が `dist/` を組み立てる。配るものは `PUBLISH` 配列の7項目だけで、**ここに無いものは配られない。**

```
index.html / 404.html / pages / components / css / js / data
```

「これは外す」という書き方にしていない理由がファイル冒頭に書かれている。外す側を並べると、新しいフォルダを足した日に `server/` や `docs/` や `reference-data/` が黙って混ざるためである。
その代わり、**`assets/` は空のままで `PUBLISH` にも入っていない。** 画像ファイルを置く場所と配布経路が現状どこにも無いので、§15 の「画像は器に入れる」を実行する前に置き場を決める必要がある。現在サイトに出ている画像はすべて外部ドメインか `data:` URI で、リポジトリ内に画像ファイルは1つも無い。

組み立ては `pages/` の中身に3つの門を置いている。通らないとその場で止まる（`dist/` を消す前に検査するので、前回の配布物は残る）：

1. 拡張子が `.html` であること（下書きの置き場は `reference-data/`）
2. `<!DOCTYPE html>` で始まること
3. **`js/main.js` を読み込んでいること** ── 共通パーツを読まないページは、別の場所で作った書き出しの紛れ込みとみなす

### 配布直前にCSPを数え直す

`dist/_headers` に `Content-Security-Policy`（CSP。読み込んでよいものをブラウザに宣言するヘッダーで、書いていない先は黙って落とされる）を書き出す。`script-src` は **そのページにある `src` 無しの `<script>` すべてのSHA-256ハッシュの列**で、組み立てのたびに数え直している。手で書き写すと、スクリプトを一文字直した日にテーマの先読みだけが黙って死ぬ。

**`<head>` に限らない。** `tools/build-site.js` の `inlineScripts()` はページ全体の `<script>` から `src` を持つものを除いて拾う。現在のハッシュは2種（16画面が共有するテーマ同期スクリプトと、`index.html` だけが持つ `importmap`）で、`index.html` の `</head>` は16行目に対して `importmap` は143行目＝**`<body>` の中にある。** それでも対象になる。`<body>` へインラインスクリプトを置いても逃げられないので、置いたら組み直す。
`build-site.js` は開いた `<script>` タグの数と拾えた中身の数が合わなければ例外で止まる。取りこぼすとそのページのCSPが効かなくなるためである。

**新しい画面を足したら `npm run build:site` を走らせ直す。** インラインスクリプトの文面が1画面でも違えばハッシュが増え、走らせていない配布物ではそのページのテーマ同期だけが止まる（＝暗い設定の人が開くと白く光る）。
許可の全体は `default-src 'self'` を土台に、`img-src` が `'self' data:`、`style-src` `font-src` `connect-src` が `'self'`、`frame-src` だけが動画埋め込み先の1ドメイン、`frame-ancestors` `base-uri` `form-action` `object-src` は `'none'`。

### データは `data/` の11本

一覧系の画面はすべてJSONを `fetch` する。`data/` に追跡されているのは11本：`catalog` / `characters` / `clips` / `events` / `fanart` / `glossary` / `goods` / `history` / `series` / `sources` / `works`。

### `src/*.ts` と `js/*.js` の併存

`tsconfig.json` は `rootDir: src` / `outDir: js` なので、`npm run build` は `src/` の `.ts` を `js/` へ出す。現在 `.ts` の元があるのは**2本だけ**：

**この2本は `js/` 側を直しても次の `npm run build` で消える。** 残り13本のJSは `.ts` の元が無く `tsc` の対象外なので、`js/` を直接直して構わない。新しい画面のJSは、既存13本と同じく `js/` に直接書けばよい（`src/` に置くと `module: none` の classic script として出力され、読み込み方は変わらないが、変換を挟む分だけ手順が増える）。

### `npm test` は今の時点で赤い（2026-10-30・6本中5本合格・1本失敗）

落ちているのは**2番目**で、原因は `js/tools-kirinuki.js`(66行) がサムネイルのURLを外部ドメインで組んでいるのに、配布版の `img-src` が `'self' data:` しか許していないことである（§1-13・§12）。**自分の変更とは無関係に、最初から赤い。**

`npm run check` は現在3本とも合格なので、こちらは**1件でも赤くなったら自分の変更が原因**として扱える。

## 15. 新しい画面を1枚足す手順

測った値から導かれる型。上から順に当てれば既存とズレない。

### 15-1 ファイルとして成立させる

1. **置き場所**：`pages/` 直下に `.html` で置く。`pages/` にHTML以外を置くと組み立てが止まる（§14）。下書きは `reference-data/` へ。
2. **`<head>` の4点**：`<meta charset>` / `<meta name="viewport">` / `<title>` / `<html lang>`。`npm test` の5番目がこの4つを見る。携帯で縮んで出る崩れは、広い画面で見ている限り気づけないため。
3. **スタイルの読み込み**：下層は `<link rel="stylesheet" href="../css/style.css">`。入口 `index.html` は `css/style.css`、**`404.html` だけは `/css/style.css`** と根からの絶対パスで書く。404 はどのURLに対しても返るので、相対にすると `/pages/` の下で開かれたときに `../css/` を探しに行って全部外れる（`404.html` のコメントに理由が残っている）。
4. **テーマ同期のインラインスクリプト**：`<head>` の中、`<link>` の後ろに置く。`localStorage` の `theme` を読んで `<html data-theme>` を立てるだけの短いもので、既存16画面すべてが**一字一句同じ文面**を持っている。`js/main.js` を待つとその間ライトで描画され、暗い設定の人はページを開くたび白く光る。
   - **文面を変えない。** 1画面でも違えばCSPのハッシュが増え、`npm run build:site` を走らせ直さない限りその画面だけテーマ同期が止まる（§14）。既存ページから丸ごと写す。
   - **改行まで含めて同じであること。** ハッシュはこのブロックのバイト列をそのまま取るので、見た目が同じでも改行を変換して保存するとハッシュが変わる。追跡されている124本の内訳は純LF 93・純CRLF 27・混在4で、**このリポジトリは全体がLFに揃っていない。** エディタの既定に任せると気づかないうちに変わる。
5. **共通パーツの空箱**：`<body>` の先頭に `<div id="header"></div>` `<div id="nav"></div>`、末尾に `<div id="footer"></div>`。`js/main.js` の `loadComponent()` がこのidを見つけたときだけ `components/*.html` を差し込む（無いページでは何もしない）。`#header` / `#nav` には高さの予約があるので消さない（§1-11）。
6. **骨組み**：`<main class="page-content">` ＋ `<h1>` ＋ `<div class="page-rule">` ＋ `<p class="page-lead">`（800px・`padding 32px 24px 60px`）。
7. **末尾のスクリプト**：`<script src="../js/main.js"></script>` を必ず置く（これが無いと組み立てが止まる）。その後ろにページ別のJSを1本。
8. **導線**：`components/nav.html` の `.site-nav` に `<a href="/pages/…">` を足さないと、そのページには到達できない。現在は入口＋下層5枚が直置き、`.nav-dropdown-menu` に3枚。
   - `href` は**根からの絶対パスで書く。** `.active`（下線）は `js/main.js` の `initNavActiveState()` が `href` のパスと現在のパスを突き合わせて付けるので、書き方が揃っていないと下線だけが付かない。
   - サイト自身についての画面（出典・検証など）はナビではなくフッターに置く取り決めがある（`components/nav.html` のコメント）。**足す先は `components/footer.html` の `.footer-nav`** で、現在4枚が入っている：`/pages/about.html` `/pages/catalog.html` `/pages/sources.html` `/pages/contact.html`。ここも `href` は根からの絶対パスで書く（フッターは全16画面に差し込まれるので、相対にすると階層の違う画面で外れる）。
9. **データ**：`fetch("/data/…")` の形で、根からの絶対パスで書く（§14）。
10. **失敗表示**：取得に失敗したら `.load-error` を出す。0件と同じ見た目にしない（§1-8）。
11. **配布と確認**：`npm run build:site` → `npm test`。データを足したなら `npm run check`、動画リンクを足したなら `npm run verify`。
    - `npm test` は**2番目が既知で落ちる**（§14）。2番目だけが赤いなら元のまま、それ以外が赤くなったら自分の変更が原因。`npm run check` は現在全部通っているので、赤くなった時点で自分の変更を疑う。

### 15-2 見た目を既存に揃える

1. 節見出しは `<h2>`（16px・明朝・左3px罫が自動で付く）。打ち消したい時だけ `border: none; padding: 0`
2. 行一覧なら `ul/li` ＋ `border-bottom: 1px solid var(--rule)` ＋ `padding: 10〜12px 4〜8px` ＋ 13px（型J）
3. カード一覧なら `display:grid` ＋ `repeat(auto-fill, minmax(180〜260px, 1fr))`、768pxで下限を140pxに下げる（型A）
   - **`gap` は隣に置く既存の棚と同じ書き方に合わせる。** 型Aの5箇所でトークンを使っているのは `.gate-grid`（`--space-4`）と `.work-grid`（`--space-3`）だけで、`.chara-grid` と `.fanart-grid` は生の `24px`、`.clip-grid` は `28px 20px` である。人物や二次創作の隣なら生の `24px`、作品の隣なら `var(--space-3)`。**値が同じでも書き方を混ぜると、後から一括で直せる範囲が分からなくなる**（§1-2）
4. 横並びのメタ行には `flex-wrap: wrap` を必ず付ける（型Fで持っていない3つを手本にしない）
5. 枠ものは `border: 1px solid var(--rule-strong)` ＋ `border-radius: 4px` ＋ `padding: 14px 16px`
6. 状態の印は `font-size:11px` ＋ `letter-spacing:.08em` ＋ `padding:3px 10px` ＋ `border-radius:2px` ＋ `white-space:nowrap`。実線枠／ベタ塗り／破線枠の3段。手本は `.src-badge`（`.work-series-status` は `nowrap` を欠く）

8. 画像は必ず `aspect-ratio` ＋ `overflow:hidden` の器に入れ、中の `img` を `100%` ＋ `object-fit:cover` にする。**ただし画像ファイルの置き場と配布経路は未整備**（§14）

10. 明暗で寸法を分けない。色は必ずトークン経由（直書きの色は黒帯の自前3色だけが例外）
11. 中身が後から入る箱には `aspect-ratio` か `min-height` で先に場所を取る（§9）

## 16. 測れなかったこと

ここに挙げたものは宣言値から導けるだけで、確認済みではない。そのつもりで使う。

- **ブラウザで描画した値は測っていない。** すべて `css/style.css` のソース読み取り。各画面幅での実際の列数、`clamp()` の解決値、はみ出しの有無は未確認
- **コントラスト比は検証していない。** ファイル内のコメントに具体的な比率が多数書かれているが、それは記述の引用で、こちらで計算し直したものではない
- 入口の気配の層は `js/hero/ambient.js`（元は `src/hero/ambient.ts`）が実行時に canvas を作る作りで、その要素の寸法指定はCSS側に無い。3Dが立った時の実際の占有領域は未計測。CSS側は `.hero-ambient.is-3d .hero-shape { display:none }` で図形を隠すことだけが分かっている
- `.chara-profile` が狭い画面で何px幅まで耐えるか（セル内の折り返しで収まるか、親を押し広げるか）は未計測。`overflow-x` の器が無いことだけが確認できている
- 印刷用のスタイル（`@media print`）は0件。紙に出したときの崩れは測っていない
- 外部3Dライブラリとアニメーションライブラリが依存に入っているが、CSSとの取り合い（インライン `style` で上書きする範囲）は調べていない
- `.chara-echo`（関係の重ね表示）や `.is-pointed` など、JSが付ける状態クラスの実際の見え方は静的読み取りのみ。重なり順や可読性の実測はしていない
- **外部サムネイルをどうするかは決まっていない。** `npm test` の2番目が落ちている原因（§14）について、`img-src` に読み込み先を足すのか、押す前のサムネイルをやめるのかは方針判断であって、計測では決まらない

**解消したもの**：配布先の `css/style.css` が元ファイルとバイト一致するかは、比較して**一致を確認した**（どちらも84,547 B）。`tools/build-site.js` は `fs.cpSync` でそのまま写すだけで、CSSには手を入れない。配布物は全50ファイル。
