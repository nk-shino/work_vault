# 技術スタック

実装を引き継いで手を動かすための実測記録。2026-10-30 時点の手元のツリーに対して実際にコマンドを走らせ、返ってきた数値だけを書いている。推定や「おそらく」は混ぜていない。測れなかったものは §12 に別立てで並べた。

題材は伏せてある。固有名称・絶対パス・リポジトリ名は書かない。パスはすべて配信物の根からの相対で示す。

## 0. 実測の前提

- 実行環境: Windows 11 / Node.js v24.18.0 / PowerShell と Bash を併用
- 手元のツリーには未コミットの変更が5件・未追跡ファイルが2件あった。変更は `css/style.css`・`data/sources.json`・`js/sources.js`・`js/work-detail.js`・`package.json`、未追跡は `tools/assign-source-ids.js`・`tools/link-sources.js`。つまり **手元の状態と最後のコミットは一致していない**。以下の数値は手元の状態に対するもの
- **この未コミット分は検査の本数に直結している。** `package.json` の変更は `npm run check` を1本から3本に増やしたもので、未追跡の2本はその増えた分が呼ぶスクリプト。クローンした人の手元では §9-1 の3本が揃わない（§2-1）
- 容量はすべて非圧縮の生バイト数。配信側の gzip / brotli 設定は確認していない

- **バイト数・件数・行数は再実行すれば同じ値が返る。例外は所要時間だけで、こちらは同じ機械でも1〜2割ぶれる。** だから時間は幅で書いてある（§9）。測定回数も併記した

## 1. 先に読む ── 知らずに触ると壊れるもの

**共通しているのは「エラーが出ないまま静かに壊れる」こと。** ビルドは成功し、型検査も通り、画面も一見成立する。だから先に出す。

### 1-1. `tsconfig.json` を単独で走らせると入口ページの3D層が死ぬ

変換（TypeScript → JavaScript）の設定が2本に割れていて、1本目の `tsconfig.json` は `include: ["src/**/*.ts"]` なので3D層のソース（`src/hero/ambient.ts`）も**対象に含んでいる**。そちらは `module: "none"` のため、`import` が CommonJS の `require` に書き換えられる。

ブラウザの `<script type="module">` に `require` は存在しないので、入口ページの3D層は読み込み時点で即死する。

**`npm run watch` だけの話ではない。`--noEmit` も `--outDir` も付けずに `tsc -p tsconfig.json` を走らせたものは、すべて `js/` を書き換える。** 実測した3通り。

| 走らせたもの | 結果 |
|---|---|
| `npm run build`（`tsc -p tsconfig.json && tsc -p tsconfig.hero.json`） | 2本目が上書きするので**順序に依存して**正しくなる |
| `npm run watch`（`tsc -p tsconfig.json --watch`） | **1本目だけを回し続ける。3D層が書き換わり、そのまま戻らない** |
| `tsc -p tsconfig.json --listFiles`（中身を調べるだけのつもりの実行） | **書き換わる。`--listFiles` は出力を止めない** |

3つ目が特に厄介で、調査のつもりの実行が本番のファイルを壊す。終了コードは0、警告も0。この資料を作る過程で実際に踏んだ。

書き換わった `js/hero/ambient.js` の冒頭はこうなる。

```js
"use strict";
// （元ファイルのコメント14行がそのまま残る）
Object.defineProperty(exports, "__esModule", { value: true });
const THREE = require("three");
```

**コメントがそのまま残るので、ファイルの頭を見ただけでは気づけない。** 正しい状態の `js/hero/ambient.js`（7,073 B）は1〜14行目がコメントで、`import * as THREE from "three";` は15行目にある。見るべきはファイルの1行目ではなく**最初のコード行**。

型検査は両方とも無警告で通る（`--noEmit` で exit 0）。**エラーは一切出ない。**

#### 壊さずに試す / 壊れたら戻す

挙動を確かめたいときは、出力先を一時領域へ逃がす。`js/` は touched されない（実測で確認。一時フォルダが存在しない場合も安全に作られる）。

```
npx tsc -p tsconfig.json --outDir <一時フォルダ>
```

既に書き換えてしまった場合は、2本目の設定を単独で走らせれば戻る。

```
npx tsc -p tsconfig.hero.json
```

これで `js/hero/ambient.js` は追跡されている内容とバイト単位で一致する（実測で確認）。`newLine: lf` が効くので改行も変わらない。

恒久的な対処は、1本目の `include` から `src/hero/**` を外すか、watch を2本立てにするか。**どちらを採っても2本目の設定は必要なまま**なので、変更したら `npx tsc -p tsconfig.hero.json` → `npm run build:site` の順で通し、`js/hero/ambient.js` の最初のコード行が `import` のままであることを目で確かめること。

### 1-2. インラインスクリプトを足して、組み立てずに配ると黙って止まる

配信ヘッダーに載るスクリプトのハッシュ（指紋）は、組み立て時に数え直して埋め込まれる。`dist/` を手で直してインラインを足すと、ヘッダーのハッシュが古いままになり、ブラウザがそのスクリプトを**黙って実行しない**。画面にエラーは出ず、開発者ツールのコンソールにだけ出る。`dist/` を手で触る経路は存在しない前提で作られている。

### 1-3. スクリプトタグの属性値に `>` を入れると、ビルドは通ってハッシュが壊れる

組み立てはスクリプトの中身を正規表現 `<script\b([^>]*)>([\s\S]*?)<\/script\s*>` で切り出している。`data-x="a>b"` のように属性値へ `>` を入れると、最初の `>` で切れるため、本来 `var a=1;` であるべき中身が `b">var a=1;` として拾われる。**数の収支は合うので組み立ては成功し、配信ヘッダーには間違ったハッシュが載り、本番でだけそのスクリプトが実行されない。** JS文字列の中に `</script>` を書いた場合も同じ。

判定ロジックを切り出して11通り流した実測結果。拾われた中身まで出して突き合わせてある。

| 書き方 | 結果 |
|---|---|
| 普通のインライン1本 | 通る |
| `src` 付き（引用符 `"`） | 通る |
| `src` 付き（引用符 `'`） | 通る |
| `src` 付き（引用符なし。`src=js/a.js`） | 通る |
| `type="importmap"` | 通る |
| `type="module"` + `src` | 通る |
| HTMLコメントで無効化したスクリプト | 通る（ハッシュが余分に1つ増えるだけ） |
| 大文字で `<SCRIPT>` | 通る |
| 散文の中に `<script>` と書く（閉じタグなし） | **止まる**（安全側の失敗） |
| 属性値の中に `>` を含む | **通るが、拾われる中身が `b">var a=1;` になる** |
| JS文字列の中に `</script>` を書く | **通るが、拾われる中身が `var s="` で切れる** |

### 1-4. サブディレクトリに置くと、場所によって壊れ方が変わる

共通パーツ（`components/{header,nav,footer}.html`）もデータ（`data/*.json`）も、`/` 始まりの絶対パスで読まれている。**データの `fetch` が25箇所、共通パーツが3箇所。合わせて28箇所で、例外は1つも無い。** ドメインの根に置く前提。

CSSとJSの読み込みは書き方が割れている。`index.html` は `css/style.css`、`pages/` の14枚は `../css/style.css` と相対で書かれているが、**`404.html` だけは `/css/style.css`・`/js/main.js` と絶対**。

さらにページ間のリンクは全部絶対パスで書かれている。HTML内の絶対パス参照は全部で29箇所あり、内訳は `index.html` 7・`404.html` 6（うち2本は上のCSSとJS）・`nav.html` 9・`footer.html` 4・`header.html` 1・`pages/about.html` 1・`pages/contact.html` 1。つまり29箇所のうち27はページ間リンク、2が `404.html` のCSSとJS。

だから根の外に置いたときの壊れ方は一様ではない。

| 対象 | サブディレクトリに置くとどうなるか |
|---|---|
| `index.html` と `pages/` の14枚 | CSSとJSは当たる。ナビ・フッター・データだけが出ない |
| `404.html` | **CSSとJSまで落ちる。** 飾りの無い素のHTMLだけが出る |
| 全ページのナビ・フッター・本文リンク | 押した先が根に飛ぶので、どれも404になる |

真っ白なら気づくが、半分だけ成立したまま壊れるので原因が分かりにくい。**「ここに置けるか」をこの節の図式だけで判断しないこと。** スモークテスト6本目が固定しているのは共通パーツとデータの絶対パス（`js/main.js` の読み込み方と、全JSの `fetch` が `/` 始まりであること）だけで、CSS/JS の書き方とページ間リンクは誰も見ていない。

### 1-5. 外部からの読み込みを足すと、データを入れた日に初めて消える

空のデータに紐づく外部参照は、画面に出ないのでブラウザで見ても見つからない。切り抜きのページがサムネイルを外部ホストから読む行が残っており、スモークテスト2本目が**不合格のまま**（詳細は §9-2）。組み立ては止まらない。**スモークテストだけが知っている。**

## 2. 動かすまでの手順

### 2-1. クローン直後に何が要るか

追跡されているのは124ファイル。**同梱ライブラリ3本（`js/lib/`）と、TypeScript から生成される2本（`js/home.js`・`js/hero/ambient.js`）も git に入っている。** だからクローンしただけで配信物は作れる。`node_modules` が必要なのは3つのコマンドだけ。

| コマンド | `node_modules` | 中身 |
|---|---|---|
| `npm run build:site` | 不要 | `node tools/build-site.js`。**`dist/` を作る唯一のコマンド** |
| `npm test` | 不要 | スモークテスト。中で `build:site` を呼び直す |
| `npm run check` | 不要 | データ整合の3本。**3本になっているのは手元だけ**（すぐ下） |
| `npm run verify` | 不要 | 外部照合（ネットには出る） |
| `npm run releases` | 不要 | 新着検出（ネットには出る） |
| `npm run build` | **必須** | `tsc` 2本。TypeScript 本体が要る |
| `npm run watch` | **必須** | `tsc --watch`。**§1-1 の落とし穴** |
| `npm run vendor` | **必須** | `node_modules` から `js/lib/` へ写す |
| `npm run deploy` | ─ | `npx void`。依存宣言に無く、実行時にネットから取る（§1-6 #14） |

**`npm run check` はクローン直後には揃わない。** 3本を呼ぶ形に直した `package.json` が未コミットで、呼ばれる側の `tools/assign-source-ids.js` と `tools/link-sources.js` は未追跡（§0）。最後のコミットの `check` は `node tools/make-catalog.js --check` の1本だけ。だから §9-1 の「3本すべて合格」は手元の状態の話で、**クローンした人が同じコマンドを叩いても再現しない。しかも1本でも合格と出るので、足りないことに気づけない。** 先に追跡へ入れること（§2-4 の2番）。

`tools/` のスクリプト全8本が読み込んでいるのは Node 標準モジュールだけで、外部パッケージは1件も無い。**ただし顔ぶれは1種類ではなく、`fs`・`path`・`crypto`・`https` に加えて `tools/smoke.test.js` だけが `child_process`・`node:test`・`node:assert` も読む。** いずれも標準なので結論は変わらない。`npm ci` が必要になるのは、`src/` の TypeScript を触るときとライブラリを入れ替えるときだけ。逆に言えば、**`npm ci` を忘れたまま `npm run build` や `npm run watch` を叩くと、そこで初めて止まる。**

### 2-2. `npm run build` は `dist/` を作らない

名前が紛らわしく、ここを読み違えると配信物が一度も作られない。

- `npm run build` = `tsc -p tsconfig.json && tsc -p tsconfig.hero.json`。**`src/` の2本を `js/` へ変換するだけ。`dist/` には触らない**
- `npm run build:site` = `node tools/build-site.js`。**`dist/` を作るのはこちら**

公開先の設定ファイルが呼ぶのも `node tools/build-site.js`（§11）。「ビルド」と言われたらどちらの話か確かめること。

### 2-3. 画面を出す

`fetch` を使うので `file://` では全ページがエラーメッセージだけになる。簡易サーバーが必須だが、**`package.json` にサーバーのスクリプトも依存も無い。** `serve.json`（`{"cleanUrls": false}`）は置いてあるが、それを読む `serve` は入っていない（`node_modules/.bin/` にあるのは `tsc` 系だけ）。

依存を増やさずに出すなら、`dist/` の中で Python の標準サーバーを立てる。手元の Python 3.13.14 で実測した。

```
cd dist
python -m http.server 8000 --bind 127.0.0.1
```

| 取りに行った先 | 応答 |
|---|---|
| `/` | 200・6,661 B |
| `/pages/works.html` | 200・1,112 B |
| `/components/nav.html` | 200・741 B |
| `/data/characters.json` | 200・21,394 B |
| 存在しないパス | 404（**`404.html` は返らない**。素の404本文になる） |

**`dist/` の中から立てるのが肝。** データと共通パーツが `/` 始まりの絶対パスなので、根がずれると §1-4 の壊れ方になる。`404.html` を404として返すのは配信側の `routing.notFound` の仕事で、手元の簡易サーバーでは再現しない（§12）。

### 2-4. 測った事実から導ける着手順

機能の実装順序は設計資料（§13）にある。ここに並べるのはそれとは別で、**先に片付けないと後の作業が黙って壊れる順**。

| # | やること | なぜ先か |
|---|---|---|
| 1 | `setup.ps1` を追跡から外す | 単独で終わり、他に何も依存しない。放置している間ずっと §1-6 #1 の事故が起きうる |
| 2 | `tools/assign-source-ids.js`・`tools/link-sources.js` を追跡に入れ、`package.json` の `check` もコミットする | この2本が無い状態の `npm run check` は1本だけ走って合格と出る（§2-1）。**検査が足りていないことが合格の報告からは見えない。** 6番でデータを入れる前に揃えないと、整合が崩れたのか検査が無いのか切り分けられない |
| 3 | `tsconfig.json` の対象から3D層を外す（§1-1） | `src/` を watch や `--listFiles` で一度触るだけで3D層が壊れる。TypeScript に手を付ける前に塞ぐ |
| 4 | 外部サムネイルの行を始末する（§9-2 の2本目） | 全数合格に戻すまで**不合格を信号として使えない**。6本中1本が常に赤い状態では、新しい違反を足しても見分けが付かない |
| 5 | `assets/` を `PUBLISH` に入れる（§1-6 #2） | 画像を1枚でも入れる前。入れた後だと「置いたのに出ない」から入る |
| 6 | 余っている115.1 KiB の去就を決める（§4） | 外すなら4箇所同時。先に決めないとスモークテスト3本目が将来の邪魔になる |
| 7 | 空の3本にデータを入れる（§12） | 1件目を入れた瞬間に未検証の経路が一斉に表に出る。1〜6が済んでいないと何が原因か切り分けられない |

`src/` にあるのは `src/home.ts`（5,208 B）と `src/hero/ambient.ts`（7,058 B）、型宣言2本（`src/types/data.d.ts` 1,100 B、`src/types/libs.d.ts` 311 B）。

|---|---|---|---|

## 5. 組み立ての工程（`tools/build-site.js`、172行）

### 5-1. 何を集めるか ── 拾う側だけを列挙する

`PUBLISH` 配列は7項目。

```
index.html / 404.html / pages / components / css / js / data
```

**ここに無いものは配られない。** 実際に配られていないのは `src/` `tools/` `docs/` `reference-data/`（258,472 B）`server/` `assets/` `node_modules/` `dist/` `setup.ps1` `.vscode/` `.claude/` `*.md` `tsconfig*.json` `void.config.ts` `serve.json` `package*.json`。

**この一覧に `assets/` が入っていることに注意。** 画像の置き場として作られているのに配信対象ではない（§1-6 #2）。`setup.ps1` は `assets/` を作るところまでやって、`PUBLISH` には足さなかった、という食い違いがそのまま残っている。

除外リストではなく収集リストにしてあるのは、新しいフォルダを足した日に黙って混ざるのを防ぐため。これは実際に効いていて、`reference-data/` には下書きHTMLやテキストの控えが入っているが外へ出ない。裏返しの代償が `assets/` で、**足し忘れたフォルダは黙って配られない。**

### 5-2. 何を弾くか ── 止まる検査は6種

**上3つは `dist/` を消す前に走る。** 止めた時点で前回の配信物が消えた中途半端な状態にならないため。

| # | いつ | 見るもの | 失敗時 |
|---|---|---|---|
| 1 | dist削除前 | `pages/` の中身が全部 `.html` か | throw |
| 2 | dist削除前 | **`pages/` の**各ファイルが `<!DOCTYPE html>` で始まるか | throw |
| 3 | dist削除前 | **`pages/` の**各ファイルが `js/main.js` を読み込んでいるか | throw |
| 4 | コピー時 | `PUBLISH` の各項目が実在するか | throw |
| 5 | ハッシュ計算時 | `<script>` の開きタグ数と、src付き＋中身を拾えた数が一致するか | throw |
| 6 | 最後 | HTML内の `src`/`href` の行き先が `dist/` に実在するか | `process.exit(1)` |

**検査1〜3のループが読むのは `fs.readdirSync(ROOT/pages)` だけ。** 根の `index.html` と `404.html` は、`<!DOCTYPE html>` も `js/main.js` も一度も確かめられていない。この2枚は手で管理する1枚ものなので実務上の害は小さいが、「全ページが門を通っている」と読むと違う。配信物の全HTML（根の2枚と共通パーツ3枚を含む19枚）を見ているのは検査5と検査6の方。

検査1〜3が入ったのは、**生のテキストを `.html` の名前で `pages/` に置いたまま配りかけた**ことがあるから（組み立てスクリプトのコメントに記録されている）。ただし見ているのは「ページの形をしているか」まで。別の場所で作った正しいHTMLをここへ置けば通る。置き場所の判断の代わりにはならない。

**検査6が見ているのは二重引用符の `src`/`href` だけ。** 正規表現は `/(?:src|href)\s*=\s*"([^"]+)"/gi` で、単一引用符（`src='...'`）と引用符なしは素通りする。除外するのは `https?:`（**`http:` も除外される**）・`data:`・`mailto:`・`#`・`//` 始まりで、`?` `#` を落としたうえで `/` 始まりは `dist/` の根から、それ以外は当該HTMLの位置から解決する。

**検査6の守備範囲の外**: importmap のJSON、JS内の `fetch()` のパス、CSSの `url()`、JSが組み立てた `<img>` の `src`、単一引用符で書いた `src`/`href`。つまり同梱ライブラリの名前を変えても importmap は誰も確かめないし、ここを当てにすると §1-3 と同じ「ビルドは通るのに本番でだけ404」に落ちる。

### 5-3. 何を生成するか

- `dist/` を毎回 `rmSync` で消して作り直す
- `dist/_headers`（657 B）。インラインスクリプトのSHA-256を配る直前に数え直して埋め込む
- 空ディレクトリもそのまま写る。実測では空の `data/data/` が `dist/data/data/` として配信物に入っている

### 5-4. 実行結果

```
dist/ に 50 ファイル・1.11 MB
HTML 19 ページ・インラインスクリプトのハッシュ 2 種
行き先の無い参照は無し
```

19は共通パーツ3枚を含む数（配信ヘッダーの走査対象）。ハッシュ2種は「テーマ先読みスクリプト（全16ページで同一バイト列）」と「importmap（入口のみ）」。16ページ分のテーマ先読みを個別にハッシュ化して突き合わせたところ全て同値で、1種に畳まれているのが同一バイト列である証拠になっている。

## 6. 配信ヘッダー（`dist/_headers`）

対象は `/*` 一本。全パスに同じヘッダーが付く。

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'sha256-…' 'sha256-…';
  style-src 'self';
  img-src 'self' data:;
  font-src 'self';
  connect-src 'self';
  frame-src <動画サイトの埋め込み用ホスト1件>;
  frame-ancestors 'none';
  base-uri 'none';
  form-action 'none';
  object-src 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: geolocation=(), microphone=(), camera=()
Cross-Origin-Opener-Policy: same-origin
```

ここに書いた許可の外に出たものは、ブラウザが**黙って実行しない**。画面にエラーは出ず、開発者ツールのコンソールにだけ残る。だから下の表は「何ができるか」の一覧ではなく、**何をすると画面が無言で壊れるか**の一覧として読む。コードレビューの約束ではなくブラウザが強制するので、見落としても本番で必ず効く。

### どの書き方が通り、どの書き方が止まるか

| やりたいこと | 結果 | 理由 |
|---|---|---|
| 新しいインライン `<script>` を書く | **組み立て直せば通る** | ハッシュが自動で追加される |
| 組み立てずに `dist/` を手で直してインラインを足す | **止まる** | ヘッダーのハッシュが古い |
| `onclick="..."` などHTML属性にJSを書く | **止まる** | ハッシュは属性を覆わない。`'unsafe-inline'` も無い |
| `href="javascript:..."` | **止まる** | 同上 |
| `eval` / `new Function` | **止まる** | `'unsafe-eval'` が無い |
| HTMLに `<style>` ブロックを書く | **止まる** | `style-src 'self'` にインライン許可が無い（現状0件） |
| HTMLに `style="..."` 属性を書く | **止まる** | 同上（現状0件） |
| JSから `el.style.color = …` / `el.style.cssText = …` | **通る** | CSSOM経由は対象外。実測で6ファイル8箇所使われている |
| 外部CDNのCSS・Webフォント | **止まる** | `style-src` / `font-src` が `'self'` |
| 外部の画像を `<img>` や `background-image` で読む | **止まる** | `img-src 'self' data:`。data URI のSVGは通る（CSSで4箇所使用中） |
| 別オリジンのAPIを `fetch` する | **止まる** | `connect-src 'self'`。**`server/` を別ドメインに置いても呼べない** |
| `<form>` を置いて送信する | **止まる** | `form-action 'none'`。現状フォームは0件 |
| このサイトを他所のページに `iframe` で埋める | **止まる** | `frame-ancestors 'none'`。手元のプレビューをiframeに入れる場合も同じ |
| 許可された1ホストの動画を `iframe` で埋める | **通る** | `frame-src` に1件だけ列挙。実装は押されるまでiframeを作らない方式 |
| `<base>` タグでパスの基準を変える | **止まる** | `base-uri 'none'` |

### 書かれていないもの

- **`Cache-Control` が一切無い。** 配信側の既定値に任されている。671.5 KiB のライブラリも毎回の判断が配信側次第
- `Strict-Transport-Security` が無い
- `X-Frame-Options` は無いが `frame-ancestors` が同じ役目を果たす
- `media-src` `worker-src` は未指定なので `default-src 'self'` に落ちる

公開先の設定ファイル側にはヘッダーを書いていない。「両方に書くと片方だけ直した日に食い違う」という理由がコメントに明記されている。

- **補助のデータ**: `if (res.ok) x = await res.json()` で、失敗しても `catch` で素通り。実測4箇所で、内訳は `js/chara-detail.js` 1・`js/work-detail.js` 2・`js/tools-fanart.js` 1。**下層の詳細ページだけの話ではなく、二次創作のページも同じ扱い**

「読めなかった」と「0件」が同じ見た目になると、読む側は無いものと受け取って戻ってこない。そこを分けるために、**失敗の表示に空状態のクラスを使わないこと**をスモークテスト4本目が固定している（許すのは `load-error` と `catalog-notice` の2つだけ）。

`js/main.js` の共通パーツ読み込みも同じ方式で、失敗時は「共通部分を読み込めませんでした」を差し込む。黙って空にすると、どこへも行けないページが普通の見た目で出てしまうため。

## 8. テーマの切り替え方

### 描画前に決める仕組み

保存先は `localStorage` の `"theme"` ただ1キー。値は `"dark"` / それ以外（＝light扱い）。

全16ページの `<head>` に、**バイト単位で同一の**短いインラインスクリプトが入っている。

```js
try {
  var t = localStorage.getItem("theme");
  document.documentElement.setAttribute("data-theme", t === "dark" ? "dark" : "light");
} catch (e) {}
```

`js/main.js` を待つと、その間ライトで描画されてダーク利用時に毎回画面が白く光る。それを避けるために `<head>` で同期実行している。この16ページ分が配信ヘッダーのハッシュ1種に畳まれているので、**1ページだけ直してもテーマの先読みは死なない**（同一バイト列を保つ限り）。逆に、ここを1文字直して組み立て直さずに配ると、先読みだけが黙って止まる。`try/catch` があるので、ストレージが使えない環境でも先読み自体は落ちない。

### 切り替えの実装（`js/main.js`、184行）

- `<head>` が決めた `data-theme` を**読むだけ**。決め直さない（決め直すと一瞬だけ別テーマで描かれる）
- ボタンはJSで生成して `document.body` に追加。`aria-pressed` を同期させる
- 切り替え時に `:root` へ `is-theme-shifting` を付け、**400ms後に外す**。CSSの `--dur-base` は320msなので80msの余裕
- `localStorage.setItem("theme", next)` は **`try/catch` に包まれていない**。しかも順序が「テーマ適用 → 保存 → `aria-pressed` 更新 → ラベル更新」なので、ストレージが使えない環境では**画面の色だけ変わって、ボタンの表示が前のまま残る**

### OSの設定は見ていない

`prefers-color-scheme` の参照は**CSS・HTML・JSのどこにも無い**（全ファイル走査で0件）。既定は常にライト。OSがダークでも初回はライトで出る。

### CSSトークン

カスタムプロパティの宣言はファイル全体で61箇所あるが、内訳は `:root` に**44個**、`[data-theme="dark"]` ブロックでの上書きが16個、`@media (max-width: 768px)` 内の `:root` で `--tilt` を潰すものが1個。**トークンの実体は44個**で、残り17個は同じ名前の再定義。

16進数の直書きは**この2ブロック（と設計意図のコメント）の中だけ**で、他では一切使われていない（コメントを除いた全行走査で確認）。トークンの正は `css/style.css` の `:root` 側で、設計資料は差分の記録にとどまっている。

地によって読める色が入れ替わるため、ライトとダークで主役の色そのものが違う。**片方だけ見て色を足すと、もう片方で読めなくなる。** コントラスト比の実測表は制作ルールにある（本文16.24:1／17.24:1、主役8.43:1／8.51:1 など）。

`@media (max-width: 768px)` が9箇所（489・641・1047・1612・2218・2333・2528・2879・3331行）、`@media (max-width: 1024px)` が1箇所、`@media (prefers-reduced-motion: reduce)` が2箇所。狭い画面では `:root` の `--tilt` を `0deg` にして傾きを一括解除している。波括弧の収支は0で、閉じ忘れは無い（コメント除去後に検算。開き481・閉じ481）。

### なぜ切り出したか

本体を丸ごと枠組みに載せる案と比較して、別アプリに切り出す側で決着している。理由が記録されている。

1. 公開中の14ページを全面移植するリスクを避けたかった
2. 本体の制約は「訪問者のIPを守るため」のものであって、**サーバー側で外部APIを叩く分にはブラウザが直接外部に繋がらないので、その理由自体は脅かされない**

### 安全側の作り

- 外部への取得先は**環境変数の許可リスト方式で、未設定なら一切取得しない**。認証が無く誰でも叩けるため、任意のURLを取る口を既定で開けない
- SSRF（内部向けアドレスへの踏み台化）対策の試験が複数ある。「同じ宛先でも書き方を変えると抜ける」「IPv6リテラル」「リダイレクト先」「検査の順番で判定が変わらない」まで見ている
- 書き換え系は `Content-Type: application/json` を必須にしている。**「CORSヘッダーを付けなければ守られる」が誤りだから。** `text/plain` などの単純リクエストはブラウザが確認なしに本文ごと送り、応答が読めないだけで処理は実行される。`application/json` は単純リクエストに該当しないので必ずプリフライトが飛び、許可ヘッダーを返していないそこで止まる
- 本文上限8 KiB
- 読み取り系は `Access-Control-Allow-Origin: *` で `GET, OPTIONS` を誰にでも許可。公開情報の読み取りだけで認証もCookieも扱わないため。**非公開データを足すならこのファイルを真っ先に見直すこと**と明記されている
- APIキーに `NEXT_PUBLIC_` を付けないよう `.env.example` に注意書きがある（付けるとブラウザのバンドルに入って誰でも読める）
- **環境変数は4件。** `.env.example` のキーも `server/app`・`server/lib` 内の `process.env` 参照も、動画サイトのAPIキー1件・`LINK_PREVIEW_ALLOWED_HOSTS`・`MEDIA_ALLOWED_HOSTS`・`MEDIA_STORE_DIR` の4つで一致する。`.env.example`（キー名だけ）は追跡し、`.env*` は除外する設定

### 親との干渉・本体との接続

親にも `package-lock.json` があるため、開発サーバーがワークスペースの根を誤認する。`next.config.ts` で自分自身を明示して警告を消している。

接続は未完。本体の催事ページからこのAPIを呼ぶボタンは未実装で、APIは動く状態だがUIの決め方を保留している。**さらに、本体の配信ヘッダーが `connect-src 'self'` で閉じている。別ドメインに置いたこのAPIは、ブラウザがそもそも呼ばせない。** 接続するには `tools/build-site.js` の宣言に接続先を書き足す必要があり、それは「外部リクエストはゼロ」の制約そのものを動かすことになる。

画像取り込みの控え置き場は既定で `server/.media`（除外済み）。**サーバーレスの一時領域を指定しないこと**と明記されている（再起動で消える）。
