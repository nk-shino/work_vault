# 03_自動スキル化

# タスク:繰り返し失敗時の自動スキル化ルールの導入(常時有効)

## 仕組み(リポジトリの AGENTS.md にも同じ内容を書く)
1. **失敗の記録**:問題・バグ・エラーが発生したら、解決の成否にかかわらず
   その都度 `.learnings/ERRORS.md` に記録する。
   形式: `[ERR-YYYYMMDD-XXX] 概要` + 発生コマンド/状況 + 解決法
   (解決時点で追記)。Pattern-Key(失敗パターンの識別子、例:
   `board.sh.field-id-mismatch`)を必ず付ける。
2. **再発の検知**:失敗前に `grep "Pattern-Key" .learnings/ERRORS.md` で
   過去の同一失敗を探す。同一 Pattern-Key があれば Recurrence-Count を
   増分し、See Also で紐付ける。新規の失敗は新規エントリ。
3. **解決時の固定**:問題を解消した時点で、エントリに
   「解決法/工夫/再発防止の確認方法」を追記し Status を resolved にする。
   この時点で解決法が未記録なら作業を完了とみなさない。
4. **自動スキル化の発火条件**(3条件):
   - Recurrence-Count >= 2
   - Status が resolved(解決法の動作確認済み)
   - 失敗が同一作業内ではなく別セッション/別タスクでも起きた
   条件を満たしたら、次の作業開始時に自動でスキルを作成する。
5. **スキル作成**:`.claude/skills/<skill-name>/SKILL.md` を作成する。
   - name はフォルダ名と一致(小文字・ハイフン)
   - description に「どんな失敗で使うか」を書く(発火条件を含む)
   - 本文は「症状 → 原因 → 解決法 → 確認手順」の4項目で書く
   - プロジェクト固有のパスや値はハードコードせず変数化する
   - 作成後、元のエントリを promoted_to_skill に更新し Skill-Path を記録
6. **レビューへの接続**:スキル作成も1つの成果物として issue を起票し、
   SKILL.md の内容をコメントして「レビュー」へ。人間の承認で完了
   (スキル自体は即時利用可能。レビューで改善指摘があれば反映する)。

## 品質ゲート(スキル化の前の確認)
- [ ] 解決法は実際に動作を確認済みか
- [ ] 元の文脈がなくても手順が再現できるか
- [ ] 既存スキルと重複していないか(`.claude/skills/` 一覧と照合)
