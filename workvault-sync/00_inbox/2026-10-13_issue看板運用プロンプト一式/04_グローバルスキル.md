# 04_グローバルスキル

# タスク:グローバルスキル2件の作成(全プロジェクトへ一括適用)

## 共通ルール
- 作成先:`~/.config/kohden-code/skills/<skill-name>/SKILL.md`
  (グローバル配置。全プロジェクトで自動的に利用可能になる)
- 認証情報(パスワード・トークン・キー)はスキルに書かない。
  アカウントの識別子(メールアドレス等)と確認コマンドのみ記載する

## スキル1: task-account-router(タスク別アカウントの区別)
- description: タスク開始時・アカウントをまたぐ操作前に、生活用/業務用/
  サイト構築用のどのアカウントで作業すべきか判定し、実際の使用アカウントと
  照合する。git commit/push、gh コマンド、デプロイの前と、新規プロジェクト・
  新規問題対応の開始時に必ず使う
- 本文は「対応表 → 確認手順 → 切替手順 → 発火条件」で書く:
  - 対応表(埋める):生活用={{識別子}}/業務用={{識別子}}/
    サイト構築用={{識別子}}。判断基準(例:業務リポジトリ=業務用、
    個人学習=生活用、Web公開物=サイト構築用)も記載
    ※プロジェクト/問題ごとにチャットセッションを分ける運用のため、
    「このセッションはどの区分か」をセッション開始時に確認する
  - 確認手順:`git config user.name` / `git config user.email` /
    `gh auth status` を実行し、期待アカウントと一致しなければ
    作業を停止してユーザーに報告する(黙って続行しない)
  - 切替手順:各アカウントへの切替方法(git config --local、
    gh auth switch など)を具体的に記載
  - 発火条件:コミット前/push前/issue・project操作前/新規セッション開始時
- 失敗パターンキー:`account.wrong-identity`(誤アカウントでのコミット)

## スキル2: forced-logging(記録の確実化)
- description: タスク完了を報告する前に、実行ログと学習記録が
  実際に書かれたかを検証する。「完了しました」と報告する前、
  git commit の前、セッション終了前に必ず使う
- 本文は「記録ルール → 検証手順 → ゲート」で書く:
  - 記録ルール:指示1件=実行ログ1エントリ
    (YYYYMMDD_<topic>/実行ログ_YYYYMMDD.md に
    指示/実施/成果物/状態+コミット番号)。失敗は .learnings/ERRORS.md
  - 検証手順:完了宣言前に grep でログエントリの存在を確認する。
    なければ先に書く。エントリの不足(指示/実施/成果物の欠落)も補完する
  - ゲート:ログ未記載のまま完了報告・コミットをしない。
    報告には検証結果(確認したファイルと行番号)を含める
- 失敗パターンキー:`logging.missing-entry`

## 導入手順
1. 2スキルをグローバルディレクトリに作成する
2. ワークスペース AGENTS.md に追記:「アカウント照合は
   task-account-router、記録検証は forced-logging で行う」
3. 動作確認:テストコミットを1回行い、(a)アカウント照合が動くか
   (b)ログ検証が完了報告を阻止するか を確認して結果をログに残す
