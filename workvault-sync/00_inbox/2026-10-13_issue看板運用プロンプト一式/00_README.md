# issue看板運用 構築プロンプト一式

「issue起点・人間は看板レビューのみ」の運用基盤を構築し、既存タスクの起票、
失敗からの自動スキル化、アカウント区分と記録の確実化までを1本の実行順に
まとめたプロンプト集。**実行は 00 のオーケストレーションを最初に1回
貼り付けるだけ**(フォルダ全体を読ませ、番号ごとに停止確認しながら進む)。

## 実行順とファイル一覧

| 番号 | ファイル | 区分 | 内容 |
|------|---------|------|------|
| 00 | `00_実行オーケストレーション.md` | 実行 | 順次実行の手順(最初に貼る。1個ずつ停止確認しながら進める) |
| 01 | `01_基盤構築.md` | 構築 | リポジトリ・看板・雛形の新規構築(前提チェック付き) |
| 02 | `02_既存タスク起票.md` | 移行 | 既存タスク・アクションのissue一括起票 |
| 03 | `03_自動スキル化.md` | 運用 | 繰り返し失敗の記録と自動スキル化ルール |
| 04 | `04_グローバルスキル.md` | 運用 | アカウント区分・記録確実化のグローバルスキル2件 |
| 05 | `05_実行ロードマップ.md` | 運用 | issue作業の実行フェーズ定義(P0〜P5) |
| 99 | `99_ワークスペース作業.md` | 補助 | 番号付きプロンプトの雛形(調査系タスク用) |

## 運用フロー全体像

```
01構築 → 02既存タスク起票 → (issue起点の作業: 05ロードマップで実行)
  → 失敗時は03で記録 → 繰り返し失敗は03で自動スキル化
  → アカウント照合(04)と記録検証(04)が全工程で常時有効
  → 人間は看板「レビュー→完了」の移動のみ
```

## 共通の埋め項目(00 実行前に埋めるのは 00 のパスのみ。残りは各番号の報告時に指示)

- 00:フォルダパス
- 01:リポジトリ名/公開区分/配置先/看板タイトル/レビュアー/主な使い方、
  git user.name と user.email(未設定の場合は01の前提チェックで確認される)
- 02:既存タスクの所在と起票粒度
- 04:アカウント対応表の識別子

## 注意

- `gh` CLI 未導入・未認証の場合、01 は前提チェックで停止する
  (事前に `winget install GitHub.cli` と `gh auth login` を済ませる)
- `gh auth login` 後に **`gh auth refresh -s project` が必要**
  (既定スコープでは看板操作が全部失敗する)。01 の前提チェックで確認される
- 01 実行前に git の user.name/user.email 未設定なら、01 内で確認される。
  事前に設定しておくと停止が1回減る
- 看板のステータス列は既定フィールドの代わりに新規フィールド
  「ステータス」を作る(既定の選択肢はCLIで編集不可のため)
- issue 追加直後は「ステータス」が空欄になる(Projects V2 仕様)。
  空欄=Backlog 扱いにするか board.sh で Backlog を設定する(01/02で案内)
- 02 の大量起票前には必ず確認で1回止まる
- 認証情報はどのプロンプト・スキルにも書かない
