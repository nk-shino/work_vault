# 02_既存タスク起票

# タスク:既存タスク・アクションの起票(01_基盤構築の完了後に実施)

## 入力(埋める)
- 既存タスクの所在:{{例: 20261013_xxx/配下のmd資料 / 前回調査報告書 /
  Teamsの議事録コピペ / 下記に直接列挙}}
- 起票の粒度:{{1アクション=1issue(推奨) または まとめ単位を指定}}
- 優先度の考え方:{{例: 調査系が先/期日が近いものが先}}

## 手順
1. **既存タスクの抽出**:指定資料を読み、アクション項目を漏れなく
   リストアップする。各項目に [出典ファイル名/行番号] を付ける。
2. **起票前の確認**:抽出した項目一覧(タイトル+出典のみ)を
   ユーザーへ提示し、重複・不要項目・粒度の確認を取る
   (大量起票の前に必ず1回止まる)。
3. **起票**:`.github/ISSUE_TEMPLATE/task.md` の4項目
   (ゴール/受け入れ基準/既知情報/出典)を埋めて
   `gh issue create` で作成する。
   - 既知情報は元資料から [事実|推定|未確認] に分類して転記する
     (出典なき断片は「未確認」)
   - 項目間の前後関係が分かるものは本文に関連issue番号を記載する
   - タイトルは「何を答える/何を作るか」で、50文字目安
4. **看板への反映**:`gh issue create -p "{{看板タイトル}}"` で直接
   プロジェクトに追加する(自動追加ワークフローが動いていなくても確実)。
   自動追加ワークフローが有効な場合は `-p` を省略できる。
   確認は `gh project item-list <番号> --owner @me --field "ステータス"`
   で行う。載っていないものがあれば手動追加する
   (`gh project item-add`)。注意:追加直後は「ステータス」が空欄。
   空欄のまま Backlog 扱いとするため、列グループの設定で
   「空の値」を Backlog と同じ扱いにするか、全issueに board.sh で
   Backlog を設定する(02 の報告時にどちらかを案内)
5. **報告**:起票済みissueの一覧(番号/タイトル/出典/関連)を表で出力し、
   実行ログに記録する。元資料のどの行がどのissueになったかが
   追跡できることを完了条件とする。

## ルール
- 元資料の文言を勝手に要約しすぎない。曖昧な項目は本文に
  「元記述:◯◯」を残す
- アクションではない文章(背景メモ等)は起票せず、
  適切なissueの既知情報に統合するか、破棄候補として報告する
