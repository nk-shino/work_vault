# 社用PC側で確認 ── エージェント9本が本当に読み込まれているか

**社用PCでしか確かめられないので、ここに置く。** 私用PC側からは見えない。

## 何を疑っているか

2026-10-30 の指示に「kohden code という固有名詞は claude code と解釈する」とあった。

もしこの2つが同じものなら、2026-10-30 に社用PC側へ配備した9本は
**置いてあるだけで一度も読み込まれていない。** 理由は2つある。

1. **場所が違う。** 配備先は `.kohden-code/agent/` と記録されている。
   Claude Code が見るのは `.claude/agents/`
2. **書式が違う。** 「原文のままコピー（書式は Kohden Code 向けのため移植不要）」と記録されているが、
   Claude Code は frontmatter に `name:` `description:` `tools:` を要求する。
   保管庫の原本にある `mode:` `permission:` は読まない。
   とくに `tools:` が無いと、そのセッションの全ツールを引き継ぐ
   （Discord への返信・Drive の共有と削除・カレンダーの作成と削除・定期タスクまで）。
   `edit: deny` と書いてあっても、道具の側では止まらない

別物（社内配布の派生ツール）なら、記録はそのままで正しい。**どちらなのかが分からない。**

## 確かめ方

社用PCのワークスペース直下で、次のどちらが在るかを見る。

```
.claude/agents/
.kohden-code/agent/
```

- `.claude/agents/` が在る（または `.kohden-code/` が無い）→ **同じもの。** 配備はやり直しが要る
- `.kohden-code/agent/` だけが在り、そのツールが実際に起動して役を呼べている → **別物。** 記録は正しい

起動できるかどうかで判断するほうが確実である。社用PC側でサブエージェントを1体呼んでみて、
役の名前（`site-research` など）で解決するなら読み込まれている。
名前が見つからないと言われるなら読み込まれていない。

## やり直しが要る場合

私用PC側で同じ移植を済ませている。手順と、移植で足した4点は保管庫の

`00_site-devlops/03_共通と運用/エージェント構成_20261029/README.md` の §3b-2

に書いた。**同じものをそのまま当てればよい。** 形式検査の道具も置いてある。

```
node .claude/check-agents.js .claude/agents
```
