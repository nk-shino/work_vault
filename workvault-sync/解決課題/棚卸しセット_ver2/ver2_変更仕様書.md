# 棚卸しマクロ ver.2 変更仕様書

対象: `リール消費マクロ.xlsm` / `ラベル再発行マクロ.xlsm` の処理を引き継いだ2モジュール
作成日: 2026-10-05
適用者: （実機で適用した人が記入）

> # まだ動かしていない
>
> **このPCには Excel の COM が登録されていないため、コンパイルも実行もしていない。**
> 本書は**コードを読んで書いた設計の説明**であって、動作の確認結果ではない。
>
> **まず `設定` シートの既定（試し実行・1件）のまま走らせて、
> ログシートに何が記録されるかを見ること。**

---

## 1. この文書の目的

旧版の2ファイルに何があり、ver.2 で何をどう変えたかを、
**この文書だけで妥当性を判断できる形で記録する。**

読み手として想定しているのは、この改修に関わっていない第三者である。

## 2. 前提として断っておくこと

**0確認マクロ ver.2 では、原因の特定を誤った。**
「`PtrSafe` の欠落と重複宣言が原因」と報告したが、**変更前のコードにも同じ2箇所があり、
それで現場では動いていた。**結果として ver.2 は何も変えずに動いた
（`0確認マクロver2_変更仕様書.md` の冒頭に訂正を入れてある）。

**その反省から、本書では「コードで確認した」と「疑い」を分けて書く。**
抽出は `olevba 0.60.2` で、`リール消費マクロ` 259行・`ラベル再発行マクロ` 336行を読んだ。

---

## 3. 旧版の構造

両ファイルは同じ骨格を持つ。

1. 相手アプリの窓のタイトルが目的の値になるまで `Do ... Loop` で待つ
2. B列の最下端を見て再開位置を決める
3. 1行ずつ、窓の左上から決まった量ずらした点をクリックし、`SendKeys` で
   シリアルと Enter などを送る
4. 窓のタイトルを読んで結果を判定し、B列に `○` か `無し` を書く
5. 想定外のタイトルなら `MsgBox "中断"` で止める

**判定も中断もすべて「窓のタイトル」に依存している。**
相手アプリの中の状態を直接見る手がかりは無く、これは変えられない。
ver.2 もタイトルを見る方式のままである。

---

## 4. 変更内容

### 4-1. 2ファイル・5処理を1組のモジュールへ統合した

| 旧版 | ver.2 |
|---|---|
| `リール消費マクロ.xlsm` の Module1（ゼロ確認・外部出庫） | `modTanaoroshi.リール消費_実行` / `外部出庫_実行` |
| `ラベル再発行マクロ.xlsm` の Module1（ラベル再発行・ゼロ確認・外部出庫） | `modTanaoroshi.ラベル再発行_実行` ほか |
| 両ファイルの Module2（getMouseCoordinate） | `modWinAuto.ShowCursorPos` / `modTanaoroshi.座標を測る` |

**0確認の処理が3ファイルに写されており、片方だけ直った状態が実在した。**
同じ直しを3回する構造そのものをやめた。

### 4-2. 宣言の重複を解消した

**旧版は Module1 と Module2 の両方で `Type coordinate` と
`Declare Function GetCursorPos` を公開宣言していた。**

```vba
' Module1 にも Module2 にも、どちらにもあった
Type coordinate
    x As Long
    y As Long
End Type
Declare Function GetCursorPos Lib "user32" (lpPoint As coordinate) As Long
```

**これはコンパイルエラーになる**（「名前が適切ではありません」）。
ver.2 では `modWinAuto` に `Private` で1組だけ持つ。
モジュール全体に `Option Private Module` を付けて、外へ漏らさない。

### 4-3. `PtrSafe` の付け漏れを直した

旧版は上の4つ（`GetForegroundWindow` `GetWindowRect` `GetWindowTextLength`
`GetWindowText`）に `#If Win64` で `PtrSafe` を付けていたが、
**`GetCursorPos` `SetCursorPos` `mouse_event` は素の `Declare` のままだった。**

**64bit版Excelではこの3つでコンパイルが止まる。**32bit版なら通る。
`めも.txt` の「現場PCは32bit版の可能性がある」と整合する。

ver.2 は**分岐を `#If VBA7` に変えて、全宣言を揃えた。**

| 理由 | 内容 |
|---|---|
| `PtrSafe` が使えるかは Office の版で決まる | VBA7 = Office 2010 以降。**32bit か 64bit かでは決まらない** |
| `LongPtr` は VBA7 なら両方に通る | 32bit で `Long`、64bit で `LongLong` に解決される |
| 結果 | **分岐が1本で済み、32bit を切り落とさない** |

あわせて次の2つの型も直した。

- `Sleep` の `dwMilliseconds` は DWORD。**旧版は `LongPtr` にしていた**
- `mouse_event` の `dwExtraInfo` は ULONG_PTR。**旧版は `Long` のまま**だった

### 4-4. 窓を1回つかみ、以後その窓だけを見る

**ここが最も大きい変更。**

旧版の `getWindowTitle` は、呼ばれるたびに `GetForegroundWindow` を呼び、
**「そのとき前面にある窓」のタイトルを読んでいた。**

```vba
' 旧版。毎回「前面の窓」を見ている
hWnd = GetForegroundWindow
```

**他のアプリの通知が前に出た瞬間に、別の窓のタイトルで分岐する。**
リール消費は取り消せるか未確認なので、ここが一番危ない。

ver.2 は `FindWindow` で目的の窓をつかみ、**その取っ手に対して
`GetWindowText` を呼ぶ。**前面が入れ替わっても、読む対象は変わらない。

### 4-5. キーを送る前に、前面になったことを確かめる

**`SendKeys` は前面の窓へ送る。**旧版は前面を確認せずに送っていた。
**前面が別の窓のままなら、入力はそちらへ流れる。**

ver.2 は `SetForegroundWindow` を呼んだあと、
**実際に `GetForegroundWindow` が目的の窓になるまで待ち、
ならなければ送らずに中断する。**

```vba
If Not modWinAuto.SendTo(EscapeKeys(serial)) Then
    observed = "前面にできなかった"
    ProcessOne = "中断": Exit Function
End If
```

### 4-6. 固定の待ちを「その状態になるまで待つ」に変えた

旧版は `Sleep 100` `Sleep 250` `Sleep 500` `Sleep 3000` を手順の間に置いていた。

| 問題 | 内容 |
|---|---|
| 短すぎると打ち漏らす | 遅いPCでは画面が追いつかない |
| 長すぎると終わらない | **ラベル再発行は1件あたり合計約5.6秒。5,848件で約9時間** |

ver.2 は `WaitForTitle` / `WaitTitleChangeFrom` で、
**条件が満たされ次第進む。**待ちの上限は設定シートに置いた（既定5秒）。

**印刷の待ちだけは固定のまま残した。**
印刷の完了が窓のタイトルに出ないため、待つ手がかりが無い。
**実機で完了が画面に出るなら、そこを待つ形に変えられる**（§7 No.4）。

### 4-7. 送信漏れと「在庫あり」を区別した

**旧版はタイトルが変わらなかった場合を「在庫あり」として扱い、
Enter を3回送っていた。**

```vba
If getWindowTitle(...) = "倉庫管理アプリケーション" Then
    ' 在庫なし
Else
    ' ここに「送信漏れ」も落ちてくる
    SendKeys "{ENTER}" : SendKeys "{ENTER}" : SendKeys "{ENTER}"
```

**打てていないのに ○ が付く。**
ver.2 は3つに分けた。

| タイトルの変化 | 判定 |
|---|---|
| 戻り画面になった | `無し`（在庫なし） |
| **変化しなかった** | **`中断`。送信漏れの疑いとしてログに残す** |
| 別の画面になった | `○`（在庫あり）として確定まで進める |

**Enter を3回送っていた理由は分かっていない。**
画面側に3段階の確認がある可能性があるため、§7 No.5 に残した。

### 4-8. 再開位置の判定を直した

```vba
' 旧版
If Cells(Rows.Count, 2).End(xlUp).Row = 1 Then
    startRow = 1
Else
    startRow = Cells(Rows.Count, 2).End(xlUp).Row + 1
End If
```

**B1 に何か入っていて B2 以降が空のとき、`End(xlUp).Row` は 1 になる。**
その結果 `startRow = 1` となり、**1行目をもう一度処理する。**
リール消費では二重計上になる。

ver.2 は **B1 自体が空かどうかを見る。**

```vba
ElseIf lastB = firstRow And Len(Trim$(CStr(ws.Cells(firstRow, COL_RESULT).Value))) = 0 Then
    ResumeRow = firstRow
```

### 4-9. シートを明示した

旧版の `Cells(...)` にはシート指定が無く、`ActiveSheet` に対して動いていた。
**設定シートやログシートを開いたまま実行すると、そちらへ結果を書く。**

ver.2 は `Set ws = ActiveSheet` で1回だけ取り、
**設定シートとログシートが選ばれていたら実行前に止める。**

### 4-10. 送る値を `.Text` から `.Value` に変えた

**`.Text` は「表示されている文字」を返す。列幅が狭いと `###` になる。**
シリアルが文字列として入っていれば起きないが、
数値と解釈された列では起きる。**疑いとして挙げ、`.Value` に変えた。**

### 4-11. 空欄を送らない

旧版は A列が空でも `SendKeys` を呼び、Enter を送っていた。
**入力欄に残っていた前の値が確定される余地がある。**
ver.2 は `空欄` と記録して次の行へ進む。

### 4-12. ログシートを追加した

旧版は B列の `○` しか残らず、**中断したとき何が見えて止まったのかが分からなかった。**

| 列 | 内容 |
|---|---|
| 日時 | 秒まで |
| 行 | シートの行番号 |
| シリアル | 先頭に `'` を付けて文字列として保存 |
| 結果 | ○ / 無し / 試 / 空欄 / 中断 / 異常終了 |
| 見えた内容 | **そのとき読んだ窓のタイトル、または中断の理由** |

### 4-13. キーの記号を逃がした

`SendKeys` は `+ ^ % ~ ( ) { } [ ]` を修飾キーや括りとして解釈する。
**旧版はシリアルを素のまま渡していた。**
現状のシリアルには含まれていないが、**品番の付け方が変わると黙って壊れる。**
ver.2 は `{+}` の形に置き換えて渡す。

### 4-14. 座標を設定シートへ出した

旧版は `WindowX + 180, WindowY + 69` のようにコードに埋め込んでいた。
**解像度・拡大率・窓のサイズが変わると実測しなおしになる。**

ver.2 は設定シートから読む。シートが無ければ初回実行時に既定値つきで作られる。

`座標を測る` は、**窓の左上からのずらし幅を直接表示する。**
旧版の `getMouseCoordinate` は画面の絶対座標だけだったので、
**窓の位置を別に調べて引き算する必要があった。**

## 5. なぜこの変更が安全といえるか

### 5-1. 業務の判定そのものを変えていない

**「どの画面が出たら在庫あり／無しとみなすか」は旧版と同じ。**
変えたのは、**そのタイトルを誰の窓から読むか**と、
**読む前に前面を確かめるか**である。

**判定の基準を増やしても減らしてもいない。**

### 5-2. 既定を「何もしない」側に倒した

| 設定 | 既定 | 理由 |
|---|---|---|
| 試し実行 | **はい** | キーを送らず、判定とログだけを取る |
| 件数の上限 | **1** | まず1件 |

**全件を流すには設定を2箇所変える必要がある。**
`0確認マクロは取り消せない`（Enter で処理が確定する）という既知の事実に合わせた。

### 5-3. 実行前に件数と範囲を出して止まる

```
作業: ReelConsume
窓:  リール消費【倉庫管理アプリケーション】
行:  1 〜 1
件数: 1 件

■試し実行。キーは送らない。判定とログだけを取る。
```

**旧版は確認なしで走り出していた。**

### 5-4. 止まる条件を増やした

| 止まる場面 | 旧版 | ver.2 |
|---|---|---|
| 窓が見つからない | **永久に回る** | 上限（既定30秒）で中止 |
| 窓が閉じた | 判定不能のまま進む | その行の手前で中断 |
| 前面にできない | **気づかず送る** | 送らずに中断 |
| タイトルが変わらない | **在庫ありとして ○** | 中断してログに残す |
| 確定後に戻らない | 中断 | 中断（**見えたタイトルをログに残す**） |

**どの場合も、止まった行番号とシリアルがログに残る。**

### 5-5. 取り消せない処理の範囲を広げていない

**キーを送る順番は旧版と同じ。**
Enter の回数が減る場合があるが、それは**画面が既に遷移していて
送る必要が無かった場合**に限る（§4-7）。

**送る相手を増やしていない。** 対象の窓は設定に書いた1つだけ。

### 5-6. 段階を分けて当てられる

| 段階 | やること | 確かめること |
|---|---|---|
| 1 | モジュール2本を取り込んでコンパイル | **エラーが出ないこと。32bit / 64bit のどちらで通ったかを記録する** |
| 2 | `座標を測る` | ずらし幅が 180/69・281/90 と一致するか。**違えば設定シートを直す** |
| 3 | 試し実行・1件 | ログに日時とタイトルが入ること |
| 4 | 試し実行・全件 | **全行ぶんの判定がログに並ぶこと。**キーは送っていない |
| 5 | 本番・1件 | 相手アプリ側で結果を目視 |
| 6 | 本番・10件 | B列と相手アプリの一致 |
| 7 | 本番・全件 | — |

**段階4が旧版にできなかったこと。**キーを送らずに、全件ぶんの画面判定だけを取れる。

## 6. 変更しなかったもの（意図的）

| 対象 | 理由 |
|---|---|
| タイトルで判定する方式 | **相手アプリの中を見る手がかりが無い。**UI Automation に替えるのは別案件 |
| `SendKeys` | **`SendInput` に替えても、相手が管理者権限なら届かない。**効果に対して変更が大きい |
| B列に `○` / `無し` を書く形 | **既存の運用がこの列を見ている。**変えると手順書も変わる |
| 1件ずつ送る形 | **アプリ側に一括取り込みがあるかを知らない。**あればマクロ自体が不要になる |
| 旧ファイル | **消していない。**`棚卸しセット` にそのまま残す |

## 8. 取り込み手順

1. 対象のブックを開き、Alt+F11 でVBEを開く
2. 旧 `Module1` `Module2` は**消さずに残す。**名前を `Module1_old` などに変える
   （**公開宣言が重複するとコンパイルが通らないため、名前の変更だけでは足りない。
   旧モジュールの先頭に `Option Private Module` を足すか、エクスポートして除去する**）
3. ファイル → ファイルのインポートで `modWinAuto.bas` と `modTanaoroshi.bas` を取り込む
4. デバッグ → VBAProject のコンパイル
5. ブックを `.xlsm` で保存
6. §5-6 の段階1から順に進める

**手順2が要点。**旧モジュールを残したままだと宣言が重複する。
**残すなら公開宣言を潰すこと。**
