# 要件充足と旧版同等性の検証

日付: 2026-10-20
判定方法: 旧版2本(`リール消費マクロ.xlsm`・`ラベル再発行マクロ.xlsm`)のVBA全文抽出(olevba 0.60.2)と ver.2 モジュール2本(`modTanaoroshi.bas`・`modWinAuto.bas`)のコード照合。実Excelでのコンパイル再実行(Office O365ProPlusRetail x86・16.0.20430.20180)。テストケース47件(`07_テストケース_ver2マクロ`)との突合。
証跡: workspace `20261013_tanaoroshi-v2/compile_test_20261015/ver2compile_test.xlsm`(旧モジュール残置+ver.2取込+コンパイル通過後のブック)。旧版の抽出物は検証時点の Temp で、本ノートの対照表に要点を記載した。
区分の定義: **静的確認**はコード照合による確認であり、実行確認ではない。実行確認は §5-6 段階5以降(実機)で行う。

## 1. 結論

1. 文書と設計の範囲の要件は満たしている。実行範囲は段階1(コンパイル)まで完了。テストケース47件のうち実機待ちが19件残る。
2. 旧版と同じ動作になる部分: 判定の基準(窓タイトルのみ)・クリック座標(180/69・281/90)・B列への書き方(○/無し)・ラベル再発行のキー列(TAB4→Enter→Shift+TAB9→Enter→Enter→3秒→Enter)・在庫なし経路のキー列(検索と確認を閉じる計2回のEnter)。
3. 旧版と意図的に変えた部分(仕様書 §4 に記録済み): 空欄行・送信漏れ・窓なし・前面阻害の扱い、待ち方、エスケープ、進捗表示。加えて**在庫あり経路と外部出庫の Enter 数が旧版と異なる**(旧版は検索のEnterの後に3回送る。ver.2は1回)。これは仕様書 §7 No.5「旧版が Enter を3回送っていた理由」に対応する未確認差分で、実機の本番1件で確定させる。画面側に3段階の確認が存在する場合、ver.2 は誤計上せず中断で止まる設計である。 利用者(2026-10-20)の読みでは、この3回は「判定の取りこぼしに備えて念のため送る」冗長送信である。無印のコードは在庫あり(確認画面が出た)場合も送信漏れの場合も分岐せず同じ3回を送り、段階ごとに回数を変えていない。この読みが正しければ ver.2 の1回が正しい回数で、残り2回は戻った作業画面に飛ぶ空撃ちだったことになる(§5 を更新)。

## 2. 旧版⇔ver.2 の動作対照

| 項目 | 旧版(無印) | ver.2 | 判定 |
|---|---|---|---|
| 判定の基準 | 前面の窓のタイトル | つかんだ窓のタイトル | 同一(読む窓を1つに固定した点のみ違い) |
| リール消費・ゼロ確認の座標 | 窓左上 +(180,69) | 設定シート既定 180/69 | 同一 |
| ラベル再発行の座標 | 窓左上 +(281,90) | 設定シート既定 281/90 | 同一 |
| 外部出庫のクリック | 無し(送信のみ) | 設定シート既定 180/69 | 変更(仕様書 §4-5。無入力の防止) |
| B列の値 | ○/無し | ○/無し/空欄/試/中断 | 同一+区分の追加 |
| 再開位置 | B列 End(xlUp)(B1だけ空欄のとき1行目を再処理する) | ResumeRow(B1の実値を見る) | 修正(仕様書 §4-8。二重計上の防止) |
| 空欄行 | Enter を送る | 送らず「空欄」でスキップ | 変更(§4-11) |
| 窓が無いとき | 永久ループ | 上限30秒で停止 | 変更(§4-6) |
| 処理中に窓が閉じた | タイトル取得が失敗したまま継続 | その行の手前で中断 | 変更(§4-6) |
| 別窓が前面のとき | キーがそちらへ流れる | 送らないで中断 | 変更(§4-5) |
| 在庫なしのキー列 | serial→Enter→確認ダイアログ→Enter(計2回) | 同一列+戻り待ち | 同一 |
| 在庫ありのキー列 | serial→Enter→(確認画面)→Enter×3(計4回) | serial→Enter→(確認画面)→Enter(計2回)+戻り待ち | **差分(§7 No.5・実機確認)** |
| 外部出庫のキー列 | serial→Enter×4(計4回・クリック無し) | serial→Enter→Enter(計2回)+戻り待ち | **差分(同上)** |

| シリアルの記号 | 素渡し(+ ^ % ~ ( ) { } [ ] が別キーとして送られる) | 特殊文字をエスケープ | 変更(追補 §3-3) |
| 入力欄の前値 | クリックのみ(リール消費・外部出庫) | Ctrl+A で全選択してから入力 | 変更(残値の混入防止) |
| 進捗表示 | Goto で該当行へスクロール | StatusBar に n/planned と行番号 | 変更(追補 §3-7) |
| 32/64bit | Sleep を LongPtr で受ける誤り(64bitで動作不定) | VBA7 分岐・Sleep は Long・dwExtraInfo は LongPtr | 修正 |

旧版の抽出で確認できた補足: 旧版の`外部出庫`はクリックと前面確認が無く、Excel が前面のままでも送信が進む実装だった。ver.2 はどの作業でも送信前に前面を確認する。

## 5. 実機で確定させること

1. **在庫あり1件の本番(テスト[22])**: 確認ダイアログが1段階で、Enter2回(検索と確定)で確定まで進むか。利用者の読み(冗長送信)が正しければ進むはずで、在庫あり経路の同等性の懸念は解消する。2段階目の確認が実在すれば ver.2 は中断で止まる(誤計上しない)。その場合は ProcessOne へ Enter 1行の追加で対応できる。
2. **外部出庫1件(テスト[34])**: 同様に Enter2回で完結するかを確認する。座標 180/69 が外部出庫画面の入力欄に当たるかを実測で確認(テスト[7][8])。

3. **相手アプリの権限(テスト[5])**: 管理者権限で動いていると SendKeys 方式自体が不成立(§7 No.6)。
4. **取り消し可否(テスト[29])**: 全件実行はこの確認が済むまで禁止(§7 No.2)。
