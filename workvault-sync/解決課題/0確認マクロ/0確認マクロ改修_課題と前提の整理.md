## 2. いま最優先で解決すべき問題 → **2026-09-28 解決**

### 真因はコンパイルエラー。CSVは正しい

**入力ファイルは正常だった。** 添付CSV `2026_09_25_113916_EGProWhereHouse.csv` を全件（29,246行）読み直した結果：

| 項目 | 実際の値 |
| --- | --- |
| 総行数 | 29,246 |
| ロケーション `0確認(L1)` | 2,090 |
| ロケーション `0確認(L2)` | 1,496 |
| ロケーション `0確認(L3)` | 3,298 |
| 品番の種類 | 4,632 |
| **条件に合う行（0確認で始まる かつ 在庫数≦9）** | **5,848** |

「全て `棚`/`貯蔵`/`10000`、品番 `667654` のみ」という以前の記述は、**貼り付けられた冒頭部分だけを見た判断**だった。実ファイルは絞り込み済みエクスポートではなく全件。

**真因は VBA のコンパイルエラー。** 標準モジュールで宣言が重複している。

```
(A) PtrSafe 欠落   Module1 126・127・130行 / Module2 314行
                   79〜118行は #If Win64 と PtrSafe で守られているのに、この4本だけ素のまま。
                   このPCの Excel は 64bit なので、ここが先に落ちる。
(B) 重複宣言       Type coordinate / GetCursorPos が Module1 と Module2 の両方にあり、
                   標準モジュールの既定が公開のため名前が衝突する。
```

VBAはプロジェクト全体をコンパイルしてから実行するため、**`Input0_Click` を含めて何も動かない。**「0件」ではなく「一度も走っていない」が正しい。この重複は [[0確認マクロ_Excelデータ仕様書]] が9/16時点で既に指摘していた。

### ファイル仕様（確定）

*   文字コード: **UTF-8（BOM付き）**。
    
*   添付CSVの1行目は**見出し行**（`シリアル番号,品番,…`）。2026-09-28に実ファイルで確認。ただし見出し行のロケーション名称は `ロケーション名称` なので `Left(loc,3)="0確認"` に一致せず、読み飛ばし処理が無くても実害はない。
    
*   ラインの見分け方: ロケーション名称の**括弧内**（例 `0確認(L1)`）。手前が状態、括弧内がライン。
    

### 抽出条件（確定）

*   ロケーション名称が `0確認` で始まる（L1〜L3を**一括**対象、ライン限定しない）。
    
*   在庫数が **9以下**（9を含む）。
    
*   `棚`・`貯蔵` など `0確認` で始まらない行は除外。
    

### 既存マクロの挙動（確定）

*   A列のシリアルをリール消費画面へ送り、ウィンドウタイトルの変化で在庫有無を判定、B列に ○/無し を書く。
    
*   在庫数・単価の列は既存マクロに存在しない。判定に使うのはウィンドウタイトルのみ。
    
*   B列は**再開位置の判定**に使われる。→ 取り込み時にB列へ書くと途中再開になるため、**取り込みはA列のみ埋め、B列は空**。
    
*   **ラベル消去は不可逆**。
    

### 設計方針（確定）

*   既存のゼロ確認ループには手を触れず、**手前にCSV取り込みボタン/処理を増設**する。
    
*   **取り込みと消し込みは分離**。取り込み後に件数と中身を目視してから消し込みを実行（不可逆対策）。
    
*   テスト環境なし → 未検証のまま運用に入る前提。まず少数行で挙動確認してから本数を広げる。

## 4. これまで潰してきた（＝原因ではないと確認済みの）論点

*   ロジック（`Left(loc,3)="0確認"`、`<=9`、`IsNumeric`）自体は正しい。
    
*   全角/半角の `0` の取り違え → 確認済み論点（半角で統一）。
    
*   文字化け（UTF-8をShift-JISで読む問題）→ ADODB.Stream + Charset=UTF-8 で対応。
    
*   BOM → Charset=UTF-8指定で自動除去。
    
*   見出し行の読み飛ばし → 当該ファイルは見出しなしのため読み飛ばし処理を除去済み。
    

→ これらを反映した現行の取り込みマクロ（`Pasted_Text_...txt`）は技術的に妥当。**残る問題はコードではなく「入力ファイルの中身が想定と違う」点**。

## 6. 現行の取り込みマクロ（参考・確定版に近い）

*   ADODB.Stream + `Charset="UTF-8"`（BOM自動除去）
