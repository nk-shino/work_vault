# kohdenGPT⇔Claude 相互運用プロンプト集

作成 2026-09-14
更新 2026-09-14
狙い .mdファイルを両者で往復させるとき、そのままコピペで使えるプロンプトを一枚に集める
原則 正はkohdenGPT側のノート、Claudeは作業台。中身修正と階層整理は別トラックで回す

## 実態フロー

kohdenGPTはObsidianを直接読み書きできない。橋渡しは手コピーひとつ。

```
kohdenGPT でノート生成/更新
  → 自分で手コピーしてObsidianへ貼る(新規作成 or 上書き)
    → Claudeへ渡す
      → 戻りを検算してObsidianへ反映
```

事故が起きるのは手コピーの段。上書きすべきを新規で作る、新規にすべきを古い版へ上書きする、どのkohdenGPTノートがどのObsidianファイルか見失う。判断はkohdenGPTに任せ、自分は指示どおり手を動かすだけにする。この分担で迷いを消す。

## 使い方の地図

上から順に、エクスポート、修正トラック、整理トラック、取り込み前チェックの並び。必要な場面のブロックをコピーして使う。角かっこ部分だけ差し替える。転記の合言葉はセクション7にまとめた。

## 0. 共通のfrontmatter雛形

全ての.mdの先頭にこれを置く。idは不変の背番号、versionは片方向に増やすだけ。

```markdown
---
id: [TANAORO-000]
title: [ノート名]
source: kohdenGPT
version: v1
exported: [YYYY-MM-DD]
folder: [棚卸/仕様書]
links:
  - [リンク先ノート名]
status: [ドラフト]
---
```

## 1. kohdenGPTでエクスポートするとき

kohdenGPT（このObsidian環境）に投げるプロンプト。手コピー前提なので、頭に転記指示ブロックを必ず付けさせる。

```text
次のノートを、Claudeへ渡す.md形式で書き出してください。
本文の前に、私がObsidianへ手コピーするための転記指示ブロックを必ず付けてください。
書式は次の通りです。

=== Obsidian転記指示 ===
操作: [新規作成 / 上書き]
対象ファイル名: [TANAORO-003__固定テーブル棚卸し_詳細設計.md]
保存フォルダ: [棚卸/仕様書]
上書き時の確認: 冒頭のidが [TANAORO-003] であることを確認してから貼り替える
version: [v3 → v4]
========================

新規か上書きかは、frontmatterのidが既存かどうかで判断してください。
既存idなら上書き、新しい内容なら新規採番して新規作成としてください。

本文の条件です。
- 先頭に共通frontmatterを付ける。idは既存の背番号を使い、なければ新規採番する。
- 本文中の [[リンク]] は残しつつ、frontmatterのlinks欄にも平文で控える。
- versionは、上書きなら1つ上げる。新規ならv1。
- exportedに本日の日付を入れる。現在時刻を取得してから記入する。
対象ノート [ノート名]
```

## 2. 修正トラック Claude側

本文を直してもらう回。数値と固有名詞を守らせるのが肝。

```text
このmdファイルを編集してください。目的は[中身の修正内容を一言で]。

守る条件です。
- frontmatterのidは変更しない。
- versionを1つ上げる。
- 数値、固有名詞、コード値(例 201 202 203 213)は変更しない。言い換えもしない。
- 事実にない数字や事例を足さない。曖昧な箇所は曖昧なまま残す。
- links欄の項目を消さない。
- 変更点は本文末尾の変更ログに1行で追記する。書式は次の通り。
  - vX YYYY-MM-DD Claude [何をどう変えたか]。数値固有名詞は不変更。

編集後、変えた箇所の要点を3行以内で報告してください。
```

## 2の補助 修正内容だけ先に相談したいとき

```text
このmdを直す前に、直し方の案だけ出してください。まだ本文は書き換えないでください。
- どこを、なぜ直すべきかを箇条書きで。
- 数値、固有名詞、コード値には触れない前提で。
- 私がGOと言ったら、前回の編集条件で実際に書き換えてください。
```

## 3. 整理トラック Claude側

フォルダ階層を設計してもらう回。本文は渡さず一覧だけ渡す。中身を触らせない。
まずkohdenGPTで一覧を作る。

```text
次のノート群について、frontmatterの id title folder links status だけを
1枚の表にまとめて.mdで書き出してください。本文は含めないでください。
対象 [ノート名を列挙、またはフォルダ名]
```

その表をClaudeへ渡す。

```text
添付は各ノートの管理情報の一覧です。本文は含みません。
フォルダ階層の再設計案を出してください。

条件です。
- 各idに対する新しいfolder値を表で返す。列は id / title / 現folder / 提案folder / 理由。
- 実ファイルの中身は対象外。配置の指示だけを返す。
- 階層は深くしすぎない。3段までを目安にする。
- linksのつながりが近いものは同じ階層へ寄せる。
- 迷う分類は保留として理由を添える。断定で埋めない。
```

## 4. 取り込み前チェック kohdenGPT側

Claudeから戻ったファイルを、取り込む前に検算する回。

```text
これはClaudeが編集して戻したmdです。取り込み前に検算してください。
- idが元と一致しているか。
- versionが1つだけ上がっているか。
- 数値、固有名詞、コード値(201 202 203 213 など)が元から変わっていないか。変わっていれば全て列挙する。
- links欄の項目が減っていないか。
- 変更ログの記述と、実際の差分が食い違っていないか。
元ファイル [v-旧 の内容またはノート名]
新ファイル [戻ってきた内容]
問題があれば箇条書きで、なければ問題なしと返してください。
```

## 5. 往復の型

```
kohdenGPT でエクスポート(1) 転記指示付き
  → 自分で手コピーしてObsidianへ反映(セクション7の合言葉で確認)
    → Claude で修正(2) または 整理案(3)
      → kohdenGPT で取り込み前チェック(4)
        → 問題なければ手コピーでObsidianへ反映、folderは配置指示に従い移動
```

修正回は本文を触る。整理回はfrontmatterと配置だけ触る。この二つを同じ回で混ぜない。混ぜるとフォルダ移動の拍子に本文が化ける。

## 6. エクスポート台帳

往復のたびに1行足す。手コピーで貼り終えたらObsidian反映済に印を付ける。ここが未記入のノートは未完了とみなす。

```markdown
| id | title | kohden更新日 | 操作 | version | Obsidian反映済 | Claude渡し済 | 戻り反映済 |
|----|-------|-------------|------|---------|---------------|-------------|-----------|
| TANAORO-003 | 固定テーブル棚卸し_詳細設計 | 2026-09-14 | 上書き | v3→v4 | ✓ | | |
```

## 7. 手コピーの合言葉

貼る前に3つだけ確認する。致命的な事故はここで止まる。

*   開いているObsidianファイルのidと、転記指示のidが一致するか。ずれていたら上書きしない。
*   versionが下がる貼り替えをしていないか。v4の上にv3を貼らない。
*   操作欄が新規作成なら、同名ファイルがまだ無いか。上書きなら、狙ったファイルを開いているか。

貼り終えたら台帳のObsidian反映済に✓。ここまでを1セットにする。
