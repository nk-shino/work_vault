# 出典付き生成_参照範囲限定RAG_セットアップ手順

2026-10-15 作成。第3次調査（`10_業務全般/PanaCIM_LNB/03_記録/AI生成文問題の解決策_第3次調査_2026-10-14.md` §4.3・優先2）の実装手順。
ツール名を固定しない要件中心の記述とする。NotebookLM・社内生成AI・他ツールのいずれを採用する場合も、本書の要件を満たすことを採用条件とする。

## 0. 前提と禁止事項

- 社内規格・手順書・指図書の多くは社外秘に該当する可能性がある。**外部 SaaS への投入可否は、情報取扱規程の確認または情報管理担当の承認を得てから行う。**未承認のまま資料を投入しない
- 顧客情報・個人情報は参照範囲に含めない。含める必要が生じた場合は承認を取り直す
- 本手順は「生成AIに資料を読ませる」運用の安全性を確保するための最低要件であり、完了後も月次点検（§5）を省略しない

## 1. 目的と効果の目安

管理文書の根拠となる社内資料を参照範囲限定型のツールに集約し、生成物が「資料名・版・節番号つきの出典」を必ず持つ状態にする。

- 架空記述（ハルシネーション）の混入を構造的に減らす。出典を示せない記述は受け入れない
- 根拠資料の探索時間の削減。総務省ガイドブックの実測で約25%削減の報告あり（`https://www.soumu.go.jp/main_content/000820109.pdf`）
- 対象となる文書: 報告書・議事録・説明資料など、数値・規格・手順の根拠を引用する社内文書

## 2. 参照資料の選定

| 項目 | 基準 |
|---|---|
| 含める資料 | 規格書・標準手順書・過去の指図書・確定版の報告書。版管理されており、正本が一意に定まるもの |
| 含めない資料 | 個人情報・顧客情報を含むもの。版が確定していないドラフト。廃止済みで参照価値のないもの |
| 版の扱い | 改版時に旧版を参照範囲から削除する。旧版と新版が混在すると、生成物が旧版の記述を「正」として出典づけする恐れがある |
| 保管場所 | 資料の正本は現行の管理場所に残す。ツール側は参照用のコピーと位置づけ、正本をツールへ移管しない |

## 3. ツール要件（採用条件）

ツールを選定するとき、次の7項目を確認する。満たさない項目がある場合は運用で代替できるかを評価し、記録に残す。

1. **参照範囲の限定**: 指定した資料セットだけを参照する構成にできる。Web 全文検索や他プロジェクトの資料を混ぜない
2. **出典の提示**: 回答に出典（資料名・箇所）が付き、原票の該当箇所へ到達できる。出典番号クリック→原票ジャンプができることが望ましい
3. **アクセス権**: ツール上の資料へ、現行の閲覧権限と同等以上の制御ができる。全社公開ツールに社外秘資料が露出しない
4. **改版追従**: 資料の差し替え・削除ができ、参照範囲の現物と同期できる
5. **ログ**: 誰が・いつ・どの資料を参照して何を生成したかの記録が残る（または運用で代替できる）
6. **学習への非利用**: 投入した資料がベンダーのモデル学習に使われない契約・設定である
7. **退出可能性**: 運用終了時に資料を削除できる。ベンダーロックインの範囲を確認する

## 4. セットアップ手順

1. **投入資料リストの作成**: §2 の基準で資料をリスト化し、資料名・版・管理責任者を記す。承認者（情報管理担当または上長）の確認印を得る
2. **投入**: リストどおりに資料を投入する。リスト外の資料を投入しない
3. **到達確認（初回）**: 資料ごとに試問を3件以上行い、「出典の資料名・節番号が実在し、該当箇所に記載があるか」を原票で確認する。到達できない出典（存在しない節・版違い）が出た場合は参照範囲または資料の版を見直す
4. **プロンプト定型の組込み**: `DeAIプロンプト.md` §5 の定型（根拠を該当箇所で示す・該当なしと答える・記載値をそのまま写す・出典を示せない記述は書かない）をテンプレートに埋め込む
5. **運用開始の告知**: 対象メンバーに「出典確認の受入れ基準」（同 §5）と月次点検の日付を通知する

## 5. 月次点検

- 到達確認の再実施: 資料から2〜3件を無作為に選び、出典ジャンプの到達を原票で確認する
- 版の突合: 参照範囲の資料版と現行の正本の版を突き合わせる。改版があれば差し替える
- ログの目視: 参照・生成の記録をざっと確認し、想定外の資料や権限での利用がないかを見る
- 点検記録: 実施日・実施者・確認結果（到達可否・版差異の有無）を1行で記録する。記録先はこのファイル末尾またはチームの点検台帳

## 6. 失敗パターンと対処

| 症状 | 原因の候補 | 対処 |
|---|---|---|
| 出典に存在しない節番号が出る | 参照範囲に旧版が残っている・資料の節構成がOCR等で崩れている | 版を突合し、崩れている資料を投入し直す |
| 出典は正しいのに本文が資料と違う | 生成時の要約・換算 | プロンプト定型の「記載値をそのまま写す」を再指示し、当該記述を修正する |
| 「該当なし」が出ない（なんでも答える） | 参照範囲が広すぎる・定型が使われていない | 参照範囲を絞り、定型の使用を運用として必須にする |
| ジャンプ先が別資料になる | 資料名の重複・同一名称の版混在 | 資料名に版・日付を含める命名へ統一する |
