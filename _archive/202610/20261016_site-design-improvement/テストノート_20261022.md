# テストノート — Web実装テストケースと定期テスト（2026-10-22）

運用: セッション内のテスト作業は本ノートを介して行う。判定は LIG 記事の運用ルールに従い「できた（OK）／できなかった（NG）」の二値のみ。ペンディング・対象外は理由を明記する。

## 1. 基準と採用原則

基準: LIG「Webサイト制作におけるテスト工程の難しさ」(liginc.co.jp/397365, 2018)。

| 記事の原則 | 本プロジェクトへの適用 |
| --- | --- |
| Vモデル（単体→結合→システム→受入） | 4層を T-01〜T-12 として維持（単体 T-01・結合 T-02・システム T-03〜T-05・受入/非機能 T-06〜T-11・リグレッション T-12） |
| 二値判定・ペンディング禁止 | 本ノートの判定欄は OK/NG のみ |
| 「設定がそうなっているからOK」禁止 | 実際に動かして確認（ヘッダ等は curl で実測） |
| 境界値・同値分割 | T-07（検索0件/1件・データ0件） |
| 0件・大量データで漏れやすい | T-07 に空データ確認を含める |
| リグレッションは必須 | T-12: 修正後 T-01〜T-05 全再実行 |
| テスターと修正者は別が望ましい | AI が実装→自己テスト、ユーザー（または別セッション）が受入確認 |
| 代表デバイスで互換性テスト | §5 の端末マトリクス（7視点）+ 実機月次 |
| 記事のインフラ項目（PHP/nginx/バッチ等） | **対象外**。本サイトは静的配信で該当サーバー処理が存在しない |

## 2. 技術要件

- 静的サイト（HTML/CSS/JS・fetch で同 origin JSON）・ビルド工程なし・外部通信なし
- 依存パッケージなし（テストは Node 標準ライブラリのみの `tools/run-tests.js`）
- 厳格 CSP（`_headers`）・ダーク/ライト自動切替・印刷対応・noscript 案内
- 公開: Cloudflare Pages（`*.pages.dev`）前提。本番確認項目は本番化後に有効化

## 8. 運用ルール

1. 判定は OK/NG の二値。理由のある例外（対象外等）のみ注記を許す
2. 実測で確認（ヘッダは curl、件数は evaluate の実測値）。「設定上そうなっている」を根拠にしない
3. 修正を入れたら T-12（リグレッション一式）を必ず実行してからコミット報告
4. 実装者（AI）と受入確認（ユーザー/別セッション）は分離
5. 発見事項は本ノートの §5.2 形式（ID・重要度・内容・対応）で追記し、コミット番号を紐づける
