# 調査まとめ: 社内アプリ「連絡記録」モックアップ

## 前提

- 対象: 連絡事項の送信と記録を行う社内アプリのUIモックアップ（新規想定だが、既存社内ツールと同じ規律を適用する）
- 画面: ①連絡事項送信フォーム ②送信記録の一覧（テーブル、空状態を含む）
- 制約: 日本語、CSS変数による配色、ダークモード追従、絵文字は使わない（SVGまたはテキスト）。外部ライブラリ不使用の単一HTML
- 根拠は公式デザインシステムの使用指針ページのみ。ブログ記事・比較記事は根拠にしない

## 一次資料

| 系统 | 項目 | 出典(公式使用指針ページ) | 指針の要点 |
|---|---|---|---|
| Atlassian | Form | https://atlassian.design/components/form/usage | ラベルは全項目に付け、フィールド上・左寄せ。1カラム。必須項目がある場合はフォーム上部に「* 印は必須」の注記。送信ボタンを disabled にせず、バリデーションで導く。primary ボタンは1つ、キャンセルはリンク |
| Atlassian | Empty state | https://atlassian.design/components/empty-state/usage | 見出しが必須、次に何ができるかをCTAで示す。CTAは動詞の命令形。メッセージは短く |
| Atlassian | Flag | https://atlassian.design/components/flag/usage | 成功・警告等は bold flag（自動消滅は成功のみ可）。成功時は続けて取れる行動を示す。クリティカルな警告に自動消滅は使わない |

## 採用候補（部分採用）

**採用する**
1. フォーム規律（Atlassian Form）: ラベル上配置、1カラム、必須は「*」＋上部注記、送信ボタンは入力前も disabled にしない、primary は「送信する」1つ、キャンセルはリンク
2. 送信成功の通知（Carbon toast）: 画面右上、緑＋チェックアイコン、タイトル「送信しました」（句点なし）、本文は記録一覧への動線1文。消滅後も記録一覧で参照できる
3. 記録一覧のテーブル（Carbon Data table）: 列名は1〜2語（日時/宛先/件名/状態）、ソート中の列だけ矢印、行hover、ページネーション風の下部表示
4. 空状態（Atlassian Empty state）: 見出し＋短い説明＋「最初の連絡を送信する」CTA。図はSVG1点
5. エラー表示（GOV.UK Error message）: 汎用禁止、入力値保持、フィールド直下＋フォーム上部に全体の要点

**採用しない（理由を明示）**
- GOV.UK Task list: 記録の一覧には使わない。順序を自分で選ぶ長いサービス向けで、テーブルで足りる
- Carbon Callout: 送信フローに出す情報がない。使わない
- Atlassian Flag: 通知は Carbon toast に一本化する。2システムの通知を混在させない
- Carbon の送信中 disable と Atlassian の「disabled にしない」: 折衷して「入力前は有効、送信処理中のみ disable」を採用

## 優先度候補

| 優先度 | 項目 | 内容 |
|---|---|---|
| P1 | フォーム規律 | ラベル・必須表記・1カラム・ボタン構成（送信/キャンセル） |
| P1 | 記録一覧テーブル | 4列構成、ソート表示、行hover |
| P1 | 空状態 | 見出し＋CTA＋SVG |
| P1 | 送信成功toast | 右上、成功色＋アイコン、記録一覧への動線 |
| P2 | エラー表示 | フィールド別エラー＋上部要点、入力値保持、送信中の進行表示 |
| P3 | 確認パネル | 参照番号つきの取引完了画面（GOV.UK流。画面遷移が増える） |
| P3 | toastの複数スタック | 複数連続送信時の積み重ね表示 |

## 判断が必要な点

1. 送信成功の表現: toast＋記録一覧遷移（現行案）にするか、参照番号つき確認ページ（GOV.UK流）にするか。取引の重さ次第
2. 通知の位置: 画面右上（Carbon）で確定してよいか。Atlassian は左下
3. 「重要度」フィールド: 通常/重要の2段を付けるか。付けない方がフォームは短くなる
4. ダークモード: prefers-color-scheme での自動追従のみでよいか、手動切替も付けるか
