# 人物題箋の二面性モーフ — 提案パターン目録

2026-10-29 / designer（des-1）。`20261016_site-design-improvement/improve/` は変更していない。
本書と試作デモ `demo/index.html` は、あとで実fixtureへ写せる形に整えてある。

**要約。** 人物ごとに「灯の相（通常の面）」と「煤の相（条件が揃ったときの面）」を宣言し、
条件（濃色モード・hover・押印）が揃ったときだけもう一つの相へ切り替える。切替には必ず
ぼけまたは走り（グリッチ）を入れる。第一候補は **案1（二層交差＋ぼけ・濃色軸）**、
hover 軸には **案2（マスク走査）**、切替瞬間の限定演出に **案3（スライス断片）**。
詳細頁のテーマ切替には **案4（View Transitions）**、実験枠として **案5（SVG 変位）** を添えた。

## 1. 前提と制約

- 対象は `improve/chara-a.html`・`improve/chara-c.html` の `.card` グリッド（13枚）と、将来の人物詳細頁。`chara-b.html` の表は対象外。
- 肖像は未整備（`data/characters.json` の `image` は空文字）。実画像の到来を待たずに仕組みだけ先に立てられるよう、面の中身は「題箋文字 → SVG 等の代用 → `<img>`」のどれでも動く構造にする。
- 守ること（確認済みの制約）:
  - 外部リクエスト禁止・新規依存禁止。CDN・ライブラリ・フォント読込は使わない。
  - 色は既存トークン（`--bg` `--text` `--accent` `--rule` 等）経由。濃色モードへ自動追従する。`--rule*` の置換・削除はしない。
  - `prefers-reduced-motion: reduce` では走らず、ぼけず、即時に切り替わる。
  - 追加する操作子のタップ領域は 44px 以上。
  - `.card` の枚数・`tbody tr` の行数などスモークテストの件数に触れない。
- 語彙の約束: **灯の相**＝通常の面（omote）、**煤の相**＝条件成立時に現れる面（ura）。
  この名称は仮置きであり、確定は確認事項（§12）に含めた。

## 2. 共通の土台（全案で使う部分）

### 2-1. HTML 構造

題箋文字版（実画像が無い間。現行の `.plate` を置き換える）:

```html
<div class="plate a-plate-fine dual"
     data-trigger="dark" data-morph="settle"
     role="img"
     aria-label="燭守 セラフの肖像（灯の相／煤の相）">
  <div class="face face-omote">燭守 セラフ</div>
  <div class="face face-ura" aria-hidden="true">煤の相</div>
</div>
```

実画像版（肖像が用意できたあと）:

```html
<div class="plate dual" data-trigger="dark" data-morph="settle"
     role="img" aria-label="燭守 セラフの肖像（灯の相／煤の相）">
  <img class="face face-omote" src="img/c001-omote.png" alt="" width="600" height="800">
  <img class="face face-ura"   src="img/c001-ura.png"   alt="" width="600" height="800">
</div>
```

- 面の中身が `<img>` でも `<div>`（文字・SVG）でも、CSS は同一で動く。
- 両面とも `alt=""` とし、二相の意味は容器の `aria-label` に一度だけ述べる。
  `role="img"` の子孫は支援技術から見て装飾になるため、画像の二重読み上げが起きない。
- 幅高属性（width/height）を付けて、読込中の格子の揺れを防ぐ。

### 2-2. 土台 CSS（`css/duality.css` として新設する想定）

既存トークンのみを参照する。16進の直書きはない。

```css
/* ---- 二面性 共通の土台 ---- */
:root {
  /* モーフ用の追加トークン（本提案で新設） */
  --morph-dur: 640ms;                          /* 交差の長さ */
  --morph-ease: cubic-bezier(0.4, 0.1, 0.2, 1); /* ゆっくり入り、静かに止まる運び */
}

.dual {
  position: relative;
  overflow: hidden;      /* 走りの断片が題箋の外へ出ない */
}
.dual .face {
  position: absolute;
  inset: 0;
  display: grid;
  place-items: center;
  transition:
    opacity var(--morph-dur) var(--morph-ease),
    filter  var(--morph-dur) var(--morph-ease);
  transition-delay: var(--morph-delay, 0ms);
}
.dual .face-omote { opacity: 1; filter: blur(0); z-index: 1; }
.dual .face-ura   { opacity: 0; filter: blur(6px); z-index: 2; }
```

### 2-3. 状態セレクタの書き方（濃色軸の二重化）

濃色へ入る経路は二つある。手動固定（`html[data-theme]`）と OS 設定
（`prefers-color-scheme`）。同じ宣言を二度書く。一見重複だが、これで
「OS は濃色でもこの頁だけ灯に固定する」操作が自然に成立する。

```css
/* 手動で煤に固定したとき */
html[data-theme="dark"] .dual[data-trigger="dark"] .face-omote { opacity: 0; filter: blur(4px); }
html[data-theme="dark"] .dual[data-trigger="dark"] .face-ura   { opacity: 1; filter: blur(0); }

/* OS が濃色のとき（手動で灯に固定されていなければ） */
@media (prefers-color-scheme: dark) {
  html:not([data-theme="light"]) .dual[data-trigger="dark"] .face-omote { opacity: 0; filter: blur(4px); }
  html:not([data-theme="light"]) .dual[data-trigger="dark"] .face-ura   { opacity: 1; filter: blur(0); }
}
```

技術上の注意（挙動は環境差あり）: 現在の主なブラウザは、媒体特徴の変化でも
`transition` を走らせる。走らない環境では遷移なしの即時切替になり、成立自体は
損なわない。全環境での実機確認は未実施なので、導入時に主要端末で一度確認する。

### 2-4. 縮小動作（共通の約束）

```css
@media (prefers-reduced-motion: reduce) {
  .dual .face { transition: none; filter: none !important; }
  /* fixture 側 style.css の全体停止（transition/animation none）と重なって、
     切替は「ぼけ無し・即時」になる。走る断片（案3）は display:none も併せて指定 */
}
```

要件どおり、縮小設定では走り（グリッチ）を出さない。切替自体は情報として残す。

### 2-5. hover 軸の共通ガード

```css
@media (hover: hover) {
  .dual[data-trigger="hover"]:hover        .face-omote { opacity: 0; filter: blur(4px); }
  .dual[data-trigger="hover"]:hover        .face-ura   { opacity: 1; filter: blur(0); }
  /* キーボード: カードがリンクになる詳細頁では focus-within でも開く */
  .dual[data-trigger="hover"]:focus-within .face-omote { opacity: 0; filter: blur(4px); }
  .dual[data-trigger="hover"]:focus-within .face-ura   { opacity: 1; filter: blur(0); }
}
```

`@media (hover: hover)` を外さないこと。タッチ端末では hover が一度触れると
固着し、煤の相のまま戻らなくなる。タッチ環境での代替は §12 の確認事項。

## 3. 二面性の条件モデル（字特定の条件化）

### 3-1. `data/characters.json` の拡張案

```json
{
  "id": "c001",
  "name": "燭守 セラフ",
  "role": "封印の継ぎ手",
  "image": "",
  "appearance": "左頬に煤の紋。白い手袋を外さない",
  "affiliation": "回廊聖堂",
  "duality": {
    "trigger": "dark",
    "morph": "settle",
    "faces": {
      "omote": { "image": "img/c001-omote.png", "label": "灯の相" },
      "ura":   { "image": "img/c001-ura.png",   "label": "煤の相" }
    }
  }
}
```

| 項目 | 値 | 既定 | 意味 |
|---|---|---|---|
| `duality` | （省略可） | 省略 | 省略時は従来どおり単面の題箋。全員に二面性を強制しない |
| `trigger` | `dark` / `hover` / `manual` | `dark` | 相を替える条件。`dark`＝濃色モード、`hover`＝ポインタが触れたとき、`manual`＝押印（押下）で替える |
| `morph` | `settle` / `wipe` / `grit` / `veil` / `bleed` | `settle` | 切替の技法。案1〜案5 に対応（§5〜§9） |
| `faces.omote` / `faces.ura` | `{image, label}` | — | 各相の画像と名称。`image` が空文字の間は題箋文字で代用する |

後方互換の規則（実装側で正規化する）:

```js
// js 側の正規化（chara-a.js / chara-c.js の頭に置く一小節）
function dualityOf(c) {
  const d = c.duality;
  if (!d || !d.faces || !d.faces.ura) return null;           // 単面の扱い
  const TRIGGERS = ["dark", "hover", "manual"];
  const MORPHS   = ["settle", "wipe", "grit", "veil", "bleed"];
  return {
    trigger: TRIGGERS.includes(d.trigger) ? d.trigger : "dark", // 不明値は既定へ落とす
    morph:   MORPHS.includes(d.morph) ? d.morph : "settle",
    faces:   d.faces,
  };
}
```

- 不明な `trigger`／`morph` の値は既定（dark／settle）へ落とす。壊れた JSON が頁を壊さない。
- `image` が空文字の間は `label` の文字（または名）で面を作る。現行の「肖像は準備中」題箋の流儀を引き継ぐ。

## 4. トリガー軸の評価（濃色・hover・押印）

| 軸 | 成立する環境 | 長所 | 短所・注意 | 向く場面 |
|---|---|---|---|---|
| 濃色（OS 自動） | 全端末 | 操作不要。OS の灯りと物語の灯りが重なる。受動なので一覧の静けさを壊さない | 見る人が選べない（OS 依存）。両相を灯・煤の双方で描く必要がある。媒体変化で遷移が走るかは環境差あり（§2-3） | 一覧グリッドの既定軸。全員に安全 |
| 濃色（手動固定） | 全端末 | 開閉器があれば誰でも確実に見られる。媒体変化によらず遷移が走る | 操作子の設置と 44px の管理が必要 | 開閉器付きの頁。案3・案4 と組み合わせる |
| hover | ポインタのある端末のみ | 能動的な発見。触れる行為と仮面が外れる動きが対応する。指を離せば戻る | タッチでは固着するため `@media (hover: hover)` が必須。キーボード単独では見えない（focus-within で補う） | 補助軸。字を限定して使う |
| 押印（手動・押下） | 全端末 | `aria-pressed` で状態を明示できる。全員が操作できる | 操作を要求する。一覧には重い。詳細頁向き | 人物詳細頁・タッチ端末の代替 |

結論: **既定軸は濃色**。hover は字を限定した補助。押印は詳細頁に置く。
めもに記載の「トリガー優先」の未決事項はこの前提で答えを出してある（§12）。

## 5. 案1 静溶け（しずみ）— 二層交差＋ぼけ

- **トリガー**: 濃色（自動・手動両対応）、hover も同じ宣言で可能。
- **技法**: 両相を重ね、離れる面は `blur(4px)` で沈み、現れる面は `blur(6px)→0` で浮かぶ。opacity と filter のみを動かす。
- **向く字・場所**: 全員。一覧グリッドの既定。13枚同時に動いても静か。

コード（土台 §2 に加えて書く。JS 不要）:

```css
/* 濃色へ入るときは僅かな段差（--i 枚目ごとに 110ms）を付け、灯へ戻るときは段差なし */
html[data-theme="dark"] .dual[data-trigger="dark"] .face-omote {
  opacity: 0; filter: blur(4px);
  transition-delay: calc(var(--i, 0) * 110ms);
}
html[data-theme="dark"] .dual[data-trigger="dark"] .face-ura {
  opacity: 1; filter: blur(0);
  transition-delay: calc(var(--i, 0) * 110ms);
}
@media (prefers-color-scheme: dark) {
  html:not([data-theme="light"]) .dual[data-trigger="dark"] .face-omote {
    opacity: 0; filter: blur(4px);
    transition-delay: calc(var(--i, 0) * 110ms);
  }
  html:not([data-theme="light"]) .dual[data-trigger="dark"] .face-ura {
    opacity: 1; filter: blur(0);
    transition-delay: calc(var(--i, 0) * 110ms);
  }
}
/* hover 軸も同じ宣言で成立する（trigger を替えるだけ） */
@media (hover: hover) {
  .dual[data-trigger="hover"]:hover        .face-omote,
  .dual[data-trigger="hover"]:focus-within .face-omote { opacity: 0; filter: blur(4px); }
  .dual[data-trigger="hover"]:hover        .face-ura,
  .dual[data-trigger="hover"]:focus-within .face-ura   { opacity: 1; filter: blur(0); }
}
```

```html
<!-- カード側: 一覧の何番目かを --i に入れる（段差の素） -->
<li class="card" style="--i:2"> … <div class="plate … dual" data-trigger="dark"> … </li>
```

- **アクセシビリティ**: 土台どおり。縮小設定ではぼけ無しの即時切替。
- **性能**: 動かすのは opacity と filter のみ。blur は題箋サイズ（約 210px 角）なので 13 枚分でも軽い。layer の常駐は避けたいので `will-change` は付けない（付けたままにする必要が確認された場合のみ詳細頁の主肖像へ限定）。
- **トレードオフ**:
  - 濃色トリガーは「見る人が能動的に替えている」感覚が薄い。発見されにくい面がある。→ 札（キャプション）で相の名を替えると成立が伝わる（デモ実装参照）。
  - 両相とも灯・煤の双方の配色で読める絵が必要（実画像は実質 2 枚／字）。コストは条件モデル側で覚悟する。

## 6. 案2 罫走（けいそう）— マスク走査＋ぼけ縁

- **トリガー**: hover（ポインタ環境。focus-within 併用）。
- **技法**: 煤の相を `mask-image: linear-gradient` で覆い、`mask-position` を動かすと
  ぼけた縁の罫が走って相が現れる。渡り終えると静止する。
- **向く字・場所**: 仮面や眼帯を「外す」字。一覧では字を限定、詳細頁の主肖像にも使える。

コード（土台に加えて書く）:

```css
.dual[data-morph="wipe"] .face-ura {
  opacity: 1; filter: blur(3px);
  -webkit-mask-image: linear-gradient(100deg, #000 0 40%, transparent 50% 100%);
          mask-image: linear-gradient(100deg, #000 0 40%, transparent 50% 100%);
  -webkit-mask-size: 260% 100%;
          mask-size: 260% 100%;
  -webkit-mask-position: 100% 0;   /* 黒部が外れた位置＝煤の相は隠れている */
          mask-position: 100% 0;
  -webkit-mask-repeat: no-repeat;
          mask-repeat: no-repeat;
  transition:
    -webkit-mask-position var(--morph-dur) var(--morph-ease),
            mask-position var(--morph-dur) var(--morph-ease),
    filter var(--morph-dur) var(--morph-ease);
}
@media (hover: hover) {
  .dual[data-trigger="hover"][data-morph="wipe"]:hover .face-ura,
  .dual[data-trigger="hover"][data-morph="wipe"]:focus-within .face-ura {
    -webkit-mask-position: 0 0;    /* 罫が走り渡り、煤の相が現れる */
            mask-position: 0 0;
    filter: blur(0);
  }
  .dual[data-trigger="hover"][data-morph="wipe"]:hover .face-omote,
  .dual[data-trigger="hover"][data-morph="wipe"]:focus-within .face-omote {
    opacity: 0.9; filter: blur(2px);   /* 奥の面も僅かにぼかして深みを出す */
  }
}
/* 退行: マスク位置の遷移が使えない環境は案1と同じ交差に落とす */
@supports not ((-webkit-mask-position: 0 0) or (mask-position: 0 0)) {
  .dual[data-morph="wipe"] .face-ura {
    -webkit-mask: none; mask: none;
    opacity: 0; filter: blur(6px);
    transition: opacity var(--morph-dur) var(--morph-ease), filter var(--morph-dur) var(--morph-ease);
  }
}
```

- **アクセシビリティ**: hover 軸の共通ガード（§2-5）に従う。縮小設定では走らず即時。
- **性能**: mask の再描画は題箋内に閉じる。交差よりやや重いが、hover で一度に 1 枚しか動かないので実害は小さい。
- **トレードオフ**:
  - Safari での `-webkit-mask-position` 遷移は実機未確認。`@supports` の退行があるため、最悪でも案1 の品質に落ちる。
  - 縁のぼけ幅は勾配の止め位置（40%→50%）で調整する。広くすると滲み、狭くすると切り替わりが硬くなる。

## 7. 案3 燈の走り（ひのはしり）— スライス断片＋色相ずれ（一射のみ）

- **トリガー**: 濃色の切替瞬間、または hover の入瞬間。**一度だけ**走って 0.5 秒で静まる。
- **技法**: canvas を使わない。煤の相の複製 2 枚（`.grit`）を `clip-path: inset()` で
  横帯に切り出し、`steps(1, end)` で位置と色相を飛び飛びに替える。土台の交差は
  ぼけのまま裏で進むので、走りは上貼りのノイズとして効く。
- **向く字・場所**: 二面性が「名の書き換え」「彩の乱れ」である字に限定。
  一覧グリッドで 13 枚同時に走らせることは避ける（使うなら段差で分散）。

構造（煤の相の複製を 2 枚足す）:

```html
<div class="plate dual" data-trigger="dark" data-morph="grit"
     role="img" aria-label="囁き ノクスの肖像（灯の相／煤の相）">
  <div class="face face-omote">…</div>
  <div class="face face-ura">…</div>
  <div class="grit g1" aria-hidden="true">…煤の相と同じ中身…</div>
  <div class="grit g2" aria-hidden="true">…煤の相と同じ中身…</div>
</div>
```

コード:

```css
.grit {
  position: absolute; inset: 0; z-index: 3;
  display: grid; place-items: center;
  color: var(--accent);
  opacity: 0; pointer-events: none;
}
@keyframes grit-a {
  0%   { opacity: .9; clip-path: inset(8% 0 78% 0);  transform: translateX(-3px); filter: hue-rotate(35deg) saturate(1.6); }
  20%  { opacity: .9; clip-path: inset(42% 0 40% 0); transform: translateX(2px);  filter: hue-rotate(-50deg); }
  40%  { opacity: 0;  clip-path: inset(0 0 100% 0);  transform: none; }
  60%  { opacity: .9; clip-path: inset(64% 0 18% 0); transform: translateX(-2px); filter: saturate(2) hue-rotate(20deg); }
  80%  { opacity: .7; clip-path: inset(24% 0 64% 0); transform: translateX(3px); }
  100% { opacity: 0;  clip-path: inset(0 0 100% 0);  transform: none; }
}
/* grit-b は切れ目の位置を替えた第二断片（値はデモ参照） */

/* hover 軸: 触れた瞬間に一度だけ。外すと初期化され、次に触れると再び走る */
@media (hover: hover) and (prefers-reduced-motion: no-preference) {
  .dual[data-morph="grit"][data-trigger="hover"]:hover .grit.g1 { animation: grit-a 460ms steps(1, end) both; }
  .dual[data-morph="grit"][data-trigger="hover"]:hover .grit.g2 { animation: grit-b 460ms steps(1, end) 60ms both; }
}
/* 濃色軸: 切替のたびに JS が一時クラスを付ける（下の JS 参照） */
@media (prefers-reduced-motion: no-preference) {
  .theme-flipped .dual[data-morph="grit"][data-trigger="dark"] .grit.g1 {
    animation: grit-a 460ms steps(1, end) both;
    animation-delay: calc(var(--i, 0) * 90ms);   /* 段差で分散 */
  }
}
@media (prefers-reduced-motion: reduce) {
  .grit { display: none !important; }            /* 縮小設定では断片を出さない */
}
```

```js
// 濃色軸の一射: 切替が実際に起きたときだけ .theme-flipped を html に付け、
// 1 秒後に外して次の切替に備える。初期描画が濃色のときは走らない（静かに始まる）。
const root = document.documentElement;
let flipTimer = 0;
function armFlip() {
  root.classList.remove("theme-flipped");
  void root.offsetWidth;              /* 強制再描画の1フレームで確実に再始動させる */
  root.classList.add("theme-flipped");
  clearTimeout(flipTimer);
  flipTimer = setTimeout(() => root.classList.remove("theme-flipped"), 1000);
}
/* 開閉器の click から setMode() 経由で armFlip() を呼ぶ。
   OS 側の切替にも matchMedia("(prefers-color-scheme: dark)").addEventListener("change", …) で合わせる */
```

- **アクセシビリティ**: 縮小設定では断片ごと消える（デモで確認済み）。走りは装飾であり、相の情報は交差と `aria-label` で伝わる。`prefers-reduced-motion: no-preference` を条件に含めて二重に挡ぐ。
- **性能**: 断片 2 枚・460ms・題箋内に閉じる。`clip-path`・`transform`・`filter` は合成層で処理される。13 枚同時走らせは再描画が一箇所に集中するので、段差（90ms×枚目）か字の限定で分散する。
- **トレードオフ**:
  - 「静かな資料館」の語彙から最も遠い演出。字を限定しないと場の格が下がる。→ 使う字の選定を資料側の設定と合わせて行う（割当例 §3-2）。
  - 複製 2 枚の分だけ DOM が増える。JS で題箋を組むなら `render()` の差分に含めるだけで済む（§11）。

## 8. 案4 継ぎ目なし — View Transitions API

- **トリガー**: 手動のテーマ切替（詳細頁の開閉器・押印と相性がよい）。
- **技法**: `document.startViewTransition()` の前後でスナップショットを取り、
  古い相と新しい相を `::view-transition-old/new` でぼけ交差させる。
- **対応（確認済み・2025-10 に Baseline Newly available）**: Chrome/Edge 111+、Safari 18+、Firefox 144+。
  非対応環境は退行して即時切替。例外も出ないので、存在確認だけして呼ぶ。

コード:

```js
function applyTheme(mode) {
  const swap = () => {
    if (mode === "auto") document.documentElement.removeAttribute("data-theme");
    else document.documentElement.setAttribute("data-theme", mode);
  };
  const reduce = matchMedia("(prefers-reduced-motion: reduce)").matches;
  if (document.startViewTransition && !reduce) {
    document.startViewTransition(swap);
  } else {
    swap();   /* 非対応または縮小設定: 即時切替 */
  }
}
```

```css
/* 主肖像だけを固有の名前にして、頁全体でなく1枚を交差させる */
.dual.hero { view-transition-name: plate-hero; }

::view-transition-old(plate-hero) { animation: vt-out 480ms var(--ease) both; }
::view-transition-new(plate-hero) { animation: vt-in  480ms var(--ease) both; }
@keyframes vt-out { to   { opacity: 0; filter: blur(8px); } }
@keyframes vt-in  { from { opacity: 0; filter: blur(8px); } }
```

- **アクセシビリティ**: 縮小設定では退行して即時（コード内で分岐済み）。支援技術への提示は DOM の状態変化のみで、演出は視覚だけ。
- **性能**: スナップショットの生成は頁全体に一度だけ起きる。主肖像 1 枚に `view-transition-name` を与え、残りは root の交差に任せると負荷を抑えられる。名前は頁内で一意にする（重複すると遷移が飛ぶ）。
- **トレードオフ**:
  - 濃色軸の CSS 遷移（案1）と役割が近い。両方入れると二重に動くので、**使うのは「手動切替」に寄せた頁**に限定する。
  - Baseline Newly available であり、まだ古い端末が残る時期は退行前提で書く（書き方は上のとおり）。

## 9. 案5 滲み — SVG 変位フィルタ（実験枠）

- **トリガー**: hover（詳細頁の主肖像 1 枚に限定）。
- **技法**: `feTurbulence` ＋ `feDisplacementMap` で輪郭を変位させ、強度を山なりに
  動かして「滲んで替わる」瞬間を作る。

コード:

```html
<!-- 頁の頭に一度だけ置く -->
<svg width="0" height="0" style="position:absolute" aria-hidden="true" focusable="false">
  <filter id="ink-bleed" x="-20%" y="-20%" width="140%" height="140%">
    <feTurbulence type="fractalNoise" baseFrequency="0.012 0.02" numOctaves="2" seed="7" result="n"/>
    <feDisplacementMap in="SourceGraphic" in2="n" scale="0" xChannelSelector="R" yChannelSelector="G"/>
  </filter>
</svg>
```

```js
/* hover-in で scale を 0 → 22 → 0 に山なりに動かす（rAF）。縮小設定では動かさない */
function bleed(plate) {
  if (matchMedia("(prefers-reduced-motion: reduce)").matches) return;
  const map = document.querySelector("#ink-bleed feDisplacementMap");
  const t0 = performance.now(), D = 700;
  (function tick(t) {
    const k = Math.min(1, (t - t0) / D);
    map.setAttribute("scale", (Math.sin(k * Math.PI) * 22).toFixed(2));
    if (k < 1) requestAnimationFrame(tick); else map.setAttribute("scale", "0");
  })(t0);
}
/* .face-ura 側に CSS で filter: url(#ink-bleed) を付けて呼ぶ */
```

- **アクセシビリティ**: 縮小設定では呼ばない（即時交差のみ）。
- **性能**: フィルタ領域の計算は交差より重い。**1 枚に限定**する。13 枚のグリッドでは使わない。
- **トレードオフ（明示）**:
  - Safari での `feDisplacementMap` の動的更新は実機未確認。Chrome では確認済み（デモ検証の対象外なので要再確認）。
  - 滲み方は `seed` と `baseFrequency` で変わる。字ごとに `seed` を変えると「滲み癖」を出せる一方、調整コストが高い。実験枠として残し、採用は詳細頁の主肖像 1 枚に限ることを勧める。

## 11. `js/chara-a.js` への差分案（確認済み構造を保つ）

```js
// 差分案: 題箋部分の生成を duality に対応させる（外側は現行のまま）
function plateHTML(c) {
  const d = dualityOf(c);

  }
  const face = (f, cls) => f.image

  return `<div class="plate a-plate-fine dual" data-trigger="${d.trigger}" data-morph="${d.morph}"

   .card の枚数・チップ・result-line は変わらない（スモーク件数に触れない） */
```
