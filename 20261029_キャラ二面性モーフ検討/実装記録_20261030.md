対象: `20261029_キャラ二面性モーフ検討/` の試作デモ。本番リポジトリ（`20261016_site-design-improvement/`）と保管庫には触れていない。
根拠: めも【セッション記録 2026-10-30】（めもB確認事項1〜5の処理結果・台帳 S-19）、`提案パターン.md` §2・§3・§4の結論。

## 1. 確定仕様（実装の前提）

- 濃色軸（煤の相）を主軸とする。全ての環境が濃色で煤の相を確認できる。
- hover 軸は `@media (hover: hover)` 内でのみ有効化する。タッチ環境では押印を表示しない。
- 押印（押下）の詳細頁への集約は、詳細頁未整備のため今回実装しない（濃色軸のみの運用）。詳細頁への誘導も設けない。
- 二面性のデータは duality フィールドの拡張で対応する（characters.json 相当・めもB確認事項2）。
- 動かす字は限定する。全字を一斉にアニメーションさせない（めもB確認事項3）。
- 「灯の相」「煤の相」は仮置き名として使用する（めもB確認事項4）。
- reduced-motion 環境ではモーフを抑制する。

## 2. 実装内容

### demo/index.html

- **CSS**
  - 濃色主軸を二面の題箋すべてへ拡張。罫走（案2）の題箋にも濃色時の規則を追加し、煤へ入るときに罫が走って煤の相を現す。手動固定（`html[data-theme="dark"]`）と OS 自動（`prefers-color-scheme` 内 `html:not([data-theme="light"])`）の両経路を §2-3 の慣例どおり二重に記述した。
  - 罫走の濃色時にも `--i` 枚目ごとの 110ms 段差を付け、灯へ戻るときは段差なし。既存の静溶け・札（キャプション）の切替と同じ運び。
  - 単面の題箋用に `.plate.single` を追加（中央寄せ・`--text-sub`・動かない）。
- **HTML**
  - 全題箋に `data-char`（c001〜c013）を付与し、データと題箋を対応させた。
  - hover 軸の 4 字（ヴェル・オクタヴィア・カノン・アレルイ）に `d-dark` を、アレルイには `g-dark` を追加し、濃色主軸に参加させた。既存の hover・走査・グリッチの挙動は温存している。
  - ヴェルに `--i:2` を付け、案1の 3 枚の段差を完成させた。
  - 看取り ヴィゴル（c013）の単面の題箋を案1の列末尾へ追加。`duality` を持たない字の例で、テキスト面は「肖像は準備中」題箋の流儀（§3-1・§3-2 の例字どおり）。
  - 冒頭の説明・各案の注記・フッターの文言を確定仕様に合わせて更新（押印の操作子を設けていない旨、走らせる字の限定、単面の例の説明）。
- **データ（characters.json 相当）**
  - 埋め込み JSON（`<script type="application/json" id="characters-data">`）に 8 字分を記載。本番では `data/characters.json` への `duality` フィールド拡張がこの役割を担う（めもB確認事項2の確定）。単体動作（file:// 直・要求ゼロ）のため埋め込みにした。
  - `duality` は §3-1 のモデルどおり `trigger`／`morph`／`faces`（omote・ura の label は「灯の相」「煤の相」）。
- **JS**
  - `dualityOf()`：§3-1 の正規化。duality の省略は単面（null）、不明な trigger/morph は既定（dark/settle）へ落とす。
  - `axisClasses()`・`applyDuality()`：データから各題箋へ軸・技法のクラス（`d-dark` `d-hover` `d-wipe` `g-dark` `g-hover`）と `aria-label` を適用。noscript のときは静的 HTML 側の記述が同じ結果を担う。
  - 点検から参照できるよう `window.__duality` にデータと関数を公開（見た目には影響しない）。
- **押印**：操作子は設けていない（S-19）。詳細頁への言及・リンクも追加していない。

### tools/verify-demo.js

- 既存 15 項目は基準値を変えずに保持。hover の 2 項目だけ、濃色主軸化により煤モードでの測定では判定が無意味になるため、手動煤の前（灯モード）へ移動した。
- 追加した点検: 濃色主軸の全題箋確認（OS 自動・手動・タッチの 3 経路）／hover 解除での復帰／押印操作子の不在／タッチ（hover 無し）で tap しても煤の相が出ないこと／データモデルの一致・正規化・noscript 用静的 markup の一致／縮小設定での hover 軸題箋の即時表示とぼけ無し／走らせる字の限定（c008・c009 のみ）。
- 判定方法の修正が一件ある。初回実行で 5 件 FAIL となり、原因は罫走の題箋を opacity で判定していた点だった。罫走の煤の相は opacity 1 のまま mask で隠す設計のため、mask 位置で判定するよう修正した。computed 値は `0 0` → `0px 0px`・`100% 0` → `100% 0px` と正規化されることも実測で確認した。製品側（デモ）の不具合ではなく、点検側の期待値の誤りだった。

### 設計判断（確定事項の読み替えについて明示）

- S-19 後の運用では濃色が全員の主軸になるため、データ上の `trigger` は「主軸に加える補助軸」を示す値として使った。`dark`＝補助軸なし、`hover`＝ポインタ環境の補助。§3-1 のフィールド構成そのものは変更していない。
- `trigger: "manual"`（押印）のデータが来た場合の正規化は、今回の運用（押印軸なし）に従い濃色へ寄せている。デモのデータには manual の字は存在しない。
- アレルイは §3-2 の割当例では trigger dark とあるが、デモでは hover 入射のグリッチを見せる構成を維持するため trigger hover とした。結果として濃色の切替瞬間と hover の入瞬間の双方で走る（§3 の仕様どおり）。
- ヴィゴルの単面題箋の追加は §3-1「duality 省略時は単面」と §3-2 c013 の例字に沿うもので、デモ上の実例として加えた。

## 3. 検証結果（実測値）

実行: `node tools/verify-demo.js demo/index.html`（Playwright + 系統 Edge）→ **31 PASS / 0 FAIL**
基準: 変更前の同一環境での実行は 15 PASS / 0 FAIL（2026-10-30 実測）。

| 項目 | 実測値 |
| --- | --- |
| 濃色主軸（OS 自動・data-theme 無し） | 7 題箋すべて opacity=1。`data-theme` は付かない |
| 濃色主軸（手動・開閉器） | 7 題箋すべて opacity=1。`theme-flipped` 付与・`grit-a` 発火を確認 |
| 濃色主軸（タッチ 390px） | `hover:hover=false`・`pointer:coarse=true` の環境で 7 題箋すべて opacity=1 |
| 灯（自動） | 主軸・hover 軸の題箋とも煤の相は opacity=0。罫走は mask=`100% 0px` |
| hover（交差型・ヴェル） | opacity 0 → 1。ポインタを外すと 0 へ復帰 |
| hover（走査型・オクタヴィア） | mask 位置 `100% 0px` → `0px 0px` |
| 押印の操作子 | 題箋内 0 個。button は開閉器の 3 個のみ（デスクトップ・タッチ双方で実測） |
| タッチでの tap | hover 軸の題箋に触れても煤の相は opacity=0 のまま（押印・hover 反応なし） |
| 縮小設定 | transition-duration 0s・filter none・断片非表示・手動煤でも走らない・煤の相は即時（opacity=1）。hover 軸の題箋も同様 |
| 走らせる字の限定 | 断片 4 個・所有は c008（ノクス）と c009（アレルイ）のみ |
| データモデル | 字数 8 ＝ 題箋 8。割当・aria-label とも一致。不明値（trigger/morph）→ dark/settle・省略 → 単面（null）。noscript 用静的 markup も一致 |
| 横溢れ | 1280px: scrollWidth=1280 / 390px: scrollWidth=390 |
| コンソールエラー | なし（全コンテキスト合計） |

記録物: `shots/` に light・hover・dark・mobile-390・touch-dark-390・reduced-dark の png（`*.png` は `.gitignore` 済み・追跡対象外）。視覚確認では、タッチ＋濃色で hover 軸を含む全二面題箋が煤の相になり、単面のヴィゴルのみ変化しないことを確認した。

- `trigger: "manual"` の正規化は暫定で濃色へ寄せている。詳細頁整備後に押印を実装する際（S-19 の本実装）に見直す。
- 相の名称は「灯の相／煤の相」のまま（仮置き・めもB確認事項4で当面使用と確定済み）。
- 本実装はデモ上の確定であり、`improve/` 本体への反映は含まない。`characters.json` への duality 追加と CSS・JS の移植は別作業になる。
- コミット・push は実施していない（オーケストレータが検証後に実施する運用のため）。
