## 現場到着後の手順(順番どおり、省略しない)

### 1. 端末とアカウントの確認(現場担当者と)

1. 対象端末のラインを確認(L1/L2/L3 のどれか)
2. **共用アカウントでログオンしていること**を現場担当者と確認
3. 端末の利用者に**収集内容の説明**(何を取るか/取らないか)。説明資料を使う
   - 取る: 端末情報(CPU/メモリ等)、Excel の最近使ったファイル一覧(パスのみ)、Windows の最近使った項目(パスのみ)
   - 取らない: ファイルの中身、ブラウザ履歴、パスワード、ネットワーク通信
4. 端末側で Obsidian や Excel が開いていれば閉じておく(書込競合と MRU 汚染の防止)

### 2. USB を挿す

1. 管理用 USB を挿す(他の USB を挿さない)
2. ドライブ文字を確認(E: とは限らない。以下は `<USB>` と書く)
3. `<USB>\Collect_LNB.ps1` がルート直下にあること。フォルダに入っていたら**移動せず**手順を中止して報告(配置条件はルート直下のみ)

### 3. 事前検証(本番の前に必ず)

この順で実施し、どれかでも失敗したら**収集を開始しない**。手順書に記録して持ち帰る。

| # | 操作 | 合格基準 |
|---|---|---|
| 3-1 | `<USB>\TEST_LNB.cmd` をダブルクリック | 窓に 14 項目すべて `"Passed": true`、`Exit code: 0` |
| 3-2 | `<USB>\PREPARE_USB.cmd` をダブルクリック | 「USB registration and approved ImportExcel 7.8.10 module checks passed.」+ `Exit code: 0` |

- 3-1 で 1 件でも false → **中止**。USB か端末の問題。改変せず持ち帰る
- 3-2 が依存エラー → ImportExcel の配置が壊れている。**現場での修復はしない**。持ち帰る

### 4. 収集本番

1. `<USB>\Run_LNB.cmd` をダブルクリック
2. 表示に従い入力:
   - `Line L1/L2/L3` → 対象ライン(例: `L1`)
   - `Check approved account/timing and type YES to collect` → `YES`(**半角大文字**。それ以外は exit 2 で止まる=仕様)
3. 進行表示(computer→os→cpu→memory→disks→printers→processes→excel_recent→office→windows_recent)を待つ。**目安: 数十秒〜数分**(R1)。途中で USB を抜かない(R7)
4. 最後に `Completed:` と出力先パスが表示され、`Exit code: 0` なら完了

### 5. 完了確認(C3/C4 相当の現場簡易確認)

1. 表示された出力先フォルダに次があること:
   - `LNB_Collector.xlsx`(約25KB)
   - `COMPLETE.txt`(中身 1 行目 = `Completed` または `CompletedWithWarnings`)
   - `status.json`
2. 終了コードを記録する: 0=完了 / 10=警告付き完了(Status の Detail を見て原因を記録) / その他=未完了
3. **XLSX は現場では開かない**(MRU 汚染防止)。確認は開発用PCに戻ってから

### 6. 撤収

1. USB を「安全な取り外し」で抜く
2. 現場担当者に終了報告(いつ・どの端末・結果)
3. メモ: 端末名・ライン・日時・終了コード・特記(警告の有無、現場での出来事)

## 異常系テスト(環境C 繰り越し分、本番の**前**に実施)

**本番収集の前に**、以下を 1 回だけ実施する。いずれも失敗(=止まってくれない)なら本番は中止。

| # | 操作 | 合格基準 |
|---|---|---|
| A-1 | `Run_LNB.cmd` を起動し、ラインに `L4` と入力 | すぐ終了(収集開始されない) |
| A-2 | `Run_LNB.cmd` を起動し、ラインは正しく、YES確認で `NO` と入力 | すぐ終了(exit 2) |
| A-3 | 出力フォルダ(`data\LNB_調査` 配下)が作られた状態で、そこに junction を作る: `cmd /c mklink /J "<USB>\data\LNB_調査\test_junction" "C:\Windows\Temp"` → Run 実行 | junction が絡む出力で拒否される。**実施後 test_junction を必ず削除** |
| A-4 | (本番直前の最終確認として)マーカーは触らない。改変テストは環境Bで実施済みのため**現場では実施しない** | — |

A-3 の後は出力フォルダを確認し、テスト由来の不完全な出力ディレクトリがあればメモして持ち帰る(現場で削除しない)。

## 帰宅後の処理(開発用PC)

1. 出力物の確認(C4/C6):
   - XLSX を開き 13 シートの名称・行数を status.json と照合
   - **機微情報が含まれていないか目視確認**(パスワード・資格情報・ブラウザ履歴・文書内容)。発見したら USB ごと組織ルールで消去し報告
2. 出力物を Work_Vault 案件フォルダへ保存(機微パスは現状ノートに直書きしない)
3. TEST_REPORT 更新、changelog/decision-log へ記録
4. L1/L2/L3 の残り端末を同じ手順で実施

## 判断に迷ったとき

- 何かが失敗した → **その場で直さない**。記録して持ち帰る(現場での改変は追跡を壊す)
- 端末で USB シリアルが取得できない(R2) → 「収集不可」として記録。代替手段は別途承認
- 利用者から質問されたら収集範囲の説明に徹する(ツールの中身をその場で変更しない)

## 終了コード対応表

| コード | 意味 | 対応 |
|---|---|---|
| 0 | 完了(警告なし) | 撤収手順へ |
| 2 | 対話拒否(ライン不正/NO) | 入力をやり直す(本番前は正常) |
| 3 | 自己テスト失敗 | 中止・持ち帰り |
| 5 | USB/依存/検証エラー | 中止・持ち帰り(エラーメッセージを記録) |
| 10 | 警告付き完了 | COMPLETE.txt と Status シートの Detail を後で確認して判定 |

## 出力フォルダ名の正確な表記

スクリプト内のリテラルは `data\LNB_調査\`(コードポイント U+8ABF U+67FB = 「調査」)。
**この文書の他の場所では `LNB_ライン` と書いていた箇所があるが、正は `LNB_調査`。**
完了メッセージの形式は `<Completion>: <出力パス>`(例: `Completed: <USB>\data\LNB_調査\...`)。
