# 回帰テスト結果 — LNB Collector v6.5-review(2026-10-13)

## 総合判定: **重大欠陥 1件を検出→修正済み。修正後 31/31 全PASS**

## 1. 検出・修正した欠陥(回帰テストの主な成果)

### 【重大】V-1: USBマーカー検証の正規表現が CRLF 行末で必ず失敗する

| 項目 | 内容 |
| --- | --- |
| 発見経路 | T5-02(マーカー書式検証)が FAIL。ツール自身が書き込む CRLF の `LNB_USB_ID.txt` に対し `(?m)^RegistrationGuid=...{36}$` が一致しない |
| 原因 | .NET 正規表現の `$`(Multiline)は `\n` の前に一致するが、行末が `\r\n` の場合最終 GUID 文字の次は `\r` であり `[0-9a-fA-F-]{36}` が `\r` を吞めず不一致。**実機では登録済み USB での収集が必ず「Registration GUID missing or malformed」で停止する**(v6.4.3-review から存在する潜在欠陥) |
| 修正 | `VerifyUsb` の3つの正規表現を `\r?$` / `(.+?)\r?$` に変更(Collect_LNB.ps1 一部) |
| 検証 | 修正後、CRLF/LF 両方のマーカーで一致を確認(T5-02/T5-03 PASS)。LFのみでも一致(`\r?` は任意) |

### 軽微(ハーネス側の調整、本ツールの欠陥ではない)
- テストハーネスの疑似USBルートを `subst` ドライブ `X:\` に変更(EnsureSafeDir はドライブルート起点の設計のため)
- `regression_test.ps1` は UTF-8 BOM 付きで保存(PowerShell 5.1 が no-BOM UTF-8 を ANSI 読みする問題の回避)
