## 1. プロジェクト概要

### 1.1 目的

LNB(=L1/L2/L3 ラインに設置された共用アカウントの PC)の管理書・手順書・チェックリスト
(「LNB 管理手順書」草案 v0.3)の作成に必要な**端末実態の把握**を目的とする。
本ツール(LNB Collector)は、対象 PC から端末情報・Excel MRU・Windows Recent を
**読み取り専用・最小限**で収集し、USB 上に 1 ブックの Excel+CSV/JSON として出力する。

### 1.2 背景

- LNB 端末は共通アカウント運用のため、利用者ごとの聞き取りでは実態を把握できない
- Excel MRU(ラベル再発行=xlsx)と Windows Recent(情報確認=ブラウザ)から利用実態を逆算する方針が会議で決定
- v6.4.3-review に対するソースレビューで指摘された 5 点を改修し v6.5-review として本計画の対象とする

### 1.3 改修履歴(v6.4.3-review → v6.5-review)

| # | 指摘 | 改修内容 |
| --- | --- | --- |
| 1 | CSV 式注入対策 `Safe` の正規表現が `@-` を文字クラス範囲として解釈される(POSIX 文字 range 扱い)恐れ | `[=+@\-]` にエスケープ修正 |
| 2 | 出力ファイル書込後の読み戻し検証がない | `WriteAllTextVerified` を新設し、status.json・CSV/JSON・COMPLETE.txt は書込後に読み戻し検証 |
| 3 | XLSX 出力先が USB 上であることの確認が `PathHasReparse` のみ | `AssertOnUsb` を追加し、CreateWorkbook 冒頭で USB 上であることを明示確認 |
| 4 | 出力ディレクトリ作成後の reparse point 再検査が EnsureSafeDir 内のみ | 作成直後に `Get-Item` で再検査を追加(TOCTOU 緩和) |
| 5 | XLSX 作成中の USB 抜去時に Metadata シートの Finished/Completion が反映されない | `$metaCopy`(pscustomobject)を作り、XLSX 用 Metadata に確定値を反映 |
| 6 | catch 節内で WriteState 失敗時に fatal 記録自体が失われる | try-catch を二重化し、 fatal 記録の失敗を許容 |

## 2. システム構成

### 2.1 サブシステム構成

```
LNB Collector (Collect_LNB.ps1: 単一スクリプト、機能単位で関数分割)
├─ S1: USB 識別サブシステム    GetUsbIdentity / RegisterUsb / VerifyUsb
├─ S2: 依存検証サブシステム    ValidateDependency (ImportExcel 7.8.10)
├─ S3: 自己テストサブシステム  SelfTest (14ケース) / Parser.ParseFile
├─ S4: 出力サブシステム        EnsureSafeDir / PathHasReparse / WriteState / Utf8File / WriteAllTextVerified
├─ S5: 収集サブシステム        Stage (CIM 6種 / Get-Process / ExcelRecent / OfficeInfo / Recent)
└─ S6: 帳票サブシステム        MakeTable / CreateWorkbook (Export-Excel + Open-ExcelPackage 検証)

起動用 CMD (Run_LNB.cmd / TEST_LNB.cmd / Register_USB.cmd / PREPARE_USB.cmd)
```

### 2.2 各サブシステムの機能概要

| サブシステム | 機能概要 | 依存先 |
| --- | --- | --- |
| S1 USB 識別 | スクリプト配置位置=USBルート確認、BusType/ディスクシリアル/ボリュームシリアル照合、登録マーカー(LNB_USB_ID.txt)の作成・検証 | Windows Storage cmdlets |
| S2 依存検証 | `tools\ImportExcel\ImportExcel.psd1` の存在・版(7.8.10)・reparse point 有無・実ロード元確認 | S1 |
| S3 自己テスト | パス判定(MruPath/DocPath)、CSV 式注入対策、空ヘッダー、構文パーサーの14ケース | なし |
| S4 出力 | 出力ディレクトリの安全な作成(一段ずつ・reparse 検査)、status.json/CSV/JSON の逐次書込と読み戻し検証 | S1 |
| S5 収集 | CIM 6種(OperationTimeoutSec=10)、プロセス(上限500+501件目観測)、Excel MRU(HKCU Office 14/15/16、上限500)、Recent(過去30日 .lnk、上限500)、Office C2R メタデータ | S4(逐次書込) |
| S6 帳票 | 13シート(10収集+Metadata/SelfTest/Status)の XLSX 作成、再open によるシート数・次元検証、Status シートへの xlsx 行追記 | S2, S4, S5 |

### 2.3 外部インターフェース

| IF | 内容 | 方向 |
| --- | --- | --- |
| IF-1 | 対話: 標準入力(ライン指定、`YES` 同意) | 入力 |
| IF-2 | USB 上 `data\LNB_調査\<Lx>_<PC>_<時刻>_<GUID>\` へのファイル出力(CSV/JSON/XLSX/COMPLETE.txt) | 出力 |
| IF-3 | USB 上 `LNB_USB_ID.txt`(登録マーカー)の読書き | 入出力 |
| IF-4 | HKCU レジストリ(Office Excel MRU)・HKLM(C2R 構成)の読取 | 入力(読取専用) |
| IF-5 | ローカル CIM(Win32_* 6種)、Get-Process | 入力(読取専用) |
| IF-6 | ImportExcel 7.8.10(Export-Excel / Open-ExcelPackage) | ライブラリ呼出 |

## 3. テスト対象

### 3.1 対象機能(結合テスト)

| No | 対象 | 種別 | 優先度 |
| --- | --- | --- | --- |
| T1 | 起動 CMD → S3 自己テスト → S1 USB 検証 → S2 依存検証 → 収集 → S4 逐次出力 → S6 帳票 → 終了コード | バッチ/CLI | 高 |
| T2 | S1: 登録(Register_USB.cmd)→ 検証(収集時自動)の連携 | CLI | 高 |
| T3 | S5 各 Stage → S4 WriteState の逐次連携(Stage ごとに CSV/JSON/status.json が更新される) | 内部 | 高 |
| T4 | S5 収集結果 → S6 XLSX 13シートへの反映と再open検証 → COMPLETE.txt 生成の連携 | 内部 | 高 |
| T5 | S4: 異常時の連携(出力先改変・USB 抜去を想定した検査の失敗 → 停止と部分出力) | 内部 | 中 |
| T6 | 終了コード体系(0/2/3/5/10)と COMPLETE.txt の有無の整合 | CLI | 中 |

### 3.2 対象外

- 対象外データ(ブラウザ履歴・資格情報・文書内容・プロセス引数・ウィンドウタイトル・ショートカットリンク先・Excel COM)が**取得されないことの確認**はセキュリティチェックリストの静的レビューで実施済み(v6.4.3-review 時点)。結合テストでは収集結果の値域から偶発混入がないことを確認するにとどめる
- ImportExcel 7.8.10 モジュール自体の品質(組織承認済み前提)
- Windows 実機以外の環境(PowerShell 7、非 Windows)は対象外

## 4. 開発方法論と本計画の位置づけ

**手法: ウォーターフォール(小規模・単一リリース)**

- 本ツールは一度の配布で運用に入る単発ツールであり、要件(LNB管理書の記入項目)は会議で確定済み
- 段階: ソースレビュー(完了) → 改修(完了) → **結合テスト(本書)** → 実機検証 → 組織承認 → 配布
- テスト実施者=改修者と異なることが望ましい(本計画では実機側の実施者を記載する欄を設け、レビュー担当者の立会いを推奨)

## 5. テスト目的と範囲

### 5.1 目的

1. サブシステム間の連携(S1→S2→S5→S4→S6→終了コード)が仕様どおり動作することを確認する
2. 改修 6 点が意図どおり機能し、既存機能に退行がないことを確認する
3. 異常系(依存不備・マーカー不備・出力先異常)で**安全に停止し、偽の完了表示(COMPLETE.txt)を出さないこと**を確認する

### 5.2 範囲

- 対象: §3.1 の T1〜T6、Windows PowerShell 5.1 Desktop 実機、組織承認済み USB
- 実施可能な環境での先行実施(§7 の環境 A/B)、実機のみで可能な項目は環境 C で実施

---

## 6. テスト観点と手法

### 6.1 機能間連携の検証方針

| 連携 | 検証方針 |
| --- | --- |
| CMD → PS1 | 各 CMD が正しいスイッチで PS1 を起動し、終了コードを正しく伝播すること(`echo Exit code` と `exit /b`) |
| S1→S5 | VerifyUsb が収集開始前・Stage 毎・書込毎に呼ばれ、USB 交換/抜去を検知して停止すること |
| S5→S4 | 各 Stage 完了直後に status.json と CSV/JSON が更新されること(途中終了時に部分結果が残る) |
| S5→S6 | 収集行数(0件含む)が XLSX の各シート行数(=行数+ヘッダー1)と一致すること |
| S6→完了判定 | 13シート再open検証成功後にのみ COMPLETE.txt が最後に書かれること |

### 6.2 インターフェースの検証方針

| IF | 検証方針 |
| --- | --- |
| IF-1 対話 | ライン不正値(`L4` 等)、`YES` 以外の入力で exit 2 となり収集が開始されないこと |
| IF-2 出力 | 出力パスが `<Root>\data\LNB_調査\` 配下に限定されること。ディレクトリ/ファイルに reparse point を設定した場合に拒否されること |
| IF-3 マーカー | 未登録/破損/別USBコピーのマーカーで停止すること。既存マーカーの上書き拒否(RegisterUSB) |
| IF-4 レジストリ | MRU の値に URL・ADS・機微名称を混在したテストデータで、Filtered/REDACTED の動作を確認(環境 B のレジストリ mock または実機の一時キー) |
| IF-5 CIM/プロセス | 6種 CIM が OperationTimeoutSec=10 で応答し、NoData/Partial が正しく記録されること |
| IF-6 ImportExcel | manifest 版不一致・モジュール不在・ツリー内 reparse で収集前に停止すること(PrepareOnly で確認) |

### 6.3 エラーケースの検証方針

| 分類 | ケース | 期待結果 |
| --- | --- | --- |
| 依存系 | ImportExcel 不在/版不一致/reparse | 収集前に停止、exit 5、出力なし |
| USB 系 | マーカー不存在/シリアル不一致/ドライブ文字変更 | 停止、出力なし |
| USB 系 | 出力パス内に junction 作成 | `Reparse point in output path` で停止、COMPLETE.txt なし |
| 出力系 | XLSX が既に存在する状態で再実行 | `refusing overwrite` で停止 |
| 出力系 | 書込検証失敗(書込直後に読めない) | WriteAllTextVerified が throw、COMPLETE.txt なし |
| 入力系 | ライン不正/`NO` 入力 | exit 2、収集開始前 |
| 自己テスト系 | TestOnly で1件でも失敗 | exit 3 |
| 収集系 | CIM 応答なし(網羅は困難、観測のみ) | Stage が Failed として記録され、収集継続/部分出力 |
| 完了系 | 警告あり完了 | exit 10、COMPLETE.txt は CompletedWithWarnings |

## 7. テスト環境要件

| 環境 | 構成 | 実施可能項目 |
| --- | --- | --- |
| A: 作業用 PC(現環境) | Windows PowerShell 5.1、非 USB の NTFS ドライブ | S3 自己テスト(TestOnly)、構文検証、CMD の起動伝播確認。※S1 は USB 要求のため不可 |
| B: 作業用 PC + 承認済み USB | 上記 + 組織承認 USB + ImportExcel 7.8.10 配置 | S1 登録/検証、S2 依存検証、PrepareOnly、TestOnly |
| C: LNB 端末相当(実機) | Windows 5.1、共用アカウント、承認済み USB、利用者説明済み | T1〜T6 の全項目(本番相当の結合テスト) |

**必須ソフトウェア**: Windows PowerShell 5.1 Desktop / ImportExcel 7.8.10(組織承認済み一式) / マルウェア対策(社内指定)

**制約**: 環境 A/B では Get-Disk の BusType=USB 判定・実 USB シリアルの検証ができないため、S1 の実機依存部は環境 C で実施する。

## 8. テストデータ要件

| データ | 用途 | 作成方法 |
| --- | --- | --- |
| MRU テスト値 | IF-4 検証: 正常パス/URL/ADS/機微名称/空値を含む File0〜FileN | レジストリ一時キーに手動設定(実施後削除)。実機では行わない(環境 B のみ) |
| .lnk ファイル | Recent: 正常/機微名称(→[REDACTED])/30日超(→対象外) | 環境 B の `%APPDATA%\Microsoft\Windows\Recent` に一時作成(実施後削除)。実機では行わない |
| junction | 出力パス内 reparse 検知 | `New-Item -ItemType Junction`(環境 B/C の USB 上、テスト後削除) |
| 改変マーカー | DiskSerial/VolumeSerial 不一致、GUID 破損 | LNB_USB_ID.txt を編集したコピー USB または編集→復元 |
| ImportExcel 異常配置 | 版不一致(psd1 の ModuleVersion 書換)/不在/reparse | 環境 B の `tools\ImportExcel` を一時的に改変(実施後、正規版に戻しハッシュ確認) |
| 収集 0 件状態 | 空シート/空 DataTable のヘッダー保持確認 | CIM 結果が空になる前提が作れないため、空 CSV/JSON は S3 の「CSV header on empty」テストで代替 |

**機微情報**: テストデータに実在の個人情報・認証情報を含めない。テストで読んだ実レジストリ値は出力物ごと機微情報として管理し、確認後は USB ごと組織ルールに従って消去する。

## 11. 合否基準

### 11.1 合格条件(すべて満たすこと)

| # | 基準 |
| --- | --- |
| C1 | 環境A: SelfTest 14ケース全 PASS、Parser エラー 0 |
| C2 | 環境B: Register → PrepareOnly が exit 0。依存異常系(不在/版不一致/reparse)がすべて収集前に停止 |
| C3 | 環境C: 正常系 1 回が exit 0 または 10 で完了し、COMPLETE.txt・LNB_Collector.xlsx(13シート)・status.json が生成される |
| C4 | 環境C: XLSX の 13シート名・列数・行数が status.json/CSV と一致する(0件シートはヘッダーのみで列数一致) |
| C5 | 環境C: 異常系(junction 設置/マーカー改変/XLSX 上書き/`NO` 入力)が期待どおり停止し、**COMPLETE.txt が存在しない** |
| C6 | 収集値に機微データ(パスワード・資格情報・ブラウザ履歴・文書内容)が含まれない(出力物の目視確認) |
| C7 | 終了コードと COMPLETE.txt の内容(Completed/CompletedWithWarnings)が整合する |

### 11.2 不合格の扱い

- 1 件でも不合格があれば環境 C の展開を中断し、改修→環境A/B 再試験→環境C 再実施とする
- 警告付き完了(exit 10)は、Status シートの Detail に原因が記録されていれば合格(C3)とする。原因不明の警告は不合格

## 12. リスクと対策

| # | リスク | 影響 | 対策 |
| --- | --- | --- | --- |
| R1 | CIM/OS provider の遅延で実行時間が読めない | 現場滞在時間の超過 | 実行時間の目安を現場へ周知(数十秒〜数分)。タイムアウト時は Status の Failed を確認して判断 |
| R2 | USB シリアルが OS/ブリッジで取得できない環境がある | S1 が停止し収集不可 | 推測/fallback はしない設計。該当端末は「収集不可」として記録し、代替手段は別途承認を取る |
| R3 | テストデータ(実レジストリ値)の機微情報混入 | 情報漏えい | 出力物は機微情報として管理。確認後、USB 内出力は組織ルールで消去 |
| R4 | 未署名スクリプトの実行ポリシー拒否 | 実行不可 | 組織の承認済み署名手順を事前に完了させる(回避策は使わない) |
| R5 | ImportExcel 承認版の入手遅延 | スケジュール遅延 | 依頼を先行。入手まで環境B/Cに進まない(自動DL・代替版は禁止) |
| R6 | 共用アカウント端末での説明不足 | 利用者懸念 | 収集範囲(MRU/Recent は使用証明ではない旨)を現場説明資料として提示 |
| R7 | XLSX 作成中の USB 抜去 | 部分出力/偽完了 | COMPLETE.txt は最終書込のため偽完了は起きない設計。テストで C5 を確認 |
