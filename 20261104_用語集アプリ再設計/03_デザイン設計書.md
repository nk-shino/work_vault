## 1. デザインコンセプト

### 1.1 一文の命題（提案）

**「朱は、人の手が入ったところにだけ刷る。」**
自動判定が育てた辞書の上に、人の判断（評価・採用・訂正・注意）だけを朱色で刻む。探す速さは索引と共有要素遷移で担保し、辞書の校正刷りのように、どこに人の手が入ったかが一目で分かる用語集にする。

### 1.2 根拠

| 根拠 | 内容 |
|---|---|
| アプリの原理 | 自動採用と人の採用を区別し、未評価を確認済みと見せない規律が既にある（確認済み: `README.md` 運用の決定事項 2026-09-28、`src/glossary/db/models.py` `ADOPTED_BY`）。視覚言語はこの規律の表現に使える |
| 業務の文脈 | 用語集の主な人の作業は「評価・訂正・裁定」。日本語の校正・検印の文化では朱が訂正と承認の色。作業の色として意味が直接伝わる |
| 現状の資産 | 定義文の明朝組版・下線規律・色非依存の badge など、編集的な規律は既に成立している（確認済み: `style.css`）。再構築はこれを「辞書の組版」として完成させる方向 |
| UI 改善要請 | 「使っていて楽しくない→使用率に効く体験を」（確認済み: `_docs/用語集アプリ_進捗_1002.md`）。奇抜さではなく、引く速さ（索引・共有要素遷移）と手応え（朱印・即時フィードバック）で答える |

### 1.3 視覚言語の三層

| 層 | 色 | 担う意味 |
|---|---|---|
| 紙と墨 | 和紙白＋墨 | 辞書の地。本文・定義・表。動かない規律 |
| 緑青 | 深緑青 | 構造と導線。リンク・フォーカス・進行。押せるところ・進むところ |
| 朱 | 朱色 | 人の手。評価・採用・訂正・混同注意・履歴の訂正線。自動には刷らない |

## 2. 設計原則（7 項目）

1. **辞書の組版を完成させる** — 見出し語は明朝の大見出し＋読み（ルビ位置）＋英語・略語のメタ行。語義番号は朱。定義は明朝・行間 1.9（現行維持）。UI 部品は角丸・余白のトークンで統一する
2. **朱は人の手に限る** — 自動生成（AI 草案・自動採用・統計の関係）には朱を使わない。評価ボタン・採用印・訂正履歴・混同注意に限る。色の意味は画面の規律として `03` 文書とテンプレートのコメントで守る
3. **引く操作を最短にする** — `Ctrl+K` のパレット・`/` フォーカス・一覧→詳細の共有要素遷移。どの画面からでも 2 キー以内で検索を始められる
4. **状態は帯と印で示す** — 成功/注意/エラーは帯（D-C2 引継ぎ）。処理待ち・未評価などの状態は badge（色＋文字併記）。トーストや幕は作らない
5. **鍵盤で完結させる** — j/k/a/r/x のトリアージ（現行維持）を一覧・見直しにも広げ、`?` で一覧を出す。入力欄では無効（現行の規律）
6. **動きは意味の変化にだけ付ける** — 共有要素遷移・朱印・帯の登場など「何が変わったか」が分かる場面に限る。hover での浮き上げ等の装飾的な常時運転は作らない
7. **壊れない段階的強化** — 新 API は全部機能検出つき。未対応環境では現行と同等の画面。テストが見る文言を壊さない

### 3.5 一覧と詳細の共有要素遷移の割付け（提案）

- 一覧の見出し語リンクに `view-transition-name: hw-<term_id>`（行ごとに一意）。
- 詳細ヒーローの見出し語に同じ名前。戻る遷移でも逆方向に効く（`@view-transition { navigation: auto }` を両テンプレートで有効化）。
- root（ページ全体）は 120ms のクロスフェードのみ。既存の `main` rise は VT 有効時には運転しない（二重運転の回避）。

| 名前と状態 | 新規部品のすべてに label（id＋label または sr-only）。パレットは combobox（aria-expanded/activedescendant）。朱印ボタンは role=group の中で名前を持つ。帯は role=status・エラーは role=alert（現行規律） | `test_all_inputs_have_labels` の回帰＋コード点検 |
| 色非依存 | badge は文字併記・評価状況点は文字（title/sr-only）つき・diff は＋/− 記号つき・朱/緑青/黄の区別は位置と文字でも成立 | スクリーンショット目視＋コード点検 |

## 7. モーション設計体系

### 7.1 モーショントークン

| トークン | 値 | 用途 |
|---|---|---|
| `--dur-1` | `100ms` | 押下応答（朱印・ボタン）。入力応答の上限 |
| `--dur-2` | `180ms` | hover・popover・小さな開閉 |
| `--dur-3` | `260ms` | パレット・ページ遷移・帯の登場。主要遷移の基準値 |
| `--dur-4` | `420ms` | タイムラインの線の成長（スクロール駆動。遷移ではない） |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 出現・入場（減速で着地） |
| `--ease-inout` | `cubic-bezier(0.65, 0, 0.35, 1)` | 共有要素遷移（往復で対称） |
| `--ease-stamp` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | 朱印のスタンプ（小さな要素限定の跳ね） |
| stagger 規律 | 遅延 `calc(var(--i) * 30ms)`・最大 6 項目・合計 ≤ 180ms | 検索結果の順次出現 |

時間の目安は要件（遷移 150〜300ms・入力応答 ≤100ms）をトークンで実装したもの（NFR-005）。

### 7.2 振付の規則

1. **1 場面 1 焦点** — 遷移の主役は共有要素（M-01）か状態の変化（M-05/M-06/M-09）のどちらか一方。
2. **stagger は≤6 項目・30ms 刻み** — 7 項目以上は順次出現させず全体フェード。
3. **動かすのは opacity と transform** — layout（幅・位置の再計算）を動かさない。例外は CSS アンカー配置（popover の位置決め）のみ。
4. **入力を妨げない** — 動きの間も操作を受け付ける。全画面のオーバーレイ・幕は作らない。
5. **reduce では「止める」ではなく「同じ情報を即時に」** — 全停止（現行規律）を維持しつつ、パターンごとに代替の見え方を定義する。
6. **二重運転の禁止** — View Transitions 有効時は `main` の既存 rise を運転しない。JS で `document.startViewTransition` の有無を見て切り替える。

### 7.4 不採用の記録（モーション）

| 項目 | 理由 |
|---|---|
| 読み込み幕（Curtains 系・loading タグの実例） | 業務ツールで作業を待たせる演出は要件違反（§4 の前提）。採用するなら初回のみ・スキップ可だが、ローカル即起動なので待ちが存在しない |
| 漂い・パララックス・スクロール語り（Awwwards 系・ScrollTrigger 実例） | 読解を妨げる。文字主体の業務画面に不要 |
| 1 文字ずつのテキストリビール（SplitText・ICS の手法） | 見出し語は読み取り・選択・読み上げの対象。分割は copy/SR に悪影響 |
| カスタムカーソル・マグネティック hover | 業務での精度を落とす。キーボード利用者に無意味 |
| WebGL・3D・Lottie・SVG 線画ライブラリ | 依存と容量の割に情報量ゼロ。つながり図は依存なしの静的 SVG で足りる |
| GSAP・Anime.js 等のライブラリ同梱 | 本書の全パターンがネイティブ API で実装可能。同梱は NFR-002 の「必要性の説明」を満たさない |
