## 3. 採用する指針

### Atlassian Design System

- 見出しは新しい内容の区切りを導入するために使い、太字やサイズ変更ではなく見出しスタイルで構造を示す。h1 は 1 ページ 1 つ、レベルは飛ばさない（Typography）
- 長文の本文には Body L（既定より 1 段大きいサイズ）を使う（Typography）
- 視覚的な階層と余白で複雑な情報を整理する（Typography の原則）
- 空状態は「見出し＋説明＋次の操作」で構成し、操作は 1 つに絞る。文言は簡潔にする（Empty state usage）
- 画面の一部への注意は section message で伝え、色だけで重要度を示さず本文で説明する。対応手段を示して行き止まりにしない（Section message usage）

### Carbon Design System

- 長文の読解には expressive、タスク中心の画面には productive のタイプスタイルを使い、画面の構造に応じて使い分ける（Typography overview）
- SemiBold はセクション見出しに使い、長文には使わない（同）
- 本文の色はニュートラルに保つ。主要色は主操作とリンクに限り、色を装飾に使わない（同）

### GOV.UK Design System

- details は「一部の利用者にだけ必要な情報」を畳んでページをスキャンしやすくするために使う。大半の利用者が必要とする情報は畳まない（Details）
- details はタブやアコーディオンより目立たないため、重要度の低い内容に向く（同）
- 警告はアイコン（装飾）＋太字の本文で伝え、警告であることはテキストで示す。アイコンの意味は隠しテキストで補う（Warning text）

## 4. 現状のまま維持するもの

取得した指針と一致している箇所。改善の対象から外す:

- 状態のテキスト併記（バッジ「状態：○○」）: Section message の「色だけで示さない」と一致
- AI チップ＋ title 属性: 出自の表示方針を維持
- 定義の明朝＋行間 1.9＋左罫: 長文読解のための体裁で、Carbon の expressive／Atlassian の Body L の趣旨と一致
- 混同注意の呼び出し（アイコン＋本文＋文言）: GOV.UK Warning text と同型。文言は変更しない
- 見出しレベルの順序（h1→h2→h3→h4、レベルを飛ばさない）: Atlassian Typography の条件を満たす
- 空状態の 3 段構成と操作リンク 1 つ: Atlassian Empty state の構成と一致
- details 2 件（関連語追加・アーカイブ）: 「一部の利用者にだけ必要な情報」の条件に一致。アーカイブは破壊的操作なので畳むのは妥当
- 色の変数管理と OS 明暗追従、reduced-motion 対応: スキルの原則どおり

## 6. 見送りとその理由

| 見送り | 理由 |
|---|---|
| MDN 自体の模倣（レイアウト・部品の移植） | MDN は使用指針を公開しておらず、根拠を示せない。方向の分解は 2. のとおり |
| GOV.UK Typography の参照 | 2 回取得したが本文を取得できなかったため参照を見送った。行長（読み幅）の指針は今回根拠に使えない |
| 本文カラムの読み幅調整 | 根拠となる指針を取得できていない。必要になった時点で別途調査する |
| サイドナビ・目次・タブ等のレイアウト移植 | 参照先はドキュメントサイトで、情報量と利用者の文脈がこのアプリと異なる。部分採用の失敗パターンに該当 |
| 見出しホバーでのアンカーリンク表示 | 採用候補 3 システムの指針に根拠がない。要望が出た時点で改めて調査する |
| 評価フォームの fieldset/legend への変更 | 現行の `role="group"`＋aria-label で同等の機能を満たし、参照した指針にも対応する記述がない |
| hero の meta（float レイアウト）の grid 置換 | デザインシステムの指針の範囲外（実装品質の課題）。折返しで崩れる等の実害を確認してから対応する |
| 関連語の表形式化 | 読み物としての流れを優先する現構成を維持する。スコア等の補足は現行の small 併記で足りる |
| 絵文字による状態の追加 | スキルの原則（SVG かテキストで示す）に反する |

## 7. 判断が必要な点

実装前に決定が必要な設計上の分岐:

1. **評価フォームを折りたたむか（候補 A6）**: GOV.UK Details は「大半の利用者が必要とする情報は畳まない」ことが前提。このアプリは「自動採用された定義は読んだら評価してください」という運用を画面に書いているため、畳むと運用と衝突する恐れがある。折りたたむ場合は、自動採用の語義では初期状態を開く設計が必要。畳まない場合は A6 を外し、A4（余白と区切り）だけを適用する
2. **語義メタ行の並び順（候補 A1・A5）**: 現行は「文脈 → 出どころ → 採用方法 → AI」の順。並び替えるなら、どの情報を先に見せるか（例: 出どころ → 採用方法 → 文脈 → AI）の決定が必要
3. **隠し接頭語の文言（候補 A3）**: 音声読み上げに影響するため、実装前に文言（例「警告。」）を確定する必要がある。画面上の表示は変わらない
