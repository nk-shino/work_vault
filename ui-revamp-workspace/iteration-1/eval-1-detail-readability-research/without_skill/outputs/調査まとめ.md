# 用語詳細ページ 読みやすさ改善 調査まとめ（公開デザインシステムの部分採用の判断）

- 作成日: 2026-10-22
- 対象: `C:\work\用語集アプリ\src\glossary\web\templates\term_detail.html`（読み取り専用で参照）
- 目的: 用語詳細ページを MDN の用語説明ページに近い読み物として成立させるため、公開されているデザインシステムの使用指針を一次資料で確認し、このページに取り入れる範囲（部分採用の判断）を決める
- 範囲: 調査と判断の記録のみ。実装・コード変更はしていない

## 結論（先に要点）

- 目標の「雰囲気」は MDN の用語ページ（Glossary）を実ページ観察と公式の書き方指針から定義する。MDN はデザインシステムとしての使用指針を公開していないため、雰囲気の基準と数値の基準を別の源から取る
- 数値・様式の基準は「デジタル庁デザインシステム」（以下 DADS）から部分採用する。DADS 自身が「導入先専用のローカルデザインシステムを作って使うこと」を前提にしており、部分採用は想定内の使い方である
- 最優先の改善点は情報の順序と視覚の順位である。「見出し語 → 定義 1〜2 文 → メタ情報 → 詳細」の順に再構成し、語義本文に本文 16px 以上・行高 160% の読み物基準を適用する
- 全面採用はしない。コンポーネント置換、行政向け作例、Display 級の文字サイズ、MDN 式の多義語ページ分割は、このページの目的と仕様に合わないため採用しない

## 1. 対象ページの現状と観察

`term_detail.html`（119 行、Jinja2 テンプレート）の構成は次のとおり。スタイル本体は `base.html` と静的 CSS 側にあり、今回の調査では未確認である。以下の観察は HTML 構造から読み取ったものである。

1. パンくず（用語一覧 ／ 見出し語）
2. hero: h1 に見出し語と状態バッジ。dl に読み・英語・略語・版と履歴リンク。編集リンク行
3. 混同注意セクション（svg アイコン + h2 + 説明 + リンクリスト）
4. 語義ループ（article.sense）: h3 に「語義 N」＋状態バッジ＋文脈タグ＋出どころ＋採用者＋AI チップ。係争中のときは警告段落。定義文。適用範囲。h4 で用例（引用 + 日時 + 出典）。編集・履歴リンク。h4 で評価フォーム（正確性 3 択、有用性 2 択、コメント入力）と評価コメント一覧
5. 関連語: 関係種別ごとに h3 + リンクリスト（方式・スコア付き）
6. `<details>` で関連語追加フォームとアーカイブフォーム

### 構造から見えた課題

- 定義が最初に来ない。h1 の直後はメタ情報（dl）と編集リンクで、定義文は語義セクションまで進まないと読めない。MDN の用語ページは冒頭 1 段落で定義が完結する
- h3 に情報が集中している。「語義 1」の見出し行に最大 5 種のラベル（状態・文脈・出どころ・採用者・AI）が並び、定義文へ視線を進める動きを妨げている
- 定義文が強調されない。定義・用例・評価フォーム・コメントが同一 article 内で同ランクに並び、本文の連続性が操作系で中断される
- 管理情報と内容が同じ視覚ランクにある。版番号・履歴・マスキング表記・スコアは運用に必要だが、読み物の本文と同格に置かれている
- 複数語義の区別が番号主体である。文脈タグがあるのに「語義 1, 2」が見出しの主役で、文脈から語義を探す動線になっていない
- 警告の表現が統一されていない。混同注意はアイコン付きセクション、係争中は警告段落で、注意情報の様式が 2 種ある

## 2. 目標の雰囲気: MDN 用語ページの観察

### 実ページの観察（Glossary/HTML、2026-10-22 時点）

- パンくずは短く 2 階層（用語集 ／ HTML）
- h1 は見出し語だけ。状態表示や装飾を持たない
- 冒頭 1 段落で定義が完結する。太字の見出し語 + 1〜2 文の説明
- 本文が長いページだけ目次（アンカー）を置く
- 章立ては h2（略歴、概念と構文）。定義文中の関連用語は文書内リンクになる
- 末尾に「関連情報」（See also）を置き、外部資料・チュートリアル・仕様書をまとめる
- 最終更新・編集者・GitHub へのリンクはページ最下部で控えめに示す
- 本文カラムは狭く、右サイドバー（用語索引）は補助。広告や操作 UI を本文中に挟まない

### MDN 公式の書き方指針（一次資料）

- 用語ページ（Glossary page）は簡潔な説明のページで、冒頭は自己完結した 1〜2 文とする
- 1 画面を超える長さになるなら概念ページへ分割する
- 多義語は disambiguation（曖昧さ回避）ページとし、文脈ごとに子ページを定義する。page-type は glossary-definition / glossary-disambiguation を使い分ける
- See also は末尾に置き、関連トピックへの相互参照を集める

### MDN を基準にできない部分

- MDN のデザインシステムは公開されていない。旧 design system「mdn-minimalist」は 2022 年 2 月にアーカイブされ更新停止、現行フロントエンド「fred」（2025 年末稼働）も使用指針を公開していない
- このため判断は次のように分けた。ページ構造・情報の順序・文体は MDN の実ページと書き方指針から採る。文字サイズ・行高・余白・コントラストなどの様式基準は、使用指針を公開しているデザインシステムから採る

## 3. 調査した公開デザインシステムと使用指針

### 3.1 デジタル庁デザインシステム（DADS）β版 v2.18.2 ― 様式基準の主な供給源

**使用指針の骨子。** DADS は「プラットフォーム型デザインシステム」で、組織固有のブランドを持たない。導入先で直接使うのではなく、導入先専用のローカルデザインシステムを定義してから使うことを前提にしている。デザイントークン（キーカラー・角の形状・余白など）の初期値は「編集の起点」であり、サービスごとに置き換えてよい。フル採用を求める文書にはなっていない。

**編集してよい範囲（ローカルデザインシステム指針より）。** カラー（キーカラー置換・共通カラー追加・セマンティックカラーの調整）、タイポグラフィ（用途に応じたサイズと行高の追加・変更）、余白（基準単位と倍率スケールの設定）、角の形状、エレベーション、リンクテキスト（青以外の色相も許容）、レイアウト（カラム割り・ブレークポイント数）。

**編集後も維持すべきアクセシビリティ要件（骨格）。**

- テキストと背景のコントラスト比 4.5:1 以上、非テキストは 3:1 以上
- セマンティックカラーの「色相と意味の結びつき」は変更しない
- 本文・UI は 16 CSS px 以上が基準。読み物コンテンツの本文の行高はフォントサイズの 1.5 倍以上
- 余白の間隔値に規則性を持たせ、インタラクティブ要素のターゲットサイズを確保
- リンクは色以外の識別手段と組み合わせる。青以外を使う場合は色覚多様性と「リンクと認識できること」に配慮
- リキッドレイアウトを採用し、視覚配置と読み上げ順序を一致させる
- コンポーネントのフォーカスインジケーターは変更してはならない。強制カラーモード対応を維持する
- コードスニペットは環境に合わせて書き換えてよいが、WAI-ARIA 指定や強制カラーモード対応を取り除いてはならない

**タイポグラフィの規定（概要ページ・更新履歴より）。**

- フォント: Noto Sans JP（本文）＋ Noto Sans Mono（等幅、コード等）。いずれも SIL Open Font License 1.1 のオープンソース
- ウェイト: N（400）と B（700）の 2 種に整理
- サイズ: 本文・UI は 16px 以上を基準。14px は付随情報や領域制約時のみ。14px 未満は原則として許容されない
- 行高の目安: 100%（ボタン等）/ 120〜130%（管理画面・情報量優先）/ 140%（見出し）/ 150%（本文の最低限度）/ 160%（本文の標準）/ 170〜175%（心理的負荷の軽減）
- 用途別テキストスタイル（Display・Heading・Standard・Dense など 5 種）。Display は 48〜64px の視覚的インパクト用

**レイアウトの規定（概要ページより）。** 基本は 12 カラムグリッド（1 カラム基本構成も可）。ブレークポイントは 1 つ、768px（未満がモバイル・タブレット、以上がデスクトップ）。カラム幅は本文文字サイズの整数倍、ガターは本文文字サイズの 2 倍。

**余白の規定（概要ページより）。** 基準単位は 8 CSS px が一般的。余白スケールは 3〜5 段程度（適用例は 8/24/64 の 3 段）。同種の要素には同じ間隔値を使い、関連の強い要素は余白を小さく、階層が上の要素は余白を大きく取る。

**ライセンス。** 政府標準利用規約（第 2.0 版、CC BY 4.0 互換）。Figma データ・コードスニペットも同様。改変や独自コンポーネント追加は可能で、アクセシビリティ適合の保証は改変前の状態に限る旨が案内されている。

**一次資料と二次情報の差異への注意。** 技術ブログではブレークポイント「520/960px」、余白「フィボナッチ数列」と紹介される例があったが、一次資料（v2.18.2、2026-10-22 確認）は「768px（1 箇所）」「基準単位 8 CSS px・スケール 3〜5 段」である。本まとめは一次資料の値を採用する。

### 3.2 MDN ― 構造と文体の供給源

3 章のとおり。デザインシステムとしての部分採用対象は「ページ構造と情報の順序」に限る。MDN の強みは用語ページの情報設計（定義ファースト・See also・disambiguation）にあり、色や余白の数値を供給する源ではない。

### 3.3 調査対象から外したもの

GOV.UK Design System、U.S. Web Design System、Material Design 等は今回見ていない。UI コンポーネント群の充実を主眼とするもので、読み物としての用語ページの様式基準には DADS で必要十分と判断した。実装段階でフォーム部品やボタンの細部が必要になった時点で参照する。

## 4. 部分採用の判断

判断基準は 3 つに置いた。①読みやすさの目的に効くか、②このアプリの既存仕様（1 ページ複数語義・評価フォーム・履歴）と整合するか、③DADS の維持要件（アクセシビリティ骨格）を満たすか。

### A. 採用する

| No | 採用内容 | 出典 | 対応する現状の課題 |
|---|---|---|---|
| A1 | 語義本文に読み物タイポ基準を適用: 16px 以上、行高 160%（最低 150%）。14px はメタ情報行までに制限 | DADS タイポグラフィ・ローカルDS要件 | 定義文が他要素と同ランク |
| A2 | 情報の順序を「見出し語 → 定義 1〜2 文 → メタ情報 → 詳細」に再構成。冒頭に最初の語義（または要約）を置く | MDN 用語ページ構造・書き方指針 | 定義が最初に来ない |
| A3 | 語義の h3 からメタ情報（状態・出どころ・採用者・AI・文脈）を外し、定義文の直下に小さめの 1 行へ集約。文脈タグは見出しの副題に昇格 | DADS 余白（関連性は余白で示す）・MDN disambiguation の考え方 | h3 の情報過剰、番号主体の語義 |
| A4 | 関連語を末尾の「関連情報」セクションに統一し、関係種別ラベルでグループ化。スコア等の内部情報はタイトル属性や折りたたみへ退避 | MDN See also 指針 | 関係種別ごとの h3 増加、内部情報の混在 |
| A5 | 操作系（評価フォーム・関連語追加・アーカイブ）を読み物カラムから区切って提示。既存の `<details>` 利用は方向として継続 | MDN（本文中に操作 UI を挟まない） | 評価フォームによる本文の中断 |
| A6 | 注意情報の様式を 1 種に統一（混同注意・係争中）。セマンティックカラーの意味（警告=注意色）を保ったままローカルで定義 | DADS 注釈ブロックの考え方・セマンティックカラー要件 | 警告表現の不統一 |
| A7 | キーカラー・角の形状・余白はローカルトークンとして自前で定義し、アクセシビリティ骨格（4.5:1 / 3:1、16px、行高 1.5 倍、フォーカス表示）を維持 | DADS ローカルデザインシステム指針 | 全体の基準の所在が不明確 |

### B. 条件付きで採用する

| No | 項目 | 条件 |
|---|---|---|
| B1 | フォント Noto Sans JP / Noto Sans Mono | ライセンス（SIL OFL 1.1）は問題なし。配信方法（セルフホストか Google Fonts か）と読み込みコストを確認してから。フォールバック指定を必ず残す。等幅は版番号・日時・コード用語の表示に有効 |
| B2 | 余白スケール（基準 8px・3〜5 段） | 既存 CSS の間隔値を確認のうえ段数を決める。既存値と新スケールの混在は避ける |
| B3 | DADS のコンポーネント作例（注釈ブロック・ボタン等） | コードスニペットはサンプルであり、環境に合わせて書き換える前提。WAI-ARIA・強制カラーモード対応は取り除かない |
| B4 | レイアウトの考え方（ガター=本文文字サイズの 2 倍、カラム幅=文字サイズの整数倍） | 用語ページは読み物なので 1 カラム（または本文+補助サイドバー）とする。12 カラム規定そのものは使わない |
| B5 | 目次（アンカー） | 語義が複数ある長いページのみ。MDN と同じ「長いページだけ」の条件 |

### C. 採用しない

| No | 項目 | 理由 |
|---|---|---|
| C1 | DADS のフル採用・コンポーネント全面置換 | ページの主体は読み物で、必要コンポーネントが少ない。DADS 自身がローカルデザインシステム経由の部分採用を前提としている |
| C2 | MDN 式の disambiguation ページ分割（語義ごとに別ページ） | 既存の「1 ページに複数語義」の仕様・データ構造と衝突する。A3 のとおり文脈を副題にして 1 ページ内で区別する代替とする |
| C3 | Display テキストスタイル（48〜64px）と行高 170%/175% | 用語ページの見出しは辞書的で、インパクト用の級数は過大。見出し 140%・本文 160% の範囲で足りる |
| C4 | 行政向けの作例・イラスト素材 | 対象が社内用語集であり用途が一致しない |
| C5 | ブレークポイント 768px 規定のそのまま適用 | 既存のレスポンシブ設計を未確認。実装時に既存と整合させ、衝突する場合は DADS 側の許容範囲（カラム割り・ブレークポイント数の変更可）で合わせる |

## 5. 次のフェーズへの引き継ぎ事項

- `base.html` と静的 CSS の確認。現行のフォント・色変数・間隔値が未調査のため、A1/B2 の具体値はそこで確定させる
- 採用した規定のバージョンを記録して進める。DADS は β 版（リビングスタンダード）で更新が続いており、本まとめの確認は v2.18.2（2026-10-22）
- ライセンスの帰属表示（政府標準利用規約・CC BY 4.0 互換）の要否を社内規程に沿って確認する
- AI チップ・マスキング表記・係争中ステータスはこのアプリ特有の情報で、DADS に対応するコンポーネントがない。ローカル定義として様式を文書化する（A6 と A3 で方向は決めてある）
- 実装後の検証項目: コントラスト（テキスト 4.5:1、非テキスト 3:1）、本文 16px・行高 1.5 倍以上、キーボード操作とフォーカス表示、強制カラーモード、リキッドレイアウト、ターゲットサイズ
